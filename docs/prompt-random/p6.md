## Objective

Eliminate genuinely unused application code, obsolete prototypes, orphaned modules, redundant exports, and unused dependencies.

**Do not confuse unused-looking code with dead code.**

This repository contains dynamically registered routes, CLI commands, workers, and server functions. Deletion must be justified by actual reachability and usage evidence.

Read:

- [AGENTS.md](http://AGENTS.md).
- All applicable `.agents/rules/`.
- [TODO.md](http://TODO.md) Bagian 4.
- Knip configuration and baseline.
- package.json files and workspace definitions.

Inspect the complete current dependency graph.

Use searches, TypeScript references, Knip results, and framework conventions.

Do not delete files from tool output alone.

## 2. Cleanup Categories

### A. Demo &amp; Temporary Routes

Inspect:

`src/routes/demo/tanstack-query.tsx`

Determine whether it is a production requirement, intentional development utility, or unused demonstration route.

If unused:

- Remove the route.
- Remove related unused imports/components.
- Regenerate the TanStack route tree.
- Verify no active navigation relies on it.

Inspect other demonstrably obsolete demo/spike files.

Do not delete active routes without verifying consumers.

### B. Orphaned Components &amp; Hooks

Audit:

- `src/components/ui/`
- `src/components/layout/`
- `src/features/*/components/`
- `src/features/*/hooks/`

Find unused components, hooks, helper types, and exports.

For every candidate, verify:

1. Static consumers.
2. Dynamic imports.
3. Re-exports.
4. Route registration.
5. Test consumers.
6. Framework conventions.
7. External/public contract requirements.

Delete only when no legitimate consumer or contract exists.

### C. Services, Utilities &amp; Schemas

Audit:

- `src/features/*/services/`
- `src/features/*/utils/`
- `src/lib/`
- Shared types and schema utilities.

Remove obsolete helpers, dead mock services, abandoned feature flags, and outdated compatibility shims only when safely proven unused.

Preserve:

- Database schema contracts.
- Security and authorization guards.
- Credit transaction logic.
- Webhook handlers.
- CLI integrations.
- Public API compatibility.
- Dynamic module entrypoints.

Do not interpret an exported API handler as unused simply because nothing imports it directly.

### D. Dependencies

Run the configured Knip audit.

Review dependencies in:

- Root package.json.
- CLI package.json.
- Shared tooling.

Verify whether packages are used by:

- Application runtime.
- Build tools.
- Configuration.
- CLI.
- Scripts.
- Code generation.
- Tests.
- Dynamic imports.

Remove truly unused packages with the project's package manager.

Update lockfiles properly.

Never manually delete package entries without dependency reconciliation.

## 3. Do Not Perform Mass Deletion

Avoid:

- Bulk removal based on filename patterns alone.
- Deleting all re-export facades.
- Removing test utilities still used by suites.
- Deleting old compatibility routes without contract verification.
- Removing apparently unused security code.
- Removing public SDK/CLI exports without compatibility analysis.

For high-risk candidates, document the finding and preserve the module until evidence is sufficient.

## 4. Deletion Ledger

Before editing, create an internal audit table:


| Candidate      | Evidence                       | Consumer status    | Risk            | Decision          |
| -------------- | ------------------------------ | ------------------ | --------------- | ----------------- |
| File or export | Search/Knip/reference evidence | Active or inactive | Low/Medium/High | Remove/Keep/Defer |


For every removal, record why it was safe.

Do not create a permanent bulky document unless it materially helps future maintenance.

## 5. Cleanup Implementation

Work in small logical batches:

1. Confirm dead code.
2. Remove the code.
3. Fix imports and type references.
4. Update or remove tests that only target deleted functionality.
5. Run focused validation.
6. Commit the batch.
7. Continue to the next category.

Do not modify behavior outside dead-code elimination.

Do not weaken meaningful existing tests.

## 6. Verification Gates

Run the actual supported commands:

- `pnpm generate-routes`
- `pnpm audit:deadcode`
- `pnpm check`
- `pnpm exec tsc --noEmit`
- Relevant Vitest suites.
- `pnpm build`

Use the repository's real scripts and account for known pre-existing tool issues transparently.

If a check fails, distinguish:

- Regression introduced by cleanup.
- Pre-existing failure.
- Tool configuration problem.

Do not silence meaningful errors or broadly ignore files to make the report green.

No browser QA, Playwright browser execution, or screenshots.

## 7. Completion Criteria

- Demonstrably dead code has been removed.
- Obsolete demo artifacts are resolved.
- No dangling import remains.
- Dependencies and lockfiles are consistent.
- Legitimate dynamic entrypoints remain intact.
- Tests and build continue to work.
- Knip findings are resolved or narrowly justified.

Use atomic commits, push to the working branch according to repository rules, and preserve unrelated changes.

Final report must include:

- Files/exports removed.
- Dependencies removed.
- Verified false positives.
- Unresolved audit findings.
- Test/build results.
- Commit identifiers.

Do not call the repository "100% dead-code-free" unless the audit genuinely supports that conclusion.
