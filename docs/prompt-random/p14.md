# TASK 14: Evolve Admin Overview into a Multi-Product Platform Dashboard

**Complexity:** HIGH  
**Prerequisites:** Dedicated Admin Kredit, universal billing integration  
**Scope:** Admin Overview, dashboard aggregates, public-facing metric labels

## 1. Objective

Update the Admin Overview to represent everythings-vibe as a multi-product SaaS platform.

The current dashboard remains heavily oriented toward VibePlan.

It should provide a useful business and operational overview without duplicating the dedicated Kredit page.

## 2. Problems Identified

Previous source/screenshot review identified:

- `System Overview` mixes English with Indonesian product copy.
- `Status Pipeline` is a count of artifacts, not necessarily an operation status.
- `Proyek Siap` suggests completion even when the query counts ordinary projects.
- `Transaksi Booster Terbaru` contains subscription payments as well as top-ups.
- Payment gateway names appear unnecessarily in the summary.
- Project count semantics may differ from the Admin Projects view, particularly for deleted projects.
- Existing metrics do not fully cover Studio/Scrape credit usage.

Reverify actual current code before editing.

## 3. Required Naming Corrections

Use:

- `Ringkasan Platform` instead of `System Overview`.
- Accurate project/artifact labels matching actual aggregation.
- `Transaksi Terbaru` instead of `Transaksi Booster Terbaru`.
- `Pembelian paket dan top-up kredit` where accurate.

Do not write `Proyek Siap` unless the query actually verifies completed/readiness state.

If retaining the artifact count, use a label such as `Dokumen & Task` only when that accurately represents the underlying data.

Avoid meaningless names such as “AI Pipeline Intelligence”.

## 5. Metric Definitions

Source all metrics from real database queries.

### Total Users

Count unique accounts according to the established Admin definition.

### Revenue This Month

Use the established successful-payment accounting policy and explicit current-month period.

Do not count failed or pending payments as revenue.

Do not silently mix all-time revenue with current-month revenue.

### Credits Used

Use actual settled credit consumption in a clearly labelled period.

Do not count:

- Unsettled reservations.
- Released amounts.
- Shadow meter simulations as paid usage.

### Successful Operations

Count actual qualifying successful logical operations.

Avoid duplicate counts from worker retries.

Define treatment of partial success explicitly.

### Tickets

Use the actual handling/archival model.

Do not label all historical tickets as currently open.

### Projects

Respect existing project lifecycle and deleted-project filtering.

Do not claim that deleted project tombstones are active projects.
