# TASK 13: Update Pricing and Billing UI for Universal Multi-Product Credits

**Complexity:** HIGH  
**Prerequisites:** Approved pricing policy, trial entitlement, Studio and Scrape integrations  
**Scope:** Public Pricing, user Billing, credit history, credit-related public copy

## 1. Objective

Update the complete user-facing pricing and credit experience to reflect the actual multi-product billing architecture.

Users must understand:

- Which features they can use.
- How their shared credits work.
- Which operations consume credits.
- Which interactions remain free.
- How the Free trials work.
- Where credits have been spent.
- When credits become available again.

Do not describe the system as if it only supports PRD, AC, and Task generation.

## 4. Correct Credit Explanation

Use natural, concise product language.

Recommended direction:

`Kredit dapat digunakan untuk menjalankan fitur sesuai paketmu. Biaya setiap operasi mengikuti jenis dan pengaturan pekerjaan.`

Only claim behavior that exists.

Explain:

- Fixed versus adaptive operation costs in understandable language.
- Estimates shown before use.
- Monthly allocation/reset.
- Top-up expiry/rollover rules where applicable.
- Trial availability.
- Free actions.

Do not reintroduce misleading claims such as:

- Every operation costs exactly one credit.
- All credits never expire.
- All revisions are free.

Distinguish VibePlan revision policies from Studio AI revision policies.

Avoid technical billing jargon on Pricing cards.

## 5. Free Trial Communication

Make trial limitations clear before users begin.

Approved product policy:

- One Studio trial per account.
- One Scrape trial per account.
- Trial does not renew monthly.
- Trial limits use the approved implementation.
- Trial does not require a payment.
- Existing results remain accessible after consumption.
- VibeTemplate is free.

Do not create an automatically renewing paid trial.

Do not promise unsupported trial modes.

## 6. User Billing Layout

- Payment preview remains capped at five transactions.
- Complete payment history remains accessible via the existing dialog/pagination.
- Mobile layout uses natural independent heights.
- No card can grow without limit due to transaction count.

Do not undo prior fixes.

Preserve payment history and transaction records.

No hard-delete financial history action.

## 10. Global One-Click Billing UX

Ensure sufficient-credit operations do not require another confirmation popup.

```
Inline estimate + operation button
                |
           Single click
                |
      Backend credit validation
                |

```

Do not remove existing payment checkout confirmation flows.
