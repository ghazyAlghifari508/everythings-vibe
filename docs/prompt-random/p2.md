# TASK 02 — Match Billing Summary Card Heights Responsively

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Complexity:** EASY  
**Scope:** `src/features/billing/components/billing-page.tsx`

## Objective

Buat dua card bagian atas halaman `/settings/billing` memiliki tinggi yang sama pada desktop.

Cards:

- Billing &amp; Kredit.
- Riwayat Pembayaran.

User secara eksplisit menginginkan kedua card sejajar bagian atas dan bawah supaya layout terlihat lebih seimbang.

**Jangan kembali ke masalah lama ketika jumlah pembayaran yang banyak membuat dua card terus memanjang.**

Riwayat pembayaran sekarang sudah menggunakan preview maksimal lima transaksi dan tombol `Lihat semua transaksi`. Pertahankan mekanisme itu.

## 1. Investigasi

Baca:

- [`AGENTS.md`](http://AGENTS.md)
- Rules UI/anti-slop/design consistency.
- `billing-page.tsx`
- `payment-history-dialog.tsx`
- Shared Settings layout.
- Tests Billing.

Current structure menggunakan grid:

`grid gap-6 lg:grid-cols-2 items-start`

`items-start` menyebabkan dua card mempertahankan tinggi independen.

## 2. Target Layout

```
Desktop:

┌───────────────────────────┐ ┌───────────────────────────┐
│ Billing & Kredit          │ │ Riwayat Pembayaran        │
│                           │ │                           │
│ Hengker                   │ │ Transaksi 1               │
│ Aktif hingga ...          │ │ Transaksi 2               │
│                           │ │ Transaksi 3               │
│ Kredit digunakan          │ │ Transaksi 4               │
│ [progress bar]            │ │ Transaksi 5               │
│                           │ │                           │
│                           │ │ Lihat semua transaksi  →   │
└───────────────────────────┘ └───────────────────────────┘
       SAME BOTTOM EDGE             SAME BOTTOM EDGE
```

Implementation requirements:

- Gunakan CSS Grid natural row stretching pada desktop.
- Pastikan dua card mengisi tinggi grid row yang sama.
- Jangan pakai fixed height besar atau hardcoded `height: 600px`.
- Gunakan `h-full` atau flex layout di internal card hanya bila memang diperlukan.
- Jaga posisi tombol dan informasi tetap terstruktur.
- Hindari area kosong yang terkesan tidak disengaja.
- Pertahankan padding, border, radius, typography, dan warna existing.

## 3. Prevent Unbounded Growth

Tetap batasi preview pembayaran maksimal lima transaksi.

Tetap pertahankan:

- `Lihat semua transaksi`.
- Dialog histori lengkap.
- Pagination histori pembayaran.
- Status pembayaran.
- Filter histori yang sudah tersedia.

Jangan mengubah backend pembayaran atau jumlah credit.

Tidak perlu menambahkan scroll internal pada dua card utama.

## 4. Responsive Rules

Desktop:

- Dua card sama tinggi.
- Dua kolom tetap proporsional.

Mobile/tablet saat sudah menjadi satu kolom:

- Tinggi card mengikuti konten masing-masing.
- Jangan memaksakan tinggi identik.
- Tidak ada ruang kosong besar.
- Tidak ada tombol terpotong.

## 5. Component-First Policy

Inspeksi komponen siap pakai existing terlebih dahulu.

Explore pendekatan yang relevan dari shadcn/ui, HeroUI, MagicUI, ReactBits, Thinking Orbs, dan AffectUI.

Gunakan card primitives yang sudah tersedia.

Jangan membangun card baru dari nol dan jangan mengganti UI yang sudah bagus hanya demi perubahan height.

No AI-slop, decorative gradients, excessive shadows, or unnecessary wrappers.

## 6. Verification

Jalankan targeted tests, TypeScript, dan Biome.

Pastikan:

- Preview tetap maksimal lima transaksi.
- History dialog tetap berfungsi.
- Grid desktop stretching dan mobile stacking benar secara struktur.
- Tidak ada perubahan fungsional billing.

No browser QA, Playwright browser execution, or screenshot automation.
