# TASK 10: Implement One-Time Studio and Scrape Trials with Safe Product Entitlements

**Complexity:** CRITICAL  
**Prerequisites:** Universal ledger architecture, shadow metering, and approved trial policy  
**Scope:** Free/Pro/Hengker access, trial lifecycle, account entitlement

## 1. Objective

Implement the owner's confirmed access policy.

Free users receive:

- Existing VibePlan entitlement.
- One Studio trial per account.
- One Scrape trial per account.

Pro and Hengker:

- Shared paid credit balance.
- Access to supported paid Studio and Scrape operations.

VibeTemplate:

- Free.

Manual Studio editing:

- Free.

Do not introduce a separate recurring Studio or Scrape allowance.

## 2. Approved Trial Structure

```
Free Account
   |
   +-- Existing VibePlan allocation
   |
   +-- Studio trial: once per account
   |
   +-- Scrape trial: once per account
   |
   +-- VibeTemplate: free
```

Studio and Scrape trials are independent.

Using the Studio trial must not consume the Scrape trial.

Neither trial resets every month.

## 3. Mandatory Codebase Investigation

Inspect:

- Existing billing entitlement logic.
- Plan gates.
- Free tier permissions.
- Credit guards.
- Billing exemption.
- User identity.
- Subscription lifecycle.
- Trial-compatible foundation from TASK 06.
- Approved limits from TASK 09.
- Existing worker reservation/recovery services.

Do not rely on client-side plan labels for authorization.

## 4. Persistent Trial Lifecycle

Represent a safe lifecycle:

```
AVAILABLE
    |
    | Atomic reservation when a valid trial job starts
    v
RESERVED
    |
    +-- Qualified success ----------> CONSUMED
    |
    +-- Total system failure -------> AVAILABLE
```

Partial success and cancellation follow the approved pricing/trial policy.

If their treatment is not yet approved, do not activate the affected operation using a guessed policy.

Requirements:

- One usable trial per feature per account.
- Atomic transition.
- Same logical operation cannot reserve twice.
- Simultaneous attempts cannot claim two trials.
- Worker retry uses the same reservation.
- Recovery of abandoned reservations.
- Persist evidence of consumption.
- Deleting a resource does not restore a consumed trial.
- Upgrade/downgrade does not create duplicate trials.
- Monthly credit resets do not reset the trials.

## 5. Resource Limits

Studio trial:

- One generated frame within approved limits.
- No unlimited AI revisions under the same trial.

Scrape trial:

- One bounded extraction using an approved mode and configuration.
- Enforce the approved limits from TASK 09.

Do not widen trial limits based on unverified UI configuration values.

Prevent direct API requests from bypassing trial restrictions.

## 6. Preserve Existing Users

Do not retroactively charge users for their previous Studio/Scrape usage.

Do not silently classify previous historical free usage as an already-consumed trial without an approved migration policy.

Preserve old project access.

After trial consumption, users may still:

- Open their existing results.
- Preview.
- Export supported existing artifacts.
- Perform free manual interactions.

Do not lock existing user data behind a new payment requirement.

## 7. Entitlement Decisions

Backend must clearly distinguish:

- Paid credit available.
- Trial available.
- Trial reserved.
- Trial exhausted.
- Insufficient paid credit.
- Plan-gated feature.
- Free non-billable operation.
- Billing exemption.

Preserve existing paid plan and Free VibePlan restrictions.

Do not automatically broaden Free VibePlan rights beyond the current product contract.

## 8. User Interaction Policy

No normal-operation permission popup.

```
Valid operation request
       |
       v
Entitlement check
       |
       +-- Allowed paid balance --> reserve and start
       +-- Available trial -------> reserve trial and start
       +-- Free operation --------> start without charge
       +-- Not eligible ----------> existing upgrade/credit UI
```

Do not introduce an extra “Are you sure?” modal when the user is already authorized and eligible.

Never route Free users through payment checkout merely to use their trial.

## 9. Security

Use authenticated, server-side entitlement enforcement.

Protect:

- Account ownership.
- Cross-feature trial independence.
- Request replay.
- Concurrent requests.
- Resource/job validation.
- Billing exemption.

Avoid overengineered surveillance or unnecessary device tracking solely for trial enforcement.

## 10. Validation

Test:

- First Studio trial succeeds.
- Second distinct Studio trial is rejected.
- Scrape trial remains independently available.
- Monthly reset does not replenish trials.
- Concurrent claims.
- Automatic retry.
- Total failure releases reservation.
- Approved partial/cancellation behavior.
- Resource deletion.
- Upgrade/downgrade.
- Existing historical results remain accessible.
- Free non-generative activities do not consume trials.
- Non-owner operations are rejected.
- Legacy paid billing remains unchanged.

Use isolated test fixtures and approved policy values.

Do not alter real trial or subscription records.

No browser QA at this phase.

## Definition of Done

The approved Free/paid entitlement policy is enforceable, atomic, and recoverable.

Trial accounting is separate from real paid credit balances.

No retroactive charges or hidden product restrictions.

Commit atomically, update verified TODO items, and report policy and test results.
