# TASK 15: Rebuild Bantuan into a Functional, Task-Oriented SaaS Help Center

**Complexity:** HIGH  
**Prerequisites:** Finalized feature behavior and accurate Pricing/Billing policies  
**Scope:** Help Center information architecture, search, articles, copy, UI

## 1. Objective

Transform `/bantuan` from a static feature catalog with a long expandable guide into a genuinely useful product Help Center.

The current interface feels plain, repetitive, overly technical, and difficult to navigate when users need specific answers.

The redesign must help users accomplish real tasks.

Do not merely replace the existing four cards with prettier cards.

## 4. Existing Copy Problems

Remove or rewrite unnecessary technical language such as:

- Inisiasi ide produk.
- Streaming & revisi PRD.
- Ekstraksi headless otomatis.
- Preview multi-viewport without understandable context.
- Internal route paths displayed as CTA text.
- “Tanpa halusinasi” as an absolute guarantee.
- Generic claims that do not explain what users should do.

Use natural Indonesian instructions.

Example:

BEFORE:  
`Inisiasi ide produk: Buka /plan/new dan tulis deskripsi ringkas ide produk.`

AFTER:  
`Buat proyek baru, lalu jelaskan aplikasi atau fitur yang ingin kamu bangun.`

Only expose actual technical syntax when it is necessary, such as a CLI command in a technical guide.

## 6. Functional Search

Implement a searchable knowledge base using verified article data.

Search relevant:

- Article title.
- Description.
- Supported task keywords.
- Category.

- Common Indonesian terms and useful aliases.

Example searches:

- Kredit habis.
- Revisi desain.
- Scrape gambar.
- Sinkronisasi repository.
- API key.
- Generate PRD.

Provide:

- Useful search results.
- Keyboard navigation.
- Empty results.
- Clear search interaction.
- Relevant article links.

Do not create a decorative input that does nothing.

Do not introduce an unnecessary AI chatbot or paid search backend.

Prefer a lightweight local/indexed search appropriate to the article corpus.
