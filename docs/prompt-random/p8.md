# TASK 08: Build Dedicated Admin Credit and Operational Cost Monitoring

**Complexity:** HIGH  
**Prerequisites:** TASK 06 and TASK 07  
**Scope:** Admin Kredit, usage analytics, operational cost monitoring

## 1. Objective

Create a dedicated Admin navigation destination:

`Kredit`

Do not merge monetary payment transactions and credit consumption into one table.

The existing Admin navigation after TASK 02 should no longer contain redundant Admin branding.

Target:

```
Ringkasan | Pengguna | Tiket | Proyek | Transaksi | Kredit
```

Preserve theme toggle and authorization.

## 2. Page Architecture

Create two functional tabs:

1. Penggunaan
2. Biaya Operasional

```
Kredit

[Penggunaan] [Biaya Operasional]

+----------------+----------------+----------------+
| Kredit terpakai| Reservasi aktif| Trial digunakan |
+----------------+----------------+----------------+

Penggunaan berdasarkan fitur
Greenfield       =================
Existing         ============
Studio           ========
Scrape           =====

[Rentang waktu] [Fitur] [Status] [Cari pengguna]

Usage records table

1-20 dari N                        [Prev] [Next]
```

This is a conceptual wireframe, not a source of fake data.

## 4. Penggunaan Tab

Provide accurate ledger-backed metrics:

- Settled credits used.
- Active reserved credits.
- Refunded credits where supported.
- Released reservations, separately identified.
- Trial Studio usage.
- Trial Scrape usage.
- Successful, partial, and failed operation statistics as applicable.

When trial enforcement is not implemented yet, clearly indicate that trial data is not available.

Do not display invented zero values for unavailable capabilities.

Provide usage breakdown by:

- Greenfield.
- Codebase Existing.
- Studio.
- Scrape.
- Legacy/unknown where applicable.

During shadow mode, do not include hypothetical Studio/Scrape charges in actual consumed-credit totals.

## 5. Usage Table

Use a paginated server-side query.

Suggested columns:

- Waktu.
- Pengguna.
- Fitur.
- Aktivitas.
- Resource/project.
- Estimated/reserved credits.
- Actual charged credits.
- Status.
- Detail.

Support server-side filters:

- Date range.
- Product family.
- Operation.
- Status.
- User search.
- Funding source where reliably recorded.

Default approximately 20 rows per page.

Reuse the existing Admin pagination primitive.

Apply filters before pagination.

Use deterministic sorting and validated bounded query inputs.

No full-table fetching.

## 6. Biaya Operasional Tab

Present actual shadow metering data.

```
Biaya Operasional

[Periode] [Fitur] [Operasi]

Measured usage
- Total AI requests
- Input/output tokens
- Worker duration
- Browser duration
- Storage/network usage, where measurable

Operation benchmark table
Operation | Samples | Median | p95 | Known Cost | Outcome
```

Display measured and estimated cost separately.

Clearly distinguish:

- Actual provider expenses.
- Paid-provider cost scenarios.
- Unknown expenses.
- Resource measurements.

Do not show total cost as fully known if significant components are missing.

Do not pretend shared CPU/RAM measurements are exact per-operation costs.

Use meaningful empty states when no benchmark data exists.

## 7. Aggregation Requirements

All KPI cards and charts must use database-backed aggregation from the correct dataset.

Do not calculate totals from `rows.length` or the currently displayed table page.

Define date-window and status semantics.

Avoid duplicate counting of:

- Retry attempts as unique operations.
- Reservations as settled charges.
- Released credits as financial refunds.
- Shadow records as actual user charges.

Use the same source of truth as Billing.

## 8. Security

All queries require Admin authorization.

No user-facing exposure of platform provider costs.

Do not return:

- API keys.
- Raw request bodies.
- Private prompts.
- Sensitive page contents.
- Provider authentication tokens.

Provide read-only monitoring.

Do not introduce arbitrary credit adjustments, destructive ledger actions, or an editable pricing administration panel in this task.
