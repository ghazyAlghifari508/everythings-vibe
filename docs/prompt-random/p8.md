# TASK 08 — Align Pricing Copy with Actual Adaptive Credit Billing

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Complexity:** MEDIUM–HIGH  
**Scope:** Pricing and billing-related public explanations

## Objective

Correct potentially misleading credit-pricing explanations throughout the application.

Current Pricing copy includes:

`1 kredit = 1 tahap (PRD, AC, atau Task). Kredit tidak pernah hangus.`

However, actual credit history has shown operations consuming multiple credits, and the codebase contains an adaptive-credit pricing system.

This suggests the public explanation may not match the real charging model.

Do NOT assume which explanation is correct without auditing server-side billing.

- Whether unused credits actually expire or reset.

## 2. Establish the Actual Pricing Contract

Build an evidence-based mapping:


| Concept                 | Verified behavior                  |
| ----------------------- | ---------------------------------- |
| Monthly plan allocation | From server/business configuration |
| PRD charging            | From actual credit policy          |
| AC charging             | From actual credit policy          |

Do not invent fixed credit prices.

Do not describe variable charges as fixed.

Do not promise that credits never expire if actual allocation resets every billing period.

Differentiate monthly allocation from purchased top-up credits if their rules differ.

## 3. Correct User-Facing Copy

`Setiap operasi menggunakan kredit sesuai jenis dan kebutuhan proses. Estimasi ditampilkan sebelum penggunaan.`

Use this wording only if the behavior is verified.

Make the description understandable to ordinary users.

Avoid:

- Technical billing jargon.
- Marketing promises unsupported by code.
- Fake minimum prices.
- Conflicting explanations across pages.

Audit relevant:

- Pricing heading/subtitle.
- Plan cards.

- Usage estimate messages.

Change only inaccurate descriptions.
