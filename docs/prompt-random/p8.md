# TASK 08 — Reconcile [TODO.md](http://TODO.md) with the Actual Codebase and Retain Only Unfinished Work

Repository: ghazyAlghifari508/everythings-vibe

Prerequisite:  
All preceding tasks in this cleanup/refactoring/rebranding workstream have been implemented or explicitly reported as blocked.

## Objective

Turn [TODO.md](http://TODO.md) into a reliable, CURRENT backlog of unfinished work.

The current TODO contains:

- Completed implementation history.
- Outdated source paths.
- Old file-size measurements.
- Tasks that are already implemented but still unchecked.
- Some statuses that disagree with implementation.
- Unfinished work mixed with already-finished milestones.

**The user wants [TODO.md](http://TODO.md) to contain only work that genuinely remains unfinished.**

Do not preserve completed checklist sections merely to make the file longer.

## 1. Mandatory Investigation

Read:

- [AGENTS.md](http://AGENTS.md).
- Relevant repository rules.
- The complete [TODO.md](http://TODO.md).
- Current git status and branch.
- The actual implementation and tests.
- Previous task commit reports.

For every TODO section:

- Identify what the requirement originally requested.
- Verify actual implementation.
- Check required tests or validation evidence.
- Determine whether work is COMPLETE, PARTIAL, BLOCKED, or NOT STARTED.

Do not rely solely on checkbox text or prior agent summaries.

## 2. Source-of-Truth Priority

When documentation and code disagree:

1. Verify the current implementation.
2. Verify behavior using appropriate tests and contract checks.
3. Compare with original acceptance criteria.
4. Update the TODO to reflect the evidence.

A file's existence alone is not proof of full completion.

A deleted file alone is not proof that its feature was properly replaced.

A passing TypeScript build alone is not proof of behavioral correctness.

## 3. Completed Work Policy

For fully completed backlog sections:

- Remove the completed section from [TODO.md](http://TODO.md).
- Remove its entry from the table of contents.
- Remove obsolete references from the remaining active TODO content.

If completion rationale must be retained for future maintainers, place essential factual documentation in an appropriate existing architecture or engineering document instead of keeping it as an active TODO.

Do not create a large duplicate history log.

Do not remove useful system documentation merely because the implementation is complete.

## 4. Partially Completed Work Policy

If a section is partially completed:

- Remove checklist items that are proven complete, or mark them complete if keeping them is needed to explain remaining dependencies.
- Rewrite the remaining tasks so they describe ONLY unfinished work.
- Replace old file paths with current paths.
- Replace stale file-size claims with verified numbers.
- Keep the remaining acceptance criteria precise.
- Preserve unresolved safety and regression requirements.

Example:

OLD:  
"Refactor 1,800-line codebase route."

If the route is already thin, do not leave that task unchanged.

If other oversized modules still exist, update the backlog to target only those modules.

Do not require an agent to repeat completed refactoring.

## 5. Incomplete Work Policy

Preserve every genuinely unfinished backlog item, including intentionally deferred high-complexity initiatives.

Do not implement deferred work.

Do not delete deferred work simply because it was excluded from this cleanup workstream.

Keep the original design rationale, important constraints, and acceptance criteria needed to implement those tasks later.

Update outdated path references only where the current location is verified.

## 6. Blocked Work Policy

If a task could not be completed due to:

- Unverified external package availability.
- Compatibility constraints.
- Missing validation environment.
- Unresolved schema-equivalence risk.
- Remaining legitimate dead-code audit findings.
- Failed tests or build checks.

Keep it in [TODO.md](http://TODO.md) as an unfinished task.

Document:

- The exact blocker.
- Evidence.
- Why it prevents completion.
- The next concrete action.
- Relevant source files.

Do not mark blocked work as complete.

## 7. Target TODO Structure

Use a concise active-backlog structure:

# everythings-vibe — Active Backlog

## Overview

Short explanation that this document tracks unfinished work only.

## Active Work

Only incomplete initiatives, with original section numbers preserved where useful.

For each remaining initiative:

- Status: Not Started / In Progress / Blocked
- Priority
- Scope
- Remaining checklist items
- Acceptance criteria
- Relevant current source paths
- Known blockers if applicable

## Deferred Work

High-complexity initiatives not currently scheduled for implementation.

## Verification Notes

Only short notes necessary to explain unresolved status.

Do not invent deadlines, assignees, milestones, or completion percentages without evidence.

Keep links and table-of-contents anchors valid.

## 8. Reconcile the Current Workstream

Audit the actual result of:

- Remaining code refactoring.
- Shared UI and database modularization.
- Secure Scrape handler decomposition.
- Dead-code auditing and elimination.
- Package cleanup.
- Application-facing rebranding.
- CLI package/command compatibility.
- Agent enforcement tooling.

Remove these backlog entries ONLY when their acceptance criteria are genuinely met.

Otherwise preserve the precise unfinished portion.

## 9. Checklist Consistency

Verify:

- No completed item is still presented as pending work.
- No unfinished item is marked complete.
- No duplicate tasks exist.
- No obsolete paths remain in actionable instructions.
- No completed historical implementation notes clutter active backlog.
- Every unresolved requirement has a concrete next step.
- Deferred work has been preserved.
- All table-of-contents links resolve to valid headings.

Avoid checkbox syntax errors and mixed numbering.

## 10. Verification

Run lightweight checks appropriate for documentation and changed project configuration.

If code changes were needed to resolve a broken reference, run the appropriate focused checks.

Do not run browser QA, Playwright browsers, or screenshot automation.

Do not claim a complete implementation audit if some tests or runtime behavior could not be verified.

## 11. Final Deliverables

Provide a concise reconciliation report containing:

1. Backlog sections removed because completed.
2. Partially completed sections reduced to unfinished items.
3. Work retained because genuinely unfinished.
4. Deferred work preserved without modification to its implementation.
5. Blockers and their evidence.
6. Remaining TODO item count.
7. Validation results.
8. Commit identifiers.

Follow repository atomic commit and push rules.

Preserve unrelated changes.

## Definition of Done

**[TODO.md](http://TODO.md) contains only actual unfinished work and the information necessary to complete it.**

Do not use [TODO.md](http://TODO.md) as a historical changelog.

Do not leave already completed tasks unchecked.

Do not delete unfinished tasks merely to make the backlog appear smaller.

Do not declare completion without evidence.
