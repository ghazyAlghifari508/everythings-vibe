## Objective

Complete automated dead-code enforcement without recreating rules or architectural work that already exists.

The repository already has mandatory agent rules, feature-driven code ownership, and a design consistency contract.

The remaining gap is a reliable dead-code auditing workflow.

Current baseline:

- `package.json` does not define `audit:deadcode`.
- Knip is not installed as a direct development dependency.
- The codebase uses TanStack Start, generated routes, dynamic workers, test files, and a separate CLI workspace.

## 2. Install and Configure Knip

Install Knip as a development dependency using pnpm.

Add the required script:

"audit": "knip"

Configure Knip for the ACTUAL project structure and installed framework versions.

Ensure it can identify:

- Unused files.
- Unused exports.
- Unused dependencies.
- Unused dev dependencies.
- Unused workspace dependencies where applicable.

Handle legitimate non-imported entrypoints, including:

- TanStack Router file-based routes.
- Generated route tree.
- Server functions/API handlers.
- Worker entrypoints.
- CLI commands and exported executable bins.
- Drizzle configuration and schema.
- Test setup and test fixtures.
- Studio assets/build scripts.
- Intentional dynamically discovered modules.

Do not label a dynamically loaded or framework-discovered module as dead simply because it lacks a conventional static import.

## 3. Safe Audit Policy

Classification must distinguish:

TRUE DEAD CODE

- No active consumer.
- No framework discovery.
- No dynamic loading.
- No operational or public contract dependency.

FALSE POSITIVE

- Loaded by convention, configuration, CLI execution, or framework registry.

DEFERRED

- Potentially dead but requires business-contract verification.

Never suppress the entire repository through broad ignore globs.

If exceptions are necessary, use narrow patterns and document WHY they exist.

Do not auto-delete files in this task.

## 4. Verification Contract

Implement a usable local command:

pnpm audit

Where practical, integrate this command into the repository's established quality verification workflow without making everyday development unnecessarily expensive.

If genuine baseline violations currently prevent a strict passing gate:

- Report each actionable finding.
- Isolate only justified temporary exceptions.
- Make the intended failure behavior explicit.
- Do not claim a clean audit until the violations are actually resolved.

The following task will handle broader dead-code removal.

## 5. Testing

Run:

- Relevant TypeScript checks.

- Relevant tooling or configuration tests.

No unnecessary files, tooling wrappers, or broad ignore rules.

Follow repository atomic-commit and push rules, preserve unrelated changes, and report:

- Real findings versus false positives.
- Remaining audit violations.
- Verification results.
- Commit identifiers.
