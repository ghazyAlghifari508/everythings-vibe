- Penjelasannya terasa seperti dokumentasi teknis, bukan copy produk SaaS.

## 2. Keputusan Naming

**Kembalikan nama menjadi** `API Keys`**.**

Terapkan pada:

- Judul halaman.
- Sidebar Settings.
- Metadata halaman jika menggunakan nama lama.
- Accessible labels atau test yang masih merujuk pada nama lama.

Jangan mengubah:

- Route `/settings/api-keys`.
- Endpoint backend.
- Nama credential dalam database.
- Logika keamanan.
- Alur pembuatan otomatis.
- Permission/scopes.

## 3. Copywriting Baru

### Header

Judul:

`API Keys`

Deskripsi:

`Kelola API key yang digunakan untuk menghubungkan AI Agent dan tool lainnya.`

### Label daftar

Ganti:

`Akses yang terdaftar`

Menjadi:

`Daftar API key`

Atau gunakan judul yang lebih sederhana apabila judul bagian tersebut terbukti redundan dengan heading halaman.

Jangan menambahkan label uppercase dekoratif tanpa tujuan.

### Empty State

Judul:

`Belum ada API key`

Deskripsi utama:

`API key akan dibuat otomatis saat kamu menggunakan fitur handoff AI Agent. Key yang sudah dibuat bisa dilihat dan dikelola di sini.`

Pastikan konteks handoff yang disebut benar-benar sesuai alur Greenfield yang ada. Jangan menyatakan bahwa sync token Codebase Existing otomatis tercatat sebagai API key jika implementasinya memang berbeda.

Tidak perlu menambahkan paragraf ketiga hanya untuk mengarahkan pengguna ke pengaturan lanjutan.

### Pengaturan Lanjutan

Ubah label menjadi:

`Buat API key manual`

Deskripsi:

`Untuk menghubungkan tool lain secara manual.`

Boleh tetap menggunakan disclosure/accordion yang sudah ada.

Jangan menjadikan pembuatan manual sebagai CTA utama.
