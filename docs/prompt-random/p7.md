# TASK 07: Implement Shadow Usage Metering and Benchmark Studio/Scrape Operational Costs

**Complexity:** CRITICAL  
**Prerequisite:** TASK 06 universal credit architecture  
**Scope:** Studio, Scrape, operational usage instrumentation, benchmark reporting

## 1. Objective

Collect reliable operational cost data before deciding actual Studio and Scrape credit tariffs.

The owner explicitly selected benchmark-based pricing calibration.

Do not invent production tariffs.

Studio and Scrape must continue working normally while shadow metering records their resource consumption.

Shadow metering is observational. It is not actual user billing.

## 2. Approved Product Decisions

- Paid products share one credit balance.
- Model pricing: fixed and adaptive.
- All AI-driven Studio revisions are billable in the future.
- Manual Studio editing is free.
- Trial: one per feature per Free account.
- VibeTemplate is free.
- Final prices and allocation changes require measured evidence.

## 4. Shadow Metering Flow

```
User starts operation
        |
        v
Existing worker processes operation
        |
        +--> Normal result to user
        |
        +--> Record usage metrics
                 |
                 v
           Shadow usage records
                 |
                 v
           Cost benchmark analysis
```

Do not subtract user credits.

Do not consume a user's future trial entitlement.

Do not create a financial charge record pretending the operation was billed.

Greenfield and Codebase Existing continue using their existing real billing.

## 5. Usage Data Requirements

Track where measurable:

### Common

- Operation identifier.
- Product family.
- Logical job identity.
- Attempt identity.
- Started/finished timestamps.
- Duration.
- Outcome.
- Retry count.
- Completed work units.
- Relevant resource limits.

### AI Processing

- Provider and model.
- Input tokens.
- Output tokens.
- Cached tokens where reported.
- Other relevant provider usage units.
- Price source and effective version.
- Actual billable cost when known.

### Studio

- Requested frames.
- Successfully generated frames.
- Revised frames.
- Operation type.
- Artifact size.

### Scrape

- Requested page limit.
- Successfully processed pages.
- Browser runtime duration.
- Extracted image count.
- Downloaded bytes.
- Generated output size.
- Storage/bandwidth use where measurable.
- [DESIGN.md](http://DESIGN.md) extraction configuration.

Record CPU/RAM where measurement can be performed reliably.

Distinguish per-operation measurements from whole-process/shared-resource observations.

Do not falsely attribute complete worker process resource usage to an individual concurrent job.

## 6. Cost Accuracy

Separate:

- Measured provider cost.
- Estimated provider cost.
- Estimated infrastructure cost.
- Unmeasured resource consumption.

If a provider reports no pricing or usage information, record it as unknown.

Unknown cost is not zero cost.

If the current provider is free or promotional:

- Record actual known cost.
- Optionally calculate a separately labelled paid-provider scenario.
- Use verified official pricing and effective dates.
- Do not present the scenario as an actual incurred expense.

Never equate one credit with a fixed currency amount without an approved financial model.

## 7. Persistence and Reliability

Persist usage records safely.

Ensure:

- Attempts are distinguishable from logical operations.
- Retries are counted for cost analysis without duplicate logical-operation totals.
- Final outcomes can be reconciled.
- Missing metrics are explicitly represented.
- Telemetry does not expose secrets.
- Telemetry failure does not unnecessarily break the core feature.

Do not silently lose all metrics when a worker encounters an exception.

Use a minimal idempotent persistence strategy appropriate to the existing database.

Define retention considerations for telemetry.

Avoid recording:

- Raw API keys.
- Authorization headers.
- Entire private prompts.
- Unnecessary page content.
- Generated private artifacts.

## 9. Benchmark Output

For each operation/scenario report:

- Sample count.
- Median duration.
- p95 duration where sample size supports it.
- Success/partial/failure rate.
- Average resource consumption.
- Actual or estimated provider cost.
- Cost per successful completed unit.
- Cost of failed attempts and retries.
- Unknown cost components.

Show variation and uncertainty.

Do not fabricate p95 statistics from inadequate samples.
