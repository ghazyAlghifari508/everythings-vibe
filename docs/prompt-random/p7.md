# TASK 07 — Establish Premium SaaS Typography Using Pricing as the Reference

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Complexity:** HIGH  
**Scope:** Shared typography system and inconsistent primary headings

## Objective

Standardize heading typography across everythings-vibe using the existing Pricing page as the primary visual reference.

The user strongly prefers the elegant, light-weight typography of:

`Pilih Paket yang Sesuai`

They dislike the overly bold, generic SaaS-style headings currently used elsewhere.

Examples requiring correction:

- Homepage: `Mau ngapain hari ini?`
- VibeScrape: `Ekstrak website`
- Other large hero/page headings that inconsistently use heavy `font-bold` or `font-semibold`.

The goal is a consistent premium SaaS typography system, NOT a global removal of bold text.

## 2. Canonical Reference

The existing Pricing heading uses a style similar to:

```
className="font-inter font-light leading-tight text-snow text-[40px] max-md:text-[36px] md:text-[48px]"
```

The Homepage currently uses:

```
className="text-4xl font-bold tracking-tight text-snow sm:text-5xl lg:text-6xl"
```

VibeScrape currently uses:

```
className="text-2xl font-semibold tracking-tight text-snow sm:text-3xl"
```

Analyze the actual visual hierarchy represented by these styles.

Do not simply copy the Pricing size of 48px into the smaller Scrape workspace.

The shared characteristics should be:

- Appropriate font family.
- Elegant weight.
- Readable line height.
- Intentional letter spacing.
- Consistent scaling.
- No unnecessary exaggerated boldness.

## 3. Define Semantic Typography Roles

Create a minimal reusable typography contract.

Proposed hierarchy:


| Role             | Desktop size | Weight  | Usage                             |
| ---------------- | ------------ | ------- | --------------------------------- |
| Display / Hero   | 40–48px      | 300     | Homepage and public hero headings |
| Page / Workspace | 28–36px      | 300–400 | Main workspace headings           |
| Section          | 20–24px      | 500     | Section titles                    |
| Card title       | 16–20px      | 500     | Card headings                     |
| Body             | 14–16px      | 400     | Descriptions and paragraphs       |
| Label / Button   | 12–14px      | 500     | Actions and controls              |


These are design directions, not arbitrary values to hardcode throughout the application.

Derive the actual final scale from existing design tokens and reference implementation.

Choose responsive sizes appropriate to each page family.

## 4. Component Architecture

Prefer existing typography utilities or primitives.

If a shared component is useful, keep it simple.

Possible API:

```
<PageHeading variant="display">
  Mau ngapain hari ini?
</PageHeading>

<PageHeading variant="workspace">
  Ekstrak website
</PageHeading>
```

Alternatively, standardized Tailwind utility classes may be sufficient.

Choose the smallest reusable mechanism consistent with the repository.

Do not create a complex typography engine.

Do not force every section heading into a React wrapper if simple styling utilities are better.

## 7. Anti-AI-Slop Design Contract

Explicitly prevent:

- Large bold headlines on every screen.
- Excessive font-size variation between sibling pages.
- Arbitrary weights chosen independently per component.
- Every word appearing emphasized.
- Generic oversized hero designs.
- Decorative headings with no functional hierarchy.
- Overly tight tracking at small sizes.
- Unreadable light weights for dense UI labels.

Premium typography should feel deliberate, not fragile.

Keep adequate contrast, readable line height, and sensible text wrapping.
