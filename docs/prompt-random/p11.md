# TASK 11: Integrate Universal Credits into VibeDesign Studio

**Complexity:** CRITICAL  
**Prerequisites:** TASK 06–10, approved Studio tariffs and entitlement policy  
**Scope:** Studio generation, AI revisions, worker lifecycle, inline cost UI

## 1. Objective

Integrate the existing shared credit balance into all real AI-driven Studio generation and revision operations.

The owner confirmed:

- Generate Studio designs uses credits.
- All AI-driven Studio revisions use credits.
- Add frame and regenerate use credits when they invoke paid generation.
- Manual editing remains free.
- Free users receive one bounded Studio trial.
- Retry caused by system failure must not double charge.

Use the universal credit architecture.

Do not create a standalone Studio balance.

## 4. Quote Contract

Generate a server-authoritative pricing estimate before starting a paid operation.

Support:

- Estimated credits.
- Maximum possible charge.
- Pricing version.
- Verified input scope.
- Relevant validity/requote rules.
- Available balance/eligibility.

Do not trust client-provided credit amounts.

The UI must not become capable of modifying its own cost.

If operation inputs change, update the estimate.

If an estimate becomes stale or no longer valid, refresh it inline and return a clear actionable state.

Do not silently authorize a higher maximum charge than the disclosed quote.

## 6. Credit Lifecycle Integration

```
User submits operation
        |
Validate ownership + quote + entitlement
        |
Atomically reserve credits/trial
        |
Persist durable job
        |
Worker processes
        |
        +-- Complete --> settle
        +-- Partial ---> settle approved completed units
        +-- Failure ---> release
```

Ensure job creation and reservation cannot diverge.

Use existing transactional/outbox/durable patterns where appropriate.

If queueing fails, release or reconcile the reservation safely.

Do not charge at enqueue without recoverable accounting.

## 8. Partial Success

Use the approved TASK 09 policy.

Example:

```
Requested frames: 5
Successfully completed: 3
Reserved maximum: based on approved quote
Settled: based on qualifying completed work
Unused reservation: released
```

Do not fabricate partial results to settle a charge.

A failed operation should not be presented as successful merely to justify charging.

Never settle above the authorized maximum.

If a worker completes but settlement fails, use existing reconciliation/recovery rather than duplicate execution.
