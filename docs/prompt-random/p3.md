# TASK 03 — Improve Feedback Submission Toast Copy

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Complexity:** EASY  
**Scope:** Feedback form success/error notifications

## Objective

Perbaiki notifikasi sukses pengiriman Feedback yang sekarang terlalu generik:

`Feedback terkirim! Terima kasih.`

Gunakan pesan yang jelas, natural, dan informatif berdasarkan jenis feedback yang benar-benar dikirim.

Jangan menulis kalimat robotik, marketing filler, atau janji tindak lanjut yang tidak didukung backend.

## 1. Mandatory Inspection

Baca repository rules dan periksa:

- `src/features/auth-settings/components/settings/feedback-form.tsx`
- `src/features/auth-settings/services/feedback.server.ts`
- `src/features/auth-settings/services/feedback.ts`
- `src/store` dan toast primitive.
- Existing feedback tests.

Sistem saat ini mendukung jenis:

- `general`
- `bug`
- `feature`

Backend menyimpan feedback dan mengembalikan sukses. Tidak ada bukti bahwa laporan pasti langsung ditinjau atau dibalas.

## 2. Approved Copy

Gunakan copy berikut.

**Feedback umum**

`Masukan berhasil dikirim. Terima kasih sudah membantu kami meningkatkan everythings-vibe.`

**Laporan bug**

`Laporan bug berhasil dikirim. Laporanmu sudah tercatat dan dapat ditinjau oleh tim.`

**Permintaan fitur**

`Usulan fitur berhasil dikirim. Masukanmu sudah tercatat untuk dipertimbangkan.`

**Gagal mengirim**

`Pesan belum berhasil dikirim. Periksa koneksi lalu coba lagi.`

Jika backend memberikan error validasi spesifik, tampilkan pesan yang benar-benar sesuai kesalahan, bukan selalu mengatakan masalah koneksi.

Jangan gunakan:

- `Tim kami akan segera memperbaikinya`.
- `Tim akan menghubungi kamu`.
- `Bug pasti ditindaklanjuti`.
- Janji SLA atau balasan yang tidak ada dalam implementasi.

## 4. UI &amp; Interaction Constraints

- Gunakan sistem toast existing.
- Jangan membuat toast baru dari nol.
- Jangan menambahkan modal konfirmasi yang tidak diminta.
- Hindari toast terlalu besar.
- Pastikan teks bisa wrap tanpa clipping.
- Pertahankan loading, disabled state, dan reset form.
- Jangan mengirim notifikasi sukses sebelum server benar-benar merespons sukses.
- Hindari dua toast sukses untuk satu submission.

Sebelum membuat UI baru, explore komponen existing serta library siap pakai shadcn/ui, HeroUI, MagicUI, ReactBits, Thinking Orbs, dan AffectUI. Gunakan primitive relevan yang sudah tersedia; jangan menambahkan animasi atau dekorasi hanya karena library tersebut ada.

## 5. Testing

Test:

- Success copy per jenis.
- Failed submission.
- Network error.
- Server validation error.
- Form reset hanya setelah sukses.
- Tidak ada duplicate success toast.

Jalankan targeted Vitest, TypeScript, Biome.

No browser QA, Playwright browser execution, or screenshot automation.

Notifikasi sesuai jenis feedback, informatif, tidak robotik, dan tidak menjanjikan behavior yang belum ada.
