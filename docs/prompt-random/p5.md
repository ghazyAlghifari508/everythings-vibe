## 3. Server-Side Pagination

- Default page size: 20.
- Bounded maximum: 100.
- Stable sort: `createdAt DESC, id DESC`.
- Return rows and filtered totalCount.
- Validate page, offset, limit, search, and step.
- Reset to page 1 when filters change.
- Preserve filters during navigation.

Search must cover:

- Project name.
- Description.
- Owner name.
- Owner email.

Use Drizzle parameterized queries.

Search and stage filtering must happen before `.limit()` and `.offset()`.

Avoid `%`/`_` wildcard surprises where exact literal search is expected.

Do not fetch the entire project database to calculate local pagination.

## 4. Correct Deleted-Project Semantics

The `projects` table already has:

`deletedAt`

Important schema contract:

- `deletedAt = null` means the project is active.
- Non-null means it was deleted from the user-facing application.
- Some project artifacts may already have been permanently purged.
- The base record remains due to credit/audit relationships.

Therefore:

**Do NOT treat deletedAt as a recoverable archive flag.**

Required behavior:

### Default View

Show active/non-deleted projects only.

### Optional Audit Filter

Allow Admin to inspect deleted project records if the existing Admin needs that audit capability.

Recommended filter:

- Aktif (default).
- Terhapus.
- Semua.

Keep deleted records visually distinct from active projects.

For deleted records:

- Do not render a functional `Buka` link into an inaccessible workspace.
- Do not promise restore/recovery.
- Show only permitted audit metadata.
- Do not expose purged content through a fallback.

Use current project deletion policies as source of truth.

## 5. Accurate Project KPIs

Currently, KPI values are calculated from the loaded `projects` array.

Replace with database aggregations.

Required:

- Total Proyek.
- Tahap PRD.
- Tahap AC.
- Tahap Task/Kanban.

Decide and document whether each KPI represents active projects or all historical project records.

**Recommended:** current project-management KPI reflects active projects, excluding deleted records.

If an audit filter shows deleted projects, make counts and labels unambiguous.

Keep aggregates independent from page size.

For `Total Proyek`, do not use `projects.length` when the server returns only one page.

Avoid rewriting the entire Dashboard metrics system unnecessarily, but ensure definitions remain coherent.

## 6. Project Deletion / Archive Decision

The user raised concerns that old projects cannot be removed from Admin.

Recommended policy:

- Pagination manages large volume.
- Existing project deletion lifecycle remains authoritative.
- Admin can distinguish active versus deleted records.
- Historical tombstones remain available for legitimate accounting/audit use.

Do NOT:

- Add direct hard delete from the Admin table.
- Automatically delete old projects.
- Restore a deleted project by setting `deletedAt = null`.
- Introduce a fake archive status that is actually the deletion tombstone.

A genuine reversible Archive feature can be planned separately if there is a real requirement for it.

It is not part of this pagination fix.
