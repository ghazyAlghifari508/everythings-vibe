**Complexity:** CRITICAL  
**Prerequisites:** TASK 06–10 and approved Scrape pricing/trial policy  
**Scope:** Crawl, Scrape HTML, Scrape Images, [DESIGN.md](http://DESIGN.md)

## 1. Objective

Integrate the shared EVVIBE credit balance into all approved billable VibeScrape operations.

Preserve the existing Scrape architecture, worker lifecycle, security protections, result history, and extraction capabilities.

Free users receive one bounded Scrape trial according to the approved resource policy.

Paid users consume the same balance used by Greenfield, Codebase Existing, and Studio.

## 3. Mode Pricing Contracts

### Crawl Website

Adaptive pricing based on approved units, primarily completed pages.

The user selects a maximum page count.

Quote and reserve against the approved maximum.

Settlement reflects qualifying completed pages.

### Scrape HTML

Fixed operation cost within approved page and resource limits.

Do not allow unbounded extraction at a nominal fixed tariff.

### Scrape Images

Fixed extraction cost within approved image/byte/storage limits.

Preserve existing image pagination or load-more behavior.

Loading previously extracted images must not be interpreted as a new scraping operation.

### Generate [DESIGN.md](http://DESIGN.md)

Adaptive according to the approved extraction/AI processing policy.

Validate supported viewport, detail, theme, or other configuration parameters.

Do not charge for settings that are not actually supported.

## 4. Billable Versus Free

```
New extraction job             -> Billable/trial
Explicit user re-scrape        -> New billable operation
Automatic worker retry         -> Same logical operation

Open existing result           -> Free
Preview extracted HTML         -> Free
Read DESIGN.md                 -> Free
Load more existing images      -> Free
Download existing assets       -> Free
Copy existing output           -> Free
Switch result tabs             -> Free
Delete history                 -> No automatic refund
```

Free reads must not bypass existing access policies.

Do not impose a new charge just because a user navigates through already-generated results.

## 5. Inline Quote UX


Update estimates as supported configuration changes.

Do not enlarge the input unnecessarily.

Do not add a separate pricing card above the form.

Do not make users read a paragraph about billing before submitting.

## 6. Explicit No-Confirmation Requirement

When credits or trial are sufficient:

One click on the existing submit action must start the operation.

Do NOT add:

- Credit usage confirmation modal.
- “Apakah Anda yakin?” dialog.
- Mandatory consent checkbox for routine credit spending.
- Intermediate permission screen.
- Redundant confirm toast.

Even a large crawl uses a clearly disclosed inline maximum, not an additional permission popup.

Only show existing insufficient-credit or upgrade UI if the user cannot proceed.

## 7. Server Enforcement

The server must:

- Authenticate the user.
- Validate resource ownership.
- Validate operation mode.
- Validate extraction options.
- Validate and pin pricing policy.
- Validate approved trial limits.
- Atomically reserve required credits/trial.
- Create the durable job.
- Prevent duplicate submission charges.

Do not trust client-reported page count, billed amount, or plan.

Maintain existing URL validation, SSRF protections, timeout limits, and capability authorization.

The billing integration must not weaken scraping security.

## 8. Worker Lifecycle

```
Validated Scrape request
         |
Atomic credit / trial reservation
         |
Durable job
         |
Scrape Worker
         |
         +-- Record completed units
         +-- Record resource metrics
         |
         v
Approved settlement or release
```

Preserve actual completed-work accounting.

Do not treat failed pages as successful billable units unless explicitly required by the approved policy.

Automatic retries must not generate new paid operation identities.

Ensure worker failures and cancellation reconcile unused reservations.

Do not charge again when polling, reopening a result, or downloading an already-produced asset.

## 9. Free Trial

Enforce trial limits from TASK 09 and TASK 10.

Requirements:

- One Scrape trial per account.
- No unbounded crawl.
- No second trial after deletion.
- Independent from Studio trial.
- Release trial on verified total system failure.
- Apply approved partial/cancellation policy.

Show a clear inline trial state.

Do not automatically redirect an eligible Free user to purchase credits.
