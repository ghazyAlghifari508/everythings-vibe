# P4 — Remove Redundant Workspace Header, Restore Five-Step Flow, and Neutralize Progress Colors

**Kompleksitas:** MEDIUM · **Prioritas:** P1  
**Urutan:** 4 dari 8 — setelah P1–P3, sebelum P5.  
**Repository:** `ghazyAlghifari508/everythings-vibe` · **Target branch:** `feature/vibeplan-greenfield`

## 1. Tiga revisi yang diminta secara eksplisit

1. Hapus bar tambahan yang menampilkan “VibePlan [nama proyek]” (contoh screenshot: “VibePlan Midtrans Laporan Export PDF”) pada seluruh flow Greenfield. Ini bukan navigasi yang diperlukan dan pengguna tidak menginginkannya. Jangan menggantinya dengan breadcrumb, label proyek lain, atau header baru.
2. Stepper Navbar hanya memiliki lima tahap: Ask → Fitur → PRD → AC → Task. Kanban adalah view untuk Task, bukan tahap keenam. Pertahankan route dan fitur Kanban.
3. Hilangkan hijau mencolok pada completed stepper Greenfield serta seluruh teks/list section progress PRD. Gunakan neutral monochrome sesuai tema. Checkmark tetap menyampaikan penyelesaian. Jangan menghapus warna hijau secara global atau mengubah semantic color lain (contohnya diff addition, error, warning, paywall).

P1–P3 harus telah memperbaiki streaming, CTA dan chat. Jangan merusak hasilnya. Ini adalah refinement shared chrome, bukan redesign.

## 4. Implementasi

### 4.1 Hilangkan header tambahan tanpa menghapus parent

Hapus hanya visual header/bar VibePlan + nama proyek dari `GreenfieldWorkspace`. Jangan hapus section semantic yang dibutuhkan, loader parent, `<Outlet>`, access guard, project identity, last route reporting, data isolation, atau initialization lifecycle. Jangan membuat parent remount pada child navigation. Pertahankan nama proyek di lokasi yang memang sudah ada dan berguna (mis. History, Feature Tree root node, dokumen); larangan hanya bar workspace redundan. Pastikan area tersisa mengisi viewport yang tersedia dengan flex/min-h-0/overflow yang sesuai, tanpa extra padding/gap bekas header. Jangan menghapus task-specific header yang masih punya kegunaan.

### 4.2 Stepper lima tahap

Hapus Kanban dari daftar step visual. Jangan menghapus nested route `/vibeplan/$id/kanban`, guard, route mapping, History resume, data, Kanban board, status management, atau link dari Task. Definisikan view→step dengan jelas: view `kanban` tetap bagian dari step `task`. Bedakan current view dari workflow completion. Saat Kanban terbuka, Task adalah tahap yang merepresentasikannya; state aktif/selesai harus sesuai contract P2 dan artifact/task status aktual, bukan dipalsukan karena URL. Pastikan tidak ada nomor 6, connector ekstra, atau label Kanban pada global stepper Greenfield. Kanban boleh tetap memiliki judul/navigasi di area Task bila memang dibutuhkan.

Jangan menjadikan progress indicator clickable baru tanpa requirement. Pertahankan existing navigation policy, locked states, dan semantics. Pastikan mobile masih dapat menampilkan lima indikator dan tidak overflow.

### 4.3 Neutral monochrome yang jelas dan accessible

- Completed flow: checkmark + surface/border/text netral, hindari filled green circle. Active flow: gunakan contrast/token neutral EvVibe sesuai light/dark; pending: muted yang tetap readable. Checkmark/angka/border dan `aria-current` menyampaikan status selain warna.
- PRD completed section: icon check netral, label netral (bukan semua row hijau), current section: spinner existing dan teks kontras, pending: muted. Pertahankan delapan section asli beserta progress aktual yang dihasilkan P1. Jangan mengubah semua status menjadi satu style tanpa differentiation.
- Hilangkan emoji centang hijau pada status heading, misalnya `✅ PRD selesai digenerate`; gunakan copy singkat/normal dan icon existing bila dibutuhkan. Saat selesai boleh menampilkan `PRD selesai` dengan section list netral, bukan celebration banner.
- Jangan touch Diff semantics: hijau/merah bisa diperlukan untuk perubahan teks. Jangan touch Existing Codebase stepper, pembayaran, error/success toast, atau fitur lain secara global.

Referensi desain: [https://designsystem.digital.gov/components/step-indicator/](https://designsystem.digital.gov/components/step-indicator/) ; [https://www.nngroup.com/articles/ten-usability-heuristics/](https://www.nngroup.com/articles/ten-usability-heuristics/) ; [https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) . Gunakan status shape/text/accessibility, bukan warna hijau sebagai satu-satunya indikasi.

Utamakan Button, Stepper, status icon, tokens existing yang memang cocok. **Gunakan komponen siap pakai yang sesuai, jangan membangun ulang stepper hanya untuk mengganti warna dan jumlah step.** Jika existing FlowStepNav sudah memenuhi fungsi, reuse/refine komponen itu dan gunakan primitives/icon yang tersedia. Catat kandidat yang dievaluasi dan pilihan akhir; custom hanya untuk gap nyata. Tidak boleh memasukkan dot/badge/gradient/glow dekoratif, membuat header pengganti, atau menambah motion tak perlu.

- Seluruh child Greenfield tidak memiliki project title bar tambahan; parent state/route/persistence tetap berfungsi.
- Stepper Greenfield tepat 5 tahap. `kanban` memetakan ke Task; Kanban masih dapat diakses dan digunakan sesuai guard.
- Active/completed/pending terbaca dan berbeda tanpa hijau, termasuk light/dark. PRD completed list tidak hijau atau memiliki emoji hijau; progress tetap benar, bukan hardcoded.
- CTA P2 dan toggle P3 tetap berfungsi, document/canvas tidak terpotong akibat adjustment flex/header.
- Existing Codebase flow dan semantic colors di luar target tidak berubah.

Tambahkan/update unit/component tests untuk jumlah step, view-to-step mapping (termasuk Kanban), accessibility/status contract, dan shared workspace header removal. Hindari snapshot markup/CSS yang rapuh; assert contract penting. Jalankan targeted tests/typecheck/lint. Jangan memainkan DB/status, menghapus test valid, atau memalsukan hasil. Jangan browser QA pada fase ini; catat visual verification untuk P8.

Sampaikan hasil dan file yang berubah, keputusan token/component, remaining blocker. P5 berikutnya hanya menyentuh generating UI setelah layout dasar ini benar. Jangan commit/push/merge tanpa otorisasi.
