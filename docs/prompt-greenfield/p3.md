## 1. Masalah yang harus diselesaikan

Pengguna melaporkan tombol `Chat` di Navbar PRD tidak membuat panel kanan terbuka/tertutup. Tombol Stop ketika AI sedang membuat PRD terletak di kiri bawah composer, padahal harus di kanan bawah. Ada masalah area bawah composer tidak bisa diklik; pengguna **belum yakin** apakah area kosong tidak memfokuskan input, tombol Stop tidak merespons, atau keduanya. Jangan menyatakan kedua masalah sudah terbukti. Investigasi keduanya. Jangan menghapus behavior disabled yang sah ketika sedang streaming hanya untuk membuat composer terlihat interaktif.

Pertahankan tiga panel PRD (TOC kiri, dokumen tengah, chat kanan), Nested Routes, panel resize, responsivitas, streaming/lifecycle P1, dan CTA P2. Jangan merombak PRD toolbar/versi atau loading di P3.

Gunakan test DOM/hook yang ada untuk membuktikan state toggle, focus, handler, dan disabled rules. CSS hit testing nyata perlu verifikasi P8; jangan klaim sudah dibuktikan tanpa browser.

## 4. Implementasi

### 4.1 Panel visibility sebagai satu kontrak

- Pastikan trigger Navbar dan container PRD menggunakan state visibility yang sama (existing Zustand UI store atau ekuivalen), tanpa state lokal yang bersaing pada breakpoint yang sama. `activeTab` boleh tetap untuk mobile bila diperlukan, tetapi perilaku turunannya harus jelas.
- Desktop: open = panel kanan benar-benar mengambil width yang tersimpan dan dapat digunakan; close = tidak menyisakan width, border, resize hitbox aktif, atau area pointer event. Dokumen tengah melebar, TOC tetap berfungsi. Jangan hanya menyembunyikan isi dengan opacity.
- Tablet: gunakan drawer/sheet existing yang terhubung state toggle yang benar; close button internal dan trigger Navbar konsisten. Mobile: pertahankan tab Dokumen/Chat yang existing; jangan membuat CTA navbar yang tidak bekerja pada breakpoint tersembunyi. Pastikan perubahan breakpoint tidak membuat dua ChatPanel aktif atau panel tidak dapat ditutup.
- Overlay penghalang dan focus trap harus sesuai pola drawer; panel tertutup tidak boleh dapat ditab/diinteraksikan. Gunakan `aria-expanded`, `aria-controls` dan label aksesibel yang benar pada trigger sesuai [https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) . Jangan menambahkan modal/animation dekoratif.
- Jangan memutus stream saat panel hanya disembunyikan. Pertahankan single mounted controller/owner (atau state durable yang sudah diimplementasi P1), draft input, percakapan, resize width, scroll yang masuk akal, dan cancellation ability. Reopen tidak boleh autosubmit lagi. Jika panel sedang tertutup ketika generation aktif, P5 akan menyediakan fallback indikator; P3 tidak menambah loading copy.

### 4.2 Composer alignment dan interaksi

Ganti alignment row satu button menjadi end alignment (`justify-end`, atau layout existing yang setara), sehingga Send dan Stop berada di posisi kanan bawah yang sama tanpa layout shift. Pertahankan satu button, ganti ikon/label mengikuti state. Reuse icon/send/stop yang konsisten dengan design system; neutral/high contrast lebih baik daripada styling baru yang tidak diperlukan. Jangan mengganti stop menjadi teks panjang.

Saat idle dan input boleh digunakan, klik/tap **area kosong dalam composer** (termasuk padding bawah) memfokuskan textarea. Implementasi boleh memakai event guard pada wrapper atau struktur input group existing. Jangan menjadikan seluruh wrapper sebagai button yang mengandung button lain; pertahankan keyboard semantics. Hindari focus stealing pada interactive element: klik Send, Stop, link, dan kontrol lain harus melakukan aksi sendiri tanpa trigger fokus/send ganda. Klik Stop saat streaming harus tetap diterima walaupun textarea disabled. Jangan menambah `pointer-events: none` pada ancestor seluruh composer. Audit z-index, overlay, shrink/min-height, resizer, event propagation, scroll area, serta kondisi disabled.

Pertahankan validasi existing: empty input tidak bisa send; Enter vs Shift+Enter sesuai behavior existing, IME composition tidak memicu submit tidak sengaja; read-only PRD tetap read-only; saat request active, jangan membuka jalan duplicate generate/revise. Stop memanggil cancellation handler nyata P1 satu kali, bukan hanya mengubah tampilan ikon. Pastikan tombol punya accessible name, focus-visible, target klik/tap memadai; tidak boleh terpotong di bagian bawah viewport.

## 5. Mandatory component exploration (frontend)

Sebelum mengubah UI, cek komponen dan design tokens existing (`src/components/ui`, HeroUI/Radix/shadcn patterns). Wajib eksplorasi komponen siap pakai yang relevan dari HeroUI, shadcn/ui, Magic UI, React Bits, [https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs), [https://www.affectui.com/components](https://www.affectui.com/components), [https://tuffui.com/](https://tuffui.com/), [https://yappologistic.github.io/CUI/](https://yappologistic.github.io/CUI/), [https://www.sakaniui.com/](https://www.sakaniui.com/) serta alternatif resmi bila perlu. Untuk kasus ini fokus pada Button/IconButton, Sheet/Drawer, InputGroup/Textarea, collapsible/resizable layout—not ornamental components. Reuse dan benar-benar gunakan kandidat yang cocok; gunakan komponen existing yang sudah memenuhi behavior terlebih dahulu. Jangan mengimpor library penuh untuk satu control, copy UI yang tidak compatible, atau membuat Chat UI dari awal. Jika tidak ada kandidat yang tepat, dokumentasikan pencarian dan buat hanya bagian kecil yang dibutuhkan. Adaptasi spacing/tokens EvVibe light/dark, tanpa efek gradient/glow/badge/copy generik.

## 6. Verification (tanpa browser QA)

Tambahkan/perbarui unit/integration DOM tests yang membuktikan:

- Navbar trigger mengubah state dan aria-expanded; close/open sesuai state, container menggunakan kontrak visibility yang benar pada desktop/tablet/mobile (sebatas test yang didukung).
- Single stream owner; toggle berulang saat generation tidak menimbulkan abort/restart/duplicate submit atau kehilangan draft/current messages.
- Click pada wrapper kosong ketika idle → textarea menerima focus. Click Send → handler sekali; click Stop saat textarea disabled → cancel sekali, tidak submit/focus palsu. Test klik/keyboard dan disabled/read-only states.
- Klik stop mengoper ke cancellation lifecycle P1; project switch tidak membawa draft/input lama.
- Layout class conflict diperbaiki secara struktural; jangan menyamakan unit test dengan real hit-testing. Catat viewport/pointer overlap/resize yang perlu diuji di P8.

Jalankan targeted test/typecheck/lint sesuai skrip repo. Jangan manipulasi database, force stream state, disable feature, skip assertions, fake tests, atau mengabaikan bug baru untuk menutup task. Jangan browser QA pada fase ini.

Chat toggle benar-benar terhubung ke visibility panel; Send/Stop konsisten di kanan bawah; idle composer dapat fokus melalui klik area kosong; Stop tetap dapat menerima event saat streaming berdasarkan test yang sesuai. Sampaikan kesimpulan investigasi masalah klik (terbukti/tidak terverifikasi), file dan test, risiko runtime yang tersisa. Jangan mengaku browser behavior sudah diverifikasi. P1/P2 tetap lulus.
