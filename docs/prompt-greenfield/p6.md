# P6 — Refine PRD Version History and Diff into One Contextual Control

**Kompleksitas:** MEDIUM–HIGH · **Prioritas:** P2  
**Urutan:** 6 dari 8 — setelah P1–P5, sebelum P7.  
**Repository:** `ghazyAlghifari508/everythings-vibe` · **Target branch:** `feature/vibeplan-greenfield`

## 1. Keputusan final pengguna

Pengguna tidak menyukai toolbar `Pratinjau` yang selalu terlihat, terutama ketika hanya ada satu versi PRD dan satu-satunya tab tidak melakukan apa pun. Toolbar tersebut membuat tiga-panel layout (TOC, document, Chat) terlihat seperti ada control tambahan yang tidak dibutuhkan. Pengguna sudah mengonfirmasi **Diff dan Version History tetap dipertahankan dan digabung dalam satu kontrol riwayat versi**. Jangan menghapus kemampuan Diff, version data, revision chat, entitlement, atau version selection. Jangan mengubah menjadi dua tab permanen yang terpisah. Jangan membuat UI dari nol.

## 2. Audit dan baseline

Baca HEAD/working tree dan repo rules. Inspeksi:

- `src/features/greenfield/components/prd/prd-viewer.tsx`: `activeTab`, unconditional toolbar dengan Pratinjau, conditional Diff, VersionHistory, content scroll, TOC/resize.
- `prd-diff-viewer.tsx`, `src/features/greenfield/utils/diff-utils.ts`: comparison engine, addition/deletion semantics.
- `version-history.tsx`: existing version selector, `FEATURES[plan].versionHistory`, current selection, latest version, version list, gate.
- `hooks/use-prd-detail.ts`, `prd-detail.tsx`: saved versions and revision refresh, `selectedVersionNum`, live content, callbacks, read-only logic.
- Public PRD share/export consumers dari PrdViewer; jangan merusak reuse.
- Global theme and installed Popover/DropdownMenu/Button primitives; implementation/design constraints P1–P5.

Pertahankan versi yang dipilih dan version list aktual; jangan menganggap data history selalu berurutan dari v1 sampai vN. Periksa existing diff policy (previous version against selected/current; fallback when v1 selected) dan buat comparison direction eksplisit agar user tidak salah membaca addition/deletion.

## 3. Target UI (progressive disclosure)

### Kondisi A — baru satu versi (atau belum ada versi tersimpan)

```
┌────────────────────────── Navbar existing ──────────────────────────┐
├──────────────┬───────────────────────────────────┬─────────────────┤
│ Daftar isi   │                                   │ Chat            │
│ 1. Overview  │ 1. Overview                       │                 │
│ 2. Goals     │ 1.1 Latar Belakang                │                 │
│ ...          │ Isi dokumen...                   │                 │
│              │                                   │ Composer    [↑] │
└──────────────┴───────────────────────────────────┴─────────────────┘
```

Tidak ada toolbar Pratinjau, segmented control, empty action row, atau replacement title bar yang mengambil ruang hanya demi satu view. Dokumen adalah default content; tidak perlu meminta pengguna memilih “Pratinjau” untuk membaca PRD.

### Kondisi B — dua atau lebih versi yang tersedia (sesuai entitlement existing)

```
┌─────────────┬────────────────────────────────────┬─────────────────┐
│ Daftar isi  │                    [◷ Versi 3  ▾] │ Chat            │
│             │ ┌────────────── Riwayat versi ───┐ │                 │
│             │ │ ✓ Versi 3          (Terbaru)   │ │                 │
│             │ │   Versi 2                      │ │                 │
│             │ │   Versi 1                      │ │                 │
│             │ ├────────────────────────────────┤ │                 │
│             │ │ ⇄ Bandingkan perubahan         │ │                 │
│             │ └────────────────────────────────┘ │                 │
│             │ 1. Overview                        │                 │
│             │ Dokumen...                        │                 │
└─────────────┴────────────────────────────────────┴─────────────────┘
```

Satu tombol/dropdown ringkas di area kontrol dokumen yang sudah ada, di kanan atas document pane; jika perlu toolbar minimal khusus banyak versi, jangan menambah bar global kedua atau bar tinggi. Gunakan label yang memuat versi aktif, bukan jargon `Version History (v3)` yang panjang atau button “Pratinjau” tak berguna. Icon history/chevron tidak wajib dua ikon jika terasa padat; gunakan existing design components.

### Kondisi C — masuk compare mode secara eksplisit dari menu

```
┌──────────────┬───────────────────────────────────────┬───────────┐
│ Daftar isi   │ Versi 2 → Versi 3   [Kembali ke dokumen]│ Chat      │
│              │ - konten sebelumnya                  │           │
│              │ + konten yang ditambahkan            │           │
│              │ perubahan lainnya...                 │           │
└──────────────┴───────────────────────────────────────┴───────────┘
```

Compare adalah mode sementara. Tunjukkan kedua versi yang dibandingkan dan arah old→new; berikan close/back action yang jelas. Jangan menjadikan Diff tab selalu visible atau meminta pengguna memilih Pratinjau saat kembali. Jangan merusak semantic highlight addition/deletion (P4 tidak berlaku untuk Diff). Preserve layout asli.

## 4. Implementasi detail

- Default document view, termasuk live generation; conditional version control hanya ketika actionable (lebih dari satu versi nyata dan mengikuti entitlement/gate existing). Bila plan existing menampilkan gated access yang sah, preserve gating secara jelas tanpa mengungkap konten history terlarang. Tidak boleh membuka entitlement yang sebelumnya terbatas.
- Reuse `VersionHistory` dan `PrdDiffViewer`/diff engine. Refactor komposisi UI dan API callbacks seperlunya, jangan tulis ulang version persistence atau diff algorithm jika tidak ada bug terbukti. Saat memilih versi lama, canvas dan TOC merefleksikan versi yang benar; current label mengikuti `selectedVersionNum`, latest marker hanya pada versi newest. Jangan memperlakukan view versi lama sebagai revisi baru, reset project step, atau auto-generate.
- Akses `Bandingkan perubahan` dari kontrol yang sama. Gunakan actual version IDs/content. Compare versi aktif dengan versi sebelumnya yang tersedia sesuai policy existing; fallback bila memilih versi paling awal harus diberi label arah lama→baru yang benar (atau pilih pasangan eksplisit jika policy existing membutuhkan). Jangan diam-diam membalik penambahan/penghapusan atau membandingkan versi dengan data streaming yang belum disimpan. Jangan membuat UI pemilih rumit bila tidak diperlukan. Jika version list invalid/kurang dari dua, compare tidak dapat dijalankan.
- Setelah revisi berhasil tersimpan, list versi terupdate, versi baru terpilih sesuai behavior existing, diff memakai persisted content yang benar. Hindari stale selectedVersion, flash content, auto-close yang menyebabkan data hilang, dan perubahan state dari proyek lain.
- Saat streaming/revisi aktif, pastikan kontrol version selection/compare tidak mengganggu live document (disable action yang tidak aman dengan reasoning singkat jika perlu; jangan freeze playback atau melemahkan lock). Pertahankan revision target existing, read-only PRD setelah AC/Task, export/share dan recovery.
- Public share dan consumer tanpa version capabilities harus langsung menampilkan dokumen tanpa blank toolbar. Jangan menambah akses versi atau user-only buttons.
- Keyboard navigation, escape/close, focus return, menu overflow/viewport, screen-reader labels, focus visible dan correct roles/aria. Gunakan komponen DropdownMenu/Popover/Select yang menangani behavior aksesibilitas; jangan membangun menu via div-clicks manual jika tersedia komponen siap pakai.

## 6. Test/acceptance criteria (tanpa browser QA)

- 0/1 persisted version: tidak ada Pratinjau/tab/blank toolbar. Current content tetap tersedia sesuai generation state.
- ≥2 versions: satu control label versi aktif; pilih versi, latest indication benar. Diff hanya tersedia melalui control yang sama; compare direction jelas, return to document bekerja. No data mutation dari view/compare.
- Plan gating existing tetap berlaku; tidak ada version disclosure unauthorized. Public share viewer bebas toolbar jika tidak ada controls yang berhak.
- Revision create vN+1: actual list refresh dan label/selection tepat; diff content benar. Selected v1/legacy/non-contiguous versions dan stale list memiliki handling benar.
- Active generation, resume/revision, Chat toggle, panel resize, TOC/Markdown/Mermaid/export, read-only lock, AC CTA dari P1–P5 tidak rusak.
- Component interaction tests untuk conditional rendering, menu action, keyboard/focus, comparison pair/direction, closing. Pure tests untuk existing diff computation jika touched.

Jalankan targeted tests/typecheck/lint. Jangan browser QA/Playwright di P6. Jangan mengubah DB, seed fake versi lewat aplikasi, force entitlement, bypass tests, hapus assertion valid atau mengabaikan bug baru. Jika test gagal, perbaiki root cause atau lapor blocker dengan evidence.
