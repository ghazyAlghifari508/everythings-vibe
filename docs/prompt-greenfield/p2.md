## 1. Laporan pengguna dan target

Setelah PRD selesai di-generate, CTA yang semestinya `Generate AC` hilang, diganti tombol `Kembali ke Fitur >` di sisi kanan Navbar. Tombol itu menunjukkan panah kanan (seolah Next) tetapi labelnya menyuruh pengguna mundur. Alur Ask → Fitur → PRD → AC → Task terputus. Ini adalah bug fungsi dan state, bukan sekadar copy. Perbaiki agar user yang memiliki PRD valid dan eligibility AC dapat maju, tanpa memalsukan progress, menggandakan generasi, atau melewati paywall. Nested Layout Routes dipertahankan.

```
SALAH:
✓ Ask ─ ✓ Fitur ─ ③ PRD ─ ④ AC ─ ⑤ Task      [Chat] [Kembali ke Fitur >]
PRD sudah berhasil disimpan, tetapi tidak dapat melanjutkan.

BENAR (setelah save valid, paket berhak):
✓ Ask ─ ✓ Fitur ─ ③ PRD ─ ④ AC ─ ⑤ Task      [Chat] [Generate AC >]
                                                      ↓
                                             /vibeplan/$id/ac
```

Diagram stepper 5 tahap adalah target keseluruhan. Penghapusan step Kanban serta warna progress dikerjakan P4; di P2 fokus pada state dan navigation actions. P1 harus sudah memperbaiki penyaluran stream dan final persistence handoff. Jika P1 belum selesai, lapor dependency dengan jelas.

## 3. Sumber kebenaran yang benar

Pisahkan empat hal:

```
current route/view ─────────── tahap yang sedang dilihat
persisted workflow step ────── progress monotonik yang dicatat
artifact availability ──────── PRD, AC, Task benar-benar tersimpan/valid
operation state + plan ─────── generating/saving/error + entitlement
                              │
                              ▼
                     derive primary CTA secara deterministik
```

- Current route bukan bukti artefak tersedia; jangan naikkan `projects.step` hanya karena URL berubah.
- Persisted step tetap monotonik dan bukan pengganti validasi prerequisite yang sebenarnya. `hasPrd` harus merepresentasikan artefak valid yang sudah dipersist, bukan sekadar non-empty streaming buffer/raw text.
- Reuse `workspaceProgress` dan availability existing apabila sesuai; jangan menduplikasi aturan domain di Navbar dan setiap child. Buat pure CTA policy yang menerima input terverifikasi secara eksplisit.
- Setelah save sukses, pastikan invalidation/refetch menyegarkan workspace parent DAN child data yang relevan. Gunakan API router yang didukung versi repo. Jangan membanjiri invalidation pada setiap token. Selama save/revalidation masih pending, tampilkan CTA disabled yang benar, bukan tombol balik atau CTA enable palsu. Hindari arbitrary sleep/polling sebagai satu-satunya fix.
- Jika benar-benar ditemukan persisted inconsistency, perbaiki sumber kesalahan transaction/advancement sesuai aturan proyek; jangan mass-update existing data, hardcode step di client, atau mengubah DB supaya test lulus. Pastikan repair jika diperlukan dapat dibuktikan dan scope minimal.
- Auth, ownership, mode Greenfield, soft delete, server prerequisite checks, billing/credit dan plan gating tetap berlaku. Parent guard bukan satu-satunya pengamanan API.

## 4. Expected CTA contract (PRD)


| Kondisi                                              | Tampilan primary CTA                                                                             | Aksi                                                                             |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| PRD generating atau belum selesai disimpan           | `Generate AC` disabled (untuk akun eligible)                                                     | Tidak dapat advance                                                              |
| PRD valid dan tersimpan, AC belum tersedia, eligible | `Generate AC`                                                                                    | Existing advance endpoint → canonical AC route → existing AC generation contract |
| AC sudah tersedia                                    | `Lanjut ke AC`                                                                                   | Buka AC existing, tidak regenerate                                               |
| Proyek sudah mencapai Task                           | Navigasi sesuai tahap yang telah dicapai (existing progress policy, label jelas)                 | Buka artifact existing, bukan generate ulang                                     |
| Plan tidak mendukung AC                              | Existing `Upgrade ke Pro` sesuai gating                                                          | Buka paywall/upgrade yang benar; jangan bypass                                   |
| PRD gagal/terhenti atau save failure                 | Retry/recovery pada area PRD yang relevan, CTA forward tidak aktif sampai prerequisite valid     | Tidak menuju AC secara palsu                                                     |
| PRD belum ada dan belum boleh dibuat                 | Aksi pemulihan/prerequisite yang benar, bila perlu kembali dengan affordance sekunder yang jelas | Tidak menganggap user sudah siap maju                                            |


Urutan evaluasi harus menghindari misleading forward/back affordance. Jangan jadikan “Kembali ke Fitur >” default primary ketika PRD valid atau sedang dibuat. Jika ada back action yang memang sah, label dan arah icon harus menunjukkan Back, bukan forward primary. Jangan tambahkan tombol baru jika tidak diperlukan.

### Perluas audit ke seluruh pipeline

Periksa CTA Generate PRD pada Fitur serta Generate Task pada AC. Pastikan generation selesai + artefak tersimpan membuka tahap berikut sesuai plan; existing artifact tidak dibuat ulang. CTA tidak boleh terhalang stale `isGeneratingPRD`, `streamingPRDContent`, `isGeneratingAC`, parent snapshot, atau status pending yang sudah tidak berlaku. Pertahankan valid disabled state selama operasi berjalan; jangan mengaktifkan semua tombol demi kesan responsif. Pastikan double-click tidak menghasilkan dua mutation/generation. Route `/vibeplan/$id/kanban` tetap tersedia sebagai Task view. History, deep link, legacy redirects, dan browser history semantics tidak diubah tanpa kebutuhan.

## 6. Regression tests dan acceptance criteria

Tambahkan/perbarui pure CTA matrix, integration test untuk parent loader/revalidation, serta flow step/server guard test yang relevan:

1. `route=prd`, `step=fitur` stale, PRD belum ada → tidak enable Generate AC; generation tidak memperlihatkan “Kembali ke Fitur” sebagai next utama.
2. `route=prd`, PRD persisted valid, metadata step tertinggal → state disinkronkan; CTA tidak salah mundur, lalu Generate AC tersedia setelah revalidation/konfirmasi.
3. Success P1 generation → server persistence → update parent + child → CTA eligible muncul dan navigasi canonical.
4. AC existing, Task existing, plan free/ineligible, failed save, aborted stream, no PRD, loading state, unauthorized project → sesuai tabel.
5. Next action tidak mengulang generasi atau mengurangi kredit ganda; kegagalan endpoint memunculkan error/retry yang tepat.
6. AC selesai dan persisted → Task CTA mengikuti aturan yang sama. Kembali melihat PRD/AC lama tidak menurunkan progress atau mengubah lock read-only.
7. Refresh/resume/legacy URL dan project switch tidak membuat CTA dari proyek lain.

Gunakan test fixtures terisolasi dan valid, bukan memanipulasi DB real, bypass ACL/paywall, force completion, skip assertions, atau fake success. Jangan mengabaikan error baru yang ditemukan. Laporkan existing vs new failures berdasarkan baseline, bukan asumsi. Jalankan tests/unit/integration, lint/typecheck terarah; **browser QA tidak dilakukan pada P2**.
