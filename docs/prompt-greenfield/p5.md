# P5 — Refine Generation UX for Fitur, PRD, AC, and Task (Minimal, Honest, Consistent)

**Kompleksitas:** HIGH / COMPLEX (lintas empat view) · **Prioritas:** P1  
**Urutan:** 5 dari 8 — setelah P1–P4, sebelum P6.  
**Repository:** `ghazyAlghifari508/everythings-vibe` · **Target branch:** `feature/vibeplan-greenfield`

## 1. Requirement final yang sudah dikonfirmasi pengguna

Pengguna tidak menginginkan UI generation yang redundan, card thinking generik, copy panjang, progress palsu, animasi tiga titik berkedip, atau raw model reasoning di header/chat. Fitur/product planning harus berfokus pada hasil nyata, bukan narasi AI sedang bekerja. Namun pengguna **secara eksplisit memilih mempertahankan skeleton node pada Feature Tree dan Task Breakdown**, dengan **satu indikator generation**. Jangan mengganti skeleton menjadi canvas kosong dengan spinner di tengah; keputusan itu sudah tidak dipilih.

Untuk PRD, daftar delapan section di panel kanan dengan spinner section aktif sudah dianggap bagus dan harus dipertahankan, dengan warna neutral sesuai P4. Hilangkan indikator duplikat di canvas dan Chat. Untuk AC dan Task pengguna belum sempat melihat UI runtime karena bug Generate AC; audit source aktual dan hapus pattern yang sama bila ditemukan. Jangan mengklaim detail visual AC/Task yang belum dilihat sebagai fakta runtime.

P1 memperbaiki live streaming PRD, P2 CTA/progress, P3 chat visibility/composer, P4 redundant header/five-step/neutral colors. Gunakan implementasi terkini; jangan mengulang atau membatalkan fix tersebut.

- Pertahankan title `Feature Tree` statis dan topbar existing yang benar-benar berfungsi.
- Satu loading status sederhana, neutral spinner/icon + `Menyusun daftar fitur...` di sisi kanan topbar. Pakai compact inline loader; tidak ada card baru, timer palsu, sparkle, atau string yang diulang di Navbar/button. Disabled forward CTA label tetap action (`Generate PRD`) ketika belum siap, bukan status duplikat. Integrasi P2 tetap benar.
- **Reuse FeatureMapCanvas skeleton node, dotted background, konektor dan layout existing.** Skeleton hanya placeholder visual yang tidak bisa dikira fitur nyata; jangan menambah fake nodes sebagai actual data atau menyatakan persentase berdasarkan jumlah placeholder. Tidak perlu skeleton tambahan di luar canvas. Bila skeleton existing sudah bagus, jangan rewrite desainnya.
- Setelah tree valid, langsung render node asli; spinner hilang, title sama, action Generate PRD enable sesuai P2. Jangan regenerate karena render/transition/loading change.
- Empty state: hapus tiga card tutorial yang mengulang stepper bila masih ada. Jika benar-benar belum ada tree dan manual generation dibutuhkan, tampilkan copy pendek `Belum ada daftar fitur` dan satu actionable button existing `Susun daftar fitur`. Jangan menghapus trigger yang dibutuhkan. Error state tetap memiliki pesan ringkas dan Coba Lagi; jangan mengklaim data aman bila tidak dapat dibuktikan.

### B. PRD — progress section kanan sebagai satu indikator utama

```
PRE-TOKEN (CHAT TERBUKA)                 SAAT DOKUMEN STREAMING
┌─────────────────────┬────────────────┐  ┌─────────────────────┬────────────────┐
│ Document area       │ Menyusun PRD   │  │ 1. Overview         │ Menyusun PRD   │
│ tenang, tidak ada   │ ◌ Overview     │  │ 1.1 Latar Belakang  │ ✓ Overview     │
│ card thinking       │ ○ Goals        │  │ Teks live bertambah │ ◌ Goals        │
│                     │ ○ Requirements │  │ ...                 │ ○ Requirements │
│                     │ ○ Core Features│  │                     │ ...            │
│                     │ ...            │  │                     │                │
│                     │ Composer  [■]  │  │                     │ Composer  [■]  │
└─────────────────────┴────────────────┘  └─────────────────────┴────────────────┘

CHAT TERTUTUP / MOBILE DOKUMEN PRE-TOKEN
┌───────────────────────────────────────────────────────┐
│                                                       │
│                    ◌ Menyusun PRD...                   │ ← fallback saja
│                                                       │
└───────────────────────────────────────────────────────┘
```

TOC kiri tetap digunakan saat heading dokumen tersedia, tidak digambarkan detail pada ilustrasi. Pertahankan tiga panel existing, Markdown rendering, resize, version selection (refinement P6), dan Chat toggle P3.

**Hapus untuk doc generation:**

- overlay/card `Menyusun PRD` yang berisi daftar “Menganalisis kebutuhan”, “Menulis dokumen”, paragraf “Sedang menganalisis kebutuhan dan menyusun dokumen. Dokumen akan langsung tampil ...”, serta timer/thinking box redundant;
- typing indicator tiga titik dan raw reasoning details ketika mode generate/resume/revisi dokumen (gunakan status yang sesuai dengan operasi aktual);
- pengulangan copy/status antar canvas, chat, dan Navbar.

**Pertahankan:**

- actual section progress di kanan: Overview, Goals & Success Metrics, Requirements, Core Features, User Flow, Architecture & Tech Stack, Database Schema, Design & Technical Constraints (sesuaikan canonical existing sections, jangan hardcode daftar baru jika sudah punya constant);
- current-section spinner dan checkmark neutral P4; pending sections yang readable, bukan raw reasoning;
- status copy pendek, mis. `Menyusun PRD` dan `PRD selesai` saat selesai secara sah. Jangan menandai semua section selesai hanya karena stream tertutup/failed;
- streaming Markdown di canvas dari token valid pertama (P1), real conversation, error/recovery, stop, composer, plan/credit handling.

Ketika progress panel terlihat/terakses, jangan beri spinner/card di center pane. Ketika panel kanan tidak terlihat (closed, mobile document tab, responsive drawer closed), gunakan **satu** compact fallback spinner + copy pendek di area dokumen sebelum token pertama. Lepas fallback ketika konten sebenarnya tampil, atau gunakan status singkat nonduplikat bila benar-benar perlu untuk saving. Jangan memaksa Chat terbuka, unmount stream owner atau membuat duplicate ChatPanel. Untuk ordinary chat yang bukan generation dokumen, jangan menghapus feedback yang dibutuhkan secara global; bila typing dots memang tidak sesuai dalam Greenfield, pilih satu indikator ringkas yang tidak bersaing dengan document progress. Conversation content yang benar tetap di Chat.

## 4. Design-system/component exploration — WAJIB, bukan sekadar rekomendasi

Sebelum membuat perubahan UI, telusuri komponen already-installed dan katalog resmi HeroUI, shadcn/ui, Magic UI, React Bits, [https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs), [https://www.affectui.com/components](https://www.affectui.com/components), [https://tuffui.com/](https://tuffui.com/), [https://yappologistic.github.io/CUI/](https://yappologistic.github.io/CUI/), [https://www.sakaniui.com/](https://www.sakaniui.com/) dan library siap pakai yang relevan. Fokus kebutuhan nyata: inline spinner/loading, status indicator, accessible icon/button, canvas skeleton existing, conditional status. Catat `library → component → link → alasan fit → digunakan di file mana` untuk kandidat terpilih.

**Wajib menggunakan komponen siap pakai yang cocok** (reuse komponen existing jika sudah memenuhi tujuan). Jangan cuma menjelajah lalu membuat versi custom sendiri tanpa alasan. Jangan memakai ornamen orb, gradient, glow, card sparkle, fake AI session panel, atau efek motion semata-mata karena tersedia di library. Import/adapt seminimal mungkin sesuai versi/dependensi, theme light/dark, accessibility, lisensi, performance. Jangan install sembilan library sekaligus. Jika tidak ada komponen yang cocok, tulis bukti evaluasi dan buat hanya primitive kecil yang dibutuhkan. Gunakan existing skeleton canvas, jangan merender ulang dari nol.

Panduan UX: [https://carbondesignsystem.com/components/loading/usage/](https://carbondesignsystem.com/components/loading/usage/) dan [https://carbondesignsystem.com/components/inline-loading/usage/](https://carbondesignsystem.com/components/inline-loading/usage/) ; [https://www.nngroup.com/articles/ten-usability-heuristics/](https://www.nngroup.com/articles/ten-usability-heuristics/) . Indeterminate spinner jika progress tidak diketahui; section progress hanya berdasarkan informasi nyata. Status dapat memakai live region/aria-busy yang tidak membanjiri screen reader setiap token; respect reduced-motion untuk animasi nonessential. Pastikan kontras dan fokus keyboard tidak rusak. Jangan menambah copy yang hanya menjelaskan aktivitas AI yang sama berulang kali.

## 5. Test dan Definition of Done (tanpa browser QA)

Buat targeted unit/component/state tests:

1. Fitur/Task loading: title statis, node skeleton existing hadir, satu indikator generation tekstual/semantic, tidak ada ThoughtLine/card/animated dots tambahan; saat sukses spinner hilang dan node actual render. No duplicate request saat status berubah. Disabled CTA sesuai P2.
2. PRD pre-token Chat terlihat: checklist/spinner aktif, tidak ada center overlay verbose atau typing dots/raw reasoning untuk dokumen. Chat tertutup/mobile doc: satu fallback. Delta pertama → live doc canvas, fallback hilang. Toggle tidak merusak stream. Complete/error/abort menampilkan status yang benar (P1/P3/P4).
3. AC: satu pre-token loading, TOC dari actual headings, streaming/saved/retry/error/credit/paywall tetap valid;
4. Task: raw thinking tidak jadi heading; skeleton dan handoff/Kanban functionality tetap ada, real data muncul tanpa faking progress;
5. Audit Ask/Kanban dan shared helpers agar tidak ada penghapusan indikator/error penting atau perubahan lintas domain; hindari global deletion `ThoughtLine` jika dipakai sah di fitur lain.
6. Responsive visibility logic, light/dark tokens, regressions in generation lifecycle; test contract, bukan hardcode seluruh CSS markup.

Jalankan targeted tests, lint/typecheck dan existing regression suite terkait. Jangan memanipulasi DB, mengubah status generation, memalsukan fixtures di aplikasi, melemahkan assertions, menyembunyikan error, atau mengabaikan bug baru. Jangan jalankan browser QA/Playwright pada P5. Laporkan visual yang masih perlu real browser verification di P8.

## 6. Handoff

Laporkan tiap view before→after, komponen/library yang benar-benar dipakai, copy yang dihapus, state logic yang dipertahankan, dan hasil checks. Pastikan keputusan user's skeleton node dipenuhi. P6 fokus version history/diff, bukan mengubah generation design. Jangan commit/push/merge tanpa izin.
