```
Home / Plan New
    ↓  project creation, handoff, ownership
/vibeplan/$id/ask
    ↓  saved answers

    ↓  Feature Tree persisted
```

Parent shell harus tetap persisten walaupun header bar tambahan telah dihapus. Stepper hanya Ask/Fitur/PRD/AC/Task. Legacy routes dan public share tetap sesuai compatibility contract. Jangan memindahkan PRD/AC/Task balik ke top-level route lama untuk menutupi problem.

Tambahkan integrated tests untuk hubungan antarperbaikan, misalnya:

- Generate PRD melalui deterministic SSE/integration harness → canvas menerima delta → persist result → parent workspace refresh → CTA AC benar; tidak ada langkah yang digantikan dengan mock yang justru menyembunyikan bug.
- Toggle Chat di tengah generation → tidak ada duplicate stream controller → close fallback P5 benar → reopen meneruskan state; Stop memanggil cancellation path aktual.
- Saved PRD v1 → revision v2 → control history muncul → pilih v1/compare → dokumen dan TOC benar; flow progress tidak mundur.
- AC/Task guard dan availability → Kanban route memetakan ke Task tanpa mengubah DB sebagai step baru.

## 5. Test integrity: strict, tidak boleh dicurangi

**DILARANG:**

- Manipulasi DB melalui SQL, script admin, ORM manual, seed ad-hoc, mengubah credits/plan/project step, menyuntikkan PRD/AC/Task atau memaksa `completed` demi menutupi kegagalan feature nyata.
- Mengubah data aplikasi karena test gagal; tidak boleh menghapus proyek/history user atau memakai production DB untuk test destruktif.
- Skip/todo/only test untuk menyembunyikan failures, mematikan suite, mengurangi cakupan assertion atau mengubah expected value yang sebenarnya salah secara produk hanya agar lulus. Jangan ubah CI config sebagai jalan pintas.
- Memalsukan response, fake SSE done, hardcode project/account, mem-bypass auth/paywall, disable error boundary, swallow exception, suppress warning/error baru, atau menjadikan mock sebagai evidence integrasi real.
- Mengabaikan bug baru yang ditemukan. Fix bug yang terkait acceptance criteria dan re-run affected tests; untuk issue di luar scope, catat reproduksi, severity, impact, dan apakah menghalangi penerimaan. Jangan diam-diam memperluas fitur atau mengklaim semuanya aman.

**Yang diperbolehkan:** deterministic unit test fixtures, mock/fake timers/SSE dalam test terisolasi yang secara eksplisit menguji logika yang benar, isolated test DB lifecycle yang sudah didukung harness dengan fixture terdokumentasi. Ini bukan manipulasi DB aplikasi atau evidence E2E. Jangan memodifikasi fixture untuk membuat behavior production yang salah terlihat benar. Beri label unit vs integration vs not verified. Jangan mengakses secrets atau data pengguna nyata tanpa kewenangan.

## 6. Commands dan execution order

Cek `package.json`, pnpm workspace, scripts/config terbaru. Gunakan command yang benar-benar ada. Jangan mengarang `generate-routes` bila tidak tersedia. Contoh (adaptasi berdasarkan script aktual):

```
# Targeted tests sesuai file/contract yang berubah
pnpm exec vitest run <relevant-test-paths>
# Lint / format checks untuk file terdampak
pnpm exec biome check <changed-paths>
# Type checking dan route generation sesuai scripts aktual
pnpm exec tsc --noEmit
# Final non-browser checks dan build, jika environment memungkinkan
pnpm check
pnpm test
pnpm build
```

Sebelum menjalankan `pnpm test`/`pnpm check`, verifikasi script tidak ikut menjalankan browser QA/Playwright. Bila mencakup browser test, jalankan subset non-browser yang sah dan laporkan browser suite pending P8. Jangan menonaktifkan browser test dalam repository hanya karena ditunda. Biarkan route generator mengelola generated tree, jangan hand-edit. Periksa route types dan imports, no new dead branches, no duplicated implementation.

Perbaiki failure secara kausal; re-run targeted tests lalu broad non-browser suite setelah setiap group fix. Simpan command, exit code, actual pass/fail counts, test names, baseline known failures dan blocker. Jangan menyatakan build lulus jika belum dijalankan atau exit code gagal.

Jika regression fix di P7 perlu UI baru, wajib eksplorasi dan reuse komponen siap pakai dari existing UI, HeroUI, shadcn/ui, Magic UI, React Bits, [https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs), [https://www.affectui.com/components](https://www.affectui.com/components), [https://tuffui.com/](https://tuffui.com/), [https://yappologistic.github.io/CUI/](https://yappologistic.github.io/CUI/), [https://www.sakaniui.com/](https://www.sakaniui.com/) dan yang relevan. Jangan masukkan dekorasi, header, loading UI, atau dependency baru yang tidak diperlukan. Custom hanya jika evaluasi komponen membuktikan gap nyata; laporkan pilihan. Scope hanya regression fixes.
