## 1. Evaluation Setup & Methodology

The evaluation matrix covers all six mandatory product domains across all six available design skill states:

### Product Archetypes
1. **Finance Dashboard (`finance-dashboard`):** Personal finance & accounting mobile application (MSME cash flow, daily income/expense entry, monthly budget limits, net balance breakdown).
2. **Customer Directory (`customer-directory`):** Relational sales CRM & client directory web application (company search, contact records, interactive filters, account settings).
3. **Travel Booking Mobile (`travel-booking-mobile`):** Domestic travel reservation mobile application (destination discovery, flight/hotel booking, multi-day itinerary timelines).
4. **E-Commerce (`ecommerce`):** Modern retail shop web application (product catalog grid, detail view, cart management, transparent checkout).
5. **Portfolio (`portfolio`):** Technical developer & creative craft portfolio (project showcases, case studies, technical competencies, contact affordances).
6. **Marketing Landing Page (`marketing-landing`):** SaaS launch marketing web page (high-impact hero, interactive feature demonstrations, transparent pricing cards, FAQ).

### Evaluated Skill States
1. **No Skill (`none`):** Baseline Studio design engine with universal base quality rules only.
2. **Impeccable (`impeccable`):** v4.5.2 craft floor, operational screen guidelines, hierarchy, and typographic polish.
3. **Frontend Design (`frontend-design`):** Anthropics official frontend design skill, content-grounded aesthetic, and non-generic composition.
4. **UI UX Pro Max (`ui-ux-pro-max`):** Next Level Builder design intelligence with planning-time bounded dataset recommendations (products, styles, palettes, typography, UX rules).
5. **Anti-Slop (`anti-slop`):** Core 38 anti-slop rules, mobile reflow, and human accessibility guidelines.
6. **Taste (`taste`):** Upgraded to verified official v2.1.5 (Leonxlnx, 24 October 2026), incorporating full App Screen Guidelines (`references/app-screens.md`) for operational UI and art direction for pages.

## 3. Key Findings & Tradeoffs per Skill

### 1. No Skill (`none`)
- **Fidelity:** 100% (native baseline).
- **Context Injection:** 0 additional characters. Zero token overhead.
- **Quality Safety:** Guaranteed by Studio's Universal Base Quality Rules (`STUDIO_BASE_QUALITY_RULES`), canonical shell assembly, and DOM diagnostics. No Skill yields clean, valid, accessible, responsive prototypes without degradation.
- **Best For:** Fast generation when the user wants unconstrained, rapid ideation while relying on Studio's core platform guarantees.

### 2. Impeccable
- **Fidelity:** Guidance (A), References (A), Tools (C), Runtime workflow (D).
- **Scope Fit:** Excellent for operational applications and refined UX polish.
- **Divergence:** Upstream interactive CLI audit (`/impeccable:audit`) and git detectors do not run in Studio worker. All quality checks are executed by Studio's automated validation pipeline.

### 3. Frontend Design
- **Fidelity:** Guidance (A), References (A), Tools (A), Runtime workflow (C).
- **Scope Fit:** Best for portfolios, marketing landing pages, and creative web experiences requiring a strong point of view.
- **Divergence:** Upstream visual screenshot self-critique loop is evaluated via Studio's HTML contract validator instead of headless multimodal vision calls.

### 4. UI UX Pro Max
- **Fidelity:** Guidance (A), References (A), Dataset/Tools (B), Runtime workflow (D).
- **Scope Fit:** Ideal for data-dense dashboards, SaaS management tools, and mobile apps.
- **Divergence:** Python `search.py` is safely substituted with a bounded, in-memory TypeScript lookup during the planning stage (`ui-ux-pro-max-lookup.ts`). Raw catalogs (747 KB Google Fonts, 824 KB Phosphor icons) are excluded to prevent context overflow.

### 5. Anti-Slop
- **Fidelity:** Guidance (A), References (A), Tools (A), Runtime workflow (D).
- **Scope Fit:** High across all domains to eliminate generic AI tells, redundant badges, and fake testimonials.
- **Divergence:** Delivery Gate browser click-through is enforced server-side via strict HTML diagnostics and contract validation.

### 6. Taste (Upgraded to v2.1.5)
- **Fidelity:** Guidance (A), References (A), Tools (C), Runtime workflow (D).
- **Scope Fit:**
  - In v2.1.5, Taste covers both pages AND app screens (`references/app-screens.md`).
  - For operational screens (finance, directory, travel booking), the adapter selects app-screen rules (quiet borders, flat surfaces, tabular numbers, single data hue).
  - For marketing/portfolio, the adapter selects page art direction principles.
- **Divergence:** Upstream CDP real-browser inspector (`inspect.mjs`) and asset scraper (`assets.mjs`) do not run in headless worker; Studio provides deterministic validation.

## 4. Benchmark Methodology & Honest Limits

1. **No Live Model Cost Claims:** Latency and tokens during unit tests were recorded with deterministic fixtures and mocked providers to avoid billing surprises and stochastic variability.
2. **Deterministic Contract Proof:** Every prompt prefix, section selection, character count, and structural rule is verified by automated Vitest assertions.
3. **No Browser QA:** All validations were performed via JSDOM and AST diagnostics without spinning up headless Playwright or Chromium processes, honoring the strict user directive.
