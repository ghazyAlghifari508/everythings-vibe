## 6. REMOVE THE REPETITIVE CONSENT EXPERIENCE

Hapus UI dan logika yang membuat user harus menyetujui credit spending pada setiap sync normal.

Target yang harus dihilangkan dari routine flow:

```
[Siapkan instruksi]

┌──────────────────────────────────────┐
│ Persetujuan biaya analisis           │
│                                      │
│ Analisis membutuhkan hingga...       │
│                                      │
│ [ ] Saya setuju ...                  │
│                                      │
│ [Tambahkan Kredit] [Setuju...]       │
└──────────────────────────────────────┘
```

Tetapi **jangan menghapus transparansi biaya atau otorisasi sah terhadap tagihan**.

Gunakan kebijakan produk berikut:

1. Ketentuan penggunaan kredit, tarif, dan batas maksimum didokumentasikan di Pricing/Billing.
2. User menyetujui kebijakan atau spending limit sekali pada titik aktivasi yang tepat, bukan setiap sync.
3. Preferensi/batas otorisasi disimpan server-side dan dapat diperbarui user.
4. Bila sebuah operasi melampaui batas yang telah disetujui, perlukan tindakan persetujuan baru yang sesuai.
5. Jika tarif tidak berubah dan tindakan berada dalam batas yang sudah disetujui, jalankan flow normal tanpa modal.
6. Jangan menganggap checkbox tersembunyi sebagai consent.
7. Jangan menghapus backend credit guards.
8. Jangan diam-diam mengenakan biaya yang belum diotorisasi.

Jika schema existing sudah mendukung persisted consent/authorization, reuse itu.

Jika belum, implementasikan mekanisme paling kecil dan aman untuk membuat keputusan billing yang transparan tetapi tidak repetitif.

Jangan memperkenalkan permission modal lain dengan nama baru.

## 7. TOP-UP RECOVERY

Ketika kredit ditambahkan:

```
LOCKED PROMPT
      │
      ▼
[Tambahkan Kredit]
      │
      ▼
Billing / Top Up
      │
      ▼
Credit updated
      │
      ▼
Revalidate eligibility
      │
      ▼
Prompt unlocked
```

Requirements:

- Tidak perlu sync ulang repository yang sudah diunggah.
- Tidak perlu full reload jika app query state dapat di-refresh.
- Tidak memerlukan permintaan AI tambahan.
- Credit state selalu berasal dari server.
- Tidak mengandalkan optimistic fake balance.
- Jangan langsung menampilkan token sebelum eligibility tervalidasi.

## 8. INTERNAL BILLING EXEMPTION

Jika user mempunyai entitlement internal billing exemption yang sudah sah:

- Jangan munculkan locked prompt.
- Jangan munculkan top-up CTA.
- Jangan munculkan credit approval.
- Gunakan flow normal sync.
- Backend tetap melakukan permission validation.
- AI provider limits dan usage logging tetap aktif.

Jangan hardcode email developer sebagai bypass.

- Tidak ada checkbox approval berulang.
- Tidak ada dua close buttons.
- Tidak ada modal biaya yang berbeda dari desain aplikasi.
- Re-sync harus tetap berfokus pada memperbarui source snapshot.
- Jangan menagih ulang ketika reuse ready analysis tidak membutuhkan generasi baru.

- Kartu kredit besar sebelum sync.
- Teks "Analisis maksimal 12 kredit" sebagai isi utama prompt.
- Tombol "Siapkan instruksi".
- Approval checkbox setiap sync.
- Native JavaScript alert/confirm.
- Modal pricing berulang.
- Placeholder credential palsu.
- Gradient/dekorasi tidak penting.
- Floating fake badges.
- Tombol yang tidak mempunyai action.
- Dark-mode palette yang berbeda dari theme.
- Hardcoded saldo atau biaya.
- Hidden credit charges.

UI harus tetap ringkas, jelas, dan konsisten.
