# P03 — Durable Workspace Conversation and Chronological Timeline

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** COMPLEX  
**Related issues:** Misplaced assistant responses, disappearing initial prompts, missing conversation history after handoff.

## Current problems

Existing Codebase workspace memiliki masalah berikut:

1. Respons assistant mengenai PRD, AC, atau Task dapat muncul di bagian atas chat, bukan di posisi tahap yang sedang dijalankan.
2. Setelah pengguna menyelesaikan workflow hingga handoff, prompt awal dapat terlihat hilang.
3. Workspace terkadang hanya menampilkan pertanyaan, generated artifacts, dan handoff sehingga terlihat seolah pengguna tidak pernah berinteraksi.
4. Mengganti feature plan atau membuka ulang workspace berpotensi menyebabkan kehilangan atau pencampuran pesan.

## Confirmed architectural findings

`use-codebase-workspace.ts` menggunakan `chatMessages` berbasis React state lokal.

`codebase-chat-workspace.tsx` me-render `CodebaseChatWorkspaceMessages` sebelum seluruh `Questions`, `ArtifactStream`, `StageHandoffs`, dan `HandoffCard`.

Akibatnya, posisi respons assistant tidak benar-benar bergantung pada urutan workflow.

Sementara itu, initial prompt, questions, dan answers menggunakan persistence yang berbeda dari chat messages.

## Objective

Bangun timeline workspace yang:

- Kronologis.
- Persisten.
- Terisolasi berdasarkan repository dan feature plan.
- Dapat direkonstruksi setelah refresh/reopen.
- Tidak membuat duplicate events.
- Tidak menciptakan pesan palsu.
- Tetap selaras dengan PRD, AC, Task, revision, dan handoff.

## Required architecture

Rancang event model yang memiliki minimal:

- Stable event identity.
- Repository identity.
- Feature/project identity.
- Event type.
- Stage association.
- Monotonic ordering atau timestamp yang konsisten.
- Artifact/operation reference jika diperlukan.
- Persisted lifecycle state.

Pertimbangkan event types:

```
user_message
assistant_message
question_set
question_answered
generation_started
generation_completed
artifact_created
revision_requested
revision_completed
handoff_ready
```

Itu conceptual event taxonomy. Sesuaikan dengan data model yang sudah ada. Tidak semua event harus ditampilkan sebagai bubble chat.

### Important

Gunakan server-authoritative persisted state. React state boleh digunakan untuk optimistic rendering, tetapi tidak boleh menjadi satu-satunya sumber riwayat.

Persist message dan event dengan idempotency yang benar. Late operation completion dari request lama tidak boleh muncul pada feature aktif yang berbeda.

Jika membutuhkan migrasi schema, buat migration versioned yang aman dan kompatibel dengan data existing. Jangan menghapus/mengubah data user secara manual.

## Rendering strategy

Jangan lagi menyusun UI berdasarkan kategori besar:

```
All messages
All questions
All artifacts
All stage actions
```

Susun berdasarkan ordered workspace events:

```
Event 1 → User message
Event 2 → Question flow
Event 3 → Feature artifact
Event 4 → PRD artifact
Event 5 → AC artifact
Event 6 → Task artifact
Event 7 → Handoff
```

Setiap event dapat menggunakan specialized reusable component.

Jangan membuat ulang card pertanyaan dan document card pada task ini. Persiapkan struktur timeline dan pertahankan rendering yang masih berfungsi. UI rinci akan dikerjakan P04–P06.

## Restore and legacy data

Saat workspace dibuka kembali:

1. Load persisted plan identity.
2. Load existing timeline/events.
3. Load persisted question/answer state.
4. Load generated artifacts.
5. Reconcile operation states.
6. Render timeline dalam urutan yang konsisten.

Untuk data lama yang belum mempunyai timeline lengkap, restore hanya informasi yang benar-benar tersedia. Initial prompt yang tersimpan pada handoff dapat digunakan sebagai fallback, dengan stable ID agar tidak muncul dua kali.

Jangan menciptakan assistant messages seolah-olah AI pernah mengirimkannya bila tidak ada data yang tersimpan.

## Critical scenarios

- Membuat feature baru dan mengirim initial prompt.
- Menjawab pertanyaan hingga selesai.
- Membuat Feature, PRD, AC, Task.
- Reopen setelah setiap tahap.
- Refresh saat generation masih berjalan.
- Reopen setelah handoff.
- Mengganti feature A → B → A.
- Re-sync repository setelah planning selesai.
- Melakukan revisi dokumen.
- Menerima late operation completion setelah berpindah feature.
- Request retry dan duplicate operation events.

Semua harus mempertahankan isolasi dan urutan.

## Component discovery requirement

Untuk presentasi timeline, audit komponen siap pakai dari HeroUI, shadcn, Magic UI, React Bits, AffectUI, TuffUI, CUI, SakaniUI, dan ThinkingOrbs.

Gunakan primitive yang tersedia untuk list, scroll, dan status jika sesuai. Jangan memakai animated notification list yang secara otomatis mereplay seluruh riwayat lama atau menggeser posisi baca user.

Untuk perubahan frontend, wajib menggunakan existing components atau komponen siap pakai yang benar-benar sesuai, bukan membangun ulang design system.

## Testing

Wajib membuat deterministic tests untuk:

- Event ordering.
- Idempotent restoration.
- Duplicate event prevention.
- Feature isolation.
- Reopen/refresh.
- Late completion handling.
- Failed artifact hydration.
- Prompt preservation.
- State transition.
- Correct association of messages with stages.

Jangan menulis test yang hanya memeriksa teks AI tertentu atau className CSS.

Tidak ada browser QA pada fase ini.

## Atomic commits

Pisahkan perubahan logis, contoh:

`feat(codebase): persist workspace conversation events`

`refactor(codebase): render planning activity chronologically`

`test(codebase): cover workspace timeline restoration`

Jangan memasukkan schema, UI, dan unrelated fixes dalam satu commit besar.

## Definition of done

- Initial prompt tetap tersedia setelah reopen.
- Assistant responses tampil pada tahap yang benar.
- History tidak mencampurkan dua feature plans.
- Existing documents dan Kanban tidak hilang.
- Re-sync tidak menghapus timeline.
- Loading/error tidak berubah menjadi empty workspace palsu.
- All targeted tests pass.

Laporkan migration, files changed, test results, commit hashes, dan setiap keterbatasan migrasi data legacy.
