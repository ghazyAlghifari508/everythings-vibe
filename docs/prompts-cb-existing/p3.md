## 1. Mission

Redesign pengalaman kredit pada Existing Codebase onboarding dan re-sync.

Current problems:

1. User dengan kredit cukup tetap dipaksa melihat card panjang tentang biaya analisis sebelum bisa membuka instruksi CLI.
2. User dengan kredit tidak cukup diarahkan ke card sederhana yang terlihat seperti placeholder.
3. Native browser `window.confirm()` muncul ketika memulai sync, re-sync, atau analisis ulang.
4. Billing notices terlalu dominan dan membuat seluruh pengalaman sync terasa berbeda dari desain VibeEverything.
5. User menerima informasi berulang yang sebenarnya hanya perlu ditampilkan saat relevan.

Target akhir adalah satu layout sync yang konsisten, dengan capability yang menyesuaikan eligibility pengguna.

**Jangan menghapus validasi kredit server-side atau menghilangkan persetujuan biaya yang memang dibutuhkan. Perbaiki presentasi dan interaksinya.**

## 5. Core UX Decision

There are three major eligibility states.

### STATE A — User Has Sufficient Credits

This is the default normal onboarding experience.

**Do not display a standalone credit notice card before the sync flow.**

Desired:

```
┌────────────────────────────────────────────────┐
│ Sync codebase dengan everything-vibe            │
│                                                │
│ 1  Salin instruksi untuk AI agent               │
│                                                │
│    ┌──────────────────────────────────────┐    │
│    │ Sync repository menggunakan CLI...   │    │
│    │                                      │    │
│    │                         [Salin]      │    │
│    └──────────────────────────────────────┘    │
│                                                │
│ 2  Buka AI coding agent                         │
│    Codex  Claude  OpenCode  Antigravity         │
│                                                │
│ 3  Pantau progress                              │
│    Menunggu agent terhubung                     │
│                                                │
└────────────────────────────────────────────────┘
```

No giant credit card.

No "Kebutuhan: hingga 12 kredit" paragraph above the entire form.

No native browser confirmation popup.

However, maintain billing transparency.

If paid analysis needs explicit consent, place concise cost disclosure immediately beside the user action that authorizes creating the session or starting analysis:

```
Analisis: maksimal 12 kredit
[Mulai sinkronisasi]
```

Or an equivalent compact inline arrangement integrated into the existing flow.

The important principle:

- User knows the maximum charge before authorization.
- Consent is connected to an explicit user action.
- Server stores/verifies approved pricing version and maximum.
- The flow does not require a separate full-page explanatory gate.
- No silent charging.

If a token has not yet been issued due to consent requirements, show the normal sync interface with a clear "Siapkan instruksi" action in the prompt area rather than a completely separate credit card.

Do not display a real token before server authorization.

### STATE B — Insufficient Credits

User remains in the SAME SYNC LAYOUT.

Show a locked prompt region.

```
┌────────────────────────────────────────────────┐
│ Sync codebase dengan everything-vibe            │
│                                                │
│ 1  Salin instruksi untuk AI agent               │
│                                                │
│    ┌──────────────────────────────────────┐    │
│    │                                      │    │
│    │              [Lock Icon]             │    │
│    │                                      │    │
│    │ Kredit tidak cukup untuk analisis.   │    │
│    │                                      │    │
│    │        [Tambahkan Kredit]            │    │
│    │                                      │    │
│    └──────────────────────────────────────┘    │
│                                                │
│ 2  Buka AI coding agent                         │
│    Codex  Claude  OpenCode  Antigravity         │
│                                                │
│ 3  Pantau progres                              │
│    Sinkronisasi belum dimulai                  │
│                                                │
└────────────────────────────────────────────────┘
```

**Critical security requirement:**

Do NOT generate a valid secret sync token and then merely hide it using CSS blur.

A blurred password/token is still readable from the DOM and client-side state.

For a blocked user:

- Do not issue usable sync credentials.
- Do not expose full tokenized CLI instructions.
- Render a safe placeholder inside the normal prompt region.
- Keep the step structure visible.
- Give one clear billing action.

If user adds credits:

- Re-fetch authoritative credit eligibility.
- Unlock the prompt step.
- Continue normal session creation.
- Do not force page reload when query invalidation suffices.
- Do not silently charge additional credits.

### STATE C — Free Initial Analysis

If eligible for free initial analysis:

- Follow the same normal sync flow as State A.
- No billing warning card.
- No unnecessary confirm popup.
- First analysis allowance must still be validated server-side.
- Do not accidentally consume allowance merely by opening the page.

## 6. Re-Sync UX

Re-sync modal must reuse the actual established modal style and sync workflow.

Expected:

```
┌────────────────────────────────────────┐
│ Perbarui repository                 X   │
│                                        │
│ 1  Salin instruksi                     │
│    [CLI prompt]          [Salin]        │
│                                        │
│ 2  Jalankan dari root repository       │
│                                        │
│ 3  Pantau sinkronisasi                 │
│    Menunggu agent                      │
│                                        │
│                             [Selesai]  │
└────────────────────────────────────────┘
```

If paid consent is required:

- Use compact inline cost disclosure or a well-designed app-owned AlertDialog when explicit confirmation is needed.
- Never invoke native `window.confirm`.
- Do not show a second standalone billing page.
- Do not put two independent close buttons in the same modal.
- Do not use a different footer background or arbitrary color palette.
- Reuse existing resync modal, not a newly invented component.

The "Selesai" button should only become enabled after the server confirms successful sync to the intended repository/session.

Whether AI re-analysis is needed depends on existing product contract; don't falsely claim analysis finished when only upload finished.

## 7. Remove Native Browser Confirm

Remove all `window.confirm()` usage from the Existing Codebase billing approval workflows.

Refactor:

- `confirmPreSyncCredit`.
- `confirmPaidAnalysis`.
- All callers in sync/re-sync/retry.

Separate:

```
Credit preflight: fetch state
Consent UI: user decision in React
Server authorization: validate consent
Session/analysis: perform action
```

Do not leave a Promise-based `window.confirm` wrapper disguised under another function name.

Do not replace with `window.alert`.

Use app-owned Dialog/AlertDialog if explicit confirmation is still necessary.

Payment and credit operations must not start just because a component mounted.

## 8. Avoid Misleading Copy

Remove unnecessary text such as:

```
Hubungkan repository

Analisis repository membutuhkan kredit.

Saldo tersedia: 105 kredit.
Kebutuhan: hingga 12 kredit.

Ukuran repository diperiksa saat sync...
```

from the default sufficient-credit onboarding screen.

Retain essential billing information where a user makes a billable decision.

Do not hide actual charges or usage history from the user.

For blocked state, concise message:

```
Kredit belum cukup untuk analisis.
[Tambahkan Kredit]
```

For successful authorization, no repeated explanation.

For failed analysis due to backend errors, do not show top-up CTA unless billing is actually the problem.

## 9. Billing Security &amp; Consistency

- Preflight server-side.
- Consent maximum verified server-side.
- Pricing version verified.
- Eligibility rechecked when session/analysis starts.
- Free allowance remains bounded.
- No token issuance on insufficient credits.
- No double session creation from repeated clicks.
- No cross-user billing leakage.
- No unsupported fallback to "free".
- If initial free allowance and admin exemption are implemented, use those existing policies correctly.

The user must not get a hidden credit charge.
