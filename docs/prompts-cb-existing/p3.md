## 4. Desired Visual Behavior

### State A — Request running

```
◌ Menyusun pertanyaan...          12.4s

  ▾ Aktivitas
    Permintaan sedang diproses.
```

Jika backend menyediakan real progress events:

```
◌ Menyusun PRD...                 28.5s

  ▾ Aktivitas
    ✓ Menyiapkan konteks repository
    ✓ Model mulai menghasilkan respons
    ◌ Menyimpan hasil...
```

Setiap activity event harus didasarkan pada peristiwa yang benar-benar terobservasi.

### State B — Activity collapsed

```
◌ Menyusun PRD...                 28.5s

  ▸ Aktivitas
```

Klik Aktivitas hanya menyembunyikan detail, tidak menghentikan AI generation.

### State C — Completed

```
✓ Pertanyaan siap                31.7s
```

Setelah settle, tampil ringkas dan auto-collapse detail jika appropriate.

Pertanyaan ditampilkan di bawahnya tanpa duplicate spinner atau running state.

### State D — Failed

```
✕ Gagal menyusun PRD             15.2s

  Detail error ditangani oleh
  contextual operation error UI.
```

Jangan menampilkan error yang sama dua kali.

## 5. Fix Expand/Collapse Interaction

Di `agent-thinking.tsx`, saat ini sudah ada handler:

```
setDetailsOpen(prev => !prev)
```

Jadi jangan langsung membuat accordion baru.

Investigasi dulu:

- Button hit target.
- Pointer events.
- Overlapping elements.
- Parent overflow.
- Positioning / stacking context.
- Controlled vs uncontrolled open state.
- Auto-collapse effect yang mungkin langsung menimpa klik user.
- Apakah area chevron dan label mempunyai click target yang konsisten.

Required behavior:

- Entire Aktivitas button clickable.
- Chevron rotates appropriately.
- Keyboard Enter/Space works.
- `aria-expanded` valid.
- Detail hidden when collapsed.
- Toggle doesn't cancel request.
- User can expand completed activity if details actually exist.
- No tiny clickable target.

## 6. Remove Nested Card Styling

Currently activity details use a bordered rounded background.

Replace with minimal inline disclosure:

```
Thinking headline
   │
   └── Activity details (optional)
```

No extra floating card.

Use typography hierarchy, small spacing, and subtle separators only when necessary.

Don't wrap every activity line in separate cards.

## 7. Genuine Activity Only

`CODEBASE_STAGE_ACTIVITY` contains static descriptions.

The question endpoint currently returns a final JSON response rather than a detailed stream of progress.

Therefore:

- Do not invent "reading files", "analyzing architecture", etc. unless corresponding backend events actually exist.
- Don't rotate fake descriptions every N seconds.
- Don't invent AI thoughts.
- Don't reveal private raw chain-of-thought.
- Prefer safe high-level operation summaries generated from real observable backend events.

If detailed events aren't available for the question endpoint, display one accurate status:

```
◌ Menyusun pertanyaan...
```

Then:

```
✓ Pertanyaan siap
```

If richer telemetry is justified, define explicit events at the server boundary.

Example real events:

```
request.accepted
generation.started
response.validated
result.persisted
operation.completed
```

Show only events actually emitted and confirmed.

Don't introduce expensive AI calls just to generate status text.

## 8. Timer Lifecycle

The duration must be based on operation timestamps.

```
startedAt → finishedAt
```

During running, elapsed time advances.

After done/failed, elapsed duration freezes permanently.

On remount, completed operations display the stored duration instead of counting from the current time.

Protect against late events changing a settled run.

Tie status and duration to request/operation ID so stale events from earlier requests cannot overwrite newer states.

## 9. Avoid Stale Thinking

Current message component renders Thinking while `run !== null`.

Change presentation behavior:

- Running → show active Thinking.
- Done → compact completed summary.
- Failed → compact failure indicator.
- Next stage → previous operation must not appear active.
- Project switch → clear or resolve state appropriately.
- Hydration → do not create fictional historical Thinking entries.

Do not remove user messages, answered questions, or persisted artifacts while cleaning activity UI.
