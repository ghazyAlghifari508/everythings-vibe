# FIX 03 — Feature Plan Management &amp; Clean Contextual Composer

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`

## Objective

Sederhanakan pengalaman mengelola beberapa feature plans dalam satu repository.

Perbaiki daftar fitur yang dipenuhi project kosong/tidak jelas dan **hapus sepenuhnya persistent intent card**:

- "Pesan berikutnya untuk apa?"
- "Revisi Fitur Saat Ini"
- "Buat Fitur Baru"

User harus memahami fitur yang sedang dibuka tanpa dipaksa memilih radio option setiap kali mengetik pesan.

## Requirements

### 1. Investigate Empty Projects

Cari tahu kenapa project kosong dibuat:

- Onboarding anchor.
- Feature draft.
- Aborted feature creation.
- Failed generation.
- Duplicate attempts.
- Legacy data.

Jangan menganggap semuanya data sampah.

Pisahkan repository analysis context dari user-facing feature plan.

Jika record hanya berfungsi sebagai internal onboarding anchor, jangan ditampilkan sebagai feature plan biasa.

Jika draft menyimpan prompt/jawaban user, pertahankan dan tampilkan sebagai draft yang dapat dilanjutkan.

Jangan menghapus data lama secara otomatis tanpa pembuktian bahwa data tersebut disposable.

### 2. Improve Feature Switcher

Tampilkan:

- Nama fitur.
- Status planning yang akurat.
- Feature aktif.
- Aksi membuat fitur baru.

Jangan tampilkan angka seperti "3 fitur · 1 berisi" jika total mencampur project internal dan user-facing feature plans.

Jangan menampilkan status "Sudah ada planning" hanya karena metadata teknis tertentu terisi. Gunakan definisi artifact readiness yang jelas.

### 3. Remove Intent Card

Hapus rendering dan ketergantungan UI pada `CodebaseIntentChoice`.

Jangan hanya menyembunyikannya dengan CSS.

Hilangkan requirement yang membuat user tidak bisa mengirim pesan sebelum memilih radio.

Perbaiki composer placeholder dan submit guard yang sebelumnya bergantung pada `selectedIntent`.

### 4. Define Natural Interaction Semantics

- Ketika user memilih **Buat fitur baru**, buat feature plan baru secara eksplisit.
- Setelah fitur baru aktif, composer memulai klarifikasi untuk fitur tersebut.
- Ketika user berada dalam feature plan existing, instruksi perubahan diarahkan pada fitur aktif.
- Jangan diam-diam membuat project baru hanya karena user mengirim pesan.
- Jangan mengubah instruksi ambigu menjadi operasi destruktif.

Jika suatu instruksi tidak cukup jelas untuk direvisi dengan aman, lakukan klarifikasi singkat yang relevan dengan konteks, bukan mengembalikan intent card permanen.

### 5. Preserve Revision Safety

Jangan menghapus revision engine.

Tetap pertahankan:

- Version history.
- Affected sections.
- Existing task progress.
- Konfirmasi jika revisi akan mengubah pekerjaan yang sudah berjalan.
- Relasi project terhadap repository.

Hapus mekanisme pemilihan intent yang buruk, bukan kemampuan revisinya.

Tidak boleh membuat nested cards berlebihan, gradient dekoratif, atau animasi yang tidak berguna.

## Verification

Uji:

- Onboarding anchor tidak mencemari daftar fitur.
- Draft dengan data valid tidak hilang.
- Existing plans tetap accessible.
- Switching plan menjaga state isolation.
- Create feature tidak menghasilkan accidental duplicate.
- Composer tetap bisa mengirim pesan tanpa intent card.
- Revision tidak mereset task secara diam-diam.

Tanpa browser QA. Jalankan unit/integration tests non-browser, typecheck, lint, dan build.

Commit secara atomic dan push sesuai [`AGENTS.md`](http://AGENTS.md).

**Definition of Done:** user bisa berpindah fitur, membuat fitur baru, dan merevisi fitur aktif tanpa pernah melihat "Pesan berikutnya untuk apa?".
