## Primary mission

Perform complete browser-based QA and engineering verification of the Existing Codebase workflow.

The final acceptance goal is non-negotiable:

**A user must be able to synchronize an existing repository, understand its analysis, create a feature plan, answer clarification questions, generate Feature Specification, PRD, AC, and Task, view its Kanban, and prepare a valid handoff for an AI coding agent.**

The workflow must be backed by real persisted data and functioning application operations.

Do not claim completion unless the required journey works.

3. No database seeding to imitate a successful user journey.
4. No bypassing authentication, authorization, credit checks, or validation.
5. No fake responses, mocked API success, or fabricated AI outputs in the actual E2E run.
6. No disabling error overlays as a substitute for fixing errors.
7. No hiding console errors.
8. No swallowing exceptions.
9. No modifying production data.
10. No silently deleting user data or planning artifacts.
11. No lowering test assertions.
12. No unbounded retry or fake loading/progress state.
13. No declaring success merely because the UI displays a success label.
14. No committing unrelated changes.
15. No push, merge, or PR creation without separate authorization.

Application operations through normal UI and authorized CLI workflows are allowed. Read-only diagnostics and tests against an appropriately isolated development environment are allowed.

If an isolated test environment requires a schema migration, use the project's approved migration workflow. Never use ad hoc database edits as a shortcut.

## Phase F — Mandatory error investigation loop

Whenever an error occurs:

```
Detect error
     |
     v
Collect evidence
(Console + Network + Server Logs + Worker Logs)
     |
     v
Locate failing request / operation
     |
     v
Trace root cause in source code
     |
     v
Implement proper fix
     |
     v
Run targeted tests
     |
     v
Create atomic commit
     |
     v
Repeat affected browser scenario
     |
     +-- Error remains? → Investigate again
     |
     +-- Resolved? → Continue regression
```

Never dismiss a reproducible error merely because a retry succeeded once.

Determine whether the failure is intermittent, state-dependent, or caused by an underlying race condition.

If the test cannot proceed because credentials or external services are unavailable, record a genuine blocker. Do not fabricate a passing result.

## Atomic commit policy

**Every real fix must be committed as a logical atomic change.**

Use Conventional Commits.

Examples:

```
fix(codebase): restore missing conversation events
fix(codebase): prevent duplicate planning artifacts
fix(codebase): correct resync dialog geometry
fix(codebase): recover interrupted kanban requests
test(codebase): cover workspace reopen regression
```

A source fix and its directly related regression test may belong to the same commit.

Do not create one giant `fix: everything` commit.

Do not commit generated test noise, credentials, or unrelated files.

Do not push without separate authorization.
