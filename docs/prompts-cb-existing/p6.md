### Positioning Requirements

- Floating layer is portaled/out of normal layout flow.
- Anchor to `@` trigger or appropriate virtual trigger.
- Prefer opening upward: `side="top"`.
- Align near the left-side trigger: `align="start"`.
- Use a small overlap offset, configured through the chosen floating positioning API.
- Do not use arbitrary global `top`/`left` coordinates.
- Respect viewport collision boundaries.
- If insufficient space exists above, allow intelligent repositioning without modifying composer dimensions.
- Apply correct z-index relative to composer, footer, and surrounding panels.
- Prevent clipping by parent `overflow` containers.
- Maintain stable width independently of composer content.
- Support long document labels with truncation.
- Limit height and use internal scrolling when needed.
- Keep keyboard focus and selection accessible.

**Do not hardcode desktop-only positioning.**

## 6. Only Actual Planning Documents

Current behavior presents missing documents as selectable candidates.

This must stop.

The `@` selector should show **only real persisted planning artifacts for the currently active feature/project**.

Expected behavior:


| Actual active feature state | Allowed @ suggestions     |
| --------------------------- | ------------------------- |
| No planning documents       | No fabricated suggestions |
| Feature exists              | Feature                   |
| Feature + PRD               | Feature, PRD              |
| Feature + PRD + AC          | Feature, PRD, AC          |
| Tasks also exist            | Feature, PRD, AC, Task    |


Important:

- Use canonical artifact existence, not filenames synthesized from project IDs.
- Ensure the artifact belongs to the current feature.
- Do not borrow documents from another feature in the same repository.
- Do not offer a document whose artifact was deleted or is no longer available.
- Filter server-confirmed documents, not merely frontend labels.
- Do not display placeholder rows marked `Belum dibuat`.
- Do not expose unavailable selections that fail after clicking.

For no documents:

- Do not fabricate PRD/AC/Task entries.
- Do not show a misleading selectable menu.
- The literal `@` may remain in the user's draft as ordinary text if there is nothing valid to reference.
- Avoid an oversized empty-state popover.

## 8. Correct @ Semantics

`@` identifies an actual planning document reference.

It is not a magical direct-edit operation.

Example in Revise mode:

```
Mode: Revise

User: Tolong perbaiki cakupan
      fitur pencarian pada @PRD
```

Expected:

- `@PRD` resolves to the actual PRD artifact for the active feature.
- Composer records its stable artifact identity.
- Submission is handled by the existing revision workflow.
- A missing PRD cannot be selected.
- Selecting a mention must not automatically start generation/revision.

### Important Distinction

```
[Plan ▾] / [Revise ▾]  → Operation mode

@PRD                    → Document reference/target
```

Keep these separate.

Do not add unnecessary modes or buttons.
