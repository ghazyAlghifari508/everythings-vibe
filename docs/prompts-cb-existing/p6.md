# FIX 06 — Investigate and Resolve Duplicate React Keys Without Unrelated Refactoring

**COMPLEXITY: EASY–MEDIUM**  
**PRIORITY: P2 — Rendering correctness**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)

Target branch: `feature/vibeplan-existing-codebase`

## 1. Mission

Cari dan perbaiki React duplicate-key warnings yang dilaporkan user.

Console:

```
Encountered two children with the same key,
`2-Everything You Need for Production`.

Encountered two children with the same key,
`Everything You Need for Production-Built-in infrastructure services that scale with`.
```

Jangan menganggap error ini otomatis berasal dari Existing Codebase. Cari komponen aktual yang menghasilkan daftar tersebut.

Jangan melakukan refactor besar hanya untuk menghilangkan warning.

## 2. Mandatory Investigation

Baca [`AGENTS.md`](http://AGENTS.md) dan repository rules.

Cari teks:

```
Everything You Need for Production
```

dan:

```
Built-in infrastructure services that scale with
```

di seluruh source code, data fixtures, config, serta komponen yang memproses content.

Periksa:

- React `.map()` rendering.
- Dynamic section rendering.
- Nested list items.
- Markdown/parsed content rendering.
- CMS-like data.
- Keys gabungan heading + description.
- Item ordering/reordering.
- Duplicate source records.

Identifikasi component stack dan parent list yang sebenarnya menghasilkan warning.

Jika teks tidak ditemukan secara literal, telusuri data transform dan konten runtime yang menghasilkan string tersebut.

Jangan mengarang file atau root cause.

## 3. Root Cause to Fix

Kemungkinan pola yang perlu diuji:

```
items.map((item) => (
  <Section key={item.title} item={item} />
))
```

Jika beberapa item memiliki judul sama, keys akan duplikat.

Namun ini hanya contoh. Root cause aktual harus dibuktikan.

## 4. Correct Key Strategy

Gunakan identity yang:

- Unik dalam daftar sibling.
- Stabil antar-render.
- Konsisten ketika item disusun ulang.
- Tidak berubah hanya karena judul/deskripsi diedit.
- Tidak berasal dari `Math.random()` saat render.
- Tidak asal menggunakan array index pada dynamic reordered list.

Preferred:

```
item.id
```

Jika data source belum memiliki ID:

- Periksa apakah parser mempunyai stable source identity.
- Gunakan struktur identitas yang dapat dibuktikan unik.
- Jika perlu menambah ID saat data dihasilkan, lakukan pada boundary data, bukan render.
- Jangan menghapus record duplikat hanya untuk menghilangkan warning jika kontennya memang valid.

## 5. Visual / Behavioral Expectation

Before:

```
Item A -> key "Everything You Need..."
Item B -> key "Everything You Need..."
             │
             ▼
       React warning
```

After:

```
Item A -> stable ID A
Item B -> stable ID B
             │
             ▼
    Correct React reconciliation
```

UI yang sebelumnya valid harus tetap terlihat.

Jangan mengubah layout, warna, atau typography tanpa kebutuhan.

## 6. Testing

Test:

1. Duplicate headings render tanpa key collision.
2. Duplicate descriptions render dengan benar.
3. Reordered items retain identity.
4. Add/remove item does not corrupt siblings.
5. Unique keys remain stable.
6. Existing UI content is not silently deduplicated.
7. No unrelated list rendering regressions.

Gunakan non-browser unit/component tests, typecheck, lint, dan build.

**No browser QA, Playwright, Puppeteer, browser automation, manual browser tests, or screenshot testing.**

## 8. Definition of Done

Root cause dan source component teridentifikasi.

Key collision hilang dengan stable identity.

Konten tetap utuh.

Laporan akhir menyebut exact component, data source, key strategy, dan hasil test.

Jangan mengklaim bug sync sudah fixed hanya karena React warning hilang.
