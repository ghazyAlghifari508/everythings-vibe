# P06 — Simplify Existing Codebase Agent Handoff

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** MEDIUM–COMPLEX  
**Dependency:** P05 completed.

## Problem

The current handoff presentation contains too many disconnected elements:

- Planning selesai.
- Revisi Planning.
- Salin prompt handoff.
- Task siap dikerjakan.
- Buka Kanban.
- Technical export instructions.
- Perintah ekspor.
- Second copy button.
- Prompt untuk agent.
- Backend/CLI/polling explanation.

Relevant file:

`src/features/codebase/components/chat/codebase-chat-workspace-handoff.tsx`

This makes the primary action unclear.

## Objective

Create a focused handoff experience whose purpose is immediately understandable:

**Help the user transfer their completed planning into their AI coding agent using the existing CLI workflow.**

Do not remove the underlying CLI export capability.

## Detailed behavior

1. The unified planning card from P05 includes `Buat Handoff` after Task is persisted.
2. Activating it reveals the focused handoff section.
3. The primary button copies the complete valid agent handoff prompt.
4. The handoff prompt must retain necessary project identity, repository root instructions, CLI export command, and required documents.
5. The prompt must clearly instruct the coding agent to read generated Feature, PRD, AC, and Task files and follow their scope.
6. The CLI remains responsible for writing files into `docs/vibeplan/` within the user's repository.
7. The UI must not claim that the export already happened when the user only copied instructions.
8. Keep copy-success and copy-failure feedback concise and reliable.

## Remove unnecessary UI clutter

Remove the visible technical paragraph:

`Agent memakai CLI untuk memperbarui status task ... lewat polling ... tasks.json adalah snapshot ... backend ...`

This should not appear in the primary user-facing handoff card.

Remove redundant buttons and repeated statements that communicate the same thing.

The standalone `Buka Kanban` button inside the handoff section can be removed because the workspace header's task progress action will provide the Kanban entry point in P08.

Do not remove Kanban functionality.

## Export command disclosure

The raw export command is useful for advanced users but should not dominate the interface.

Place it in a collapsible section named:

`Ekspor dokumen secara manual`

Expanded state:

```
Ekspor dokumen secara manual

Jalankan perintah berikut dari root repository
untuk menyimpan dokumen planning.

npx everythings-vibe export plan <id> --root .

[Salin perintah]
```

The real command must be generated from the project ID and existing CLI contract. The `<id>` shown above is explanatory only.

Do not hardcode example project IDs or repository paths.

## Data and status rules

Handoff availability must depend on real persisted Task readiness.

If Task generation failed or is unresolved, do not show a successful handoff.

If export or copy fails, display a useful error instead of a false success message.

Keep per-feature isolation and existing server-side authorization.

Preserve the Task/PRD/AC integrity checks already present in the codebase.

## UI component discovery

Inspect HeroUI, shadcn, Magic UI, React Bits, ThinkingOrbs, AffectUI, TuffUI, CUI, and SakaniUI.

Reuse suitable existing Card/Disclosure/Accordion/Button/Tooltip/Code primitives. Choose a ready-made disclosure component rather than creating an entire accordion system from scratch.

No unnecessary flashy animation, AI glow, gradients, decorative badges, or duplicated bordered containers.
