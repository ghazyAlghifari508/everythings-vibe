# FIX 06 — Unify Dark-Mode Notifications, Destructive Dialogs &amp; Floating Widget Safe Areas

**Complexity: MEDIUM**  
**Priority: P2 — Design Consistency &amp; Feedback Accessibility**  
**Scope: Toast, dialog, theme tokens, overlays, floating widget positioning**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
Branch: `feature/vibeplan-existing-codebase`

## 1. Objective

Perbaiki notifikasi berhasil menghapus repository pada Existing Codebase History.

Observed screenshot problems:

- Toast "Project dihapus" menggunakan latar abu-abu terang yang tidak cocok dengan dark mode.
- Toast terlihat seperti komponen asing, bukan bagian design system VibeEverything.
- Toast sebagian tertutup floating widget di kanan bawah.
- Feedback penghapusan menjadi sulit dibaca.

Target: seluruh notifikasi dan dialog destructive menggunakan komponen, warna, spacing, dan layering yang konsisten dengan sistem UI aplikasi.

**Jangan membuat toast baru khusus History jika global toast sudah ada.**

## 2. Required Code Investigation

Baca [`AGENTS.md`](http://AGENTS.md) dan project rules.

- `src/components/ui/toast.tsx`

## 3. Target Visual

### Success Toast

```
┌──────────────────────────────────────┐
│ ✓  Project berhasil dihapus          │
└──────────────────────────────────────┘
```

### Error Toast

```
┌──────────────────────────────────────┐
│ !  Project tidak dapat dihapus       │
│    Coba lagi.                        │
└──────────────────────────────────────┘
```

Design requirements:

- Dark surface consistent with VibeEverything.
- Text contrast appropriate.
- Subtle border.
- Compact height.
- No exaggerated icon or bright badge.
- No unnecessary secondary text.
- Natural entrance/exit animation, if already supported.
- Support reduced motion.

No white-gray palette that ignores dark-mode tokens.

## 4. Toast and Floating Widget Collision

Current layout can produce:

```
BOTTOM-RIGHT

    [Project dihapus ✓]
                    [Floating widget]
```

This obscures feedback.

Fix safe positioning:

```
BOTTOM-RIGHT

    [Project dihapus ✓]

          [safe vertical gap]

                    [Floating widget]
```

Or move toast to another consistent location if more appropriate for the app.

Requirements:

- Account for widget dimensions and spacing.
- Work with responsive layouts.
- Respect safe area insets.
- Avoid overlap with mobile viewport controls.
- Avoid toast being hidden beneath modal overlays.
- Maintain correct dialog focus trapping.
- Do not place important feedback behind floating controls.

The solution should be systematic rather than a hardcoded one-off offset that breaks at different viewport sizes.

Audit Delete Project dialog and any new bulk-delete dialog from FIX 05.

Ensure both use the same approved design system.

Expected:

│ akan dihapus permanen.             │

One clear destructive action.

Correct footer/background color.

No duplicate close buttons.

No native JavaScript alert/confirm.

Do not redesign unrelated dialogs.

## 7. Tests

Verify:

1. Success toast uses correct theme tokens.
2. Error toast uses correct theme tokens.
3. Dark/light mode behave consistently.
4. Toast position accounts for floating widget.
5. Notification is accessible.
6. Destructive confirmation remains functional.
7. No duplicate toast after repeated callbacks.
8. No duplicate dialogs.
9. Global toast consumers remain compatible.
10. Dismissal and timing behave correctly.
11. Modal stacking and focus management remain correct.

Use non-browser component tests, styling/config checks, typecheck, lint, and build.

**No browser QA, Playwright, Puppeteer, browser automation, manual browser verification, or screenshot testing.**

## 8. Definition of Done

Delete feedback is clearly visible, visually coherent with VibeEverything, and never intentionally rendered beneath the floating widget.

Existing global notification behavior remains intact.

Report component chosen/reused, root cause, design tokens changed, layering strategy, and tests.
