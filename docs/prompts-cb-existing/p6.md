# FIX 06 — Context-Aware Clarification Questions &amp; Professional Question UI

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`

## Objective

Tingkatkan kualitas AI clarification questions sekaligus memperbaiki UI pertanyaan pada Existing Codebase.

Pertanyaan harus benar-benar membantu menyusun requirements yang akurat, bukan hanya pertanyaan singkat dan generik untuk memenuhi jumlah tertentu.

UI harus terasa seperti structured question tool pada AI coding assistant: satu pertanyaan aktif, pilihan jelas, progres terlihat, dan jawaban sebelumnya ringkas.

## Current Issues

- Setiap pertanyaan dibungkus card besar.
- Jawaban yang sudah dikirim berubah menjadi card hijau.
- Banyak card menumpuk vertikal.
- Pertanyaan AI kadang terlalu sederhana.
- Opsi terlalu pendek sehingga kurang menjelaskan konsekuensi pilihan.
- Konteks repository belum dimanfaatkan secara optimal untuk membedakan pertanyaan yang perlu ditanyakan dengan keputusan yang bisa ditentukan sendiri oleh AI.

## Workstream A — Improve Question Generation

Pertahankan pertanyaan adaptif berdasarkan ketidakpastian.

Namun jangan menggunakan batas jumlah pertanyaan sebagai target kualitas.

Perbaiki prompt agar AI:

1. Membaca original user intent.
2. Memahami repository context yang tersedia.
3. Mengidentifikasi keputusan produk yang belum dijelaskan.
4. Memisahkan fakta yang bisa dibuktikan dari keputusan yang perlu user tentukan.
5. Menyusun pertanyaan yang benar-benar memengaruhi implementation.
6. Menghindari pertanyaan berulang atau sudah terjawab.
7. Menyesuaikan kedalaman berdasarkan kompleksitas fitur.

Prioritas yang relevan:

- Expected behavior.
- User flow.
- Input/output.
- Search/filter semantics.
- State persistence.
- Edge cases.
- UX behavior.
- Compatibility constraints.
- Product decisions yang belum dapat disimpulkan.

Jangan menanyakan arsitektur teknis yang sudah diketahui dari source code.

### Example

Prompt user:

"Tambahkan search dan filter kategori pada daftar artikel."

Pertanyaan yang mungkin relevan jika belum terjawab:

- Apakah pencarian memeriksa judul saja atau juga ringkasan artikel?
- Bagaimana kombinasi keyword dan kategori memengaruhi hasil?
- Apakah filter dipertahankan ketika URL dibagikan?
- Apa yang sebaiknya terjadi saat hasil kosong?

Pertanyaan tersebut hanya boleh muncul apabila keputusan belum diketahui dari prompt maupun repository.

Jangan mengeluarkan semuanya secara otomatis sebagai template hardcoded.

### Anti-Generic Requirements

- Tidak memaksakan jumlah maksimum pertanyaan.
- Tidak membuat pertanyaan demi mengisi kuota.
- Tidak menanyakan hal yang jelas.
- Tidak menambahkan fitur baru melalui pertanyaan sugestif.
- Rekomendasi harus memiliki bukti.
- Opsi jawaban harus saling berbeda secara bermakna.
- Pilihan jawaban boleh singkat, tetapi harus tidak ambigu.

## Workstream B — Improve Question UI

Gunakan progressive disclosure:

- Satu pertanyaan aktif.
- Progress counter.
- Radio group untuk single select.
- Checkbox untuk multi select.
- Input/textarea untuk jawaban bebas.
- Opsi "Lainnya" bila relevan.
- Satu primary action.
- Previous answers ditampilkan sebagai compact completed lines.

Pastikan user dapat memahami pilihan yang direkomendasikan tanpa menjadikan rekomendasi sebagai keputusan wajib.

Pertahankan keyboard accessibility, focus management, dan responsive behavior.

Jika editing previous answers didukung dengan aman oleh persistence contract, pertahankan atau implementasikan secara konsisten. Jangan membuat UI edit yang tidak tersimpan.

## Mandatory Component Discovery

Gunakan komponen siap pakai:

- shadcn Radio Group, Checkbox, Input, Textarea, Button.
- HeroUI form components jika lebih sesuai dengan arsitektur existing.
- shadcn Collapsible/Accordion untuk jawaban sebelumnya.
- Magic UI atau React Bits hanya untuk subtle transitions apabila benar-benar diperlukan.

Eksplor seluruh sumber yang relevan sebelum coding:

[https://www.heroui.com/](https://www.heroui.com/)  
[https://magicui.design/](https://magicui.design/)  
[https://reactbits.dev/](https://reactbits.dev/)

Wajib memakai komponen siap pakai yang relevan. Jangan membuat radio group, checkbox group, atau accordion dari nol.

Jangan menambah gradient, green answer cards, atau nested cards berlebihan.

## Persistence &amp; Integration

Pastikan:

- Answers tersimpan pada project yang benar.
- Reopen dapat memulihkan jawaban.
- Jawaban lama tidak muncul pada feature baru.
- Feature generation menerima compiled answers yang benar.
- Perubahan question format tetap kompatibel dengan backend.
- Malformed model output ditolak dengan error yang jelas.
- AI tidak perlu mengulang pertanyaan ketika user kembali ke workspace.

## Verification

Buat regression tests untuk quality constraints berbasis contoh input tetap, parsing, option validation, deduplication, recommendation evidence, answer persistence, dan restoration.

Jangan hanya membuat unit test yang memastikan prompt string tidak kosong.

Tidak perlu browser QA, Playwright, Puppeteer, atau screenshot testing.

Typecheck/lint/build wajib sesuai project.

Lakukan atomic commit dan push sesuai [`AGENTS.md`](http://AGENTS.md).

**Definition of Done:** pertanyaan yang dihasilkan relevan dengan perubahan yang diminta, dan UI menampilkan interaksi compact tanpa tumpukan card.
