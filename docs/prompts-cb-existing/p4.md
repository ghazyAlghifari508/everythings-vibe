## 4. Status Mapping

Status sebaiknya membedakan:

- Sync belum selesai.
- Analisis berjalan.
- Analisis membutuhkan tindakan.
- Repository siap untuk planning.
- Existing historical planning tersedia meskipun analisis terbaru bermasalah.

Buat mapping terpusat yang konsisten dengan backend readiness contract.

Contoh aksi:

```
READY
  → Buka Workspace

ANALYZING
  → Lihat Progres

CREDIT REQUIRED
  → Selesaikan Analisis

ANALYSIS FAILED
  → Coba Analisis Lagi

UPLOAD INCOMPLETE
  → Lanjutkan Sinkronisasi
```

Jangan hanya mengubah label sementara semua aksi tetap menuju `/codebases/:id` tanpa memeriksa tujuan yang benar.

## 5. Navigation Requirements

- Ready repository → normal planning workspace.
- Analysis pending → onboarding/progress screen.
- Analysis failed/blocked → recovery screen.
- Upload incomplete → sync recovery.
- Historical plan existing → tetap bisa diakses sesuai hak user.
- Navigation harus menggunakan canonical codebase ID.
- Jangan membuat history record baru ketika user mencoba recovery.
- Jangan mengubah active feature secara tidak sengaja.

Saat analisis berubah dari pending menjadi ready, data History harus dapat diperbarui dengan benar.

Jangan mengharuskan reload penuh hanya untuk memperoleh status terbaru jika existing query/polling system mendukung update.

## 6. Public Copy

Gunakan teks ringkas:

```

Perlu analisis
Sinkronisasi belum selesai
```

Hindari:

```
analysis_attempt_failed
snapshot_context_unavailable
workspace not initialized
AI-generated project anchor
database live
```

Tidak perlu menampilkan backend internals pada History.

Jangan menciptakan status palsu hanya demi variasi label.

## 7. No Data Loss

- Snapshot tersimpan tetap muncul.
- Failed analysis tidak menghapus history item.
- Existing feature plans tetap terhubung.
- Rename repository tetap dihormati.
- Re-sync tidak membuat duplicate cards.
- Pagination dan search tetap berfungsi.
- User tidak melihat repository milik orang lain.

## 9. Verification

Test:

1. Ready analysis → Buka Workspace.
2. Pending analysis → Lihat Progres.
3. Credit blocked → recovery.
4. Failed analysis → retry.
5. Upload incomplete → sync recovery.
6. Old plan tetap accessible.
7. No duplicate History entry on retry/re-sync.
8. Repository rename tetap benar.
9. Pagination/search tidak regresi.
10. Authorization dan navigation correct.
11. Status updated after analysis success.

Jalankan unit/integration tests non-browser, typecheck, lint, build.

**Skip browser QA, Playwright, Puppeteer, manual browser testing, dan screenshot tests.**

## Definition of Done

History menjadi daftar repository dengan status yang dapat dipercaya. Setiap primary action membawa user ke tahap yang memang dapat digunakan, bukan ke workspace yang belum siap.
