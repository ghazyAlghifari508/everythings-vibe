## 1. Objective

Perbaiki UI pertanyaan klarifikasi Existing Codebase agar rapi, minimal, dan konsisten.

Fokus pada:

1. Menghapus badge "Klarifikasi".
2. Merapikan input custom "Lainnya".
3. Menghapus informasi berulang setelah pertanyaan selesai.
4. Menghapus label "Fitur aktif" di atas composer.
5. Menjaga interaksi jawaban, edit, dan generation tetap berfungsi.

Tidak perlu mendesain ulang seluruh workspace atau mengubah proses AI question generation.

## 3. Remove "Klarifikasi" Badge

Current:

```
[Klarifikasi] Pertanyaan 1        1 dari 5
─────────────────────────────────────────
```

Expected:

```
Pertanyaan 1                     1 dari 5
─────────────────────────────────────────
```

Remove the unnecessary badge.

No replacement badge.

No alternative "Tahap Klarifikasi" label.

Question position and total are already sufficient.

## 4. Redesign "Lainnya" Input

Current problem:

- Other option has the same card/row as regular choices.
- A separate shaded rectangle appears underneath.
- The text input is indented differently.
- Input spacing and width are inconsistent.

Expected visual:

```
┌─────────────────────────────────────┐
│ ○ Buat halaman Blog terpisah        │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ ○ Gunakan halaman existing          │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ ◉ Lainnya                           │
└─────────────────────────────────────┘

   Tulis jawaban sendiri...
   _________________________________
```

Input should have:

- Transparent or theme-consistent background.
- Underline/bottom-border emphasis.
- No second rounded rectangle/card.
- Width aligned with question content.
- Consistent text size.
- Comfortable vertical spacing.
- Proper focus-visible styling.
- Correct accessible label.
- Auto-focus only when appropriate.
- No accidental submit when user is composing text with an IME.
- Multiselect compatibility where applicable.

Maintain the regular choice row as the selection control.

Use the existing shadcn Input component and adjust its variant/styles rather than creating a new text field from scratch.

Don't hide the input's accessible label merely because the visual design becomes simpler.

## 5. Remove Redundant Completion Copy

Current:

```
Berikutnya: Spesifikasi fitur

Semua pertanyaan sudah dijawab.
Spesifikasi fitur disusun dari jawaban
tersebut dan konteks repository.

                   [Buat Spesifikasi Fitur]
```

Expected:

```
                   [Buat Spesifikasi Fitur →]
```

The CTA alone is sufficient.

Do not add "Selamat, semua jawaban selesai" or another generic paragraph as replacement.

The button appears only when all answers are valid and generation is allowed.

If a prior generation attempt failed, respect the stage-specific retry state implemented in Phase 01; do not reintroduce duplicate generation buttons.

## 6. Remove Composer Target Label

Current:

```
Fitur aktif: Buatin Fitur Blog Repo

┌──────────────────────────────────────┐
│ Jelaskan perubahan yang diinginkan   │
└──────────────────────────────────────┘
```

Expected:

```
┌──────────────────────────────────────┐
│ Jelaskan perubahan yang diinginkan   │
└──────────────────────────────────────┘
```

The active feature is already shown in the workspace header/switcher.

Remove unnecessary public label:

- "Fitur aktif: ..."
- "Fitur baru" above composer if redundant.

Keep feature identity in application state.

Don't remove backend project identifiers or change request routing.

## 7. Preserve Existing Functionality

Do not break:

- Recommended option selection.
- Single-choice questions.
- Multi-choice questions.
- Custom answers.
- Confirmation.
- Edit answer during valid stages.
- Answered-question summaries.
- Keyboard accessibility.
- Read-only state after finalized specification.
- Project isolation.

Changes must be visual/presentational unless a functional bug directly prevents the required UX.

## 8. Mandatory Ready-Made Components

Explore and use suitable existing components from:

- shadcn/ui: Input, RadioGroup, Checkbox, Button.
- HeroUI: Input, Radio, Checkbox where compatible.
- Existing adaptive-question components.
- Magic UI, React Bits, Thinking Orbs only if genuinely needed; these are not requirements for a static question form.

[https://ui.shadcn.com/](https://ui.shadcn.com/)  
[https://www.heroui.com/](https://www.heroui.com/)  
[https://magicui.design/](https://magicui.design/)  
[https://reactbits.dev/](https://reactbits.dev/)  
[https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs)

**Wajib reuse actual ready-made components. Do not rebuild primitive inputs or selection controls from zero.**

Use one consistent design system. Avoid mixing different component libraries visually in the same question.

Strict anti-slop:

- No new decorative cards.
- No excessive background layers.
- No gradient ornaments.
- No repetitive explanatory copy.
- No technical/internal process explanations without user value.
- No random badges.
- No oversized padding that makes the question unnecessarily long.

## 9. Tests

Verify:

- Question header displays index without "Klarifikasi".
- Standard selection remains functional.
- Custom answer can be entered and submitted.
- Empty custom answer cannot be confirmed.
- Switching away from "Lainnya" follows correct answer semantics.
- Multiselect behavior remains valid.
- Recommended option still works.
- Completion area contains only appropriate CTA.
- Composer no longer displays redundant feature label.
- Finalized answer read-only behavior remains intact.

Run automated component/unit tests, typecheck, lint, and build.

**Do not run browser QA, Playwright, Puppeteer, browser E2E, manual browser tests, or screenshot tests.**

## Definition of Done

The question UI becomes cleaner and more consistent without losing functionality or accessibility.

No redundant public copy remains, and the "Lainnya" input visually integrates with the question instead of appearing as an unrelated second card.

Provide files changed and test results.
