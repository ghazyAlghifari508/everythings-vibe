## Objective

Redesign terbatas pada pengalaman sinkronisasi Existing Codebase, mencakup initial sync dan re-sync.

1. Sync ulang ditampilkan sebagai panel inline di atas workspace dan menggeser seluruh layout tiga panel.

4. Sync progress menggunakan beberapa card hijau berurutan.
5. Footer berisi teks berulang seperti "Tombol lanjut aktif setelah sinkronisasi dan analisis codebase selesai."
6. Status teknis raw tidak memberikan UX yang jelas.

## Design Target A — Re-Sync Drawer

Re-sync tetap tersedia karena source code lokal dapat berubah setelah snapshot sebelumnya disimpan.

Namun jangan menjadikan re-sync sebagai keharusan untuk membuka planning yang sudah ada.

### Visual

```
WORKSPACE TETAP UTUH
┌──────────┬────────────┬────────────┐
│ Explorer │ Chat       │ Preview    │
│          │            │            │
└──────────┴────────────┴────────────┘
                +
      [Sync ulang diklik]
                ↓
     DRAWER / OVERLAY
┌────────────────────────────────────┐
│ Perbarui source code          ×    │
│                                    │
│ Salin instruksi untuk AI agent     │
│ ┌────────────────────────────────┐ │
│ │ Prompt multiline terformat     │ │
│ │                                │ │
│ │ ## Informasi Sinkronisasi      │ │
│ │ ...                            │ │
│ └────────────────────────────────┘ │
│                  [Salin prompt]    │
│                                    │
│ Status sinkronisasi                │
│ ✓ Agent terhubung                  │
│ ◌ Source code disiapkan            │
│ ○ Upload snapshot                  │
│ ○ Analisis codebase                │
└────────────────────────────────────┘
```

Drawer tidak boleh menambah tinggi workspace, mengubah ukuran panel, atau menggeser composer.

Gunakan portal/overlay sebagaimana pola component library yang dipilih.

## Design Target B — Progress Timeline

Gunakan status list tanpa card per tahap.

```
✓ Agent terhubung
✓ Source code siap
◌ Menyinkronkan repository...
○ Menganalisis codebase
○ Ringkasan siap
```

Icon semantics:

- Pending: neutral circle.
- Active: spinner.
- Completed: checkmark.
- Failed: error icon dan actionable retry.

Hanya satu tahap aktual yang aktif pada satu waktu, jika lifecycle backend memang mendukung urutan tersebut.

Jangan menciptakan progress palsu atau stage buatan.

Gunakan server events dan persisted timestamps sebagai source of truth.

Jika "Source code siap" tidak didukung event backend yang dapat diverifikasi, sesuaikan label/status daripada menampilkan klaim palsu.

## Functional Requirements

### 1. Fix Prompt Rendering

- Preserve newline dan indentation.
- Preserve Markdown/code formatting yang diperlukan.
- Gunakan area scroll internal.
- Hindari horizontal overflow dan uncontrolled word wrapping.
- Prompt tetap selectable.
- Copy harus mengambil plain text utuh.
- Jangan melakukan sanitasi yang mengubah isi command/token sehingga tidak dapat dipakai.
- Jangan membocorkan sync token ke logs atau analytics.

### 2. Copy Interaction

- Gunakan tombol berukuran layak.
- Tempatkan dekat prompt.
- Tampilkan feedback setelah salin berhasil.
- Tampilkan feedback jika clipboard gagal.
- Gunakan accessible label dan keyboard interaction.

### 3. Correct Re-Sync State

- Re-sync membuat session baru untuk codebase existing.
- Jangan membuat repository/history baru.
- Snapshot dan planning lama tetap aman.
- Drawer dapat ditutup tanpa membatalkan planning.
- Token kedaluwarsa menghasilkan recovery action yang benar.
- Failed sync tidak menghapus snapshot sebelumnya.
- Jangan mengklaim upload sukses sebelum backend mengonfirmasi.

### 4. Initial Sync Footer

Hapus teks:

"Tombol lanjut aktif setelah sinkronisasi dan analisis codebase selesai."

Jangan menggantinya dengan pesan berulang.

Cukup tampilkan CTA yang enabled/disabled berdasarkan readiness aktual.

Error harus muncul di area tahap yang terkait.

## Mandatory UI Component Workflow

Sebelum membangun UI, telusuri komponen lokal, lalu dokumentasi resmi:

- shadcn Drawer/Dialog/ScrollArea/Button.
- HeroUI Drawer.
- Magic UI Animated List, jika benar-benar membantu.
- React Bits untuk motion ringan.
- Thinking Orbs untuk status AI jika sesuai.

Gunakan komponen siap pakai yang kompatibel. Jangan memasang dua sistem Drawer sekaligus.

Dilarang membuat drawer dari kumpulan div custom sebelum mengevaluasi komponen yang tersedia.

UI harus restrained, profesional, kontras, responsive, accessible, dan mengikuti VibeEverything design tokens.

Tidak ada green success cards, gradient AI generik, atau animasi berlebihan.

## Verification &amp; Completion

Uji state transition, status reconciliation, clipboard helper, expiry, retry, dan successful re-sync dengan automated tests non-browser.

Jalankan lint/typecheck/build sesuai package scripts.

Tidak melakukan browser QA, Playwright, Puppeteer, atau screenshot testing.
