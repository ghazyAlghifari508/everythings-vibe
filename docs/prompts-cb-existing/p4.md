# P04 — Adaptive Question Wizard Redesign

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** COMPLEX  
**Dependency:** P03 completed.

## Problems to fix

Existing Codebase adaptive questions currently suffer from:

1. Option heading and description are visually misaligned.
2. Wrapped description lines do not share one consistent left alignment.
3. Some description lines appear disconnected from their heading.
4. Answered questions become separate success/check cards containing `Q1... Jawaban... Ubah`.
5. The completed question list becomes excessively long.
6. The `Buat Spesifikasi Fitur` CTA appears as a disconnected action below the questions.
7. Previous answer editing depends on these summary cards instead of proper wizard navigation.

## Exact layout requirements

Gunakan satu horizontal layout untuk option control dan content:

```
Radio/Checkbox | Heading
               | Description line 1
               | Description line 2
               | Description line 3
```

Heading dan description harus berbagi text column yang sama. Jangan memposisikan description menggunakan padding manual terpisah seperti `padding-inline-start:2.625rem`.

Gunakan `grid` atau `flex` yang benar dengan `min-width: 0`, kontrol `shrink-0`, dan text container fleksibel. Pastikan heading panjang dan deskripsi multiline tetap rapi.

Recommended badge boleh tetap berada di heading row, tetapi:

- Recommended answer selalu menjadi opsi pertama.
- Semua opsi memiliki heading dan description yang jelas.
- Jangan membuat section explanation terpisah di bawah options.
- Tidak ada green glow, gradient, blur, atau decorative AI badge.
- Badge rekomendasi netral dan subtle.
- Selection state memiliki border/control yang jelas.
- Semua opsi tetap keyboard accessible.

## Interaction requirements

1. Question index dikontrol oleh wizard navigation state, bukan hanya `next unanswered question`.
2. `Berikutnya` menyimpan atau memvalidasi jawaban aktif sebelum berpindah.
3. `Sebelumnya` membuka pertanyaan sebelumnya dan mempertahankan selected answer.
4. Jika user mengubah jawaban lalu kembali maju, perubahan tersimpan secara benar.
5. Tidak boleh muncul duplicate question cards.
6. Tidak boleh ada `Q1... Ubah` success card.
7. Pada pertanyaan terakhir, CTA berubah menjadi `Buat Spesifikasi Fitur`.
8. CTA terakhir disabled sampai semua jawaban valid dan persistence requirement terpenuhi.
9. Saat generation berjalan, tampilkan status dari operation yang nyata.
10. Jika generation gagal, jangan menghilangkan jawaban.

## Post-generation behavior

Jika Feature/PRD/AC/Task sudah ada, jangan membiarkan pengguna mengubah answer secara diam-diam sehingga generated planning menjadi stale.

Gunakan read-only review atau alur revisi yang sudah tersedia. Jangan membuat planning baru otomatis saat user sekadar meninjau pertanyaan lama.

## Component discovery

Eksplorasi seluruh daftar UI library yang diminta user:

Magic UI, HeroUI, shadcn, React Bits, ThinkingOrbs, AffectUI, TuffUI, CUI, SakaniUI.

**Mandatory:** gunakan existing HeroUI Radio/Checkbox primitives atau komponen siap pakai yang lebih tepat dan kompatibel. Gunakan reusable Button, progress indicator, dan accessible controls dari library yang relevan.

Jangan membuat radio control custom dari nol kalau primitive yang ada sudah memenuhi kebutuhan.

Jangan memasang heavy animation library hanya untuk memindahkan satu question card.
