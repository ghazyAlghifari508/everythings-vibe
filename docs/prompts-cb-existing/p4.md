# PHASE 04 — Dedicated Repository Re-Sync Modal &amp; Session-Verified Completion

**Repository:** [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
**Target branch:** `feature/vibeplan-existing-codebase`

## Objective

Redesign pengalaman Sync Ulang pada Existing Codebase menjadi centered modal yang ringkas, jelas, dan tidak mengganggu workspace.

Bangun dedicated re-sync instructions, gunakan status nyata dari backend, dan tampilkan tombol "Selesai" yang hanya aktif setelah sinkronisasi baru berhasil diverifikasi.

Pertahankan CLI sebagai satu-satunya mekanisme sync repository.

## Current Implementation

Komponen `codebase-resync-drawer.tsx` menggunakan Radix Dialog tetapi dirender sebagai full-height right drawer.

Prompt-nya menggunakan `buildAgentPrompt()`, yang juga dipakai pada initial connection.

Di `use-codebase-sync.ts`, terdapat logic yang menutup drawer secara otomatis setelah status tertentu mempunyai snapshot yang usable.

Problems:

- Drawer memakan terlalu banyak ruang.
- Resync prompt tidak berfokus pada tindakan memperbarui repository existing.
- Modal belum memiliki intentional completion action.
- Keberhasilan sync lama dan sync baru harus dapat dibedakan.
- Footer berisi teks seperti "Drawer dapat ditutup tanpa membatalkan proses."

## A. Replace Drawer With Modal

Gunakan centered Dialog.

Specifications:

- Desktop: centered, comfortable max-width.
- Mobile: responsive dengan internal scrolling.
- Tinggi modal dibatasi viewport.
- Konten panjang scroll secara internal.
- Modal tidak menggeser workspace.
- Header dan footer dapat tetap terlihat selama content scroll.
- Proper focus trap, Escape handling, accessible title/description.
- Tidak ada double overlay atau z-index collision.
- Tidak ada navbar/layout baru.

Rename komponen dari Drawer menjadi Modal jika hal tersebut memperjelas arsitektur. Tidak perlu mempertahankan nama misleading.

## B. Dedicated Re-Sync Prompt

Pisahkan intent:

```
INITIAL SYNC:
Hubungkan repository pertama kali.

RE-SYNC:
Perbarui snapshot repository existing.
```

Buat explicit sync prompt mode atau dedicated prompt builder yang reuse command/safety rules yang sama.

Re-sync instructions harus menjelaskan:

1. User sudah memiliki repository yang terhubung.
2. Jalankan CLI pada root repository yang sama.
3. Gunakan sync session/token terbaru.
4. Fokus pada pembaruan snapshot codebase.
5. Jangan mengubah source code.
6. Jangan mengubah PRD/AC/Task.
7. Jangan membuat repository/history/project baru.
8. Jangan commit atau push hanya untuk sync.
9. Laporkan hasil CLI asli secara akurat.
10. Jangan menyatakan AI analysis selesai jika yang baru selesai adalah upload snapshot.

Gunakan instruksi yang singkat tetapi lengkap. Jangan menyalin seluruh onboarding document apabila banyak bagian hanya relevan untuk pengguna baru.

CLI command yang valid tetap harus didapat dari implementasi resmi. Jangan mengarang command baru.

Perintah yang membutuhkan token harus tetap copyable dan benar untuk PowerShell/terminal yang digunakan.

Jangan menulis token ke log, analytics, storage permanen, atau output error.

## C. Correct Completion Gating

Tombol "Selesai" memiliki dua state:

```
SESSION INCOMPLETE
[Selesai] disabled

SESSION VERIFIED
[Selesai] enabled
```

Source of truth adalah status session baru pada backend.

Jangan aktifkan tombol hanya karena:

- `codebase.snapshotId` lama tersedia.
- Snapshot lama berstatus ready.
- AI agent mengatakan "sukses".
- User sudah mengklik Salin.
- Timer telah berlangsung beberapa detik.
- Prompt dialog ditutup dan dibuka lagi.

Periksa session ID/attempt ID, snapshot linkage, dan upload verification.

Jika backend melakukan deduplication snapshot dengan konten identik, gunakan keberhasilan attempt/session yang diverifikasi, bukan asumsi bahwa snapshot ID pasti berubah.

## D. Separate Sync Completion From Analysis

Sinkronisasi source code dan analisis AI adalah proses berbeda.

- Jika upload/verification selesai, re-sync dapat dinyatakan berhasil.
- Jika AI analysis masih berjalan, informasikan hanya jika relevan.
- Jangan menahan tombol Selesai menunggu proses yang bukan bagian transport sync, kecuali kontrak produk secara eksplisit mensyaratkannya.
- Jangan mengklaim codebase analysis selesai lebih awal.

## E. Modal Dismissal Rules

- Jangan auto-close ketika status berubah ke success.
- Tombol Selesai aktif hanya setelah verified.
- Klik Selesai menutup modal.
- Tombol X/Escape boleh menutup tanpa membatalkan background sync jika arsitektur mendukung.
- Reopen harus menampilkan attempt yang sama dan status terbarunya.
- Jangan menciptakan session baru setiap kali modal dibuka.
- Retry/renew token harus terpisah dari close/reopen.

Hapus footer copy "Drawer dapat ditutup tanpa membatalkan proses." bila tidak menambahkan nilai yang diperlukan.

## F. Preserve Existing Planning

Re-sync tidak boleh:

- Membuat duplicate repository history.
- Menghapus feature plans.
- Menghapus PRD/AC.
- Mengubah Task status.
- Mereset active project.
- Membuat workspace kosong.
- Melakukan AI regeneration otomatis tanpa request yang valid.

Snapshot baru boleh tersedia untuk planning berikutnya, sedangkan planning existing tetap memiliki hubungan dengan snapshot asalnya sesuai data model.

## Verification

Tambahkan regression tests non-browser:

- Initial sync prompt berbeda dari re-sync prompt.
- Valid CLI command tetap terjaga.
- Re-sync modal tidak membuat project baru.
- Snapshot lama tidak mengaktifkan tombol Selesai.
- Successful new session mengaktifkan Selesai.
- Failed/expired session tetap disabled.
- Reopen mempertahankan session.
- Same-content successful sync didukung jika backend deduplicates snapshot.
- Analysis pending tidak salah diklaim complete.
- Existing plans dan Task progress tidak berubah.

Jalankan unit/integration tests, typecheck, lint, dan build.

**Browser QA, Playwright, Puppeteer, manual browser testing, dan screenshot tests tidak diperlukan. Skip seluruhnya.**

## Definition of Done

Sync Ulang tampil sebagai centered modal dengan prompt khusus, progress aktual, dan tombol Selesai yang hanya aktif berdasarkan keberhasilan sync session yang benar-benar diverifikasi.
