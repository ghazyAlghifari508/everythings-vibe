**PRIORITY: P1**

## 1. Mission

Perbaiki tampilan **Perbarui repository / Sync ulang** pada workspace tiga panel.

Current UI tidak konsisten dengan initial sync, memiliki jarak dan ikon yang berlebihan, menampilkan token warning teknis, serta menampilkan error yang sama di beberapa tempat.

User ingin modal resync **menggunakan kembali presentasi prompt initial sync yang sudah bagus**, bukan membuat variasi UI baru dari nol.

Jangan mengubah desain secara kreatif di luar brief.

## 2. Current Problems

Reported:

```
Perbarui repository

Salin instruksi sync ulang

Token sync sudah kedaluwarsa atau belum tersedia.

[Dapatkan token baru]
```

Then:

```
Sesi sync gagal dibuat. Coba lagi.

[Coba lagi]
```

Error juga dapat muncul sebagai banner merah di atas workspace yang sama.

Problems:

- Initial prompt tidak tersedia akibat lifecycle yang salah.
- Modal memiliki layout, spacing, icon dan ukuran berbeda dari original sync.
- Recovery state teknis muncul untuk normal resync.
- Error ganda.
- Generic retry tidak benar-benar melakukan pemulihan yang tepat.
- Modal dapat memperlihatkan progress sesi lama.
- Proses baru belum tentu dibedakan dari proses lama.
- Terlalu banyak elemen yang tidak memberi nilai.

## 4. Required Layout

The modal should look like a compact adaptation of the initial sync interface.

```
┌──────────────────────────────────────────────┐
│ Perbarui repository                       ✕  │
│ Ghazy Portofolio                            │
│──────────────────────────────────────────────│
│                                              │
│ ① Salin instruksi sync ulang         [Salin] │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ ACTUAL CLI RESYNC PROMPT                 │ │
│ │                                          │ │
│ │ ...                                      │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ ② Jalankan di AI coding agent                │
│    Gunakan root repository yang sama.        │
│                                              │
│ ③ Pantau sinkronisasi                        │
│    ○ Menunggu agent                          │
│    ○ Menyiapkan source code                  │
│    ○ Mengunggah repository                   │
│    ○ Analisis AI                             │
│                                              │
│──────────────────────────────────────────────│
│                                  [Selesai]   │
└──────────────────────────────────────────────┘
```

### Layout Rules

- One modal.
- One close control in header.
- Consistent horizontal spacing.
- Consistent step numbers.
- No unnecessary duplicate icons.
- No separate giant black recovery card.
- No nested cards for simple status text.
- Prompt width follows existing modal content width.
- Prompt scrolls internally when long.
- Modal respects viewport height.
- Header and footer stay usable.
- Mobile/narrow viewport adapts using existing responsive primitives.
- No arbitrary different background on the footer.
- No oversized empty gaps.
- No competing scroll containers without reason.

## 6. Functional UI Behavior

### Opening modal

- Request a genuine new resync session as established in FIX 03.
- Display the prompt once returned.
- Show a small real loading indicator only while the server is preparing the session.
- No credit approval.
- No extra "prepare" button.
- No generic error message while request is still pending.

### CLI waiting

```
○ Menunggu agent
```

No spinner before CLI activity.

### CLI active

Render server-confirmed progress.

### Completed

All stages reach valid completion.

```
[Selesai] ENABLED
```

### Closing modal

User can close the modal without canceling the server operation.

Reopening it should restore the correct active attempt and status.

Do not accidentally create a new resync merely because modal was reopened.

## 7. Correct Error Placement

**One operation = one primary error presentation.**

When resync fails inside the modal:

- Display the actual relevant error at the modal step where it occurred.
- Avoid simultaneously showing the same error at the top of the entire three-panel workspace.
- Do not show both `Dapatkan token baru` and `Coba lagi` for the same condition.
- Do not leave old errors visible after a successful retry.
- Do not display old session progress under a new attempt.

Approved copy for a genuine session-creation failure:

```
Sinkronisasi belum bisa dimulai.
```

Action:

```
Coba lagi
```

If a specific recoverable condition exists, provide one action that performs the correct server request.

The button MUST be functional and reflect loading/disabled states accurately.

After a successful retry, remove the error and show the actual prompt.

Do not show a full-width global error banner for a failure belonging exclusively to the open modal.
