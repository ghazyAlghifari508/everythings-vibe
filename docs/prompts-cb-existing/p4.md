## 1. Mission

Implementasikan mekanisme billing exemption untuk akun internal/developer yang terotorisasi agar pengembangan dan testing VibeEverything tidak terhambat oleh saldo kredit atau langganan.

Target:

- Akun internal yang diberi hak khusus dapat menggunakan fitur AI VibeEverything tanpa pemotongan kredit aplikasi.
- Tidak perlu top-up atau subscription aktif untuk testing internal.
- Semua penggunaan tetap tercatat untuk observability dan pengukuran biaya AI.
- User biasa tetap mengikuti sistem billing.
- Tidak membuka celah privilege escalation.
- Tidak memberikan saldo palsu yang sangat besar.

## 3. Recommended Policy

Use an explicit **internal billing exemption entitlement**.

Conceptual policy:

```
NORMAL USER
  Subscription and credit checks apply.

AUTHORIZED INTERNAL USER
  Application credit charges bypassed.
  Real provider calls still run.
  Usage and cost remain observable.
```

Prefer a server-controlled entitlement distinct from general admin authorization if the architecture permits.

Example concept:

```
type BillingEntitlement = {
  billingExempt: boolean;
  reason: "internal" | "development" | "support" | null;
};
```

Use the actual project conventions and schemas.

Do not blindly copy this interface.

## 4. Why Not Use Fake Unlimited Credits?

Do not:

```
credits = 999999999;
```

Do not create fake subscriptions that make ledger data misleading.

Do not hardcode developer email.

Do not use a client-side role check.

Do not make an unrestricted URL/query parameter such as:

```
?skipCredits=true
```

Billing exemption must be authorized by the server.

## 5. Authorization Model

Requirements:

- Explicit assignment to authorized internal users.
- Access restricted to trusted administrators/owners according to existing role governance.
- Admin role and billing exemption can be separated if appropriate.
- Audit log for enable/disable changes.
- Existing regular account cannot self-grant exemption.
- Server-side permission check on every billable operation.
- No trust in frontend `isAdmin` or `billingExempt` values.
- No implicit global bypass for all visitors in development mode.
- Entitlement revocation takes effect reliably.
- If possible, keep a distinct audit trail explaining why a charge was bypassed.

## 6. Centralized Billing Behavior

Do not scatter:

```
if (user.isAdmin) return;
```

across many routes.

Create or reuse a central billing authorization/policy boundary.

Desired:

```
AI OPERATION REQUEST
          │
          ▼
AUTHENTICATED USER
          │
          ▼
BILLING ENTITLEMENT CHECK
          │
     ┌────┴────┐
     │         │
  EXEMPT     NORMAL
     │         │
     │     CREDIT PREFLIGHT
     │         │
     └────┬────┘
          │
          ▼
    AI OPERATION
          │
          ▼
    RECORD USAGE
```

Ensure the same exemption policy works for:

- Initial codebase analysis.
- Re-analysis.
- Existing Codebase planning generation.
- Greenfield generation.
- Other currently billable VibeEverything AI operations, after inventorying their accounting contracts.

Do not accidentally expand exemption to third-party costs or unrelated paid services.

## 7. Accounting and Ledger

For exempt operations:

- No user credit deduction.
- No normal credit reservation unless schema requires a legitimate zero-charge path.
- No misleading credit ledger entries that imply actual user payment.
- Still record operation identity, usage, provider/model, outcome, and internal cost when available.
- Do not expose provider secrets.
- Avoid special-casing analysis only while other AI generation still deducts credits.
- Ensure failed exempt operations do not invoke an invalid credit release path.

If existing service methods require a credit-operation object, design a well-typed exempt operation path rather than fabricating active reservations.

## 9. Security and Operational Guardrails

"Unlimited" means no VibeEverything application credit deduction for authorized internal usage.

It does NOT mean:

- Unlimited upstream provider quota.
- Unlimited request concurrency.
- No rate limiting.
- No observability.
- No audit logs.
- No provider spending controls.

Keep technical safeguards to prevent accidental runaway model usage.

## 10. Tests

Required:

1. Normal user remains billable.
2. Exempt internal user bypasses credit deduction.
3. Exempt user can run analysis with zero app credits.
4. Exempt user can generate planning without subscription.
5. Exempt failure does not trigger invalid credit release.
6. Exempt usage is logged.
7. Normal user cannot impersonate exempt role.
8. Client-provided `billingExempt` is ignored.
9. Entitlement cannot be self-granted.
10. Entitlement revocation works.
11. Admin management permissions are respected.
12. Existing billing operations remain correct.
13. Greenfield and Existing Codebase use consistent policy.
14. Provider quota/rate limits remain functional.

Use unit/API/database tests, typecheck, lint, and build.

**No browser QA, Playwright, Puppeteer, manual browser checks, or screenshots.**

## 11. Definition of Done

Authorized internal accounts can develop/test VibeEverything's AI features without consuming application credits or requiring subscription payments.

The exemption is server-verified, auditable, centralized, and cannot be self-enabled by ordinary users.

Report authorization design, billing service changes, accounting behavior, tests, and provider-spend safeguards.
