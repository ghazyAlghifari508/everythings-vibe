## 1. MISSION

Benahi lifecycle Existing Codebase agar sistem bisa membedakan secara akurat:

1. User ingin menghubungkan repository baru.
2. User ingin melanjutkan sync yang belum selesai.
3. User ingin mengulang AI analysis dari snapshot yang sudah tersimpan.
4. User membuka repository yang analisisnya sudah READY.

Masalah sebelumnya:

- User keluar dari onboarding setelah analisis gagal.
- Saat kembali untuk melakukan sync baru, UI masih menampilkan progress analisis lama.
- Muncul pesan "Buat sesi baru" bersamaan dengan "Menganalisis repository".
- Session/prompt lama dan baru menjadi ambigu.
- User bisa terdorong upload ulang padahal snapshot sudah tersimpan.

**Jangan memperbaiki ini hanya dengan menyembunyikan teks. Perbaiki source of truth, route intent, dan session state ownership.**

```

```


### C. Snapshot uploaded, analysis pending


### F. READY


## 5. Session &amp; Attempt Identity

Ensure explicit separation:

```
CODEBASE
   ├── SYNC SESSION 1
   │        └── SNAPSHOT 1
   │             ├── ANALYSIS ATTEMPT 1
   │             └── ANALYSIS ATTEMPT 2
   │
   └── SYNC SESSION 2
            └── SNAPSHOT 2
```

Every status, event, and error must belong to the correct identity.

Requirements:

- Old session polling cannot overwrite new session UI.
- Old analysis error cannot overwrite retry status.
- Snapshot 1 output cannot masquerade as Snapshot 2 analysis.
- New onboarding must not inherit unrelated repository state.
- Retry analysis uses current uploaded snapshot.
- Refresh restores persisted server truth.
- Client reconnection does not duplicate generation.
- No two active analysis attempts for the same logical operation.
- No cross-user data leaks.

## 6. Token Lifecycle

Audit CLI token expiration handling.

- Valid token: prompt available.
- Expired before upload: offer new token for same repository.
- Uploaded snapshot: token no longer required for analysis recovery.
- Token absent from browser after refresh: do not automatically conclude sync must restart.
- Do not save raw tokens in localStorage.
- Do not automatically rotate a token already copied to an agent without explicit lifecycle handling.

## 7. Retry UI

When retry analysis is initiated:

```
OLD FAILED
     │
     ▼
STARTING NEW ATTEMPT
     │
     ▼
RUNNING
     │
     ├── READY
     └── FAILED
```

Current attempt has priority over previous attempt error.

A stale red error panel must not remain while the current attempt is genuinely running.

After successful retry, update workspace readiness.

## 8. Backend Readiness

Planning Workspace must not allow starting new AI planning against an analysis that isn't ready.

But do not delete or hide already completed historical planning when a newer sync/analysis fails.

Distinguish:

- Reading saved planning.
- Creating new AI planning requiring ready context.

Use authoritative backend guards.
