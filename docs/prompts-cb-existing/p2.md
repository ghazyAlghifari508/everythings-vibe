## 1. MISSION

Perbaiki multiple-select dan bulk-delete UI pada halaman Project Tersimpan Existing Codebase.

Implementasi saat ini tidak sesuai requirement.

Developer sebelumnya langsung menampilkan checkbox "Pilih semua", checkbox pada setiap repository, dan tombol "Hapus semua" saat halaman History pertama kali dibuka.

**INI SALAH.**

User menginginkan pola selection yang sama dengan VibeScrape, terinspirasi pengalaman Google Photos:

- Normal mode bersih tanpa checkbox.
- User membuka menu titik tiga pada repository.
- User memilih "Pilih".
- Barulah masuk selection mode.
- Checkbox muncul dalam selection mode.
- User dapat memilih beberapa repository.
- User dapat memilih seluruh repository yang relevan.
- User dapat menghapus pilihan.
- User dapat keluar dari selection mode.
- Delete operation tetap memakai backend yang aman.

Jangan membuat pola multiple select alternatif.

Jangan hanya menyalin API bulk delete; reuse perilaku interaksi VibeScrape.

## 7. SELECTION INTERACTION REQUIREMENTS

### Default Mode

- Checkbox tidak terlihat.
- Selection toolbar tidak terlihat.
- Row berfungsi sebagai repository card normal.
- Dropdown ⋮ menyediakan tindakan Pilih.

### Selection Mode

- Checkbox muncul.
- Row click dapat toggle selection jika itu mengikuti pola VibeScrape.
- Click pada checkbox tidak memicu navigasi.
- Keyboard interaction tetap accessible.
- Selected count akurat.
- Search dan pagination tetap bekerja.
- User dapat menghapus pilihan.
- Terdapat cara jelas untuk keluar dari selection mode.
- Ketika seluruh pilihan dibatalkan, kembalikan UX ke normal mode sesuai pola VibeScrape.

### Select All

Reuse semantics dan limit yang sudah ada pada shared history selection infrastructure.

Bedakan:

```
Select all on current page
Select all filtered results
Select all entire History
```

Jangan diam-diam menghapus seluruh repository ketika hanya satu halaman yang dipilih.

Bila pilihan lintas pagination tersedia, selected IDs harus tetap konsisten.

### Hapus Semua

User tetap membutuhkan kemampuan menghapus seluruh History.

Namun **jangan tampilkan "Hapus semua" sebagai tindakan permanen pada default History**.

Tampilkan dalam selection mode, setelah user mengaktifkan pengelolaan massal.

Bisa melalui:

```
Pilih semua repository
            │
            ▼
Hapus yang dipilih
```

atau action eksplisit di selection toolbar bila implementasi existing menyediakan semantik yang jelas.

Jangan memunculkan dua tindakan delete yang melakukan operasi identik.

## 8. DELETE CONFIRMATION

Untuk bulk deletion:

```
┌──────────────────────────────────────────┐
│ Hapus 3 repository?                      │
│                                          │
│ Repository dan planning terkait          │
│ akan dihapus permanen.                   │
│                                          │
│                   [Batal] [Hapus 3]      │
└──────────────────────────────────────────┘
```

Requirements:

- Jumlah berasal dari selected IDs aktual.
- Konfirmasi wajib untuk destructive operation.
- Server memverifikasi ownership.
- No accidental cross-project deletion.
- No duplicate request.
- No stale selection causing unexpected deletion.
- Return actual results.
- Update pagination/count/cache after success.
- Show one concise toast.

Jangan mengubah cascade deletion policy yang sudah ada tanpa alasan.
