# FIX 02 — Repair Sync Session Reset, Analysis Retry State &amp; Honest Progress Lifecycle

**Complexity: COMPLEX**  
**Priority: P0 — Onboarding Recovery &amp; State Consistency**  
**Scope: React hooks, session reconciliation, polling, progress UI, retry behavior**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
Branch: `feature/vibeplan-existing-codebase`

## 1. Mission

Perbaiki state lifecycle Existing Codebase onboarding agar:

1. Token sync baru selalu menghasilkan tampilan attempt baru yang bersih.
2. Error dan progress dari session lama tidak terbawa.
3. Retry AI analysis langsung mengganti tampilan gagal menjadi loading sesuai operasi aktual.
4. Error lama tidak muncul kembali akibat stale response.
5. Refresh browser dapat memulihkan attempt aktif berdasarkan backend.
6. Retry AI analysis tidak meminta upload CLI baru.

Sistem harus benar-benar konsisten antara active session, active analysis attempt, dan status yang ditampilkan.

## 2. Symptoms

### Case A — New Token

User klik:

```
[Dapatkan token baru]
```

Tetapi:

- Error "Analisis codebase belum berhasil" masih muncul.
- Progress sync lama tetap ada.
- Tampilan tidak kembali ke initial sync state.

### Case B — Analysis Retry

User klik:

```
[Coba lagi analisis]
```

Tetapi:

- Error lama masih terlihat.
- Hanya label tombol berubah menjadi "Menganalisis...".
- Tidak muncul progress aktif yang jelas.

### Case C — Expiration

User meninggalkan halaman sync cukup lama.

UI berpotensi menyimpan prompt lama yang berisi token kedaluwarsa tanpa memberi status yang jelas.

## 4. Known Suspicious Code

Dalam `use-codebase-onboarding.ts`, `retrySession()` membersihkan beberapa state:

```
setPayload(outcome.payload);
setRecoveredStatus(null);
setAnalysis(null);
setAnalysisError(null);
analysisAttemptedFor.current = null;
```

Tetapi `use-codebase-sync-status.ts` memiliki state/pinned session reference sendiri.

Periksa apakah perubahan `initialStatus` atau `sessionId` benar-benar me-reset active polling identity.

Di `sync-stage-list.tsx`, failure branch dapat tetap menang saat `isAnalyzing` true:

```
showAnalysisFailure && onRetryAnalysis
  ? /* failure UI */
  : analysisRow
    ? /* actual status */
    : null
```

Ini membuat old failure UI tetap aktif saat retry.

**Perbaiki prioritas render dan operation identity, bukan sekadar menyembunyikan error menggunakan timeout.**

## 5. New Sync Session Lifecycle

Desired:

```
OLD SESSION
  status: analysis_failed
          │
          │ User requests a new sync token
          ▼
SERVER ISSUES NEW SESSION
          │
          ▼
NEW SESSION ID
          │
          ├─ Clear old visible error
          ├─ Clear old visible progress
          ├─ Reset old analysis presentation
          ├─ Replace old prompt/token
          ├─ Reset current stage
          └─ Bind polling to new session
          │
          ▼
WAITING FOR CLI
          │
          ▼
AGENT CONNECTED
          │
          ▼
UPLOAD IN PROGRESS
```

Historical failures remain persisted in database, but must not appear as active attempt state.

No fake success transitions.

### Atomic Session Identity

The new active session ID should govern:

- Prompt credential.
- Expiration display.
- Polled status.
- Error message.
- Progress list.
- Retry availability.
- Active analysis reference when relevant.

Implement robust reset through explicit session identity, state reducer, controlled remount, or another architecture consistent with existing hooks.

Do not rely on unrelated `setState` calls that can race.

### Stale Response Protection

If old polling returns after new session is activated:

```
old response → ignored
```

Do not overwrite new session state.

Abort old requests when possible and validate session identity on response.

## 6. Analysis Retry Lifecycle

Correct behavior:

```
ATTEMPT 1 — FAILED

    ✕ Analisis belum berhasil
      [Coba lagi analisis]

                │ click
                ▼

ATTEMPT 2 — STARTING

    ◌ Menyiapkan analisis...

                │ accepted by server
                ▼

ATTEMPT 2 — RUNNING

    ◌ Menganalisis repository...
      [real elapsed time, if available]

                │
        ┌───────┴────────┐
        ▼                ▼

     SUCCESS           FAILED

 ✓ Analisis siap     ✕ Analisis gagal
 [Lanjutkan]         [Coba lagi]
```

**Failure attempt 1 must never be shown as the current status of attempt 2.**

Use persisted backend state as the source of truth for running/completed/failed statuses.

Client may show a brief immediate "starting" state after click while server confirms request acceptance.

Do not fabricate model reasoning stages.

## 7. Render Priority

Establish explicit view state priority:

```
active attempt running
    > previous attempt error

current attempt failed
    > generic waiting

ready analysis for correct snapshot
    > obsolete retry failure
```

But never mark READY unless backend validates stored output.

Inspect `analysisAttemptStatus`, `analysisStatus`, `analysisWorking`, and current attempt identity to avoid contradictory render states.

A disabled "Menganalisis..." button under a red failure panel is not acceptable.

## 8. Token Expiration

Current CLI sync session lifetime is 30 minutes.

Expected:

### Valid Token

```
Instruksi sync tersedia
[Salin prompt]
```

### Near Expiry

```
Sesi segera berakhir
[Perbarui sesi]
```

### Expired Token

```
Sesi telah berakhir
[Buat sesi baru]
```

Show expiration based on authoritative server `expiresAt`, not guessed client timers.

Do not automatically regenerate token in the background and silently invalidate prompt already copied to an agent.

Do not persist raw sync tokens in localStorage.

If raw token is only delivered once, preserve that security property.

## 9. Separate Sync Recovery From Analysis Recovery

Critical rule:

```
UPLOAD NOT COMPLETED
       → Retry Sync / New Token

UPLOAD COMPLETED + ANALYSIS FAILED
       → Retry Analysis on Existing Snapshot
```

Do not generate a new token as the default action for analysis failure.

Do not upload source files again when snapshot is already valid.

Do not lose old completed planning after retry.

## 10. Refresh &amp; Reopen

On refresh:

- Read authoritative persisted active session.
- Restore correct snapshot.
- Restore latest applicable analysis attempt.
- Restore running/failed/ready state.
- Never reconstruct fake pending state from local timers.
- Never use an analysis result belonging to another snapshot.
- Do not duplicate model requests.

On reconnect after internet outage:

- Reconcile latest server state.
- Do not mark an unknown request failed solely because frontend lost connection.
- Avoid duplicate generation and billing.

Anti-slop:

- No nested error cards.
- No fake Thinking updates.
- No hourglass icon.
- No huge animated loader.
- No duplicate retry buttons.
- No irrelevant sync IDs in prominent UI.
- No generic explanatory paragraphs repeated under every progress stage.

## 12. Tests

Required non-browser tests:

1. New session clears old visible status.
2. New session uses new session ID.
3. Old polling response is ignored.
4. Prompt credential matches current session.
5. Expired session prompts valid renewal.
6. Refresh restores correct active session.
7. Analysis retry replaces failed UI with running UI.
8. Running state stops when attempt finishes.
9. Failed retry renders new failure.
10. Successful retry renders ready state.
11. Double click does not create duplicate analysis.
12. Upload success + analysis fail does not require re-sync.
13. Network reconnect reconciles state correctly.
14. Old completed plans remain persisted.
15. Session A status does not contaminate session B.

Use unit tests, React component tests with non-browser tooling, service integration tests, typecheck, lint, and build.

**No browser QA, Playwright, Puppeteer, browser automation, manual browser testing, or screenshots.**

## 13. Definition of Done

A newly issued sync token produces a clean session view, analysis retry shows immediate honest progress, historical failures never leak into current attempts, and refresh recovers the correct state.

Report root cause, changed state ownership, session/attempt identity strategy, and test results.

Do not claim completion merely because the red error text disappeared.
