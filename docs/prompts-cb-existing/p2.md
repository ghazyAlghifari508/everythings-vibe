# FIX 02 — Eliminate Stale Credit Gate, Restore Prompt Rendering After Session Creation, and Fix Contradictory Sync Loading

**COMPLEXITY: MEDIUM–HIGH**  
**PRIORITY: P0 — Frontend onboarding blocker**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)

Target branch: `feature/vibeplan-existing-codebase`

## 1. Mission

Perbaiki frontend onboarding Existing Codebase yang menampilkan locked prompt lama walaupun user sudah eligible atau sync session berhasil dibuat.

Juga perbaiki progress yang menampilkan "Menghubungkan server..." ketika instruksi CLI masih terkunci dan tidak ada sesi valid yang dipantau.

**Kontrak UX wajib konsisten dengan FIX 01: CREDIT SUFFICIENT → CLI PROMPT READY, otomatis, tanpa approval tambahan.**

Jangan membuat approval baru sebagai workaround.

## 2. Reported Reproduction

User membuka:

```
/plan/codebase?intent=new
```

Lalu melihat:

```
Tarif analisis diperbarui
Setujui hingga 12 kredit...
```

User menekan tombol:

```
Setujui dan lanjutkan
```

Namun:

- Locked prompt tetap terlihat.
- Prompt CLI tidak muncul.
- Progress menampilkan "Menghubungkan server...".
- User tidak tahu apakah session sudah berhasil dibuat.
- User tidak bisa melakukan sync.

Ini merupakan UI dengan dua state yang saling bertentangan.

## 4. Confirmed Suspicious Logic

Di `use-codebase-onboarding.ts`, create operation berhasil lalu melakukan:

```
setCodebase(outcome.codebase)
adoptPayload(outcome.payload, null)
setStep("sync")
```

Tetapi alur sebelumnya tidak selalu memperbarui `creditStatus`.

Pada `plan-codebase-page.tsx`, locked view dibangun dari `creditStatus`.

Pada `screen-connect-prompt-step.tsx`:

```
lockedPrompt
  ? <LockedPromptStateView />
  : <CLI Prompt />
```

Sehingga `lockedPrompt` bisa tetap mengalahkan payload valid.

**Periksa dan hilangkan konflik state tersebut.**

Setelah FIX 01, eligibility sudah tidak memerlukan approval gate rutin. Pastikan UI tidak mempertahankan code path lama.

## 5. State Model

Gunakan state yang mempunyai arti jelas:

```
CHECKING_ELIGIBILITY
CREATING_SESSION
PROMPT_READY
CREDIT_BLOCKED
SESSION_CREATION_FAILED
```

Sync progress merupakan lifecycle terpisah yang hanya relevan setelah ada sesi valid.

Jangan memaksa enum baru jika discriminated union atau state model existing lebih tepat, tetapi mutual exclusivity harus terjamin.

### Correct state transitions

```
CHECKING_ELIGIBILITY
         │
   ┌─────┴─────┐
   ▼           ▼
ELIGIBLE    BLOCKED
   │           │
   ▼           ▼
CREATING    LOCKED PROMPT
SESSION     + TOP UP
   │
   ├── Failure → RETRY SESSION CREATION
   │
   └── Success → PROMPT_READY
```

Tidak ada transisi menuju approval.

## 7. Single Source of Truth

Pastikan UI menggunakan:

- Authoritative server eligibility.
- Successful session creation response.
- Validated sync prompt payload.
- Active session identity.
- Server-reported sync status.

Jangan biarkan stale `creditStatus` menimpa valid `payload`.

Jangan menganggap adanya `codebaseId` saja berarti prompt siap.

Prompt siap hanya ketika server benar-benar menghasilkan payload yang valid untuk sesi tersebut.

Saat eligibility berubah, invalidasi query atau lakukan state reconciliation dengan benar.

Jangan mengandalkan timeout untuk menghapus lock.

## 8. Idempotent Request Handling

Perhatikan:

- React Strict Mode.
- Re-render setelah `setCreditStatus`.
- State updates asynchronous.
- Request pertama selesai setelah komponen unmount.
- Double click.
- Refresh.
- Navigasi keluar sebelum response.
- Network timeout saat server sebenarnya berhasil membuat sesi.

Jika response client hilang, pastikan ada cara aman memulihkan session yang sudah dibuat.

Jangan mengulang POST secara membabi buta hingga membuat duplicate codebase di History.

Gunakan operation identity/idempotency dari backend jika tersedia.

## 9. Real Error Handling

Jika POST `/api/codebases` gagal:

- Jangan tampilkan generic progress success.
- Jangan mempertahankan locked credit state jika masalah sebenarnya adalah server error.
- Tampilkan satu pesan di area yang sesuai.
- Sediakan retry pembuatan sesi jika benar-benar diperlukan.
- Pertahankan failure detail untuk logging internal.
- Jangan mengirim raw token ke error logs.

Jika POST berhasil:

- Render prompt yang benar.
- Tidak boleh perlu klik kedua.
- Tidak boleh tetap menunjukkan error lama.
- Aktifkan polling pada session ID yang benar.

## 11. Regression Tests

Wajib test:

1. Eligibility sufficient → auto session creation.
2. Successful response → CLI prompt rendered.
3. Valid prompt never hidden by stale credit state.
4. No approval variant.
5. Locked prompt only for genuinely blocked eligibility.
6. Blocked state has no sync progress pretending to connect.
7. Real pending request shows loading.
8. Failed create shows one correct error.
9. Successful create removes obsolete errors.
10. Double create is prevented.
11. Refresh recovers correct session.
12. Old response cannot overwrite a newer session.
13. Missing/malformed payload is handled safely.
14. Clipboard action copies correct active session instructions.
15. Session expiry handled without credential leakage.
16. Greenfield and other consumers unaffected.

Run non-browser unit/component/API tests, typecheck, lint, and build.

**No browser QA, Playwright, Puppeteer, browser automation, manual browser testing, or screenshots.**

## 12. Definition of Done

Dengan kredit cukup, user membuka Hubungkan Repository lalu prompt asli otomatis tampil.

Tidak ada modal, approval card, atau tombol perantara.

Loading hanya muncul untuk request nyata; locked prompt dan progress aktif tidak pernah muncul bersamaan secara kontradiktif.

Laporkan root cause, state ownership, request lifecycle, changed files, dan test results.
