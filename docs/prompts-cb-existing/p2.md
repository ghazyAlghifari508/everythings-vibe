# PHASE 02 — Create Truly Isolated Feature Workspaces Within the Same Repository

**Repository:** [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
**Target branch:** `feature/vibeplan-existing-codebase`

## 1. Objective

Perbaiki workflow "Buat fitur baru" pada Existing Codebase.

Ketika user memilih aksi tersebut dari dropdown "Fitur Repository", workspace harus langsung berpindah ke pengalaman planning baru yang kosong, tetapi tetap menggunakan repository, source code, snapshot, dan repository analysis context yang sama.

Planning sebelumnya harus tetap tersimpan dan dapat dibuka lagi melalui feature switcher.

**Satu repository dapat memiliki banyak feature plans yang independen.**

## 2. Current Problem

Saat ini `handleCreateFeature()` pada `use-workspace-composer.ts` hanya menjalankan:

```
setIsCreatingNew(true)
```

Workspace kemudian menampilkan label "Fitur baru" di composer.

Namun chat lama, artefak, pertanyaan, dan konteks UI dapat tetap terlihat sampai user mengirim pesan berikutnya.

Ini membuat tindakan membuat fitur baru tidak jelas dan tidak memberikan pengalaman workspace baru.

## 5. State Isolation Requirements

### Repository-scoped state — MUST PRESERVE

- Codebase ID.
- Repository name.
- File explorer.
- Current synced source snapshot.
- Tech stack information.
- Repository analysis context.
- Repository-specific navigation.
- Sync history dan permissions.

### Feature-scoped state — MUST RESET ON NEW FEATURE

- Active feature ID.
- Chat messages.
- Composer draft lama.
- AI questions.
- Clarification answers.
- Editing question state.
- Feature tree.
- PRD content.
- AC content.
- Task tree.
- Kanban project binding.
- Pipeline stage.
- In-flight generation status.
- Stage errors.
- Active artifact.
- Right panel feature preview.
- Any feature-specific cached result.

Jangan reset seluruh repository untuk membuat fitur baru.

## 6. Expected Interaction Lifecycle

### Step A — Click "Buat fitur baru"

Workspace langsung masuk ke empty creation mode.

User tidak perlu melakukan refresh.

Tidak ada chat, pertanyaan, Task, maupun dokumen dari fitur sebelumnya yang masih ditampilkan.

### Step B — User types first request

Contoh:

"Tambahkan fitur bookmark artikel."

Saat submit:

1. Validasi input.
2. Buat feature project baru yang terikat pada codebase ID yang sama.
3. Simpan request awal.
4. Set new project sebagai active plan.
5. Jalankan clarification workflow dengan codebase context yang sesuai.
6. Perbarui feature switcher.

Jangan gunakan ID project fitur sebelumnya untuk request fitur baru.

### Step C — User cancels before submitting

Jika user kembali ke fitur lama sebelum membuat prompt:

- Jangan membuat empty project record.
- Jangan meninggalkan history kosong.
- Jangan menghilangkan data fitur lama.
- Restore plan lama dari persisted data.

### Step D — User reopens a previous feature

Contoh:

```
Fitur Repository
├── Pencarian Artikel  ✓
├── Bookmark Artikel   Draft
└── + Buat fitur baru
```

Saat Pencarian Artikel dipilih:

- Load kembali planning asli.
- Restore PRD/AC/Task dan Kanban.
- Jangan membawa chat Bookmark Artikel.
- Jangan membuat ulang Task.
- Jangan mengonsumsi kredit hanya karena membuka plan.

## 7. Async Safety &amp; Persistence

Audit race conditions.

Misalnya:

1. Request feature A sedang loading.
2. User mengklik "Buat fitur baru".
3. Response lama dari feature A datang.
4. UI tidak boleh memasukkan PRD/Task A ke workspace baru.

Gunakan project identity dan request guard/abort sesuai arsitektur existing.

Pastikan data dari request project lama tidak menimpa state project baru.

Perbaiki efek rehydration yang dapat mengembalikan feature lama sebagai active plan ketika creation mode sedang aktif.

Jika request pembuatan project gagal, pertahankan prompt yang diketik user dan tampilkan error yang bisa dicoba lagi tanpa membuat duplicate project.

## 8. UX Requirements

Gunakan empty state yang jelas, sederhana, dan sesuai design system.

Contoh:

```
Apa yang ingin kamu tambahkan?

Rencanakan fitur baru untuk Ocean Guard.

[Jelaskan fitur yang kamu inginkan...]
```

Jangan menambahkan hero section berlebihan, gradient, multi-card suggestions yang tidak perlu, atau placeholder AI generik.

Feature switcher tetap menjadi tempat utama untuk berpindah fitur dan membuat fitur baru.

Hindari duplikasi tombol "Buat fitur baru" di beberapa lokasi tanpa kebutuhan.

## 9. Mandatory Component-First Design

Sebelum coding UI, eksplor komponen yang sudah terpasang.

Wajib evaluasi komponen siap pakai dari:

- shadcn/ui — DropdownMenu, Command, Button, Empty State.
- HeroUI — dropdown/listbox primitives jika sesuai.
- Magic UI — hanya untuk transisi yang benar-benar diperlukan.
- React Bits — subtle motion apabila relevan.
- Thinking Orbs — hanya untuk AI processing, bukan empty state dekoratif.

Dokumentasi:

[https://ui.shadcn.com/](https://ui.shadcn.com/)  
[https://www.heroui.com/](https://www.heroui.com/)  
[https://magicui.design/](https://magicui.design/)  
[https://reactbits.dev/](https://reactbits.dev/)  
[https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs)

**Wajib menggunakan komponen existing/siap pakai yang sesuai, bukan membangun UI dari nol.** Custom code hanya untuk composition dan state handling yang memang spesifik pada aplikasi.

Pertahankan layout tiga panel VibeEverything.

## 10. Tests

Tambahkan regression coverage untuk:

- Click new feature immediately clears feature-specific UI.
- Repository context remains unchanged.
- No blank DB record before first prompt.
- First submitted prompt creates the correct new project.
- Feature A persists after Feature B creation.
- Switch A → B → A restores correct data.
- Stale async responses cannot overwrite another feature.
- Failed creation does not lose draft.
- No cross-project artifacts or Kanban progress.
- No accidental regeneration or duplicate project creation.

Gunakan unit/integration tests non-browser serta typecheck, lint, dan build.

**Jangan menjalankan browser QA, Playwright, Puppeteer, manual browser testing, ataupun screenshot tests.**

## 11. Definition of Done

Tombol "Buat fitur baru" langsung membuka planning workspace baru yang kosong. Repository tetap sama, dan semua feature plans sebelumnya tetap aman, independen, serta dapat dibuka kembali.

Laporan akhir wajib mencantumkan root cause, state boundaries, files changed, hasil tests, dan potensi risiko migrasi data.
