# FIX 02: Resolve React Hydration Mismatch in Existing Codebase Workspace

**COMPLEXITY: COMPLEX**  
**PRIORITY: P0 — BLOCKER**  
**CATEGORY: React SSR / TanStack Start / Workspace State / Navigation**

Repository: `ghazyAlghifari508/everythings-vibe`

Target branch: `feature/vibeplan-existing-codebase`

**Prerequisite: FIX 01 completed and verified.**

## 1. Objective

Perbaiki React hydration mismatch pada Existing Codebase Workspace secara struktural.

Saat user membuka workspace atau melakukan planning, server-rendered text berbeda dari initial client render.

Error yang dilaporkan:

```
Hydration failed because the server rendered
text didn't match the client.

+ Demi Kemudahan Eksplorasi Karya
- Ghazy Portofolio
```

Mismatch terjadi di area plan switcher yang menggunakan Radix DropdownMenu.

Tujuan utamanya bukan menyembunyikan warning, tetapi memastikan server HTML dan initial client render menghasilkan konten yang konsisten.

## 2. Initial Finding

Periksa:

- `src/features/codebase/hooks/use-workspace-plan.ts`
- `src/features/codebase/services/plan-storage.ts`
- `src/features/codebase/services/active-plan.ts`
- `src/features/codebase/components/planning/codebase-plan-switcher.tsx`
- `src/features/codebase/components/chat/codebase-chat-workspace-header.tsx`
- `src/features/codebase/components/chat/codebase-chat-workspace.tsx`
- `src/features/codebase/services/workspace-loader.functions.ts`
- Workspace hydration/resolution services.

Current suspected cause:

```
requestedProjectId ??
  readActivePlanPointer(codebase.id)
```

Kode tersebut digunakan dalam plan resolution pada render, sementara `readActivePlanPointer()` mengambil data dari `sessionStorage`.

Server tidak mempunyai browser sessionStorage. Initial client render dapat mempunyai pointer berbeda.

Ini sangat mungkin menyebabkan server menampilkan satu plan, sedangkan browser langsung menampilkan plan lain.

Verifikasi melalui data flow dan tests. Jangan menganggap ini satu-satunya kemungkinan tanpa pemeriksaan.

## 3. Required Architecture

Gunakan deterministic initial plan resolution.

Target:

```
SERVER
  Persisted Plans
  Onboarding Identity
  Initial Plan Resolution
             |
             v
  Deterministic Initial State
             |
             v
FIRST CLIENT RENDER
  Same Plan Name
  Same Active Plan ID
  Same Dropdown Content
             |
             v
AFTER HYDRATION
  Reconcile Browser Preference
             |
             v
  Valid Active Plan
```

Prinsip:

- Server dan initial client harus menghasilkan markup identik.
- Browser preference boleh diterapkan setelah hydration.
- Preference harus divalidasi terhadap plans aktual.
- Tidak boleh ada plan ID yang tidak valid dipaksa aktif.
- Jangan menggunakan feature name sebagai repository name.
- Jangan mengubah canonical database state hanya karena pointer browser berbeda.

Referensi:

[https://tanstack.com/start/latest/docs/framework/react/guide/hydration-errors](https://tanstack.com/start/latest/docs/framework/react/guide/hydration-errors)

[https://react.dev/reference/react-dom/client/hydrateRoot](https://react.dev/reference/react-dom/client/hydrateRoot)

## 4. Recommended Solution

Gunakan server-provided initial state sebagai sumber konsisten untuk SSR dan hydration.

Jika sessionStorage hanya menyimpan preferensi navigasi, lakukan rekonsiliasi setelah mount menggunakan React effect, atau pendekatan external-store yang menyediakan server snapshot konsisten.

Pilih implementasi yang paling sesuai dengan arsitektur existing.

Jika ada cara membaca preferensi navigasi yang sah dari server, evaluasi sebagai alternatif, tetapi jangan membuat storage baru yang tidak diperlukan.

Jangan memindahkan seluruh workspace menjadi client-only sebagai solusi instan.

## 5. Prohibited Workarounds

Dilarang menggunakan:

```
suppressHydrationWarning
```

sebagai solusi utama.

Dilarang:

- Menonaktifkan SSR pada seluruh workspace.
- Membuat dynamic import client-only untuk menutupi bug tanpa alasan arsitektural.
- Menghapus plan switcher.
- Mengosongkan label sampai hydration tanpa memikirkan UX.
- Menggunakan `Math.random()` atau timestamp untuk memaksa remount.
- Mengabaikan server/client differences.
- Menghapus sessionStorage secara menyeluruh.
- Membuat kondisi yang hanya bekerja setelah refresh kedua.

## 6. Preserve Active Plan Semantics

Pastikan seluruh kondisi berikut tetap berjalan:

1. Repository dengan satu feature plan.
2. Repository dengan beberapa feature plans.
3. User memilih plan dari dropdown.
4. User refresh halaman.
5. User kembali melalui history.
6. User membuat feature plan baru.
7. User berpindah plan.
8. Plan yang pernah aktif sudah dihapus.
9. Browser sessionStorage kosong.
10. Browser sessionStorage mengandung stale pointer.
11. Pergantian repository.
12. Server loader mempunyai data lebih baru daripada pointer lokal.

Plan switcher harus tetap menampilkan nama feature plan yang benar.

Repository title pada header tetap berbeda dari feature plan title.

## 7. Visual/State Expectations

Incorrect:

```
SERVER RENDER
Active: Ghazy Portofolio

FIRST CLIENT RENDER
Active: Demi Kemudahan Eksplorasi Karya

Result: Hydration mismatch
```

Correct:

```
SERVER RENDER
Active: Server-resolved plan

FIRST CLIENT RENDER
Active: Same server-resolved plan

AFTER HYDRATION
Validate stored preference
        |
        +-- Valid -> update selected plan
        |
        +-- Stale -> use valid fallback
```

Jika user mempunyai saved preference yang valid, pilihan itu tetap boleh dipulihkan tanpa hydration mismatch.
