# FIX 02 — Authoritative Workspace Recovery &amp; Pipeline State Consistency

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`

## Objective

Perbaiki seluruh mekanisme pemulihan workspace Existing Codebase agar stage Feature → PRD → Acceptance Criteria → Task → Handoff selalu sesuai dengan artefak yang benar-benar tersimpan.

Ketika user membuka kembali repository melalui History, workspace tidak boleh kembali ke stage sebelumnya, menampilkan tombol generasi yang sudah selesai, atau salah membaca data dari feature plan lain.

Ini adalah perbaikan data/state architecture, bukan UI-only fix.

## Reproduction Scenario

User sudah menyelesaikan:

- Feature Specification.
- PRD.
- Acceptance Criteria.
- 30 Task.
- Kanban dengan progress yang dapat diperbarui AI coding agent.

Ketika user keluar dan membuka kembali workspace, kadang muncul:

- "PRD selesai" disertai aksi membuat AC lagi.
- "Acceptance Criteria selesai" disertai tombol "Buat Task".
- Stage Feature/PRD yang seharusnya sudah lewat.

Padahal panel Kanban menunjukkan 30 task dari database.

### State yang benar

```
EXISTING DATABASE
     │
     ├─ Feature    ✓
     ├─ PRD        ✓
     ├─ AC         ✓
     └─ Tasks      ✓ (30)
                 │
                 ▼
RESUME: AGENT HANDOFF
Tidak ada tombol generate ulang.

Jika Tasks belum tersedia:
RESUME: Tahap pembuatan Task

Jika proses hydration gagal:
ERROR / RETRY
Bukan empty workspace.
```

Potensi race condition:

1. Workspace dibuka.
2. PRD/AC selesai dimuat lebih dahulu.
3. UI mengubah stage menjadi AC.
4. Task selesai dimuat belakangan.
5. Derived stage menjadi Handoff.
6. Pipeline state tidak ikut maju karena guard sebelumnya.

Verifikasi kemungkinan tersebut, termasuk kasus lain sebelum menentukan solusi.

## Implementation Requirements

### A. Authoritative Stage Resolution

Persisted artifacts harus menjadi sumber kebenaran.

Gunakan aturan resolusi:

```
TASK AVAILABLE → HANDOFF
AC AVAILABLE   → AC
PRD AVAILABLE  → PRD
FEATURE READY  → FEATURE
NO ARTIFACTS   → QUESTIONS
```

Ini adalah prioritas tahap, bukan instruksi untuk selalu menampilkan salah satu secara prematur.

Jangan membuat UI stage bergantung pada urutan acak respons HTTP.

Pisahkan:

- Persisted completion state.
- Hydration/loading state.
- In-flight generation state.
- User navigation atau revisi yang disengaja.

Jika diperlukan, gunakan reducer/state machine terstruktur yang tetap terintegrasi dengan arsitektur existing.

### B. Deterministic Rehydration

Saat workspace dibuka kembali:

1. Resolve active `projectId` milik repository yang benar.
2. Ambil artefak project tersebut.
3. Tunggu status pembacaan yang diperlukan untuk memastikan tahap terakhir.
4. Reconcile pipeline state.
5. Render stage yang benar.
6. Restore Kanban progress dari database.

Jangan menampilkan CTA "Buat Task" sebelum dipastikan bahwa task memang belum ada.

Jangan melakukan AI generation ketika prosesnya hanya membaca ulang data.

### C. Race Condition Protection

Setiap request asynchronous harus terikat dengan identitas project yang memulainya.

Jika user berpindah dari Feature A ke Feature B ketika request A masih berjalan, respons A tidak boleh menimpa data B.

Evaluasi:

- AbortController.
- Request generation identifiers.
- Query keys.
- Stale response guards.
- State reset saat project berganti.

Pilih pendekatan yang sesuai dengan existing data layer, bukan menambahkan state manager kedua tanpa kebutuhan.

### D. Existing Task Protection

- Task yang sudah tersedia tidak boleh dianggap belum dibuat.
- Status `completed`, `in_progress`, dan status lainnya harus tetap tersimpan.
- Reopen tidak boleh memicu task regeneration.
- Refresh tidak boleh mengonsumsi credit.
- Re-sync repository tidak boleh mereset pipeline planning.
- Tombol generasi awal tidak boleh muncul pada tahap yang sudah selesai.
- Regeneration/revision harus merupakan aksi eksplisit dengan proteksi data.

### E. Error Handling

Bedakan secara jelas:

```
Pending hydration
Successful hydration
Artifact genuinely missing
Partial read failure
Unauthorized
Project not found
```

API failure tidak boleh menghasilkan false empty state.

Jika task ada tetapi PRD sementara gagal dibaca, jangan menyimpulkan seluruh planning hilang.

### F. Resume After AI Agent Progress

Tambahkan coverage untuk:

- 30 task awal.
- Sebagian task sudah in progress.
- Sebagian task sudah completed.
- User menutup website.
- AI agent memperbarui task melalui CLI.
- User membuka kembali workspace.

Progress yang muncul harus sesuai persisted backend state terbaru.

## Testing Matrix

Wajib menguji:

- PRD-only.
- PRD + AC.
- Full Task/Handoff.
- Out-of-order responses.
- Slow Task API.
- Switching feature ketika hydration berlangsung.
- Failed AC fetch dengan Task tersedia.
- Refresh/reopen repeated.
- Existing agent progress.
- In-flight generation.
- Duplicate generation prevention.

Gunakan unit dan integration tests non-browser.

Jangan jalankan browser QA, browser automation, Playwright, Puppeteer, atau screenshot comparison.

## Constraints

- Jangan membuat ulang workspace.
- Jangan menghapus artefak lama.
- Jangan menggunakan localStorage sebagai canonical artifact storage.
- Jangan menambahkan fallback stage palsu.
- Jangan menyembunyikan tombol dengan CSS sebagai solusi root cause.
- Pertahankan kompatibilitas greenfield.

Perubahan UI jika diperlukan wajib memakai komponen siap pakai yang sudah tersedia; audit shadcn/HeroUI sebelum menulis komponen baru. Jangan redesign area unrelated.

## Completion

Setelah test dan build, lakukan final data/state audit, atomic commit, dan push sesuai aturan repo.

Laporkan root cause, state transition lama versus baru, regression coverage, serta commit status.
