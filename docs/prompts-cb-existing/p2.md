# FIX 02 — Eliminate Refresh-Dependent Conclusion Gate After Successful Codebase Analysis

**Complexity:** COMPLEX  
**Priority:** P0  
**Prerequisite:** FIX 01 completed  
**Scope:** Existing Codebase onboarding → conclusion transition

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)

## 1. Mission

Perbaiki bug saat semua progress sync dan AI Analysis sudah menunjukkan checkmark selesai, tetapi tombol **Lanjut ke Kesimpulan** masih disabled.

User baru bisa melanjutkan setelah refresh halaman.

**Ini bug critical pada sinkronisasi state, bukan alasan untuk menyuruh user refresh atau menampilkan tombol secara paksa.**

Required:

```
✓ Agent terhubung
✓ Source code siap
✓ Sinkronisasi selesai
✓ Analisis selesai

[Lanjut ke Kesimpulan]  ← ENABLED
```

Tanpa refresh.

## 3. Key Source Finding

Current:

```
useOnboardingSummaryGate(...)
```

memanggil:

```
canContinueToCodebaseConclusion(...)
```

Predicate mengharuskan:

- Sync status valid.
- Analysis status `ready`.
- Analysis ID cocok dengan status server.
- Codebase ID cocok.
- Feature project ID cocok.
- Snapshot ID cocok.
- Output analisis tersedia.
- Output schema valid.
- `starterSuggestions` tersedia dan valid.

Tetapi UI progress dapat menunjukkan:

```
✓ Analisis selesai
```

sementara predicate masih false.

Screenshot juga menunjukkan informasi:

```
Perlu pembaruan rekomendasi task awal untuk melanjutkan
```

Jadi investigasi harus mencakup pipeline rekomendasi awal, bukan hanya status sync.

## 4. Required Root-Cause Analysis

Periksa urutan event:

```
Snapshot upload completed
          │
          ▼
AI analysis generated
          │
          ▼
Analysis persisted
          │
          ▼
Starter suggestions validated
          │
          ▼
Server marks review ready
          │
          ▼
Client receives latest output
          │
          ▼
Continue button enabled
```

Temukan apakah bug disebabkan oleh:

- Analysis status lebih cepat daripada output fetch.
- Effect tidak terpicu saat `lastStatus` berubah.
- Data analysis masih cached/stale.
- Starter suggestions belum lengkap.
- Project ID berbeda.
- Snapshot ID berbeda.
- Stale response dari attempt sebelumnya.
- Error saat background repair.
- Valid output sudah tersimpan tetapi client belum melakukan revalidation.

Jangan memilih satu dugaan tanpa bukti.

## 5. Authoritative Readiness Model

Gunakan satu kontrak readiness yang konsisten antara backend dan frontend.

Ideal:

```
ANALYSIS RUNNING
       │
       ▼
ANALYSIS PERSISTED
       │
       ▼
REVIEW DATA VALIDATED
       │
       ▼
CONCLUSION READY
       │
       ▼
BUTTON ENABLED
```

Jika `starterSuggestions` memang mandatory untuk kesimpulan:

- Pastikan dihasilkan dan disimpan sebelum status final siap untuk direview.
- Jika butuh repair, jalankan pipeline yang benar.
- Berikan status yang sesuai tanpa menyatakan semua selesai secara menyesatkan.

Jika `starterSuggestions` sebenarnya bukan prerequisite inti kesimpulan:

- Evaluasi ulang gating tersebut berdasarkan schema dan kebutuhan UI.
- Jangan menjadikan field opsional sebagai blocker permanen.
- Jangan menonaktifkan validasi output yang benar-benar dibutuhkan.

**Jangan mengubah** `canContinueToCodebaseConclusion()` **menjadi** `return true`**.**

## 6. Real-Time State Reconciliation

Saat server menyatakan analysis `ready`:

1. Ambil output untuk analysis ID dan snapshot yang tepat.
2. Validasi data.
3. Update client state secara atomik.
4. Recompute eligibility tombol.
5. Tampilkan tombol aktif jika semua syarat terpenuhi.

Jika aplikasi memakai TanStack Router cache atau query cache, lakukan invalidasi/revalidation dengan pola existing.

Jangan:

- `window.location.reload()`.
- Menambah timeout 3 detik.
- Memaksa tombol enabled sebelum data valid.
- Memasang polling berlebihan.
- Menambah tombol Refresh.
- Membuat local fake analysis output.
