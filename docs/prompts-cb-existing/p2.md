## 1. Mission

Perbaiki alur navigasi Existing Codebase supaya user baru dapat masuk ke Planning Workspace setelah snapshot repository dan analisis AI yang sesuai benar-benar siap.

Saat ini:

```
CLI Sync ✓
    ↓
AI Analysis ✕
    ↓
Workspace tetap bisa dibuka
    ↓
User mengirim prompt
    ↓
CODEBASE_CONTEXT_UNAVAILABLE
```

Ini adalah kontradiksi UX.

**Target: snapshot berhasil bukan berarti onboarding selesai. Planning Workspace hanya siap setelah analisis yang valid tersedia.**

Jangan menghapus snapshot yang sudah berhasil diunggah.

## 4. Required Readiness Model

Pisahkan tiga kondisi:

### Repository Uploaded

Snapshot valid berhasil disimpan.

User dapat melihat status repository dan melanjutkan onboarding.

### Analysis Ready

Tersedia hasil analisis valid yang terhubung ke snapshot yang benar.

Analisis bukan sekadar request HTTP selesai. Output harus valid dan tersimpan.

### Planning Ready

Repository dan hasil analisis siap digunakan untuk memulai Feature → PRD → AC → Task.

Kesiapan planning harus dinilai berdasarkan snapshot dan project context yang benar.

Jangan memakai satu boolean `isReady` untuk seluruh domain tanpa membedakan maknanya.

## 5. Navigation State Machine

Expected:

```
NEW REPOSITORY
      │
      ▼
Sync via CLI
      │
      ├── Failed
      │     └── Retry Sync
      │
      └── Uploaded
             │
             ▼
        AI Analysis
             │
      ┌──────┴──────┐
      │             │
   Pending       Blocked/Failed
      │             │
      │         Recovery Screen
      │             │
      │         Retry Analysis
      │             │
      └──────┬──────┘
             │
             ▼
        Analysis Ready
             │
             ▼
     Planning Workspace
```

Do not create fake success states.

### Direct URL Access

Jika user membuka:

```
/codebases/:codebaseId
```

untuk repository yang belum siap:

- Jangan render normal planning composer.
- Jangan membuat feature plan baru secara diam-diam.
- Arahkan user ke recovery/onboarding state yang sesuai.
- Pastikan URL/loader behavior benar setelah refresh.
- Pastikan user tetap tidak bisa melewati prerequisite hanya dengan mengubah URL.

Gunakan existing TanStack Start router patterns.

Jangan membuat routing workaround dengan localStorage boolean.

## 7. Critical Edge Case — Existing Completed Plans

Jangan mengorbankan planning lama hanya demi gating baru.

Contoh:

- User sudah menyelesaikan Feature A memakai Snapshot 1.
- User melakukan re-sync ke Snapshot 2.
- Analysis Snapshot 2 gagal.
- Feature A, PRD, AC, dan Task dari Snapshot 1 masih valid sebagai artefak historis.

Expected:

- User tetap dapat membaca planning yang sudah tersimpan.
- User tetap dapat melihat Kanban dan progress existing jika data tersedia.
- Jangan membuat Feature A menghilang.
- Jangan otomatis menghubungkan Feature A ke Snapshot 2.
- New generation yang membutuhkan konteks Snapshot 2 harus mengikuti readiness Snapshot 2.
- Jika histori memang terikat ke Snapshot 1, pertahankan linkage tersebut.

Bedakan akses membaca existing artifacts dengan izin memulai generasi baru.

**Completion-gated onboarding berlaku pada planning baru, bukan penghapusan akses terhadap hasil lama.**

## 8. Backend Gating

Setiap endpoint yang membutuhkan analysis context harus memvalidasi readiness di backend.

Jangan mengandalkan disabled button frontend sebagai satu-satunya proteksi.

Pastikan:

- Analysis terikat pada snapshot yang tepat.
- Output valid dan persisted.
- User memiliki ownership.
- Tidak ada fallback analysis dari repository lain.
- Tidak ada placeholder context saat generation.
- Feature creation tidak menghasilkan project kosong yang tidak bisa digunakan.
- Reopen tidak memicu AI generation otomatis.

Gunakan existing `generation-context-requirement.ts` dan shared readiness predicates bila sesuai.

Jangan membuat beberapa implementasi readiness yang saling berbeda.

## 9. Loading &amp; Hydration

Pada first render, status mungkin belum tersedia.

Jangan render composer aktif sesaat kemudian menggantinya dengan error setelah status selesai dimuat.

Gunakan initial loading state yang sederhana.

Setelah data terverifikasi, tampilkan hanya salah satu:

```
onboarding
analysis_pending
recovery_required
planning_ready
existing_plan_readonly
```

Sesuaikan model final dengan schema existing; jangan memaksakan enum baru bila tidak diperlukan.

## 11. Regression Tests

Wajib test:

1. Upload success + analysis pending → workspace belum terbuka.
2. Upload success + insufficient credit → recovery screen.
3. Upload success + analysis failed → recovery screen.
4. Valid ready analysis pada snapshot aktif → workspace bisa dibuka.
5. Direct workspace URL tidak mem-bypass readiness.
6. Refresh selama analisis tidak menampilkan composer prematur.
7. Validasi backend tetap berlaku.
8. User lain tidak bisa mengakses repository.
9. Failed analysis tidak menghapus snapshot.
10. Plan lama tetap bisa dibaca setelah re-sync gagal.
11. Re-sync Snapshot 2 tidak menggunakan analysis Snapshot 1 untuk generasi baru.
12. Completed existing Task/Kanban tidak hilang.
13. Tidak ada blank project akibat premature feature creation.

Jalankan unit/integration tests non-browser, typecheck, lint, dan build.

**DILARANG browser QA, Playwright, Puppeteer, manual browser testing, atau screenshot testing.**

## 12. Definition of Done

User tidak pernah diarahkan ke normal Planning Workspace yang belum bisa melakukan planning.

Upload success tidak boleh dianggap sebagai onboarding success.

Plan lama tetap aman, direct URL terlindungi, dan readiness berasal dari data backend yang valid.

Laporkan root cause, state model, perubahan route/loader/API, dan test results.
