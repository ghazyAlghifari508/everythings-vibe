# P02 — Diagnose and Fix ECONNRESET / HTTP 500

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** COMPLEX

## Problem statement

Saat menggunakan Existing Codebase workspace, muncul berulang:

```
[Vite] Internal server error: read ECONNRESET
at TCP.onStreamRead
(node:internal/stream_base_commons:216:20)
```

Browser juga mengembalikan HTTP 500 dari beberapa endpoint codebase.

Belum diketahui apakah ini berkaitan dengan Vite HMR, koneksi HTTP, server-side fetch, polling, database, atau koneksi ke upstream service.

Tugasmu adalah menemukan penyebab nyata, bukan menyembunyikan error.

## Investigation scope

1. Baca aturan repository dan skill debugging.
2. Audit `vite.config.ts`, konfigurasi development server, TanStack Start SSR, serta scripts pada `package.json`.
3. Telusuri endpoint `/api/codebases/*` yang gagal, termasuk route handlers, service layer, dan dependency eksternal.
4. Periksa source preview requests, sync status polling, Kanban polling, dan background worker jika berhubungan.
5. Bedakan error yang dihasilkan Vite dev middleware dari error API aplikasi.
6. Periksa hubungan antara HMR update dan kejadian `ECONNRESET`.
7. Periksa timeout, abort, cancellation, streaming, socket closure, dan kemungkinan race condition.
8. Audit apakah suatu exception dilempar ulang sebagai HTTP 500 tanpa klasifikasi dan logging yang memadai.

Jangan berasumsi bahwa database adalah penyebabnya.

## Metode diagnosis

- Gunakan log terminal beserta timestamp dan request ID jika tersedia.
- Reproduksi melalui targeted tests, integration tests, atau HTTP requests yang aman.
- Cocokkan setiap stack trace dengan request yang menyebabkan kegagalan.
- Bedakan koneksi yang dibatalkan secara normal dari request failure yang benar-benar harus diperbaiki.
- Jangan membuat log error berulang tanpa informasi tambahan.
- Jangan memasukkan credential, token, atau data sensitif ke diagnostic logs.

## Larangan keras

- Tidak boleh mematikan `server.hmr.overlay` hanya agar error tidak terlihat.
- Tidak boleh swallow exception dengan empty catch.
- Tidak boleh mengubah semua error menjadi status success.
- Tidak boleh memasang retry tanpa batas.
- Tidak boleh memperpanjang timeout secara acak.
- Tidak boleh menghapus validasi atau menurunkan standar test.
- Tidak boleh membuat fake response atau fake success.
- Jangan mengubah database secara manual untuk menyelesaikan HTTP 500.

## Expected behavior

```
User membuka source / workspace
              |
              v
       Request dikirim
              |
      ┌───────┴────────┐
      |                |
   Berhasil          Gagal
      |                |
 Konten benar    Error terklasifikasi
                      |
            Diagnostik internal jelas
                      |
          User mendapat pesan relevan
                 + Retry jika aman
```

HTTP 500 harus dipakai untuk kegagalan server yang memang tepat menggunakan status tersebut. Jangan memaksakan success status agar log terlihat bersih.

## Testing dan acceptance criteria

- Akar penyebab yang ditemukan mempunyai bukti dari log atau reproduksi.
- Kondisi yang menyebabkan kegagalan diperbaiki pada lapisan yang tepat.
- Request sukses tidak berubah perilakunya.
- Cancellation normal tidak diperlakukan sebagai fatal error bila memang aman.
- Request error tetap menghasilkan status dan pesan yang benar.
- Tidak ada infinite retry, duplicate request storm, atau log spam.
- Tambahkan regression test untuk bug yang terbukti.

Pada fase ini **jangan menjalankan browser QA**. Browser console dan Network DevTools akan diperiksa pada fase QA terakhir.

Jika error hanya bisa direproduksi melalui runtime browser, laporkan sebagai unresolved runtime verification dan sediakan instrumentation yang diperlukan. Jangan membuat klaim keberhasilan palsu.

## Atomic commits

Pisahkan perbaikan berdasarkan concern yang benar-benar berbeda. Contoh:

`fix(codebase): handle interrupted upstream connections`

`test(codebase): cover interrupted request lifecycle`

Commit hanya jika perubahan telah terverifikasi dengan pengujian yang tersedia. Jangan push tanpa izin.

Jelaskan:

- Error chain lengkap.
- Root cause beserta bukti.
- Solusi yang dipilih dan alasannya.
- File yang berubah.
- Test pass/fail.
- Commit hash.
