# PHASE 01 — Fix Unsafe Revision Confirmation &amp; Remove Misleading Impact UI

**Repository:** [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
**Target branch:** `feature/vibeplan-existing-codebase`

## 1. Objective

Audit dan perbaiki lifecycle revisi planning Existing Codebase, terutama hubungan antara PRD lock, confirmation, dan Kanban task progress.

Hilangkan teks dampak revisi yang selalu muncul tanpa konteks, sekaligus memastikan dokumen yang sudah mencapai tahap Task tidak dapat diubah secara tidak sengaja.

Perubahan harus memperbaiki akar masalah frontend dan backend. Jangan sekadar menyembunyikan elemen UI.

## 2. Reported Problem

Di workspace muncul teks:

> Revisi ini tidak menyentuh task yang sudah berjalan, jadi status Kanban tetap utuh.

Teks tersebut tampil meskipun user tidak sedang melakukan revisi.

Selain tidak berguna, pesan ini memberikan kesan bahwa semua perubahan planning aman terhadap Task, padahal kesesuaian PRD, Acceptance Criteria, dan Task tidak otomatis terjamin.

### Critical Code Finding

Pada `use-workspace-revision.ts`, request revisi menggunakan:

```
...(requiresTaskReplacementConfirmation
  ? { confirmedImpact: true }
  : {})
```

Sementara di `prd-chat-context.server.ts`, flag `confirmedImpact` dapat melewati PRD lock ketika planning sudah mencapai AC/Task.

Artinya, frontend berpotensi mengirim konfirmasi tanpa tindakan persetujuan eksplisit dari user.

Investigasi hubungan ini secara menyeluruh.

## 4. Expected Behavior

### Normal workspace

```
FITUR: Pencarian Artikel

✓ Feature selesai
✓ PRD selesai
✓ AC selesai
✓ Task selesai dibuat

[Lihat Planning] [Handoff AI Agent]
```

Tidak ada:

```
"Revisi ini tidak menyentuh task..."
"Status Kanban tetap utuh..."
Pesan dampak revisi permanen.
```

### Explicit revision flow, jika revisi didukung

```
User memilih "Revisi Planning"
            │
            ▼
Sistem memeriksa dokumen dan Task
            │
            ▼
   Apakah revisi berdampak?
         /          \
       Tidak         Ya
         │           │
         │    Tampilkan dampak aktual
         │           │
         │    Perlu konfirmasi user
         │           │
         └─────┬─────┘
               ▼
       Proses revisi aman
               │
               ▼
   Simpan versi baru, jaga histori
```

Jika workflow revisi terkontrol belum didukung dengan benar, lebih aman menolaknya dengan status yang jelas daripada melewati PRD lock secara otomatis.

## 5. Implementation Requirements

### A. Remove Persistent Revision Copy

Hapus penampilan `revisionImpactNotice` dari composer normal.

Jangan menggantinya dengan teks generik lain.

Informasi dampak hanya ditampilkan ketika user secara eksplisit melakukan tindakan yang memang memerlukan penilaian risiko.

### B. Correct Confirmation Contract

- Jangan pernah mengirim `confirmedImpact: true` hanya karena task non-pending ditemukan.
- Confirmation hanya boleh berasal dari aksi user yang eksplisit.
- Verifikasi ownership dan izin pada backend.
- Validasi stage serta versi planning yang akan direvisi.
- Validasi kondisi Task terbaru ketika konfirmasi diproses.
- Cegah stale confirmation ketika task berubah di antara review dan eksekusi.
- Jangan menggunakan boolean client sebagai satu-satunya bukti kelayakan mengubah planning terkunci.

Jika memerlukan konfirmasi dua tahap, ikat konfirmasi dengan project, versi dokumen, dan dampak yang benar-benar sudah diperiksa. Jangan membuat confirmation token palsu atau state yang hanya berlaku di frontend.

### C. Preserve Existing Progress

Tidak boleh ada perubahan yang secara diam-diam:

- Menghapus Task.
- Mengubah In Progress menjadi To Do.
- Menghapus Completed status.
- Menghapus PRD/AC versi lama.
- Mengganti Task lama dengan Task hasil revisi.
- Mengubah project atau repository yang berbeda.

Dokumen versi sebelumnya harus tetap tersedia jika versioning menjadi bagian workflow.

### D. Review PRD/AC/Task Consistency

Periksa kemungkinan PRD revision menyebabkan AC dan Task menjadi tidak sesuai dengan spesifikasi terbaru.

Jangan mengklaim Task tetap valid hanya karena status Kanban tidak berubah.

Jika workflow revision resmi tersedia, berikan status kebutuhan peninjauan terhadap downstream artifacts dengan jelas.

Jangan otomatis melakukan regenerasi AI atau mengonsumsi kredit.

### E. Fail Closed

Jika data dampak revisi tidak dapat dibaca, jangan mengasumsikan tidak ada dampak.

Jika backend belum mendukung revisi aman setelah Task, tolak operasi sampai workflow eksplisit tersedia.

## 6. UI Component Requirement

Jika diperlukan confirmation dialog, lakukan component discovery sebelum implementasi:

- Existing shadcn/ui `AlertDialog` / `Dialog`.
- HeroUI Modal/AlertDialog yang kompatibel.
- Komponen confirmation existing dari greenfield.
- Magic UI, React Bits, dan Thinking Orbs hanya jika benar-benar relevan.

Referensi:

[https://ui.shadcn.com/](https://ui.shadcn.com/)  
[https://www.heroui.com/](https://www.heroui.com/)

**WAJIB menggunakan komponen siap pakai yang sesuai. Jangan membuat confirmation modal, buttons, radio controls, atau overlays dari nol jika komponen matang sudah tersedia.**

Tidak boleh ada nested cards berlebihan, status decoration, atau teks teknis internal yang tidak membantu user.

## 7. Regression Tests

Wajib uji minimal:

1. Tanpa Task, revisi yang diizinkan berjalan normal.
2. Semua Task pending: revisi tidak boleh melewati lock secara diam-diam.
3. Ada In Progress Task: tidak boleh auto-confirm.
4. Ada Completed Task: tidak boleh auto-confirm.
5. Confirmation missing/invalid: backend menolak operasi yang memerlukannya.
6. Confirmation stale: backend menolak atau meminta peninjauan ulang.
7. PRD/AC/Task lama tetap tersimpan setelah pembatalan.
8. Unauthorized project tidak dapat direvisi.
9. Greenfield tetap kompatibel.

Jalankan focused unit/integration tests non-browser, typecheck, lint, dan build berdasarkan scripts repository.

**SKIP browser QA sepenuhnya. Jangan menjalankan Playwright, Puppeteer, browser automation, manual browser testing, atau visual screenshot testing.**

## 8. Completion Criteria

- Tidak ada lagi pesan dampak revisi permanen di composer.
- Locked PRD tidak dapat dilewati tanpa proses persetujuan yang benar.
- Tidak ada silent destructive update.
- Task progress tetap terlindungi.
- Root cause dan perbaikannya terbukti melalui automated tests.

Berikan laporan file berubah, alasan perubahan, tests yang dijalankan, hasil aktual, dan risiko yang masih tersisa. Jangan mengklaim aman jika belum diverifikasi.
