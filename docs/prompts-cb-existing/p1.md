# P01 — Fix Source File Preview Accuracy

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** MEDIUM

## Konteks dan masalah

Pada fitur Existing Codebase, pengguna dapat membuka file repository dari explorer kiri dan membaca kontennya melalui side panel kanan.

Ada dua contoh nyata:

- [`DESIGN.md`](http://DESIGN.md) terlihat memiliki konten sampai sekitar baris 297, tetapi viewer tetap menampilkan nomor hingga 398 dengan banyak baris kosong.
- [`AGENTS.md`](http://AGENTS.md) juga memiliki sejumlah baris kosong setelah konten terakhir.

Belum terbukti apakah baris-baris tersebut berasal dari file asli, proses CLI sync, snapshot, atau transformasi viewer.

**Jangan langsung menghapus baris kosong tanpa membuktikan sumbernya.**

## Audit kode terlebih dahulu

Periksa setidaknya:

- `src/features/codebase/components/explorer/codebase-source-preview.tsx`
- `src/features/codebase/services/source-view.ts`
- `src/features/codebase/services/source-view-highlight.ts`
- `src/features/codebase/services/source-view-cache.ts`
- `src/features/codebase/services/snapshot-preview.ts`
- `src/features/codebase/hooks/use-workspace-source.ts`
- Jalur CLI upload, penyimpanan snapshot, dan pembacaan file server.

Baca [`AGENTS.md`](http://AGENTS.md), rules, dan skill engineering yang relevan. Telusuri alur data dari file lokal sampai string yang diterima viewer.

## Investigasi wajib

1. Bandingkan isi file asli dengan isi file dalam snapshot yang diunggah.
2. Periksa line ending LF/CRLF, trailing newline, whitespace-only lines, chunk assembly, decoding, dan truncation.
3. Pastikan `split("\n")` tidak menyebabkan perbedaan yang tidak disengaja saat file berakhir dengan satu terminator newline.
4. Bedakan trailing blank line yang benar-benar ada dalam source dari baris yang muncul akibat bug.
5. Pastikan highlight.js, original mode, dan formatted mode tidak menghasilkan numbering yang tidak sinkron.
6. Pastikan line number dan token konten menggunakan satu sumber data yang konsisten.

## Perilaku yang harus dicapai

- Konten asli tidak boleh diubah diam-diam.
- Jika terdapat bug pada sync atau decoding, perbaiki sumber penyebabnya.
- Jika baris kosong memang berasal dari file asli, viewer harus tetap mempertahankan integritas source.
- Bila diperlukan, sediakan opsi presentasi untuk menyembunyikan trailing blank lines tanpa memodifikasi data asli.
- Fitur Copy dan Download tidak boleh mengambil versi tampilan yang sudah dimodifikasi.
- Nomor baris tetap akurat saat file memiliki baris kosong di tengah, trailing newline, atau konten terpotong.

Jika file asli memang berisi baris kosong, jangan mengklaim jumlah baris aslinya lebih sedikit. Tampilkan secara akurat atau sediakan opsi penyembunyian visual yang eksplisit.

## Testing

Tambahkan atau perbarui deterministic tests untuk:

- File tanpa newline terakhir.
- File dengan satu newline terakhir.
- File dengan banyak trailing blank lines.
- CRLF vs LF.
- Blank lines di tengah file.
- Truncated preview.
- Kesesuaian nomor baris dengan actual source.
- Original vs formatted view.

Gunakan targeted Vitest, Biome, dan typecheck sesuai aturan repository. Tidak perlu browser QA.

## Atomic commit

Buat commit terpisah untuk perubahan logis jika menyentuh beberapa concern, misalnya:

`fix(codebase): preserve accurate source preview line boundaries`

Jangan commit perubahan yang tidak berkaitan.

## Laporan akhir

Laporkan root cause yang terbukti, file yang berubah, perbandingan source asli dan snapshot, tests yang dijalankan, hasilnya, dan hash commit.

Jangan menyebut bug telah diperbaiki bila sumber perbedaan baris belum berhasil diverifikasi.
