## 1. MISSION

Perbaiki progress sinkronisasi VibePlan Existing Codebase.

User melaporkan bahwa ketika baru membuka halaman Hubungkan Repository, prompt CLI sudah tersedia tetapi belum disalin ataupun dijalankan, indikator **"Menunggu agent terhubung..."** sudah berputar seperti proses aktif.

INI SALAH.

Sebelumnya user memang meminta agar transisi dari loading menuju checkmark tidak muncul secara mendadak. Namun agent sebelumnya salah memahami requirement tersebut dan membuat spinner langsung aktif sejak sesi dibuat.

**Requirement yang benar adalah:**

- Sebelum user menjalankan CLI, status harus menunggu secara pasif.
- Setelah CLI benar-benar memulai proses koneksi, barulah indikator aktif boleh muncul.
- Setelah koneksi berhasil, indikator berubah menjadi checkmark.
- Tahap berikutnya menampilkan loading hanya ketika proses terkait benar-benar berlangsung.
- Jangan memalsukan loading dengan timer atau delay.
- Jangan menganggap tindakan copy prompt berarti CLI sudah dieksekusi.

**Bedakan WAITING FOR USER ACTION dengan SYSTEM ACTIVITY.**

## 4. REQUIRED PROGRESS MODEL

Pisahkan dengan jelas:

```
SESSION_PREPARING
SESSION_READY
WAITING_FOR_CLI
CONNECTING_AGENT
AGENT_CONNECTED
PREPARING_SOURCE
UPLOADING
SNAPSHOT_UPLOADED
ANALYSIS_RUNNING
ANALYSIS_READY
FAILED / EXPIRED
```

Tidak wajib membuat enum baru dengan nama persis tersebut.

Gunakan existing state machine dan extend hanya jika diperlukan.

Namun semantic behavior harus sesuai.

### A. Session Preparing

Server sedang membuat sesi/prompt:

```
◌ Menyiapkan instruksi...
```

Loading dibenarkan karena request server benar-benar berjalan.

### B. Session Ready / Waiting for CLI

Prompt sudah ada, belum ada kontak dari CLI:

```
3. Pantau progres

   ○ Menunggu agent
     Jalankan prompt di AI coding agent
     untuk memulai sinkronisasi.

   ○ Menyiapkan source code
   ○ Mengunggah repository
   ○ Analisis AI
```

**Semua indikator pasif. Tidak ada spinner. Tidak ada timer.**

Status yang harus ditampilkan:

```
WAITING_FOR_CLI ≠ ACTIVE_CONNECTION
```

### C. Actual Connection Started

Hanya setelah backend benar-benar menerima aktivitas koneksi:

```
3. Pantau progres

   ◌ Menghubungkan agent...
   ○ Menyiapkan source code
   ○ Mengunggah repository
   ○ Analisis AI
```

Spinner ini wajib merepresentasikan event aktual.

### D. Agent Connected

```
3. Pantau progres

   ✓ Agent terhubung
   ◌ Menyiapkan source code...
   ○ Mengunggah repository
   ○ Analisis AI
```

### E. Upload Running

```
3. Pantau progres

   ✓ Agent terhubung
   ✓ Source code siap
   ◌ Mengunggah repository...
   ○ Analisis AI
```

### F. Upload Complete / Analysis Running

```
3. Pantau progres

   ✓ Agent terhubung
   ✓ Source code siap
   ✓ Sinkronisasi selesai
   ◌ Menganalisis repository...
```

### G. Analysis Complete

```
3. Pantau progres

   ✓ Agent terhubung
   ✓ Source code siap
   ✓ Sinkronisasi selesai
   ✓ Analisis selesai

   [Lanjut ke Kesimpulan]
```

## 5. STRICT REQUIREMENT: NO FAKE LOADING

Jangan menggunakan:

```
setTimeout(() => setStatus("connected"), 2000);
```

Jangan menggunakan fake progress seperti:

```
const fakeStages = [
  "Menghubungkan...",
  "Memeriksa source...",
  "Mengunggah...",
];
```

Jangan menjalankan animasi koneksi setelah user menekan tombol Salin.

**Copy clipboard bukan bukti proses sync dimulai.**

Jangan menganggap polling yang sedang berjalan sama dengan CLI yang sedang terhubung.

Polling adalah proses pemantauan internal, bukan bukti bahwa tahap sinkronisasi aktif.

## 6. REAL CONNECTING EVENT INVESTIGATION

Investigasi apakah current CLI/backend benar-benar menyediakan event:

```
agent_connection_started
```

atau event serupa yang terjadi sebelum koneksi berhasil.

Jika belum ada, periksa arsitektur:

```
CLI sends connection request
          │
          ▼
Server receives request
          │
          ▼
Connection attempt begins
          │
          ▼
Authentication / handshake completed
          │
          ▼
Agent connected
```

Apabila backend memang dapat mengobservasi state koneksi yang berbeda secara akurat, implementasikan event ringan yang persisted/scoped sesuai arsitektur existing.

Namun:

- Jangan mengarang event yang tidak pernah terjadi.
- Jangan merekam `connecting` hanya karena browser mulai polling.
- Jangan mengubah status menjadi `connecting` hanya karena prompt disalin.
- Jangan menambahkan waktu tunggu buatan.
- Jangan mengubah CLI protocol secara tidak kompatibel tanpa kebutuhan.
- Jangan memaksa pengguna republish CLI jika perubahan murni frontend/backend sudah cukup.

Jika handshake memang berlangsung terlalu cepat untuk menampilkan spinner secara nyata, langsung tampilkan `Agent terhubung`.

**Keakuratan lebih penting daripada spinner yang sengaja dipertontonkan.**

## 7. EVENT &amp; STATUS CONSISTENCY

Audit:

- `waiting_for_cli`
- `connected`
- `scanning`
- `filtering`
- `uploading`
- `uploaded`
- `analyzing`
- `ready`
- `failed`
- `expired`

Pastikan status UI berasal dari server observation yang benar.

Event harus scoped ke:

```
codebaseId
syncSessionId
eventId / sequence
timestamp
stage
status
```

Jika event stream putus, UI harus reconcile status persisted tanpa mengulang tahap secara palsu.

Saat refresh:

- Session waiting tetap waiting.
- Session uploading tetap uploading.
- Session ready tetap ready.
- Session failed tidak kembali tampil loading.
- Old session event tidak boleh masuk ke new session.

## 10. DEFINITION OF DONE

Task selesai ketika:

- Prompt ready tidak menyebabkan spinner sync langsung berjalan.
- `waiting_for_cli` benar-benar tampil idle.
- Spinner hanya aktif ketika proses benar-benar terjadi.
- Agent connected berubah menjadi checkmark berdasarkan bukti nyata.
- Tidak ada loading palsu atau timer buatan.
- Seluruh lifecycle dan refresh behavior konsisten.
- Existing components direuse.
- Tests membuktikan seluruh state.

Laporan akhir wajib mencantumkan:

1. Root cause.
2. State mapping sebelum dan sesudah.
3. Event aktual yang digunakan.
4. Apakah CLI perlu perubahan atau tidak, beserta alasannya.
5. Komponen yang direuse.
6. File yang berubah.
7. Automated test results.

Jangan menganggap task selesai hanya karena spinner waiting disembunyikan tanpa mengaudit transisi sesungguhnya.

Jangan commit, push, publish, atau merge tanpa izin user.
