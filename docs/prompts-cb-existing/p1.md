## 1. Mission

Perbaiki dua masalah pada initial sync VibePlan Existing Codebase:

1. Ketika AI coding agent menjalankan CLI, tahap "Agent terhubung" sering langsung berubah menjadi checkmark tanpa pernah terlihat sedang menghubungkan.
2. Setelah source code berhasil diunggah, kotak prompt CLI berubah menjadi pesan "Source code berhasil diterima.", padahal user tidak pernah meminta perubahan isi kotak prompt setelah sync.

Kedua masalah harus diperbaiki **tanpa fake loading, delay buatan, perubahan layout onboarding, atau penambahan teks tidak perlu**.

Jangan memaksa spinner muncul sebelum user benar-benar menjalankan CLI.

## 4. Investigate Handshake Observability

Periksa bagaimana CLI dan server berkomunikasi ketika agent pertama kali menyambung.

Kemungkinan saat ini:

```
CLI requests handshake
         │
         ▼
Server authenticates
         │
         ▼
Server persists connected
         │
         ▼
Frontend sees connected
```

Jika tidak ada event sebelum `connected`, frontend memang tidak mempunyai informasi untuk menampilkan fase `connecting` secara akurat.

Tugas:

1. Identifikasi titik awal handshake yang benar-benar observable.
2. Periksa existing persisted event timeline dan streaming.
3. Tentukan apakah `connecting` dapat direpresentasikan oleh event nyata sebelum `connected`.
4. Jika arsitektur mendukungnya, implementasikan event dengan identitas sesi dan urutan yang jelas.
5. Jika diperlukan perubahan CLI, evaluasi kompatibilitas protocol dan kebutuhan release.
6. Jangan mengubah CLI hanya untuk menciptakan visual loading palsu.
7. Jika handshake sangat cepat, tampilkan checkmark langsung; jangan sengaja menahan penyelesaiannya.

Contoh event konseptual:

```
session.waiting_for_cli
cli.handshake_started
agent.connected
source.preparing
source.prepared
upload.started
upload.completed
analysis.started
analysis.completed
```

Nama dan payload wajib mengikuti existing architecture.

**Jangan mengklaim event** `handshake_started` **sudah tersedia sebelum dibuktikan.**

## 5. Synchronization Source of Truth

Event harus diidentifikasi berdasarkan:

```
codebaseId
syncSessionId
eventId / sequence
stage
status
timestamp
```

Pastikan:

- Tidak ada event palsu dari frontend polling.
- Copy prompt tidak mengaktifkan spinner.
- Browser menunggu tidak dianggap CLI connecting.
- Duplicate event tidak menyebabkan dua transisi.
- Event lama tidak menimpa sesi baru.
- Out-of-order event tidak mengembalikan status ke belakang.
- Reconnect SSE memulihkan state aktual.
- Refresh menampilkan state terakhir yang disimpan backend.
- Status terminal menghentikan spinner.
- Perubahan snapshot/attempt tidak mencampur timeline.

Gunakan transport/event infrastructure existing. Jangan membangun sistem realtime baru kalau yang ada sudah memadai.

## 6. Problem B — Prompt Replaced After Successful Sync

Confirmed source:

```
src/features/codebase/components/workspace/screen-connect-prompt-step.tsx
```

Current component memiliki conditional rendering:

```
promptUsable
    → actual CLI prompt

transportComplete
    → "Source code berhasil diterima."

cliActive
    → "Agent sedang menyinkronkan repository."
```

Akibatnya, isi kotak prompt berubah menjadi pesan status.

**User secara eksplisit meminta supaya kotak prompt tidak berubah menjadi informasi status setelah agent connected atau upload selesai.**

### Required UI

Before:

```
1. Salin instruksi untuk AI agent

┌──────────────────────────────────────┐
│ Real CLI prompt                      │
│ ...                                  │
│ ...                                  │
└──────────────────────────────────────┘
```

During upload:

```
1. Salin instruksi untuk AI agent

┌──────────────────────────────────────┐
│ Real CLI prompt                      │
│ ...                                  │
│ ...                                  │
└──────────────────────────────────────┘
```

After upload:

```
1. Salin instruksi untuk AI agent

┌──────────────────────────────────────┐
│ Real CLI prompt                      │
│ ...                                  │
│ ...                                  │
└──────────────────────────────────────┘

3. Pantau progres

✓ Agent terhubung
✓ Source code siap
✓ Sinkronisasi selesai
◌ Menganalisis repository...
```

### Strict Requirements

- Jangan mengganti prompt dengan "Source code berhasil diterima."
- Jangan menggantinya dengan "Agent sedang menyinkronkan repository."
- Jangan menggantinya dengan success card lain.
- Status progress hanya ditampilkan pada bagian Pantau Progres.
- Jangan menambahkan duplikasi informasi.
- Jangan menghapus prompt dari current active view hanya karena transport selesai.
- Jangan mereset scroll, layout, atau ukuran prompt container saat status berubah.
- Jangan melakukan re-fetch credential hanya untuk mempertahankan tampilan.

### Security Boundary

Pertahankan one-time token security.

Jika current view masih mempunyai prompt secara sah dalam client memory, konten boleh tetap terlihat sebagaimana sebelumnya sampai lifecycle layar selesai.

Jika token benar-benar kedaluwarsa atau sudah tidak tersedia setelah full reload, jangan memalsukan prompt lama atau membuka akses credential server. Ikuti mekanisme recovery aman yang sudah ada.

Jika token expired dan tindakan copy tidak lagi valid, cegah penggunaan credential tidak valid tanpa mengganti seluruh prompt dengan pesan kesuksesan generik.

Jangan menyimpan token mentah dalam localStorage atau sessionStorage.

## 8. Automated Regression Tests

Wajib membuktikan:

1. `waiting_for_cli` tidak memiliki spinner.
2. Copy prompt tidak mengubah waiting state.
3. Handshake event nyata menghasilkan connecting state jika observable.
4. Connected event menghasilkan checkmark.
5. Fast handshake tidak diberi artificial delay.
6. Source preparation hanya aktif saat proses nyata.
7. Upload dan analysis menggunakan state masing-masing.
8. Status terminal menghentikan loading.
9. Duplicate/out-of-order event tidak merusak urutan.
10. SSE reconnect memulihkan state server.
11. Refresh tidak membuat progress mundur.
12. Original prompt tetap terlihat setelah connected.
13. Original prompt tetap terlihat setelah uploaded jika masih tersedia secara sah.
14. Teks "Source code berhasil diterima." tidak menggantikan prompt.
15. Tidak ada token disclosure atau unsafe persistence.
16. Existing credit policy, new-sync idempotency, dan analysis pipeline tidak rusak.

Jalankan unit tests, server integration tests, non-browser component tests, typecheck, lint, dan build.

**JANGAN menjalankan browser QA, Playwright, Puppeteer, manual browser testing, atau screenshot QA.**

## 9. Definition of Done

Task selesai hanya jika:

- Status menunggu pasif.
- Loading koneksi berasal dari sinyal proses nyata.
- Checkmark hanya muncul ketika connected benar-benar terkonfirmasi.
- Tidak ada fake delay.
- Prompt CLI tidak berubah menjadi success text setelah sync.
- Progress menampilkan semua status yang diperlukan tanpa redundansi.
- Existing components tetap dipakai.
- Regression tests pass.

Laporan akhir harus memuat root cause, sumber event, perubahan mapping, perubahan prompt lifecycle, CLI compatibility, file yang diubah, dan hasil tes.

Jangan commit, push, atau merge tanpa izin.
