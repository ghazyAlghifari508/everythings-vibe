## 4. Fix the Contract Mismatch

Periksa format berikut:

```
Legacy:
options: [
  "Judul proyek saja",
  "Judul dan deskripsi"
]

New:
options: [
  {
    label: "Judul proyek saja",
    description: "Pencarian hanya mencocokkan nama proyek."
  },
  {
    label: "Judul dan deskripsi",
    description: "Pencarian mencocokkan nama dan ringkasan proyek."
  }
]
```

Keduanya tidak boleh diperlakukan sebagai objek tanpa normalisasi.

Gunakan satu canonical normalization boundary yang jelas dan tervalidasi.

Pastikan:

- `label` tidak pernah diasumsikan tersedia pada unknown input.
- `description` tervalidasi sesuai kebutuhan mode Existing Codebase.
- ID opsi tidak berubah ketika rekomendasi dipindahkan secara visual.
- `recommended` menunjuk opsi yang tepat.
- Data legacy tetap dapat dipulihkan.
- Greenfield tidak dipaksa menggunakan kontrak baru secara tidak sengaja.
- Generation response dan persisted handoff menggunakan kontrak yang kompatibel.
- Panjang field sesuai batas schema database/handoff.

Jangan menyelesaikan masalah dengan:

```
opt?.label?.slice(...) ?? ""
```

atau fallback kosong semacam itu tanpa validasi.

Itu hanya bisa mengubah data rusak menjadi data kosong dan membuat bug lebih sulit ditemukan.

Jika input invalid, tangani dengan validation error yang terstruktur, atau gunakan normalisasi legacy jika memang input tersebut merupakan format yang sah.

## 6. Fix Persistence Failure Handling

Periksa mengapa `persistAskHandoffAndStep()` menangkap error penyimpanan lalu proses bisa berlanjut sampai artifact verification gagal.

Target:

- Persistence failure harus diketahui pemanggil yang bertanggung jawab.
- Artifact tidak boleh dianggap tersedia sebelum benar-benar tersimpan.
- Operation tidak boleh berstatus completed ketika artifact belum ada.
- Jangan menelan error penting hanya dengan `console.error`.
- Jangan membuat database row kosong sebagai bukti sukses palsu.
- Jangan melakukan manual database insert untuk memaksa test lolos.
- Jangan menandai stage questions berhasil jika handoff belum valid.

Pastikan transaction dan error propagation sesuai desain durable generation.

Jangan mengubah seluruh arsitektur worker jika masalah dapat diperbaiki secara lokal dan konsisten dengan desain existing.

## 7. Preserve High-Quality Question Behavior

Perbaikan tidak boleh mengorbankan fitur yang sebelumnya sudah diminta:

- Recommended option selalu ditampilkan pertama bila ada rekomendasi valid.
- Semua opsi baru Existing Codebase mempunyai heading dan description.
- Description menjelaskan konsekuensi nyata.
- Recommendation reason berada pada informasi opsi rekomendasi, bukan card terpisah.
- Tidak ada rekomendasi yang dipalsukan.
- Single-select dan multi-select tetap berbeda.
- Custom answer tetap berfungsi.
- Data jawaban lama tetap valid.

Jangan menurunkan kualitas generation menjadi opsi pendek tanpa description hanya agar schema lebih mudah dipenuhi.

- Jangan mengubah saldo atau status billing langsung di database.
