# PHASE 01 — Transparent Credit Policy &amp; Pre-Sync Eligibility for Existing Codebase

**COMPLEXITY: COMPLEX**  
**PRIORITY: P0 — Billing Integrity &amp; Onboarding Trust**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
Target branch: `feature/vibeplan-existing-codebase`

## 1. Mission

Perbaiki kebijakan penggunaan kredit pada fitur VibePlan Existing Codebase agar user mengetahui eligibility dan biaya analisis AI **sebelum menjalankan CLI dan mengunggah repository**.

Masalah saat ini: CLI berhasil mengunggah source code, tetapi analisis AI ditolak karena kredit tidak cukup. User baru mengetahui adanya persyaratan kredit setelah melewati proses sync.

Ini menciptakan pengalaman onboarding yang menyesatkan.

Implementasikan credit preflight dan kebijakan first-analysis allowance yang aman, transparan, serta terintegrasi dengan sistem billing existing.

**Jangan menghapus sistem kredit secara membabi buta, jangan menagih diam-diam, dan jangan membuat sistem billing kedua.**

### Existing Code Concern

`analysis-route-credits.server.ts` memeriksa:

```
availableCredits < quote.maximumCredits
```

Sementara operasi `codebase_analysis` sudah memakai adaptive credit quote.

Audit apakah:

- Retry setelah gagal menagih lagi.
- Reuse analysis tersimpan dikenai biaya.
- Preflight menggunakan quote yang sama dengan execution.

Jangan berasumsi kredit AI coding harness sama dengan kredit VibeEverything.

## 3. Product Policy to Implement

Gunakan aturan produk berikut sebagai target:

### A. First Analysis Allowance

Berikan satu jatah analisis awal gratis bagi repository baru yang memenuhi eligibility pada akun user.

Eligibility harus diverifikasi secara server-side.

Persyaratan:

- Alokasi gratis dibatasi oleh policy terpusat.
- Tidak unlimited.
- Tidak bergantung pada nama repository yang bisa diganti.
- Tidak bisa diperoleh berulang dengan refresh atau duplicate request.
- Failed attempt karena gangguan sistem tidak otomatis menghabiskan jatah berhasil.
- Penggunaan allowance dicatat secara idempotent.
- Ukuran repository dan resource limits tetap diperiksa.
- Data repository existing yang sudah dianalisis tidak kehilangan statusnya.

Definisikan aturan yang jelas untuk repository yang sudah tersinkron tetapi analisis awalnya belum pernah berhasil.

Gunakan existing entitlement/billing infrastructure jika mendukungnya. Jangan memperkenalkan counter paralel tanpa kebutuhan.

### B. Subsequent Analysis

Untuk analisis ulang atau repository yang tidak eligible gratis:

- Hitung quote sesuai kebijakan billing.
- Periksa saldo aktual.
- Tampilkan kebutuhan kredit sebelum operasi berbayar dijalankan.
- Gunakan persetujuan user atas biaya atau batas maksimum yang relevan.
- Jangan menagih ulang hanya karena membuka ulang hasil analisis yang sudah tersimpan.
- Jangan menagih dua kali untuk retry dari operasi yang sama.

### C. Pre-Sync Eligibility

Sebelum menghasilkan instruksi CLI:

1. Periksa sesi user.
2. Periksa entitlement/allowance.
3. Tampilkan apakah analisis awal gratis atau memerlukan kredit.
4. Jika kredit tidak mencukupi dan tidak eligible gratis, jangan memberi kesan onboarding bisa selesai seperti biasa.
5. Sediakan tindakan yang relevan untuk melanjutkan.

Periksa biaya secara authoritative sebelum analisis dimulai.

Jika exact quote membutuhkan manifest/file count yang baru diketahui setelah CLI memindai repository, jangan mengarang estimasi presisi. Tampilkan batas dan aturan biaya di depan, lalu lakukan final quote setelah data tersedia dan sebelum mengenakan biaya.

## 5. Technical Requirements

### A. Single Source of Truth

Credit eligibility, quote, reservation, settlement, dan release harus memakai domain service yang konsisten.

Frontend tidak boleh memutuskan gratis/berbayar hanya dari boolean lokal.

Backend wajib memverifikasi eligibility lagi pada execution boundary untuk mencegah TOCTOU/race condition.

### B. Idempotency &amp; Accounting

- Repeated preflight tidak menagih kredit.
- Repeated trigger dengan operation identity yang sama tidak membuat tagihan tambahan.
- Successful ready analysis dapat digunakan ulang.
- Failed provider call mengikuti refund/release policy yang benar.
- Credit reservation tidak menggantung akibat timeout.
- Concurrent requests tidak dapat memakai free allowance yang sama berkali-kali.
- User tidak mendapat allowance baru hanya dengan Rename.
- Pembuatan repository duplikat tidak boleh menjadi cara trivially bypass policy.

### C. Honest Error States

Bedakan:

```
FREE_ALLOWANCE_AVAILABLE
CREDIT_REQUIRED
INSUFFICIENT_CREDITS
SUBSCRIPTION_PAUSED
ANALYSIS_IN_PROGRESS
ANALYSIS_FAILED
```

Gunakan existing error conventions bila tersedia.

Jika analisis belum berjalan karena kredit kurang, jangan labeli sebagai model generation failure.

### D. Legacy Data

Jangan menghapus credit ledger lama.

Dokumentasikan apakah existing repository yang belum berhasil dianalisis memenuhi free initial allowance.

Jika migrasi diperlukan, buat migrasi aman dan idempotent.

Jangan mengubah historical charges secara diam-diam.

## 7. Required Tests

Tambahkan regression tests untuk:

1. Eligible new repository mendapat first-analysis allowance.
2. Repeated request tidak mendapatkan allowance ganda.
3. Free allowance tidak habis pada kegagalan sebelum operasi berhasil.
4. Paid analysis meminta credit eligibility yang benar.
5. Insufficient credit terdeteksi sebelum onboarding mahal dimulai.
6. Exact/final quote tidak melebihi consent yang diberikan.
7. Reused ready analysis tidak dikenai biaya.
8. Failed attempt mengikuti release/refund policy.
9. Concurrent requests tidak double-charge.
10. Cross-user entitlement isolation.
11. Legacy subscriptions tetap kompatibel.
12. Existing Greenfield billing tidak mengalami regresi.

Jalankan unit tests, integration tests non-browser, typecheck, lint, dan build sesuai scripts project.

**JANGAN menjalankan browser QA, Playwright, Puppeteer, browser automation, manual browser verification, maupun screenshot testing.**

## 8. Completion

Jangan mengklaim berhasil hanya karena credit guard dimatikan.

Laporkan:

- Policy sebelum dan sesudah.
- Perhitungan dan eligibility gratis.
- Cara mencegah abuse.
- Perubahan database/API/UI.
- Hasil test billing/idempotency.
- Konsekuensi untuk legacy repositories.

**Definition of Done:** user mengetahui kebutuhan kredit sebelum menjalankan CLI, analisis awal gratis tersedia secara terbatas sesuai eligibility, dan tidak ada double charge atau biaya tersembunyi.
