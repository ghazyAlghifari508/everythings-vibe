## 1. MISSION — NON-NEGOTIABLE PRODUCT BEHAVIOR

Perbaiki workflow sinkronisasi Existing Codebase agar user yang memiliki kredit cukup **langsung mendapatkan prompt CLI yang siap disalin**, tanpa persetujuan tambahan apa pun.

**INI REQUIREMENT UTAMA. JANGAN DIINTERPRETASIKAN ULANG.**

Ketika user memilih "Hubungkan Repository":

1. Server memverifikasi sesi user dan eligibility secara otomatis.
2. Jika kredit cukup atau user memang billing-exempt, sistem langsung membuat sesi sinkronisasi yang valid.
3. Setelah respons server berhasil, instruksi CLI langsung ditampilkan.
4. User bisa langsung menekan "Salin".
5. Tidak ada tombol persiapan, modal persetujuan, checkbox, atau langkah tambahan.
6. Jika kredit tidak cukup, prompt terkunci dan user diberi opsi menambah kredit.

**Tidak boleh ada approval berulang, walaupun sistem menyebutnya "persetujuan sekali", "tarif diperbarui", "pre-authorization", atau nama lain.**

### Confirmed Existing Issue

`analysis-credit-policy.ts` saat ini membedakan saldo cukup dengan `approvedMaximum`.

Secara konseptual:

```
approved =
  (approvedMaximum ?? -1) >= maximumCredits

canStart =
  FREE_ALLOWANCE_AVAILABLE ||
  (CREDIT_REQUIRED && approved)
```

Sehingga saldo cukup masih dapat menghasilkan `canStart: false`.

`locked-prompt-state.tsx` kemudian menampilkan variant `"approval"`.

Jangan cuma menyembunyikan teks approval di frontend.

## 6. BILLING CONTRACT

Requirement "tanpa approval per sync" **bukan** izin menarik kredit secara tersembunyi.

Implementasikan kebijakan produk berikut:

- Penggunaan kredit dan tarif diinformasikan pada Pricing/Billing serta pada titik aktivasi penggunaan kredit yang sesuai.
- Kebijakan atau spending limit diatur sebagai bagian dari account billing, bukan modal setiap kali user sync.
- Untuk operasi dalam otorisasi penggunaan kredit yang sudah berlaku, tidak perlu approval tambahan.
- Jika ketentuan billing berubah material dan membutuhkan persetujuan baru, tangani di billing settings/account flow, bukan dengan memblokir prompt memakai pesan "Tarif analisis diperbarui".
- Jangan diam-diam menaikkan batas biaya.
- Jangan otomatis menerima kebijakan baru atas nama user.
- Jangan menagih hanya karena halaman sync dibuka atau session credential diterbitkan.
- Kredit tetap dipotong hanya menurut lifecycle operasi analisis yang sah.
- Jangan membuat subscription baru secara diam-diam.
- Jangan mengubah first-analysis allowance menjadi unlimited.

User dengan kredit cukup dan otorisasi billing akun yang berlaku harus langsung memperoleh prompt.

## 7. SERVER-SIDE REFACTOR

Audit dan rapikan kontrak preflight.

Seharusnya tiga kondisi utama dapat dibedakan:

```
ELIGIBLE
INSUFFICIENT_CREDITS
BILLING_UNAVAILABLE
```

Dan internal exemption/first-analysis allowance ditangani dalam eligibility.

Jika enum lain sudah dipakai luas, lakukan transisi secara kompatibel.

Eliminasi `requiresApproval` sebagai gate rutin sync.

Pastikan:

- `canStart` tidak false hanya karena metadata persetujuan dari sync session lama tidak ditemukan.
- Tidak ada dependency pada last sync session untuk membuktikan "pernah menekan tombol setujui".
- Frontend tidak mengirim persetujuan palsu agar backend menerima request.
- API create/retry session konsisten dengan credit preflight.
- AI analysis endpoint tidak kembali memblokir user eligible karena memakai policy berbeda.
- Backend tetap memverifikasi saldo, entitlement, dan batas biaya.
- No double charge.
- No duplicate session.
- No bypass melalui forged client state.
- No cross-user credit usage.

## 8. AUTO SESSION PREPARATION

Pada user yang eligible:

```
route entry / explicit connect intent
         │
         ▼
eligibility response
         │
         ▼
one idempotent session creation
         │
         ▼
valid prompt payload
         │
         ▼
render prompt + copy action
```

Implementasikan guard terhadap Strict Mode rerenders, repeated effects, refresh, double requests, dan response races.

Jangan membuat sesi baru berkali-kali setiap kali React component remount.

Jika perlu request pending state, tampilkan indikator singkat yang merepresentasikan request server aktual. Jangan memberi tombol tambahan untuk melanjutkan.

Jangan otomatis memanggil model AI sebelum source code tersinkron.

## 11. DEFINITION OF DONE

User yang memiliki kredit cukup dapat membuka Hubungkan Repository dan langsung memperoleh CLI prompt yang siap disalin tanpa melakukan tindakan tambahan.

User dengan kredit kurang hanya melihat locked prompt dan top-up CTA.

Tidak ada approval gate tersisa di frontend maupun backend untuk routine sync.

Credit accounting tetap benar, aman, transparan, dan sesuai policy akun.

Laporan akhir wajib menjelaskan perubahan eligibility contract, removed approval paths, session creation idempotency, komponen yang direuse, serta hasil tests.

Jangan mengklaim selesai jika tombol "Setujui" hanya disembunyikan tetapi backend masih menolaknya.
