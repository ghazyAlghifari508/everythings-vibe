# FIX 01 — Repository Identity &amp; Persistent Naming

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`

## Objective

Perbaiki sistem identitas dan penamaan repository pada fitur VibePlan Existing Codebase. Repository yang berhasil disinkronkan melalui CLI harus menggunakan nama repository sebenarnya, bukan nama generik atau placeholder `"Repository Lokal"`.

Perbaikan harus dilakukan dari sumber datanya: CLI → handshake → database → API → History → Workspace.

### Bug yang dilaporkan

User menyinkronkan repository Ocean Guard. Snapshot berhasil diterima, analisis AI mengenali aplikasi Ocean Guard, dan file explorer berisi source code yang benar.

Namun nama yang muncul di History maupun workspace tetap `"Repository Lokal"`.

Bug ini pernah diperbaiki sebelumnya tetapi masih berulang. Jangan menyelesaikannya dengan mengganti placeholder menjadi nama fallback lain.

### Target visual


Nama tampilan dapat diformat secara manusiawi, tetapi harus berasal dari identitas repository yang benar-benar terdeteksi, bukan nama karangan AI.

Baca [`AGENTS.md`](http://AGENTS.md) dan aturan repository sebelum coding.

Investigasi minimal:

- Drizzle schema, migrasi, serta endpoint Rename.

Temuan yang perlu diperiksa secara khusus:

1. `PROVISIONAL_CODEBASE_NAME = "Repository Lokal"`.
2. Perbedaan `nameSource: "auto"` dan `"user"`.
3. Kondisi auto-rename yang hanya mengubah nama ketika `nameSource === "auto"`.
4. Kemungkinan data legacy memiliki placeholder dengan provenance yang tidak tepat.
5. Apakah CLI benar-benar mengirim `repositoryName`.
6. Apakah rename berhasil di database tetapi UI masih memakai loader/cache lama.

Jangan menyimpulkan penyebab sebelum memverifikasi masing-masing jalur.

## Requirements

**A. Repository Name Resolution**

Gunakan urutan prioritas yang jelas:

1. Nama yang sengaja ditentukan user melalui Rename.
2. Nama repository yang dapat diverifikasi dari metadata Git/CLI.
3. Nama root folder repository yang valid apabila identitas Git tidak menyediakan nama yang lebih tepat.

Jangan memakai feature title, prompt user, atau judul analisis AI sebagai nama repository.

Nama repository dan nama feature plan adalah dua identitas yang berbeda.

**B. Persistence &amp; Provenance**

- Pastikan repository name yang terdeteksi tersimpan secara persisten.
- Pastikan provenance tersimpan dengan benar.
- Perbaiki kondisi yang membuat placeholder bertahan setelah handshake sukses.
- Tangani repository legacy secara aman.
- Jangan menimpa nama custom milik user.
- Jangan melakukan backfill dengan nama yang tidak memiliki bukti identitas.
- Jangan menggunakan fallback generik sebagai pengganti kegagalan resolusi.

**C. UI Consistency**

Satu canonical repository name harus dipakai oleh:

- History / Project Tersimpan.
- Header workspace.
- Repository selector.
- Sync ulang.
- Ringkasan repository.
- Handoff metadata yang membutuhkan repository name.

Setelah sync berhasil, nama harus diperbarui tanpa user perlu melakukan refresh manual.

Ketika identitas benar-benar belum tersedia, tampilkan status belum teridentifikasi secara jujur. Jangan menyamarkannya sebagai nama repository.

**D. Security**

- Jangan menyimpan atau menampilkan credential dari Git remote URL.
- Jangan menggunakan absolute path lokal sebagai display name.
- Pastikan nama aman untuk dirender.
- Jangan menggabungkan dua repository hanya karena namanya sama.

## Verification

Tambahkan regression tests untuk auto naming, explicit rename, legacy placeholder, re-sync, dan sinkronisasi nama di API.

Jalankan unit/integration tests non-browser, typecheck, lint, serta build relevan.

Tidak perlu browser QA, Playwright, Puppeteer, screenshot testing, atau manual browser testing.
