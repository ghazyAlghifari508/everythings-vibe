## 1. Mission

Perbaiki bug critical di pertanyaan klarifikasi Existing Codebase.

Ketika AI selesai menghasilkan pertanyaan dan user mencoba memilih salah satu opsi jawaban:

1. Radio button terlihat terpilih.
2. Dalam waktu sangat singkat, radio button kembali kosong.
3. User tidak bisa mempertahankan pilihannya.
4. Tombol `Konfirmasi` tetap disabled.
5. User terjebak dan tidak bisa melanjutkan planning.

**This is a state-management bug, not merely a visual issue.**

Do not solve it with CSS, fake selected states, delayed event handlers, or disabling parent rerenders.

Current:

Current selection hook contains logic similar to:

```
const initialSelections = useMemo(() => {
  // Derive from submitted answer and question.options
}, [submitted, question.type, question.options, customId]);

const [selectedOptionId, setSelectedOptionId] = useState(
  initialSelections.selectedId,
);

useEffect(() => {
  setSelectedOptionId(initialSelections.selectedId);
  setMultiOptionIds(initialSelections.multiIds);
  setCustomText(initialSelections.custom);
}, [initialSelections]);
```

**This is a credible reset mechanism.**

If `question.options` gets recreated with a different array identity during parent rerenders, `initialSelections` can be recalculated even when the logical question has not changed.

The effect can then overwrite the user's local choice with the initial empty selection.

However, do not assume this is the only cause before checking the entire event/state lifecycle.

Use evidence from tests to identify the actual reset trigger.

## 5. Correct State Ownership

For an unanswered active question, **the user’s current selection must remain the source of truth until they confirm it**.

A server-provided initial answer is only an initialization/hydration input.

It must not continuously overwrite in-progress user interaction.

Conceptual state:

```
QUESTION LOADED
      │
      ▼
INITIAL ANSWER HYDRATED ONCE
      │
      ▼
USER CHOOSES OPTION
      │
      ▼
LOCAL DRAFT SELECTION UPDATED
      │
      ▼
PARENT RERENDER
      │
      ▼
SELECTION PRESERVED
      │
      ▼
USER CLICKS CONFIRM
      │
      ▼
ANSWER SUBMITTED/PERSISTED
```

Only reinitialize intentionally when:

- [`question.id`](http://question.id) genuinely changes.
- User explicitly starts editing a different submitted question.
- A legitimate external answer revision requires reconciliation.
- An explicit reset operation occurs.

Use stable identity and controlled input design rather than relying on unstable object/array reference identity.

Do not use `JSON.stringify(question.options)` as an indiscriminate workaround.

Do not freeze the whole question object to hide the lifecycle issue.

## 7. Support All Question Types

Do not fix only single-select.

Preserve:

### Single-select

Only one option selected.

### Multi-select

Multiple selections persist independently.

### Custom Answer / Lainnya

Selecting `Lainnya` retains that state while the user types.

Custom text must not disappear after an unrelated rerender.

### Text Input

Draft text persists until submission or intentional reset.

### Editing Previously Answered Questions

When user intentionally edits an answer:

- Initialize from the persisted answer.
- Allow selection changes without automatic rollback.
- Cancel restores the previous confirmed answer.
- Confirm saves the updated answer through the existing pipeline.

Do not accidentally unlock finalized questions or already-completed task plans outside their current permissions.
