# FIX 05 — Unified Agent Thinking Experience &amp; Cardless Generation Workflow

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`

## Mission

Bangun pengalaman generation yang terasa seperti AI coding assistant profesional, bukan rangkaian form dan card status.

Perbaiki presentasi aktivitas AI untuk:

1. Generasi pertanyaan klarifikasi.
2. Feature Specification.
3. PRD.
4. Acceptance Criteria.
5. Task breakdown.

Gunakan satu pola Thinking/Activity UX yang konsisten, akurat, ringan, dan terintegrasi ke chat.

## Existing Problems

- Aktivitas AI dibungkus card dengan border/background.
- Judul langsung menampilkan "Menyusun pertanyaan" meskipun proses thinking belum memiliki fase yang jelas.
- Timer kadang terus berjalan setelah generasi selesai.
- Tahap berikutnya masih ditampilkan sebagai card "Berikutnya: ...".
- Tombol besar berubah menjadi "Menyusun spesifikasi..." sehingga terkesan sebagai loading block.
- Terlalu banyak komponen status yang menduplikasi informasi.
- Pengalaman menunggu request panjang tidak memberikan feedback yang baik.

## Visual Specification

```
Tambahkan pencarian artikel berdasarkan judul.

◉ Thinking...                     3.5s
  ▼ Aktivitas

  Menganalisis kebutuhan fitur...
  Menunggu hasil model...
```

### When verified generation phase is available

```
✓ Thinking                        3.5s
◌ Menyusun pertanyaan klarifikasi...
```

### After successful persistence

```
✓ Pertanyaan siap                8.2s

  Pertanyaan 1 dari 4
  Bagaimana perilaku pencarian...?
```

Tidak ada outer card besar yang membungkus aktivitas tersebut.

Gunakan label tahap yang benar-benar didukung oleh lifecycle backend. Teks di atas merupakan konsep visual, bukan izin untuk memalsukan event model.

### Feature → PRD → AC → Task

```
✓ Spesifikasi fitur selesai
  [feature.md]

Selanjutnya: PRD          [Buat PRD]

(User mengklik)

◉ Thinking...
◌ Menyusun PRD...

✓ PRD selesai
  [PRD.md]

Selanjutnya: AC           [Buat AC]
```

CTA harus kecil, jelas, dan conversational. Jangan menggunakan card besar sebagai container CTA atau progress.

## Mandatory Component-First Workflow

**Dilarang langsung membuat komponen Thinking custom dari nol.**

Lakukan component discovery:

1. Periksa ThoughtLine dan komponen activity/Thinking yang sudah ada.
2. Baca source komponen PRD revision greenfield yang dijadikan referensi.
3. Evaluasi [https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs) secara langsung.
4. Evaluasi Magic UI dan React Bits untuk transition/status animation.
5. Evaluasi shadcn untuk primitive controls seperti Collapsible/Button.
6. Evaluasi HeroUI bila ada kebutuhan interaksi yang belum ditangani.

Untuk animasi Thinking, prioritaskan penggunaan komponen `Orb` dari Thinking Orbs jika kompatibel dengan stack dan performance constraints.

Gunakan komponen siap pakai tersebut dalam implementasi aktual, bukan sekadar menyebutnya di laporan.

Custom implementation hanya untuk composition/adapter dan logic aplikasi yang tidak disediakan library.

Jangan memakai efek dekoratif yang mengganggu keterbacaan atau menyebabkan layout shift.

## Functional Requirements

### A. Reliable Lifecycle

Definisikan operation state minimal:

- Idle.
- Running.
- Completed.
- Failed.

Untuk phase Thinking vs Generating:

- Pisahkan hanya jika backend/provider mengirim sinyal yang benar-benar dapat diandalkan.
- Jika endpoint mengembalikan JSON tanpa fase yang terobservasi, tampilkan status request umum yang akurat.
- Jangan membuat timer buatan untuk mengasumsikan kapan Thinking selesai.
- Jangan menampilkan fake model reasoning.
- Jangan mengekspos private chain-of-thought model.
- Tampilkan aktivitas tingkat tinggi atau progress backend yang memang tersedia.

Jika perlu menambah status event backend, lakukan dengan kontrak typed dan backward-compatible.

### B. Timer Correctness

Timer harus:

- Dimulai dari timestamp operasi yang benar.
- Berjalan hanya selama operasi aktif.
- Berhenti segera setelah request benar-benar settle.
- Tidak melanjutkan hitungan ketika user sudah di tahap berikutnya.
- Tidak bertambah lagi setelah refresh ketika operasi telah selesai.
- Tidak bercampur antarproject/operasi.
- Menampilkan durasi final dari start dan finish timestamps.

Investigasi kenapa timer saat ini bisa tampak aktif setelah pertanyaan selesai.

Jangan hanya menyembunyikan timer tanpa memperbaiki state lifecycle.

### C. Thinking Details

Jika aktivitas/stream memang menyediakan detail yang aman ditampilkan:

- Gunakan expandable section.
- Default collapsed setelah selesai.
- Default tidak memenuhi ruang chat.
- Hindari panel bertingkat.
- Gunakan typographic hierarchy yang sederhana.

Jika tidak ada data detail, jangan tampilkan dropdown kosong atau contoh reasoning buatan.

### D. Remove Stage Handoff Cards

Refactor `CodebaseStageHandoff` dan related render branches agar:

- Tidak menggunakan large bordered cards.
- Tidak menduplikasi file artifact card.
- Hanya ada satu obvious next action.
- Busy feedback terpusat pada Thinking component.
- Completed stage tetap bisa dibaca.
- Failure memiliki retry yang relevan.
- File hasil baru muncul setelah server memverifikasi persistence.

### E. Long-Running UX

Request bisa berlangsung puluhan detik hingga beberapa menit.

Pastikan:

- User mengetahui operasi masih berlangsung.
- Animasi tidak berhenti palsu.
- Tidak ada runaway interval.
- Tidak ada duplicate generation akibat double click.
- Operation tetap terikat pada project yang benar.
- User tidak kehilangan draft yang sedang diketik.
- Error/timeout jelas dan dapat ditindaklanjuti.
- Reduced-motion preference didukung.

### F. Visual Constraints

Tidak boleh:

- Outer thinking card besar.
- Nested cards untuk tiap status.
- Gradient loading overlay.
- Skeleton untuk setiap paragraf.
- Fake token streaming.
- Artificial progress percentage.
- Badge status berlebihan.
- Block CTA yang berubah menjadi card spinner.
- Animasi orb berukuran besar yang mengganggu content.

Targetkan pola UI coding harness: compact, readable, progressive disclosure, dan transparan.

## Automated Tests

Tambahkan tests untuk:

- Running → Completed.
- Running → Failed.
- Finished timer frozen.
- Multiple sequential runs.
- Stage change.
- Project switch.
- SSE error/abort.
- Non-streaming question endpoint.
- No fake progress transition.
- No duplicate generation.
- Artifact only revealed after persistence.

Gunakan testing tools repo, tanpa browser QA/Playwright/Puppeteer/screenshot testing.

Jalankan typecheck, lint, dan build.

## Final Audit

Periksa apakah ada card loading legacy atau duplicate thinking implementation yang masih digunakan dalam Existing Codebase.

Jangan menghapus komponen shared jika masih diperlukan greenfield.

Buat atomic commits, push sesuai [`AGENTS.md`](http://AGENTS.md), lalu laporkan komponen yang dipakai, lifecycle yang diperbaiki, hasil tests, dan git status.

**Definition of Done:** semua tahap generasi memiliki Thinking UX yang konsisten, cardless, timer akurat, dan tidak memalsukan aktivitas AI.
