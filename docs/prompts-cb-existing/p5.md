# PHASE 05 — Kanban Preview Layout, Sticky Header &amp; Minimal Public UI

**Repository:** [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
**Target branch:** `feature/vibeplan-existing-codebase`

## Objective

Perbaiki tampilan Kanban preview dalam workspace tiga panel Existing Codebase.

Hilangkan header yang terlihat bertabrakan ketika scroll, rapikan view switcher Kanban/Checklist, dan bersihkan metadata teknis yang tidak perlu ditampilkan kepada user.

Jangan mengubah Kanban business logic, Task persistence, progress tracking, atau Full Kanban routing yang sudah berfungsi.

## Problems

1. Sticky mini-toolbar menempel pada header di atasnya sehingga terlihat seperti mengambang/bertabrakan.
2. Terlalu banyak lapisan toolbar.
3. Label "Papan Kanban" ditampilkan berulang.
4. Teks "KANBAN LIVE" dan "Live dari database" tidak memberikan informasi yang berguna saat koneksi normal.
5. Mode "Papan Kanban" dan "Checklist Tree" menggunakan teks yang terlalu panjang.
6. Panel kanan yang sempit membutuhkan layout action yang lebih efisien.

## Implementation Requirements

### A. Fix Sticky Architecture

- Pisahkan fixed toolbar dari scrolling content.
- Jangan membuat nested sticky header jika tidak diperlukan.
- Hindari negative margin hack untuk sticky offset.
- Jangan hanya meningkatkan z-index sebagai solusi.
- Toolbar tidak boleh bertabrakan atau tertutupi header.
- Pertahankan vertical scrolling natural.
- Pertahankan horizontal scrolling dan navigation arrows.
- Jangan memotong Task cards.
- Jangan membuat double scrollbar yang membingungkan.

Prefer layout:

```
Artifact Toolbar
View Switcher
Kanban Progress Toolbar
Scrollable Kanban Columns
```

Toolbar progress boleh tetap terlihat tanpa `position: sticky` jika ditempatkan di luar content scrolling area.

### B. View Switcher — Icon + Text

Gunakan dua label:

```
▦ Kanban
☷ Checklist
```

Jangan icon-only karena dua mode tidak selalu jelas bagi pengguna.

Gunakan accessible tab semantics, keyboard navigation, visible active state, dan consistent spacing.

Jangan membuat tabs baru dari nol jika sudah ada shadcn Tabs/ToggleGroup atau komponen sejenis.

### C. Remove Unhelpful Internal Copy

Audit dan hapus dari public UI bila tidak berguna:

- "KANBAN LIVE"
- "Live dari database"
- "Task tree dan papan Kanban live"
- Label teknis lain yang hanya menjelaskan implementasi internal.

Jangan menggantinya dengan placeholder lain.

User tidak perlu tahu bahwa Kanban menggunakan polling atau database selama semuanya berjalan normal.

**Tetap tampilkan error penting.**

Contoh:

```
Koneksi terputus.
[Coba lagi]
```

Itu relevan karena memengaruhi kepercayaan user pada status Task.

### D. Progress &amp; Navigation

- Gunakan satu progress summary.
- Jangan menampilkan hitungan yang sama di beberapa header dalam preview.
- Pertahankan status To Do, In Progress, Done.
- Pertahankan horizontal arrow navigation.
- Disable arrows saat tidak bisa scroll lebih jauh.
- Full Kanban tetap membuka URL Existing Codebase pada tab baru.
- Gunakan tombol/icon compact yang memiliki accessible labels.

Jika memakai icon-only external-link action, tambahkan tooltip "Buka Kanban Penuh".

### E. Visual Quality Rules

Target visual: professional coding workspace, minimal dan konsisten.

Tidak boleh:

- Floating sticky toolbar tanpa pembatas jelas.
- Nested cards untuk setiap navbar.
- Double headers.
- Decorative gradients.
- Status badges tanpa informasi penting.
- Tiny unreadable controls.
- Layout berbeda dari preview PRD/AC tanpa alasan.
- Border yang berlebihan.
- Copy generik yang ditulis hanya untuk memenuhi ruang.

## Automated Verification

Uji:

- Kanban dan Checklist tabs berubah sesuai state.
- Progress tetap sesuai task data.
- Horizontal scroll boundaries.
- Navigation buttons disabled/enabled.
- Full Kanban link tetap benar.
- Tidak ada duplicate progress label.
- Tidak ada "KANBAN LIVE" dan "Live dari database" saat normal.
- Disconnected/stale status tetap jelas.
- Existing task data tidak berubah akibat perbaikan UI.

Gunakan unit/component tests non-browser, typecheck, lint, dan build.

**Jangan browser QA, Playwright, Puppeteer, manual browser testing, atau screenshot testing.**

## Definition of Done

Kanban preview memiliki satu hierarki toolbar yang rapi, tidak ada overlap saat scroll, mode Kanban/Checklist mudah dipahami, dan UI tidak dipenuhi informasi teknis yang tidak diperlukan.
