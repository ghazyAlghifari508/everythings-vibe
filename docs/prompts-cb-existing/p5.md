No green status cards per step.

No fake progress percentage.

No hourglass icon.

No misleading success state.

## 5. Functional Requirements

### A. Consistent Indicators

Use:

- Pending: simple neutral indicator.
- Running: clean spinner.
- Completed: checkmark.
- Failed/blocked: appropriate error indicator.

Prefer existing spinner from the repository's design system.

Animation must support reduced-motion preferences.

Do not add oversized Thinking Orbs to a small sync status row.

### B. Real Status Only

Every status must correspond to actual persisted backend state.

Do not show:

```
AI analyzing architecture...
AI scanning dependencies...
AI checking routes...
```

unless the corresponding activity is actually observable from backend events.

### C. No Duplicate Feedback

Avoid showing:

```
Sync failed
```

when CLI upload succeeded but analysis failed.

Instead show:

```
Sync completed
Analysis incomplete
```

One primary recovery action per failure state.

### D. Action Gating

"Buka Workspace" becomes available only when authoritative planning readiness is satisfied.

If analysis is pending/failed/blocked, show its relevant action rather than a workspace CTA.

Reuse Phase 02 readiness contract.

### E. Clean Layout

- Compact rows.
- Consistent spacing.
- No nested cards.
- No extra "Tombol lanjut aktif setelah..." explanation.
- No large decorative loader.
- No raw status strings visible to user.
- No generic AI-written filler.
- Responsive and accessible.

Use one coherent visual system. Do not mix animation libraries merely for decoration.

## 7. Tests

Verify:

- Correct spinner for active state.
- Completed state shows checkmark.
- Failed analysis does not mark upload failed.
- Analysis pending remains visibly pending.
- Credit blocked displays correct recovery action.
- Buka Workspace not available prematurely.
- Ready state enables navigation.
- No duplicate status rows.
- Reduced-motion support.
- Existing sync/re-sync functionality preserved.

Run unit/component tests non-browser, typecheck, lint, build.

**NO browser QA, Playwright, Puppeteer, manual browser testing, or screenshot tests.**

## Definition of Done

Sync progress feels consistent and trustworthy. User can distinguish uploading source code from analyzing it, and never sees a false success indicator or misleading workspace action.
