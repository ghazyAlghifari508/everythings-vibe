## 3. CONFIRMED PROBLEMS

### A. Incorrect Selection Bar Placement

Current `codebase-library-view.tsx` merender:

```
HistorySelectAll
HistorySelectionBar
Repository List
LibraryPagination
```

Sementara VibeScrape merender:

```
HistorySelectAll
History List
HistorySelectionBar
Pagination
```

**Perbaiki urutan layout Existing Codebase.**

### B. Unwanted Filter-Wide Selection

Current `HistorySelectAll` mempunyai:

```
onSelectAllFiltered
```

Existing Codebase mengimplementasikannya dengan:

```
selection.applyFiltered({
  ids: filtered.map((item) => item.id),
  total: filtered.length,
  truncated: false,
});
```

Ini memungkinkan selection melampaui halaman saat ini.

Requirement user: **Select All hanya berlaku untuk item yang sedang tampil pada halaman pagination aktif.**

### C. Unwanted Minus Checkbox

Current shared component mengatur:

```
checkboxRef.current.indeterminate = isPartiallySelected;
```

User tidak menginginkan mixed visual.

Expected:

```
0 dari 10 terpilih   -> [ ]
3 dari 10 terpilih   -> [ ]
10 dari 10 terpilih  -> [✓]
```

Jangan tetap menggunakan mixed icon lalu hanya mengubah warna atau tooltip.

## 6. PAGE-SCOPED SELECT ALL — STRICT REQUIREMENTS

Misalkan terdapat:

```
Total repository: 45
Items per page: 10

Page 1: Repository 1–10
Page 2: Repository 11–20
Page 3: Repository 21–30
Page 4: Repository 31–40
Page 5: Repository 41–45
```

Saat user berada di page 1 dan memilih:

```
[✓] Pilih semua di halaman ini
```

Maka yang terpilih HANYA:

```
Repository 1–10
```

TIDAK BOLEH memilih:

```
Repository 11–45
```

Ketika user klik Hapus Terpilih:

```
Delete target IDs = selected page 1 IDs
```

Repository halaman lain harus tetap aman.

### Implementation Requirements

- Derive selected page IDs from actual paginated items.
- Gunakan `pageIds`, bukan seluruh `filtered` collection.
- `Select All` memanggil `setPageSelection(pageIds, selected)`.
- Jangan menyediakan `Select All Filtered` pada Existing Codebase.
- Jangan memanggil `selection.applyFiltered()` dari UI Existing Codebase.
- Jangan menginterpretasikan "Select All" sebagai seluruh History.
- Jangan mengirim ID yang tidak dipilih secara eksplisit oleh user.

### Navigation Safety

Untuk Existing Codebase, ikuti perilaku page-scoped yang konsisten:

- Ketika user berpindah pagination, selection halaman sebelumnya dibersihkan.
- Ketika filter/search berubah, selection dibersihkan agar target deletion tidak ambigu.
- Ketika item terakhir di-deselect, selection mode kembali ke normal.
- Jangan diam-diam mempertahankan selected IDs yang tidak terlihat untuk operasi delete berikutnya.

Jika state controller existing mendukung selection lintas halaman untuk Scrape, **jangan menghapus kemampuan tersebut dari shared hook secara global**.

Terapkan perilaku page-scoped khusus untuk Existing Codebase melalui konfigurasi atau composition yang aman.

## 7. BINARY SELECT-ALL CHECKBOX

Checkbox harus memiliki dua visual state:

```
NONE / PARTIAL SELECTED
[ ] Pilih semua di halaman ini

ALL ITEMS ON PAGE SELECTED
[✓] Semua repository di halaman ini dipilih
```

Tidak boleh:

```
[−] Pilih semua di halaman ini
```

### Implementation Requirements

- `checked = selectedOnPage === pageIds.length` untuk halaman nonkosong.
- Jika `selectedOnPage` berada di antara 1 dan jumlah item, checkbox tetap unchecked.
- Jangan set `indeterminate = true` untuk variant Existing Codebase.
- Jangan set `aria-checked="mixed"` pada variant binary ini.
- Pertahankan accessible label dan keyboard interaction.
- Jika user mengklik unchecked Select All saat sebagian item terpilih, pilih seluruh page IDs.
- Jika user mengklik checked Select All, batalkan pilihan seluruh page IDs.

Jika `HistorySelectAll` shared dipakai Scrape dan Scrape tetap memerlukan indeterminate, gunakan prop/variant yang eksplisit untuk membedakan mode.

**Jangan mengubah shared behavior secara global sehingga UI Scrape rusak.**

## 8. BULK DELETE SEMANTICS

Bulk delete hanya boleh menerima IDs yang terpilih pada current page.

Expected:

```
Page 1: 10 items
User selected: 4 items

[Hapus Terpilih]

Confirmation:
  Hapus 4 repository?

Payload:
  ids = [4 selected IDs]
```

Server:

- Validate ownership.
- Validate IDs.
- Delete exactly selected records.
- Keep unaffected repositories.
- Preserve existing cascade rules.
- Avoid duplicate requests.
- Return actual deleted IDs and counts.

Frontend:

- Do not remove unconfirmed rows.
- Clear selection after successful deletion.
- Update count and pagination.
- Display one concise success feedback.
- Handle stale/missing IDs accurately.

**Jangan mengubah backend bulk-delete service jika behavior existing sudah benar.**

### Important Distinction

"Hapus Terpilih" setelah page Select All ≠ "Hapus Seluruh History".

Jika memang ada fitur dedicated Hapus Seluruh History dari requirement sebelumnya, itu harus berupa tindakan terpisah dengan konfirmasi eksplisit. Jangan mengaitkannya secara otomatis dengan checkbox Select All.
