# P08 — Replace Kanban Live Badge with Actionable Task Progress

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** MEDIUM  
**Dependency:** P07 completed.

## Problems

Existing workspace header displays:

`Kanban Live: 1/12 Selesai (8%)`

This looks like a status badge but does not clearly communicate that users can open task progress from it.

A persistent warning banner also appears:

`Repository sudah disinkronkan ulang setelah planning ini dibuat. Planning lama tetap tersimpan — tinjau apakah masih sesuai.`

The banner occupies a large horizontal area and visually interrupts the workspace.

## Objective

1. Remove the persistent post-resync banner from the main workspace header.
2. Replace `Kanban Live` with `Progress task`.
3. Make the progress indicator interactive.
4. Clicking it must open the exact same side-panel Task Kanban used by generated Task artifacts.
5. Do not create a separate Kanban view or independent state source.

Use the same state transitions that occur when the user opens the generated Task artifact:

- Correct active artifact ID.
- Correct selected canvas view.
- Correct open state.
- Correct feature/project identity.

If the user has not generated tasks, show an honest unavailable state or omit the control according to existing workspace behavior. Do not open an empty panel under the false pretense that tasks exist.

## Copywriting

Replace:

`Kanban Live: 1/12 Selesai (8%)`

with:

`Progress task · 1/12 selesai`

The `Live` word is not needed.

The count must reflect real task progress. Do not display a fake real-time indicator.

If data is stale or disconnected, preserve the appropriate honest status within the opened Kanban.

## Remove the banner

Remove the existing persistent header banner, including `Tinjau planning`.

Clean up banner-only props, handlers, and dead code.

However, retain the underlying snapshot mismatch detection.

If a planning snapshot predates a repository re-sync, surface that information contextually within plan details or review actions, not through a permanent global banner.

Do not silently regenerate or overwrite existing planning after re-sync.

## UI requirements

Discover relevant ready-made components from HeroUI, shadcn, Magic UI, React Bits, ThinkingOrbs, AffectUI, TuffUI, CUI, and SakaniUI.

Use the existing design system's Button/Tooltip/Progress primitives.

Do not create a decorative badge with no clear affordance.

The control must have correct semantic button behavior, keyboard focus, and accessible label.
