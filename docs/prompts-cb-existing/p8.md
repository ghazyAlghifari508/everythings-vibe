# PHASE 08 — Fix Incomplete Tech Stack Detection for Synced Repositories

**COMPLEXITY: MEDIUM**  
**PRIORITY: P1 — Metadata Accuracy &amp; Repository Intelligence**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
Target branch: `feature/vibeplan-existing-codebase`

## 1. Mission

Perbaiki pendeteksian technology stack pada Existing Codebase.

Contoh bug: repository berbasis Astro, Tailwind, dan TypeScript hanya menampilkan "Tailwind" di sidebar.

Sistem harus mampu mendeteksi teknologi berdasarkan bukti nyata dari snapshot repository, bukan berdasarkan hardcoded repository name, tebakan AI, atau fallback yang menghilangkan informasi lain.

## 2. Codebase Investigation

Baca repository rules dan audit:

- `src/features/codebase/services/stack.ts`
- `src/features/codebase/hooks/use-workspace-source.ts`
- `src/features/codebase/services/workspace-snapshot.functions.ts`
- `src/features/codebase/services/analysis-inference.ts`
- `src/features/codebase/services/analysis-schema.ts`
- `src/features/codebase/tests/stack.test.ts`
- Relevant CLI manifest/snapshot metadata and file explorer.

Periksa seluruh konsumen stack output sebelum mengubah format datanya.

## 3. Confirmed Problems

### Missing framework rules

`stack.ts` sudah mendukung React, Vite, Tailwind, TypeScript, Next.js, Vue, Nuxt, Svelte, Express, Fastify, Hono, dan Drizzle.

Namun belum ada rule Astro.

### Incomplete merging

Existing logic:

```
if (primary.length > 0)
  return [...primary];

return [...fallback];
```

Akibatnya, satu teknologi yang berhasil terdeteksi dari dependencies dapat menyebabkan teknologi tambahan dari sumber lain tidak digunakan.

Ini perlu diperbaiki dengan evidence-based merging, bukan mengganti fallback dengan hardcoded labels.

## 4. Desired Result

Contoh repository:

```
Ghazy Portofolio

tsconfig.json
package.json
src/
public/
```

Dependencies:

```
astro
tailwindcss

```

Expected:

```
STACK TERDETEKSI

[Astro] [Tailwind CSS] [TypeScript]
```

Hasil hanya boleh menampilkan teknologi yang didukung bukti.

Jangan otomatis menambahkan TypeScript hanya karena framework biasanya mendukung TypeScript, kecuali sumber repository memberikan bukti yang cukup sesuai aturan deteksi.

## 5. Detection Sources

Prioritize real evidence:

1. `package.json` dependencies/devDependencies.
2. Framework/configuration files.
3. Source file extensions, when relevant.
4. Package manager metadata.
5. Verified codebase analysis metadata if available.

Contoh framework evidence:

```
astro → Astro
next → Next.js
nuxt → Nuxt
@sveltejs/kit → SvelteKit
@angular/core → Angular
react → React
vite → Vite
```

Perluas rule hanya untuk teknologi relevan dan dapat diidentifikasi secara andal.

Perhatikan bahwa beberapa framework menggunakan bundler/framework lain secara internal. Jangan otomatis menampilkan Vite sebagai independent primary framework hanya karena Astro memakai Vite secara internal.

## 6. Detection Architecture

Gunakan layered detection:

```
SYNCED SNAPSHOT
      │
      ▼
Read package manifests
      │
      ▼
Read relevant config files
      │
      ▼
Determine technologies
      │
      ▼
Merge compatible evidence
      │
      ▼
Deduplicate & normalize
      │
      ▼
Render stack badges
```

Jangan membuat AI call baru hanya untuk menampilkan stack labels.

Analisis AI boleh memberikan supplementary evidence, tetapi tidak boleh mengarang teknologi.

### Key Requirements

- Tidak hardcode nama repository.
- Tidak hardcode stack untuk sample project.
- Tidak membuat fallback "React" atau "JavaScript" ketika data kurang.
- Tidak mendeteksi framework dari substring yang ambigu.
- Tidak menampilkan duplikasi.
- Tidak mencampur dependency project A dengan project B.
- Tidak memakai stale analysis dari snapshot lama.
- Tidak bergantung pada keberhasilan AI analysis untuk mendeteksi dependencies yang sudah tersedia.
- Jangan menganggap lockfile sebagai bukti utama runtime yang digunakan.
- Jika package manifest tidak tersedia, gunakan evidence lain yang terpercaya atau tampilkan unknown state tanpa membuat label palsu.

## 7. Framework, Language &amp; Tooling

Pisahkan kategori secara internal jika membantu akurasi.

Contoh:

```
Framework: Astro
Language: TypeScript
Styling: Tailwind CSS
Package manager: npm
```

Public UI tidak harus menampilkan seluruh kategori dalam card terpisah.

Tetap pertahankan compact stack badges di sidebar.

Jika metadata package manager tersedia, jangan mencampurnya secara sembarangan dengan framework utama.

## 8. Monorepo &amp; Multi-Package Support

Audit apakah snapshot mendukung beberapa `package.json`.

Jika mendukung:

- Deteksi root dan nested workspaces secara tepat.
- Jangan menyimpulkan seluruh repository hanya memakai framework dari root package.
- Jangan membaca dependency dari excluded folders seperti node_modules.
- Deduplicate hasil.
- Jangan membuat asumsi bahwa setiap nested package adalah aplikasi independen.
- Pertahankan deterministic ordering.

Jika dukungan monorepo belum lengkap, perbaiki dengan memanfaatkan snapshot manifest existing dan dokumentasikan batasannya.

## 9. Stack UI

Current:

```
STACK TERDETEKSI

Expected:

```

Gunakan badge/tag existing.

Tidak perlu card baru, progress animation, atau branding masing-masing framework.

Stack harus dapat diperbarui secara benar ketika snapshot aktif berubah.

Jangan menggunakan stale stack dari repository sebelumnya selama loading.

## 11. Tests

Wajib:

1. Astro + Tailwind + TypeScript terdeteksi bila evidence tersedia.
2. React + Vite tidak menyebabkan duplicate labels.
3. Next.js + React dikenali secara konsisten.
4. SvelteKit tidak salah diklasifikasikan hanya sebagai Svelte.
5. Angular dependency terdeteksi.
6. Framework tidak terdeteksi dari substring package yang tidak relevan.
7. Missing package.json ditangani dengan benar.
8. Malformed package.json tidak membuat aplikasi crash.
9. Config file detection terverifikasi.
10. Multi-package repository tidak kehilangan stack yang relevan.
11. Stale snapshot tidak memengaruhi hasil baru.
12. Analysis fallback tidak menghapus hasil deterministik.
13. Deteksi tetap dapat berjalan tanpa AI analysis.
14. No duplicate stack labels.
15. Existing sidebar rendering tidak regresi.

Jalankan unit/integration tests non-browser, typecheck, lint, dan build.

**Dilarang browser QA, Playwright, Puppeteer, browser automation, manual browser testing, dan screenshot tests.**

## 12. Definition of Done

Stack Detection mendukung Astro dan teknologi relevan lainnya berdasarkan bukti repository aktual.

Deteksi tidak bergantung sepenuhnya pada AI analysis, tidak menampilkan fallback palsu, dan tidak menghilangkan framework hanya karena satu teknologi berhasil ditemukan.

Laporan akhir:

- Root cause.
- Detection rules yang diperbaiki.
- Cara merge evidence.
- File berubah.
- Hasil tests.
- Limitations untuk monorepo/unsupported technology.
