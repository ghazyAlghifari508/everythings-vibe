# FIX 08 — Dedicated Existing-Codebase Kanban Route &amp; New-Tab Navigation

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibeplan-existing-codebase`

## Objective

Pisahkan navigation context Full Kanban antara Greenfield dan Existing Codebase.

Saat user membuka Kanban dari workspace Existing Codebase, mereka harus mendapat Full Kanban yang menggunakan data feature plan yang sama, tetapi memiliki route, header, dan navigasi yang sesuai dengan repository.

Buka Full Kanban di tab browser baru agar workspace tiga panel tidak tergantikan.

## Current Bug

Tombol "Buka Kanban Penuh" mengarah ke route umum:

`/kanban/$id`

Route tersebut menggunakan shared `KanbanBoard` greenfield.

Hasilnya:

- Header terasa seperti greenfield.
- Tombol "Kembali ke Chat" menuju `/plan/new`.
- Tidak ada navigasi kembali ke repository workspace.
- Full Kanban menggantikan halaman workspace yang sedang digunakan.

## Desired Architecture

```
GREENFIELD
/kanban/:projectId
      │
      └── Greenfield navigation

EXISTING CODEBASE
/codebases/:codebaseId/kanban/:projectId
      │
      └── Repository-aware navigation

Kedua route:
      │
      └── Shared Kanban data and board core
```

Route proposed dapat disesuaikan dengan TanStack Router conventions aktual, tetapi harus tetap eksplisit dan tidak ambigu.

## Desired UX

```
Tab 1: Existing Codebase Workspace
┌───────────────────────────────┐
│ Explorer | Chat | Preview     │
└───────────────────────────────┘

               │
         Buka Kanban Penuh
               ▼

Tab 2: Existing Codebase Kanban
┌───────────────────────────────┐
│ ← Kembali ke Workspace        │
│ Ocean Guard / Filter Artikel  │
│                               │
│ To Do | In Progress | Done    │
│                               │
└───────────────────────────────┘
```

Tab pertama tetap terbuka dan tidak kehilangan state.

## Implementation Requirements

### A. Separate Navigation Context

Jangan membuat salinan seluruh Kanban engine.

Reuse:

- Kanban task API.
- Polling.
- Column/task components.
- Progress calculation.
- Status update flow.
- Existing shared business logic.

Pisahkan hanya route/page context, header, breadcrumb, navigation actions, dan presentation yang memang perlu berbeda.

### B. Open in New Tab

"Buka Kanban Penuh" harus membuka tab baru menggunakan link yang valid, dengan `target="_blank"` dan `rel="noopener noreferrer"` atau mekanisme router yang setara.

Jangan memakai pendekatan yang menimpa current workspace.

Link harus memiliki destination yang benar dan bekerja dengan normal browser behavior.

### C. Authorization

Pastikan:

- `codebaseId` benar.
- `projectId` benar.
- Project benar-benar terhubung ke repository tersebut.
- User memiliki akses ke repository dan project.
- Tidak ada cross-tenant data exposure.
- Plan entitlement tetap mengikuti aturan produk existing.

Jangan hanya menyembunyikan navigasi yang salah; validasi juga pada loader/backend.

### D. Dedicated Header

Existing Codebase Full Kanban harus menampilkan konteks:

- Repository name.
- Active feature plan.
- Task progress.
- Back to Workspace.
- Informasi koneksi task bila relevan.

Jangan tampilkan "Kembali ke Chat" yang mengarah ke greenfield.

Greenfield route tetap mempertahankan perilaku dan navigasinya sendiri.

### E. State Preservation

- Task dan status tetap berasal dari database.
- Perubahan task dari CLI tetap muncul.
- Kedua tab merepresentasikan project yang sama.
- Membuka tab baru tidak melakukan duplicate generation.
- Menutup tab Kanban tidak menghapus atau mereset workspace.
- Reload route Kanban tetap bisa memuat data yang benar.

## Mandatory UI Component Reuse

Evaluasi komponen navigasi siap pakai dari shadcn/HeroUI dan existing Kanban components.

Gunakan shared components, bukan UI baru dari nol.

Eksplor Magic UI/React Bits hanya jika ada interaksi yang benar-benar membutuhkan motion tambahan.

Jangan menciptakan visual styling baru yang tidak konsisten dengan VibeEverything.

## Verification

Tambahkan automated tests non-browser untuk:

- Route ownership.
- Codebase/project mismatch.
- Full board navigation URL.
- Greenfield compatibility.
- New-tab link attributes.
- Shared task data consistency.
- Unauthorized access.

Jalankan lint/typecheck/build.

Tidak ada browser QA, Playwright, Puppeteer, atau screenshot comparison.

Atomic commit dan push sesuai aturan repository.
