# P11 — Fix Re-sync Modal Layout and Spacing Consistency

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** MEDIUM  
**Priority:** High visual-quality requirement.

## Problem

The `Perbarui repository` modal looks excessively spacious compared to the original repository sync screen.

The user has requested this spacing correction repeatedly, but previous modifications have not solved the visual problem.

**Do not repeat a superficial padding adjustment.**

The problem concerns the whole layout composition:

- Dialog width.
- Outer and inner spacing.
- Header alignment.
- Stepper indentation.
- Prompt box width.
- Agent selection alignment.
- Progress alignment.
- Footer spacing.
- Vertical density.
- Possible stacking of nested paddings.

## Exact layout requirements

### 1. Shared geometry

Compare initial sync layout and re-sync modal.

Extract shared spacing/layout primitives when appropriate so both use the same:

- Step number rail.
- Step content indentation.
- Horizontal padding rhythm.
- Vertical step spacing.
- Prompt container density.
- Agent options arrangement.

Do not maintain separate near-identical layout systems that drift over time.

### 2. No excessive nested padding

Audit every nested container and establish one clear owner for each spacing responsibility.

Example:

```
Dialog content
  └─ Main body horizontal padding
      └─ Stepper
          ├─ Number rail
          └─ Step content
              └─ Prompt surface padding
```

The step component should not add another large outer horizontal offset on top of the parent body's padding.

### 3. Consistent alignment

The start of these elements must align:

- Step heading.
- Prompt box.
- Agent icons/options.
- Progress content.

The step number column remains separate and consistently sized.

### 4. Content-driven height

Do not assign arbitrary fixed heights that leave excessive empty space.

Use a sensible maximum viewport height with scrolling only when necessary.

The dialog should remain compact when its content is short and scroll safely when its prompt is long.

### 5. Prompt width

The prompt box should take the available width of the step content column.

No unnecessarily narrow code block inside an excessively wide modal.

Long prompt text should scroll within a bounded content area without stretching the modal horizontally.

### 6. Footer consistency

Footer padding, border, close action, and alignment must follow the shared dialog layout.

Avoid excessive separation between the last step and footer.

## Preserve behavior

Do not break:

- Sync session identity.
- One-time credential handling.
- Copy prompt.
- Retry.
- Session expiration.
- Sync progress.
- Analysis progress.
- Complete button verification.
- Close behavior.
- Keyboard focus.
- Scroll preservation.

Do not redesign the workflow itself.

## Component discovery

Inspect HeroUI Modal, Radix Dialog, shadcn Dialog and ScrollArea, plus the other user-requested catalogs: Magic UI, React Bits, ThinkingOrbs, AffectUI, TuffUI, CUI, SakaniUI.

Reuse existing Dialog and ScreenConnect primitives. If a ready-made component provides the required accessibility and scroll behavior, use it instead of a new custom modal implementation.

Do not migrate the entire application to another modal library for this small layout correction.
