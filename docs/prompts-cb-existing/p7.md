# PHASE 07 — Redesign VibePlan Chat Composer With Plan/Revise Modes, @ Mentions &amp; Slash Commands

**COMPLEXITY: MEDIUM–HIGH**  
**PRIORITY: P1 — Frontend UX &amp; AI Workflow Interaction**

Repository: [https://github.com/ghazyAlghifari508/everythings-vibe](https://github.com/ghazyAlghifari508/everythings-vibe)  
Target branch: `feature/vibeplan-existing-codebase`

## 1. Mission

Redesign Chat Composer pada Existing Codebase Workspace agar memiliki kualitas pengalaman setara AI coding harness modern seperti Google Antigravity, Cursor, Claude Code, dan OpenCode.

Target: minimal, profesional, ergonomis, mudah dipahami, dan konsisten dengan VibeEverything.

Tambahkan:

1. Composer visual hierarchy yang lebih baik.
2. Mode dropdown Plan/Revise.
3. Default mode Plan.
4. Tombol submit menggunakan arrow-up sederhana.
5. `@` mentions untuk referensi file/dokumen.
6. `/` commands untuk tindakan workflow.
7. Integrasi ke revision engine Existing Codebase.
8. Handling draft, loading, failure, dan completed planning yang benar.

**Jangan membuat dropdown dekoratif yang tidak mengubah workflow.**

## 5. Mode Selector

Gunakan dropdown ringkas di kiri bawah composer.

```
┌──────────────────────────────────┐
│ ✓ Plan                           │
│   Susun planning fitur           │
│                                  │
│   Revise                         │
│   Tinjau dan ubah planning       │
└──────────────────────────────────┘
```

### Plan Mode

Purpose:

- Memulai planning fitur baru.
- Mengikuti clarification workflow.
- Generate Feature Specification.
- Generate PRD.
- Generate Acceptance Criteria.
- Generate Task.

Default untuk workspace fitur baru adalah Plan.

Jangan otomatis menganggap pesan user sebagai revisi hanya karena ada artefak.

### Revise Mode

Purpose:

- Memilih dokumen yang sudah ada.
- Memberikan instruksi revisi.
- Meminta revision proposal.
- Menampilkan preview diff.
- Meminta approval sebelum menerapkan.

Revise harus menggunakan explicit target artifact.

Mode ini bukan izin untuk mengedit langsung dokumen aktif.

### Completed Planning

Setelah Task selesai dibuat:

- Composer default tidak perlu tetap terbuka.
- Workspace dapat menampilkan hasil planning dan Handoff.
- Aksi eksplisit "Revisi Planning" membuka composer dalam mode Revise.
- Target dokumen dapat dipilih melalui toolbar/reference picker.
- User dapat membatalkan revisi dan kembali ke completed workspace.

Jangan mengaktifkan chat umum tanpa alasan setelah planning complete.

## 6. @ Reference System

Implementasikan context reference picker untuk:

```
@Feature
@PRD
@AC
@Task
@src/...
@README.md
```

Referensi harus menggunakan data aktual dari project dan snapshot.

### User Interaction

User mengetik:

```
@
```

Tampilkan popover searchable:

```
┌─────────────────────────────────┐
│ Cari dokumen atau file...      │
├─────────────────────────────────┤
│ Dokumen Planning               │
│   Feature Specification        │
│   PRD                          │
│   Acceptance Criteria          │
│   Task                         │
│                                 │
│ File Repository                │
│   src/pages/Content.jsx        │
│   package.json                 │
└─────────────────────────────────┘
```

Ketika user memilih:

- Simpan structured reference identity.
- Tampilkan chip atau inline mention yang jelas.
- Dukung remove reference.
- Dukung keyboard navigation.
- Pastikan referensi tetap milik repository/project yang benar.
- Validasi lagi di backend sebelum membaca isi referensi.
- Jangan memasukkan semua file repository ke context window tanpa seleksi.

Gunakan current artifact version dan snapshot ID yang benar.

Jika file sudah tidak ada di snapshot aktif, tampilkan status yang jelas.

Hindari referensi yang secara diam-diam berubah ke file berbeda setelah sync ulang.

## 7. Slash Commands

Implementasikan command interface ringan.

Minimal commands:

```
/plan
/revise
/help
```

Purpose:

- `/plan`: memilih Plan Mode.
- `/revise`: memilih Revise Mode.
- `/help`: membuka daftar command yang benar-benar tersedia.

Jangan implementasikan command palsu.

Jika command membutuhkan capability yang belum didukung, jangan tampilkan.

### Interaction

User mengetik:

```
/
```

Tampilkan:

```
┌─────────────────────────────────┐
│ Commands                        │
│                                 │
│ /plan    Susun planning         │
│ /revise  Revisi dokumen         │
│ /help    Bantuan perintah       │
└─────────────────────────────────┘
```

Gunakan command selection yang benar, bukan menambahkan teks slash command ke prompt AI.

Jika user memilih `/revise`, mode composer berubah dan target selection tersedia.

Jika user memilih `/plan`, kembali ke planning mode hanya jika lifecycle mengizinkan.

Jangan membypass locked planning state.

## 8. Submit Button Redesign

Hapus morph/squash/tilt animation dari submit pada Existing Codebase.

Gunakan arrow-up sederhana.

Expected states:

```
EMPTY
↑ disabled / muted

READY
↑ enabled / primary

SUBMITTING
◌ processing indicator

FAILED
↑ available for valid retry
```

Jangan membuat tombol Stop jika backend tidak mendukung cancellation yang benar.

Jika stop memang didukung, action harus benar-benar membatalkan operasi terkait, bukan sekadar menyembunyikan spinner.

### Accessibility

- Button accessible name: "Kirim pesan".
- Target cukup besar.
- Focus ring visible.
- Disabled state jelas.
- Tooltip jika icon-only.
- Reduced-motion compliance.
- Keyboard submit mengikuti aturan composer existing.

## 9. Composer Interaction Architecture

Jangan menyatukan Plan dan Revise menjadi satu handler AI yang ambigu.

Konsep:

```
COMPOSER
   │
   ├── Mode: PLAN
   │      │
   │      └── Planning Workflow
   │
   └── Mode: REVISE
          │
          └── Revision Proposal Workflow
                     │
                     ▼
                Preview Diff
                     │
                     ▼
                User Approval
```

Mode dipilih secara eksplisit dan tersimpan dalam component state.

Request backend harus menerima operation intent yang valid.

Jangan hanya mengubah placeholder agar tampak seperti dua mode.

## 10. Draft &amp; State Management

Pastikan:

- Draft tidak hilang ketika dropdown dibuka.
- Memilih reference tidak menghapus draft.
- Command picker tidak mengirim pesan secara tidak sengaja.
- Mode change tidak membuat AI request.
- Project change tidak membawa draft project lama.
- Failed request mempertahankan draft sesuai lifecycle existing.
- Duplicate submit dicegah.
- Composer loading mengikuti operasi aktual.
- Stale responses tidak mengubah mode/project aktif.
- IME composition tidak memicu submit prematur.
- Enter/Shift+Enter sesuai pola aplikasi yang sudah ada.

Jangan menyimpan sync token atau credentials di composer state persistence.

## 12. Mandatory Component Discovery &amp; Reuse

**PENTING: jangan mulai membuat JSX baru sebelum eksplorasi komponen.**

Wajib tinjau:

1. Existing `PromptBar`.
2. Existing VibeEverything dropdown/popover components.
3. shadcn/ui DropdownMenu, Command, Popover, Combobox, Textarea, Button, Tooltip.
4. HeroUI equivalent controls jika lebih cocok.
5. Magic UI untuk purposeful microinteraction.
6. React Bits untuk subtle motion jika dibutuhkan.
7. Thinking Orbs hanya untuk actual AI processing state.

Referensi:

[https://ui.shadcn.com/](https://ui.shadcn.com/)  
[https://www.heroui.com/](https://www.heroui.com/)  
[https://magicui.design/](https://magicui.design/)  
[https://reactbits.dev/](https://reactbits.dev/)  
[https://www.thinkingorbs.com/#orbs](https://www.thinkingorbs.com/#orbs)

**WAJIB menggunakan ready-made components yang sesuai. Jangan membuat dropdown, command palette, popover, textarea, atau button primitive dari nol jika komponen matang tersedia.**

Agent harus memilih komponen yang kompatibel dengan dependencies dan design system yang sudah ada.

Jangan memasang banyak UI library tanpa kebutuhan.

Custom code hanya diperbolehkan untuk integration, composition, dan interaksi khusus yang belum disediakan komponen siap pakai.

### Strict Anti-AI-Slop

Dilarang:

- Gradient mencolok.
- Dekorasi tambahan tanpa fungsi.
- Extra badge di atas composer.
- Status copy generik.
- Multiple nested composer cards.
- Floating controls yang menutup textarea.
- Mode dropdown yang hanya mengubah label.
- Placeholder attachment buttons tanpa fitur.
- Model selector palsu.
- Animasi send button berlebihan.
- Hardcoded repository/document names.
- Fake tool calls atau fake thinking events.

## 13. Automated Tests

Wajib:

1. Default mode pada new feature adalah Plan.
2. Dropdown memilih Plan/Revise.
3. Mode Revise memerlukan target artifact valid.
4. Revise tidak langsung mengubah dokumen.
5. `@` menampilkan referensi yang benar.
6. Memilih reference membuat structured binding.
7. Invalid/cross-project reference ditolak backend.
8. `/plan` dan `/revise` mengubah mode dengan benar.
9. Commands tidak dikirim sebagai plain text ke model.
10. Arrow submit mengikuti valid input state.
11. No duplicate submissions.
12. Draft tetap aman saat mode/reference berubah.
13. Completed planning tetap read-only sampai revisi dibuka eksplisit.
14. Project switching tidak membawa draft/reference yang salah.
15. Keyboard dan focus management valid.
16. Existing Greenfield PromptBar tidak rusak.
17. Failure/retry menggunakan lifecycle operasi yang benar.

Jalankan unit tests, component tests non-browser, typecheck, lint, dan build.

**Jangan menjalankan browser QA, Playwright, Puppeteer, browser automation, manual browser testing, atau screenshot testing.**

## 14. Definition of Done

Composer menjadi minimal dan profesional, dengan:

- Plan/Revise dropdown yang fungsional.
- Arrow submit yang sederhana.
- Context references nyata.
- Slash commands yang bekerja.
- Integration ke revision engine.
- Keyboard/accessibility yang baik.
- Existing PromptBar direuse.
- Tidak ada UI dekoratif atau kontrol palsu.

Laporan akhir harus menjelaskan komponen siap pakai yang digunakan, file berubah, integrasi backend, hasil tests, dan hal yang belum didukung.

Jangan mengklaim fitur selesai jika Plan/Revise hanya mengubah label UI.
