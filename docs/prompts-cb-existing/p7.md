# P07 — Shared Kanban Card Presentation for Existing Codebase

**Branch:** `feature/vibeplan-existing-codebase`  
**Complexity:** MEDIUM

## Problem

The Kanban UI inside the existing-codebase side panel differs significantly from the full Kanban page at:

`/codebases/kanban/:codebaseId/:projectId`

The side panel uses:

- `CodebaseKanbanBoard`
- `CodebaseKanbanColumn`
- `CodebaseKanbanCard`

The full preview uses Greenfield Kanban presentation components, including:

- `KanbanBoard`
- `KanbanColumn`
- `FeatureGroup`
- `KanbanCard`

The side-panel cards are overly simplified, lack important information, and render `Kosong` for empty columns.

## Objective

Make the side-panel Kanban card experience visually and functionally consistent with the full Kanban page.

**Scope restriction:** Only improve the Kanban cards, their feature grouping, relevant column empty states, and shared presentation components.

Do not redesign unrelated side-panel navigation, arrow controls, tabs, or the full Kanban page.

## Current vs expected

Current:

```
┌────────────────────┐
│ To Do           12 │
│ ┌────────────────┐ │
│ │ CATEGORY       │ │
│ │ Implementasi   │ │
│ │ pencarian      │ │
│ │ 0/2 subtask    │ │
│ └────────────────┘ │
│                    │
│ In Progress: Kosong │
└────────────────────┘
```

Expected:

```
┌─────────────────────────────────┐
│ Belum Mulai                  11 │
│                                 │
│ Pencarian Instan Proyek         │
│ ┌─────────────────────────────┐ │
│ │ Implementasi input          │ │
│ │ pencarian interaktif        │ │
│ │                             │ │
│ │ Komponen pencarian dengan   │ │
│ │ debounce untuk input user.  │ │
│ │                             │ │
│ │ Penting        0/2 subtask  │ │
│ └─────────────────────────────┘ │
│                                 │
│ Dikerjakan                   0  │
│ Belum ada task yang dikerjakan. │
└─────────────────────────────────┘
```

This is a structural illustration, not an instruction to force every column into vertical stacking. Preserve the existing horizontal-scroll behavior.

## Required refactor

1. Inspect full Kanban components and their data contracts.
2. Identify reusable presentation primitives for feature group, task card, priority indicator, and progress.
3. Prefer extraction/shared reuse over duplicating Greenfield component logic.
4. Allow compact responsive layout in side panel without changing the underlying card semantics.
5. Preserve task names, descriptions, feature group labels, priorities, dependencies, subtasks, and actual statuses where supported.
6. Keep the side panel usable in narrow and wide widths.
7. Preserve current horizontal scrolling, arrows, and full-board navigation.
8. Preserve `Kanban` and existing second tab functionality. Do not invent a new Diagram implementation or rename tabs without an explicit requirement.

## Status correctness

Investigate this important issue:

A side-panel card currently may display `Agent coding...` based on a column-level highlight flag rather than a confirmed agent execution signal.

Do not claim an agent is coding merely because a task has `in_progress` status.

Display a neutral actual status unless there is a verified real agent activity signal.

Also investigate any inconsistency where a completed task shows `0/2 subtask`. Determine whether this is valid domain state or incorrect projection/mapping.

Never falsify counters to make the card appear correct.

## Empty states

Replace the generic `Kosong` with context-specific wording:

- Belum Mulai: `Belum ada task`.
- Dikerjakan: `Belum ada task yang dikerjakan`.
- Selesai: `Belum ada task yang selesai`.
- Gagal: `Tidak ada task gagal`.

Preserve the full board's existing empty-state logic where it can be reused.

## Card interaction

If the full Kanban card opens details, the side-panel card should support equivalent relevant task details without breaking focus or creating nested-dialog conflicts.

Reuse the same component whenever practical.

## UI libraries

Explore the requested catalogs, including HeroUI, shadcn, Magic UI, React Bits, ThinkingOrbs, AffectUI, TuffUI, CUI, and SakaniUI.

Use suitable existing Task/Card/Tooltip/Scroll primitives from installed libraries. Avoid custom-building a second competing Kanban component ecosystem.

Do not introduce unrelated animations.

## Testing

Cover:

- Pending/in-progress/completed/failed columns.
- Feature grouping.
- Priority display.
- Subtask counts.
- Empty states.
- Task detail interaction contracts.
- Horizontal-scroll state preservation.
- Correct task identity and ordering.
- Shared component reuse.
- No false agent-activity status.

No browser QA.

## Atomic commits

`refactor(codebase): reuse shared kanban task presentation`

`fix(codebase): align kanban empty states and status labels`

Test targeted components and create atomic commits.

## Final report

Explain which shared components were reused, which duplicates were removed, and what behavior remains intentionally different because of side-panel constraints.
