1. Loading marker terlihat seperti jam pasir, bukan spinner melingkar yang profesional.

4. Status proses terasa statis, meskipun backend sedang melakukan pekerjaan.
5. Feedback antarjenis scrape belum sepenuhnya konsisten.

Pertahankan progress state sebenarnya. Jangan membuat progress palsu atau animasi yang menyembunyikan masalah backend.

## 4. Spinner Replacement

Temuan awal:

`scrape-progress-steps.tsx` menggunakan `Loading01Icon` dari Hugeicons yang dianimasikan dengan `animate-spin`.

Ganti dengan ikon/loading component yang secara visual jelas menyerupai circular spinner.

Requirements:

- Gunakan komponen dari library siap pakai.
- Pertahankan Hugeicons jika tersedia ikon spinner yang cocok.
- Jangan memakai icon hourglass, gestur tangan, atau loading indicator yang ambigu.
- Spinner harus benar-benar berotasi saat state aktif.
- Step yang completed menggunakan check.
- Step pending tetap netral.
- Step failed memakai icon error yang sesuai.
- Connecting lines tetap konsisten dan tidak hilang saat state berubah.
- Tidak ada lompatan layout ketika marker berubah bentuk.

## 5. Activity Animation

Bagian aktivitas terbaru saat ini terutama menampilkan plain text.

Tambahkan animasi subtle yang membuat proses terasa aktif.

Recommended structure:

```
AKTIVITAS TERBARU

   [SPIN] Memeriksa tampilan mobile...

          Tampilan 2 dari 2

   ───── subtle animated loading indication ─────
```

Rekomendasi teknik:

- Circular spinner di sebelah activity label.
- Transisi teks yang halus ketika aktivitas benar-benar berubah.
- Shimmer lembut atau animated ellipsis jika sesuai.
- Elapsed timer aktual tetap tersedia.
- Jangan membuat typing/deleting animation per karakter.
- Hindari flicker, flashing, dan efek yang terus-menerus menarik perhatian.

Animasi harus menghormati `prefers-reduced-motion`.

Untuk screen reader, batasi live announcements agar pembaruan cepat tidak dibacakan terus-menerus.

## 7. Shared UX, Not Duplicate UI

Pertahankan prinsip satu progress hierarchy.

Jangan membuat:

- Dua spinner besar untuk proses yang sama.
- Progress bar duplikat tanpa fungsi.
- Dua area `Aktivitas terbaru`.
- Dashboard loading baru.
- Loading card berlapis-lapis.
- Persentase palsu dari estimasi waktu.

Jika ingin memakai progress bar, harus jelas apakah itu jumlah tahap selesai, jumlah item diproses, atau progres aktual yang didukung data. Jangan menampilkan angka persen seolah-olah backend mengetahui completion percentage jika tidak.

## 9. State Behavior

Verifikasi:

```
QUEUED
  │
  ▼
CAPTURING ◌
  │
  ▼
EXTRACTING ◌
  │
  ▼
GENERATING ◌  (DESIGN.md only)
  │
  ▼
SAVING ◌     (when applicable)
  │
  ├───────────────┐
  ▼               ▼
COMPLETED ✓     FAILED !
```

Gunakan stage sebenarnya untuk tiap mode.

- Jangan tampilkan tahap yang tidak ada pada mode terkait.
- Gagal di tengah proses harus menunjukkan titik kegagalan secara akurat.
- Ketika retry berhasil dimulai, UI kembali ke state pemrosesan yang benar.
- Refresh/reopen halaman tidak boleh membuat progress berbohong.
- Aktivitas yang berhenti diperbarui harus ditangani sesuai server state, bukan sekadar terus memutar spinner tanpa batas.

## 10. Tests &amp; Definition of Done

- Semua mode menggunakan progress pattern yang konsisten.
- Active stage memakai circular spinner yang jelas.
- Completed/pending/failed markers benar.
- Connecting lines sesuai state.
- Aktivitas terbaru mempunyai animasi subtle.
- Activity copy mudah dipahami.
- Tidak ada fake progress.
- Tidak ada duplicate loaders atau redundant status panels.
- Reduced-motion didukung.
- Status tetap akurat setelah retry/reload.
- Tidak ada layout shift yang mengganggu.
- Automated component/state tests lulus.

**Jangan lakukan browser QA.** Gunakan unit tests, component tests, typecheck, lint, dan build sesuai kebutuhan.

Final report harus menjelaskan komponen library yang digunakan, perubahan state presentation, dan bukti pengujian tanpa mengklaim verifikasi browser.
