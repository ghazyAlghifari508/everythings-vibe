# TASK: Fix VibeScrape HTML Preview — Full Scrolling, Rendering Reliability, and Visible Recovery

**Kompleksitas: COMPLEX**

## Masalah

Pada fitur Scrape HTML, saya menemukan beberapa masalah:

1. HTML berhasil diambil dan file download memiliki banyak section, tetapi preview di aplikasi hanya menampilkan sebagian konten.
2. User tidak selalu dapat melakukan scroll untuk melihat section lain.
3. Terkadang muncul `Preview DOM gagal dimuat`.
4. Ketika mencoba lagi, preview kadang berhasil.
5. Ketika DOM preview gagal dan sistem menampilkan screenshot, tombol `Coba lagi` justru berada di bawah screenshot sehingga sulit ditemukan.
6. Screenshot fallback tidak selalu menampilkan keseluruhan halaman.
7. User tidak diberi penjelasan yang jelas apakah yang sedang ditampilkan adalah preview HTML atau gambar statis.

Perbaiki akar masalahnya. Jangan hanya mengganti copywriting error.

## 2. Fix masalah scrolling dan konten terpotong

Investigasi minimal:

- Tinggi iframe dan parent container.
- Perhitungan scale dan transform.
- CSS overflow pada wrapper.
- CSS overflow bawaan HTML hasil scrape.
- `html`, `body`, dan root container dari website sumber.
- Konten dengan `height: 100vh`, fixed layout, atau nested scroller.
- CSS yang mengunci scrolling.
- Perbedaan antara preview DOM dan screenshot fallback.
- Kemungkinan scroll event ditangkap oleh container yang salah.
- Perubahan HTML akibat rewriting, sanitization, dan asset handling.

Target:

```
┌──────────────────────────────────────────┐
│ Visual             HTML Source           │
├──────────────────────────────────────────┤
│                                          │
│ WEBSITE HERO                             │
│                                          │
│ SECTION 1                                │
│                                          │
│ SECTION 2                                │
│                                          │
│ SECTION 3                                │
│                                          │
│ ...                                      │
│                                    │     │
│                                    ▼     │
└──────────────────────────────────────────┘
```

User harus dapat menjelajahi seluruh konten yang berhasil direkonstruksi, bukan berhenti pada viewport pertama.

Jangan menambahkan `overflow: auto` secara membabi buta pada semua elemen. Itu dapat merusak layout website sumber. Tentukan scroll container dengan benar.

Bila website aslinya menggunakan nested scrolling, tangani perilaku tersebut secara masuk akal dan aman.

## 3. Perbaiki state machine preview

Periksa seluruh state:

- Preparing.
- Ready.
- Degraded.
- Empty.
- Failed.

Pastikan:

1. Halaman yang masih memuat konten tidak terlalu cepat dianggap gagal.
2. Error resource minor tidak otomatis menjadikan seluruh preview failed jika konten utamanya masih tersedia.
3. Readiness reporter tidak memberi hasil sukses palsu.
4. Timeout atau batas polling tidak menghasilkan error generik tanpa informasi yang benar.
5. Retry benar-benar membuat attempt baru.
6. Status lama tidak tertinggal setelah retry.
7. Pergantian Visual/HTML Source tidak menyebabkan reload tak perlu.
8. Progress loading tidak terjebak permanen.

Gunakan hasil observasi yang nyata; jangan memalsukan readiness.

## 4. Perbaiki fallback screenshot

Di implementasi yang sebelumnya diperiksa, screenshot dibuat tanpa `fullPage: true`, sehingga tidak otomatis menangkap seluruh dokumen.

Tinjau apakah fallback membutuhkan tangkapan halaman penuh.

Jika memang memungkinkan secara aman:

- Tangkap full-page screenshot.
- Terapkan batas ukuran/tinggi yang rasional.
- Hindari konsumsi memori tidak terkendali pada halaman sangat panjang.
- Tampilkan gambar dengan ukuran yang tepat.
- Izinkan scrolling pada screenshot yang lebih tinggi dari area viewer.

Jangan mengklaim screenshot sebagai preview HTML interaktif.

**DOM preview tetap prioritas utama. Screenshot hanya fallback atau referensi visual.**
