# TASK: Fix VibeScrape Active Mode Persistence Across Navigation, Reload, and Browser History

**Kompleksitas: MEDIUM — TanStack Router search params, client state, and navigation consistency.**

## Problem

VibeScrape memiliki empat mode:

- Crawl Website.
- Generate [DESIGN.md](http://DESIGN.md).
- Scrape HTML.
- Scrape Images.

Saat ini, ketika user memilih mode tertentu lalu berpindah halaman, tab aktif terkadang kembali ke default [DESIGN.md](http://DESIGN.md).

Contoh:

```
VibeScrape → Scrape Images
                 │
                 ▼
               Riwayat
                 │
                 ▼
             VibeScrape
                 │
                 ▼
            ❌ DESIGN.md
```

Padahal seharusnya:

```
VibeScrape → Scrape Images
                 │
                 ▼
               Riwayat
                 │
                 ▼
             VibeScrape
                 │
                 ▼
            ✅ Scrape Images
```

Masalah ini juga terjadi ketika user memilih Scrape HTML kemudian meninggalkan halaman.

Saya ingin mode aktif tetap dipertahankan secara konsisten.

## 1. Root cause

Pada codebase yang sebelumnya diperiksa:

`src/features/scrape/components/scrap-mode-switcher.tsx`

menggunakan:

```
const [mode, setMode] = useState<ScrapeMode>(initialMode);
```

Pemilihan tab hanya memanggil `setMode`.

Sedangkan:

`src/routes/scrape/index.tsx`

membaca mode awal dari route search parameter.

Artinya, state lokal dan URL belum tersinkron dengan baik.

Audit:

- `scrap-mode-switcher.tsx`
- `scrape-workspace-view.tsx`
- `src/routes/scrape/index.tsx`
- Search parameter parser
- Navigation links VibeScrape/Riwayat
- Header navigation
- History navigation
- Back/Forward behavior
- Workspace form state

Gunakan struktur kode aktual.

## 2. Expected behavior

Ketika user memilih Scrape Images:

```
[ Crawl ] [ DESIGN.md ] [ HTML ] [ IMAGES ● ]

URL:
/scrape?mode=images
```

Ketika memilih HTML:

```
[ Crawl ] [ DESIGN.md ] [ HTML ● ] [ Images ]

URL:
/scrape?mode=html
```

Ketika memilih Crawl:

```
[ CRAWL ● ] [ DESIGN.md ] [ HTML ] [ Images ]

URL:
/scrape?mode=crawl
```

Mode aktif harus dapat dibaca dari URL.

## 3. State architecture

Gunakan TanStack Router dengan pendekatan yang benar.

Prioritaskan URL search parameter sebagai **source of truth** untuk mode aktif jika parameter valid tersedia.

Namun jangan lupa kasus berikut:

- User memilih Images.
- User membuka Riwayat.
- User menekan nav VibeScrape yang mungkin mengarah ke `/scrape` tanpa query.
- User tetap ingin kembali ke Images.

Karena itu, periksa apakah navigation links dapat mempertahankan parameter mode ketika berpindah antarhalaman.

Jika tidak memungkinkan untuk semua jalur, gunakan mekanisme remembered-mode yang minimal dan konsisten, seperti session-scoped state, dengan aturan prioritas yang jelas:

1. Explicit valid URL mode.
2. Last selected mode dalam sesi, jika URL tidak menentukan mode.
3. Default mode sebagai fallback.

Jangan membuat local state, URL, dan storage saling bertentangan.

Jangan mengakses browser storage saat SSR tanpa guard yang benar.

## 5. Jangan kehilangan form state secara tidak sengaja

Periksa apakah perpindahan mode menyebabkan:

- URL input hilang.
- Parameter lanjutan berubah tanpa sengaja.
- Settings mode lain ditimpa.
- Submit menggunakan mode lama.
- Deskripsi mode tidak sesuai.
- Form submit menuju jenis scrape yang salah.

Jangan mengubah seluruh state architecture jika masalah cukup diperbaiki pada routing.
