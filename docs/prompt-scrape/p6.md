# TASK — SIMPLIFY CRAWL SITEMAP NAVIGATION AND LINK SEMANTICS

## Objective

The current Crawl Visual Sitemap has two navigation modes:

- Discovery Map.
- All Links.

The user cannot clearly understand their difference because both show nearly identical nodes and layout, with only some connecting lines changing.

The objective is to make the graph understandable without forcing the user to understand crawler implementation details.

Prefer one clear sitemap over multiple nearly identical modes.

## TASK A — Correct the UX Model

Currently:

```
[Discovery Map] [All Links]          [Fit] [-] [+]
```

The selected mode changes which relationships are visible, but the user has no obvious reason to use two tabs.

Recommended:

Use ONE primary Visual Sitemap.

Its default view should represent actual discovery relationships.

Secondary links should be exposed only when meaningful and requested or when focusing a selected page.

## TASK B — Remove Unnecessary Dual Modes

If a separate "All Links" tab adds little user value, remove the top-level mode switch.

Do not merely rename Discovery Map / All Links to two other technical labels.

Prefer:

- Primary discovery graph as default.
- Selected page focus.
- Optional secondary link visibility when secondary links exist.
- Clear relationship counts.

A contextual action such as "Tampilkan tautan lainnya" may be useful, but only when there are relevant additional relationships.

Do not add a new toolbar or additional panel that merely replaces the old complexity.

## TASK C — Truthful Relationship Semantics

Graph edges represent different facts:

```
Home ────> Pricing
      Discovery relationship

Pricing - - -> FAQ
      Additional observed link
```

Rules:

- Discovery edges represent the crawler's actual discovery parent relationship.
- Secondary edges represent links observed in HTML.
- No fake hierarchy.
- No arbitrary grouping by URL path that is presented as observed fact.
- No duplicate edges.
- Self-links handled intentionally.
- Circular links do not create infinite layout recursion.
- Failures/skipped pages remain accurately represented.

## TASK D — Selection Experience

When a user selects a node:

1. Highlight the selected page.
2. Show its meaningful incoming/outgoing link counts.
3. Distinguish selected-page links without highlighting every unrelated edge.
4. Synchronize selection with Page Inventory and Page Explorer.
5. Preserve the user's zoom/pan where reasonable.
6. Ensure selection remains keyboard accessible.
7. Show full title/URL when truncated.

Optional secondary relationships can be revealed contextually for that node.

Do not force all secondary links to appear at once if doing so creates a spaghetti graph.

## TASK E — Dense Graph Readability

The Notion screenshot shows one root with many child nodes spread horizontally.

Improve readability for wide graphs:

- Reasonable initial fit and minimum readable zoom.
- Stable spacing.
- Graph pan and zoom.
- No unnecessary edge crossings.
- Node label clarity.
- No clipped nodes at default fit where avoidable.
- Grouping/collapsing only if supported by accurate relationships.
- No fake intermediate parents invented for aesthetics.

Do not redesign the graph algorithm from scratch if current layout can be improved incrementally.

Do not install another heavy graph library without evidence that existing utilities cannot satisfy requirements.

## TASK F — Copywriting

Avoid user-facing technical explanations such as:

"Primary discovery edges and secondary observed cross-links."

Prefer:

"Peta halaman berdasarkan link yang ditemukan."

For contextual relationship details, use understandable labels:

- "Ditemukan dari".
- "Tautan ke halaman lain".
- "Tautan menuju halaman ini".

Do not add explanatory cards full of crawler jargon.

## TASK G — Empty/Edge States

Handle:

Do not show a disabled or meaningless "additional links" control when there are none.
