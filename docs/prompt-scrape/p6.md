# TASK: Investigate and Optimize VibeScrape End-to-End Performance Without Sacrificing Output Quality

**Kompleksitas: COMPLEX — Browser capture, extraction pipeline, worker orchestration, asset processing, and performance profiling.**

## Konteks

VibeScrape terkadang membutuhkan waktu sangat lama untuk melakukan scraping.

Contoh yang pernah diamati:

- Scrape HTML [`https://littlespace-alpha.vercel.app/`](https://littlespace-alpha.vercel.app/)
- Proses berjalan sekitar 162 detik pada aktivitas memuat konten tambahan.
- Website tersebut adalah aplikasi game 3D yang menggunakan banyak JavaScript dan asset.

Namun masalah performa tidak boleh diasumsikan hanya terjadi karena website berat.

Saya ingin kamu **menginvestigasi akar penyebab secara menyeluruh dan mengoptimalkan pipeline agar lebih cepat, tetap berkualitas, dan tidak mengurangi kelengkapan hasil**.

## 3. Audit bottleneck

### A. Browser lifecycle

Periksa:

- Apakah browser baru selalu dijalankan meskipun tidak diperlukan?
- Apakah ada startup overhead yang signifikan?
- Apakah resource cleanup benar?
- Apakah context leaks menyebabkan performa menurun?
- Apakah browser concurrency melebihi kapasitas server?

Browser reuse hanya boleh diterapkan jika aman, terisolasi antar-job, dan terbukti menguntungkan.

### B. Navigation and readiness

Periksa:

- Apakah `networkidle` benar-benar diperlukan di semua kondisi?
- Apakah halaman memiliki request yang tidak pernah idle?
- Apakah websocket, analytics, atau animasi membuat proses menunggu terlalu lama?
- Apakah readiness bisa didasarkan pada konten penting yang benar-benar siap?
- Apakah timeout terlalu agresif atau justru terlalu permisif?
- Apakah terdapat waktu tunggu berulang yang tidak memberikan nilai tambah?

Jangan langsung menghapus semua `waitForLoadState`.

Gunakan strategi sesuai kebutuhan mode dan karakter halaman.

### C. Auto-scroll

Periksa:

- Apakah auto-scroll wajib untuk setiap mode?
- Berapa banyak langkah scroll dilakukan?
- Apakah scrolling memicu loading konten tambahan tanpa batas?
- Apakah halaman game/canvas memerlukan strategi berbeda?
- Apakah auto-scroll membuat halaman berubah state?
- Apakah proses bisa dibatasi dengan cara yang tetap menjaga kualitas hasil?

Jangan membuat perubahan yang menyebabkan section penting tidak ikut dicapture.

### D. Asset handling

Periksa:

- Duplicate downloads.
- CSS/font/image fetch.
- Asset rewriting.
- Inline resource conversion.
- Large file handling.
- Compression.
- Storage I/O.
- Sequential operations yang sebenarnya independen.
- Retry yang tidak perlu.

Optimalkan concurrency secara aman dan terukur.

Jangan melakukan request agresif ke website pihak ketiga atau melewati pembatasan akses.

### E. AI synthesis

Untuk [DESIGN.md](http://DESIGN.md):

- Ukur waktu AI synthesis secara terpisah.
- Periksa ukuran evidence payload.
- Periksa duplicated evidence.
- Validasi apakah payload terlalu besar.
- Hindari repeated calls tanpa alasan.
- Pastikan optimasi tidak menurunkan kualitas synthesis.

Jangan memangkas evidence penting hanya demi mempercepat respons.

## 5. Optimasi wajib berbasis pengukuran

Buat baseline sebelum mengubah implementasi.

Bandingkan:

- Durasi sebelum/sesudah.
- Jumlah halaman/gambar ditemukan.
- Jumlah hasil valid yang tersimpan.
- Kelengkapan HTML.
- Jumlah asset yang tersedia.
- Akurasi hasil [DESIGN.md](http://DESIGN.md).
- CPU/memory jika metrik tersedia.
- Error rate.
- Retry rate.

Contoh target evaluasi:

```
BEFORE
Total:         measured baseline
Completeness: measured baseline
Failures:     measured baseline

AFTER
Total:         measured optimized value
Completeness: same or better
Failures:     same or lower
```

Jangan membuat klaim seperti "2x faster" tanpa hasil benchmark.

Jika optimasi membuat proses lebih cepat tetapi output kehilangan konten penting, optimasi tersebut tidak dianggap berhasil.

## 6. Performance safety

- Hindari timeout tanpa batas.
- Hindari retry storm.
- Hormati HTTP 429 dan Retry-After.
- Jangan menonaktifkan URL safety validation.
- Jangan menonaktifkan robots/access restrictions yang berlaku.
- Jangan membebankan concurrency berlebihan pada situs sumber.
- Jangan menyimpan browser context terlalu lama tanpa cleanup.
- Jangan menghapus logging error yang masih diperlukan untuk diagnosis.
- Pastikan abort/cancellation tetap berfungsi.
