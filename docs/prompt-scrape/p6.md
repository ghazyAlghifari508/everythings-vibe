# TASK: Replace VibeScrape Activity Spinner with Thinking Orbs &amp; Improve Truthful Activity Feedback

**Priority:** P2  
**Complexity:** Medium  
**Branch:** `feature/vibedesign-scrape`

## 1. Goal

Perbaiki hanya pengalaman visual dan informasi pada area **Aktivitas terbaru** di progress VibeScrape.

User sudah menyatakan bahwa **desain loading progress/stepper saat ini sudah benar dan tidak boleh diubah lagi**.

Masalah spesifik:

- Aktivitas terbaru menggunakan loading spinner.
- Stepper progress juga memakai loading spinner.
- Akibatnya UI terlihat memiliki double spinner.
- Teks aktivitas seperti "Menyusun analisis desain" dapat bertahan lebih dari 100 detik.
- Tidak ada visual thinking yang cukup komunikatif.
- User ingin Thinking Orbs, bukan spinner tambahan.
- Aktivitas harus menunjukkan proses nyata, bukan teks palsu yang berganti-ganti.

**Stepper spinner tetap dipertahankan.**

Jangan mengubah status icons untuk completed/failed stages.

Jangan mengubah urutan tahapan loading, card, column arrangement, typography halaman, atau layout yang sudah disetujui.

## 5. State mapping

Orb harus mengikuti status pekerjaan sebenarnya.

Contoh konseptual:


| Backend condition        | Activity display                           |
| ------------------------ | ------------------------------------------ |
| Queued                   | Waiting / non-misleading idle state        |
| Loading website          | Working                                    |
| Discovering pages        | Searching / Working                        |
| Checking visual evidence | Working                                    |
| AI synthesis active      | Reasoning                                  |
| Saving result            | Working                                    |
| Completed                | Done; stop animation                       |
| Failed                   | Stop animation; use existing error state   |
| Stalled                  | Do not present as healthy active reasoning |


Jangan memakai state `reasoning` untuk semua operasi. Crawl dan resource loading tidak otomatis merupakan aktivitas berpikir AI.

Pilih state sesuai fakta backend yang tersedia.

## 6. Aktivitas tidak boleh fiktif

Jangan membuat text carousel dengan aktivitas palsu hanya untuk membuat UI terlihat hidup.

Contoh yang dilarang:

```
0–10s  Menganalisis warna
10–20s Mempelajari tipografi
20–30s Menyusun komponen
30–40s Memikirkan layout
```

Jika perpindahan didasarkan pada timer dan bukan actual backend events, itu misleading.

Yang diinginkan:

```
Actual backend activity:
  "AI menyusun analisis design system"
                  |
                  v
Public activity:
  "Menyusun analisis desain"
                  |
                  v
Orb keeps animating while work is active
```

Ketika backend benar-benar berpindah operasi, teks ikut berubah.

Jangan mengarang progress percentage.

Jangan mengarang estimates.

## 7. Perbaiki granularitas event yang nyata

Audit activity events yang saat ini sudah ada.

Jika pipeline memang memiliki transisi nyata seperti:

```
Mengambil halaman
       |
Memeriksa gaya dan komponen
       |
Menyiapkan data analisis
       |
Menyusun analisis desain
       |
Memvalidasi hasil
       |
Menyimpan hasil
```

Pastikan transisi tersebut dikirim dan ditampilkan.

Jangan memecah satu operasi AI panjang menjadi substeps palsu yang backend tidak bisa verifikasi.

Jika satu AI call memang berlangsung 109 detik, aktivitas boleh tetap menampilkan "Menyusun analisis desain" selama durasi tersebut, dengan orb yang aktif dan timer yang benar.

Boleh tambahkan metadata subaktivitas hanya jika sumbernya benar-benar ada.

Jangan membuat aktivitas buatan untuk sekadar merotasi teks.

## 8. Animation requirements

- Animasi Orb halus.
- Tidak memakai loading spinner pada activity.
- Tidak menyebabkan layout shift.
- Tidak mengubah lebar/tinggi baris ketika teks berganti.
- Label boleh diberi subtle shimmer bila kompatibel dengan existing ThoughtLine, tetapi jangan berlebihan.
- Tidak ada bouncing atau flashing agresif.
- Respect `prefers-reduced-motion`.
- Hindari hydration mismatch.
- Tidak ada animation ketika status selesai atau gagal.
- Timer menggunakan stage start yang benar, bukan reset setiap teks berubah.
- Tidak memalsukan heartbeat atau server activity.

## 9. UX states

Pastikan seluruh kondisi:

1. Queued.
2. Active processing.
3. Long-running processing.
4. Completed.
5. Failed.
6. Stalled.
7. Activity temporarily missing.
8. Refresh/reopen while processing.
9. Reduced-motion enabled.

Activity fallback harus tetap jujur berdasarkan persisted stage.

Jangan membuat activity text generik "AI sedang berpikir" untuk operasi Crawl, HTML, atau Images yang tidak sedang memanggil AI.
