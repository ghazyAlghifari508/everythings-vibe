## 6. Strengthen [anti-ai-slop.md](http://anti-ai-slop.md)

Perketat file `.opencode/rules/[anti-ai-slop.md](http://anti-ai-slop.md)`.

Tambahkan aturan eksplisit dan dapat dipraktikkan, tanpa menghapus aturan existing yang masih berlaku.

### A. No Internal Implementation Leakage

Informasi teknis internal tidak boleh otomatis muncul pada UI publik.

Contoh yang tidak layak ditampilkan sebagai copy utama:

- `robots.txt dihormati`
- `pengukuran browser yang terverifikasi`
- `HTML statis tanpa eksekusi JavaScript`
- `AI synthesis unavailable`
- `resource verification`
- `snapshot capture`
- `DOM selector`
- `queue/worker status` yang tidak relevan

Pengecualian hanya apabila informasi teknis memang penting bagi keputusan user dan disampaikan melalui konteks atau detail yang tepat.

### B. No Redundant Controls

Dilarang membuat action baru jika fungsi yang sama sudah ada.

Contoh:

```
BAD:
[ Visual ] [ HTML Source ]
                  +
          [ Lihat HTML Source ]

GOOD:
[ Visual ] [ HTML Source ]
```

Sebelum menambahkan tombol, agent wajib memeriksa apakah fungsi tersebut telah tersedia melalui tab, menu, keyboard action, atau existing component.

### C. No Redundant Feedback

Jangan menampilkan toast, banner, dan icon sukses untuk satu aksi kecil jika satu feedback sudah cukup.

### D. No Debug Text Disguised as UX

Raw error codes, stack traces, CSS dumps, worker logs, dan internal implementation notes bukan pengganti pesan user-facing.

Error copy wajib menjawab:

- Apa yang terjadi?
- Apa dampaknya pada hasil?
- Apa yang dapat dilakukan user?

Jika suatu informasi tidak membantu user, jangan tampilkan.

### E. No Decorative Complexity

Jangan menambahkan:

- Card hanya untuk satu kalimat.
- Loading indikator ganda.
- Badge tanpa nilai informasi.
- Animasi yang tidak memberi feedback.
- Panel atau tab yang sebenarnya tidak dibutuhkan.
- CTA palsu atau disabled tanpa alasan.
- Informasi generik untuk sekadar mengisi whitespace.

### F. Mandatory Component Exploration

Sebelum membuat UI:

1. Audit existing reusable components.
2. Eksplorasi HeroUI, shadcn/ui, Magic UI, React Bits, Thinking Orbs, dan library siap pakai lain yang relevan.
3. Gunakan komponen library yang paling tepat dan kompatibel.
4. Jangan membuat ulang komponen standar dari nol.
5. Custom implementation hanya jika kebutuhan tidak terpenuhi oleh pilihan siap pakai.
6. Pertahankan design tokens, icon system, dark/light mode, accessibility, dan responsiveness.

Untuk task backend/non-UI, aturan ini tidak berarti harus memaksakan penambahan komponen.

### G. Change Scope Discipline

Agent tidak boleh menambah fitur, CTA, komponen, atau navigasi di luar kebutuhan task hanya karena dianggap akan memperindah UI.

Setiap penambahan kontrol harus punya use case, perilaku, dan alasan yang jelas.

## 7. Acceptance Criteria

- Warning preview lebih natural.
- Tidak ada redundant success toast saat copy HTML berhasil.
- Copy failure tetap memiliki feedback.
- Retry menggunakan refresh-style icon yang benar.
- Retry label konsisten dan mudah dipahami.
- Anti AI Slop rules diperketat.
- Existing functionality tidak rusak.
- Tidak ada UI baru yang tidak diminta.
- Relevant tests/typecheck/lint lulus.
