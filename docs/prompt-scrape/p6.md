# TASK: Restore Clean Scrape Images UX — Remove Duplicated Failure Surfaces

**Kompleksitas: MEDIUM**

## Masalah

UI Scrape Images mengalami downgrade, terutama ketika semua gambar gagal diambil.

Contoh kasus:

- 154 gambar ditemukan.
- 0 gambar tersimpan.
- 154 gambar gagal.

Namun UI saat ini menampilkan informasi yang sama berkali-kali:

1. Progress card menunjukkan status gagal dan statistik.
2. Hasil pengambilan gambar menunjukkan statistik lagi.
3. Card error menunjukkan jumlah gagal dan rinciannya.
4. Filter Format/Jenis tetap muncul padahal galeri kosong.
5. Empty-state card kembali memberitahu bahwa semua gambar gagal.

Hasilnya terlalu panjang, repetitif, dan tidak membantu user.

**Saya lebih menyukai tampilan Images Explorer sebelumnya. Pulihkan bagian yang memang lebih baik, bukan membuat UI baru.**

## 3. Information hierarchy

Tentukan satu tempat utama untuk menjelaskan hasil Scrape Images.

Progress card bertugas menunjukkan proses.

Result area bertugas menunjukkan hasil.

Failure summary bertugas menjelaskan kegagalan **hanya jika dibutuhkan**, bukan menjadi halaman kedua yang mengulang seluruh progress.

Pastikan semua komponen tidak menampilkan informasi yang sama tanpa alasan.

## 4. Aturan error state

- Semua gambar berhasil: tampilkan galeri biasa.
- Sebagian gagal: tampilkan galeri dan satu pemberitahuan ringan.
- Semua gagal: tampilkan satu empty/error state yang jelas.
- Belum selesai: tampilkan progress aktual.
- Tidak ada gambar ditemukan: bedakan dari gambar ditemukan tetapi gagal disimpan.
- Ada gambar tersimpan tetapi hasil fetch metadata gagal: jangan menyatakan seluruh proses gagal.

Jangan menyembunyikan hasil yang sudah berhasil hanya karena ada sebagian kegagalan.

Jangan membuat teks internal seperti `resource failed`, `persistent bytes`, atau `verification contract` tampil sebagai copy utama untuk user.
