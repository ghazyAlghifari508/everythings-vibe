# TASK 1 — FIX HISTORY MULTI-SELECT UX WITHOUT SELECTION MODE

## Context

Repository: `ghazyAlghifari508/everythings-vibe`  
Target branch: `feature/vibedesign-scrape`

Halaman Riwayat VibeScrape sekarang memiliki tombol "Pilih" dan "Selesai memilih" untuk mengaktifkan/menonaktifkan mode seleksi.

Ini merupakan interaksi yang tidak diinginkan. User ingin memilih beberapa hasil scrape dan menghapusnya sekaligus tanpa masuk ke mode khusus terlebih dahulu.

**Objective:** Hilangkan selection mode yang tidak diperlukan. Gunakan checkbox langsung pada setiap history item, dan tampilkan bulk-action toolbar hanya ketika ada item yang dipilih.

Jangan menghapus kemampuan multi-select, select-all, pagination, atau bulk delete yang sudah ada.

## 2. Remove Artificial Selection Mode

Hapus tombol:

- "Pilih"
- "Selesai memilih"

Hapus kebutuhan user untuk memanggil `selection.enter()` dan `selection.exit()` sebelum bisa memilih item.

Refactor selection state agar tidak bergantung pada active/inactive selection mode jika dependency tersebut sudah tidak diperlukan.

Jangan sekadar menyembunyikan tombol menggunakan CSS.

Hapus dead state, unused props, obsolete imports, dan test assumptions terkait mode lama.

## 4. Interaction Requirements

### A. Item Selection

- Checkbox memilih atau membatalkan pilihan satu item.
- Klik checkbox tidak membuka detail.
- Klik area konten item tetap membuka detail scrape.
- Checkbox dan link menggunakan elemen interaktif terpisah; jangan nesting button di dalam link.
- Selection harus tetap accessible melalui keyboard dan screen reader.
- Gunakan selected-row styling yang subtle, bukan highlight berlebihan.
- Touch targets cukup besar untuk perangkat mobile.

### B. Contextual Bulk Action

Ketika tidak ada item terpilih:

```
Selected count = 0
Bulk toolbar = hidden
```

Ketika ada pilihan:

```
Selected count > 0
Bulk toolbar = visible

[2 hasil dipilih]   [Batal] [Hapus 2]
```

Ketika user mengklik Batal:

- Clear selection.
- Toolbar menghilang.
- Checkbox tetap tersedia.
- Tidak perlu berpindah mode.

### C. Select All

Preserve:

- Pilih semua hasil di halaman aktif.
- Kemampuan memilih semua hasil yang cocok dengan filter di beberapa halaman, jika sudah didukung.

Pastikan scope seleksi jelas.

Contoh:

```
☑ 10 hasil dipilih di halaman ini.

[Pilih semua 120 hasil yang sesuai filter]
```

Jangan mengklaim memilih seluruh 120 item jika hanya memilih 10 item yang sedang dimuat.

### D. Pagination and Filters

- Selection behavior tetap benar ketika pagination berubah.
- Search/filter/sort tidak boleh menyebabkan penghapusan item yang tidak dimaksud.
- Perubahan filter yang membatalkan selection harus punya aturan konsisten dan dapat diprediksi.
- Jangan menambahkan mode baru untuk memperbaiki masalah ini.
- Setelah delete sukses, count dan pagination harus akurat.

### E. Delete Confirmation

```
┌───────────────────────────────────────────┐
│ Hapus 2 hasil scrape?                     │
│                                           │
│ Hasil yang dipilih akan dihapus permanen. │
│                                           │
│                  [Batal] [Hapus 2]        │
└───────────────────────────────────────────┘
```

Pertahankan existing backend authorization, cleanup, serta error handling.

Jangan rewrite bulk-delete backend kecuali ditemukan masalah yang benar-benar memerlukan perubahan.

## 5. UI Design Constraints

- Jangan menambahkan button Pilih/Selesai dalam bentuk lain.
- Jangan menggantinya dengan dropdown "Mode Pilihan".
- Jangan membuat tab atau halaman khusus untuk menghapus beberapa item.
- Jangan menampilkan checkbox dalam card besar terpisah.
- Jangan menambahkan petunjuk panjang mengenai cara memilih item.
- Gunakan komponen reusable yang sudah tersedia.
- Pertahankan layout filter dan pencarian yang sekarang sudah baik.
- Perhatikan light mode, dark mode, desktop, dan mobile.
