# TASK: Improve VibeScrape HTML Capture Fidelity for JavaScript-Heavy and Interactive Websites

**Kompleksitas: COMPLEX — HTML capture, asset dependencies, interactive website compatibility, and secure preview.**

## Konteks

Saya menggunakan fitur Scrape HTML pada:

[`https://littlespace-alpha.vercel.app/`](https://littlespace-alpha.vercel.app/)

Website tersebut merupakan game eksplorasi antariksa 3D.

Hasil VibeScrape mampu menampilkan beberapa bagian UI, seperti:

- Heading.
- Pilihan pesawat.
- Statistik pesawat.
- Kontrol warna.
- Tombol mulai.

Namun pengalaman interaktifnya tidak sama dengan website asli. Game tidak dapat dimainkan sebagaimana mestinya.

Saya ingin kamu memeriksa apakah terdapat masalah pada proses capture, penyusunan HTML, asset handling, atau rendering preview.

**Penting:** Saya tidak meminta aplikasi menyalin seluruh source code/backend/game engine website pihak ketiga. Saya ingin meningkatkan kelengkapan dan ketepatan hasil yang memang dapat didukung fitur Scrape HTML secara aman.

## 1. Audit arsitektur existing

Periksa:

- `src/features/scrape/services/render-page.ts`
- `src/features/scrape/services/render-page-helpers.ts`
- `src/features/scrape/services/page-capture.ts`
- Asset extraction dan rewriting.
- HTML serialization.
- Preview HTML generation.
- CSP.
- Iframe sandbox.
- Resource fetch/storage.
- HTML result download.
- Tests terkait.

Telusuri perbedaan antara:

1. Website original.
2. DOM yang berhasil dirender saat capture.
3. HTML hasil serialization.
4. HTML hasil download.
5. HTML hasil preview dalam aplikasi.

## 2. Bedakan jenis masalah

```
ORIGINAL WEBSITE
        │
        ▼
Browser rendered page
        │
        ▼
Captured DOM + assets
        │
        ▼
Serialized HTML
        │
        ├── Content missing?
        │       └── Capture/extraction issue
        │
        ├── Assets missing?
        │       └── Resource/dependency issue
        │
        ├── Layout broken?
        │       └── CSS/rendering issue
        │
        └── Interactions unavailable?
                ├── Script/runtime dependency
                ├── Game state
                ├── WebGL/canvas
                ├── Server dependency
                └── Sandbox restriction
```

Jangan mengklasifikasikan seluruh masalah sebagai satu bug.

## 3. Capture fidelity

Audit:

- Apakah DOM hasil capture lengkap?
- Apakah konten lazy-loaded sudah tersedia?
- Apakah bagian yang dirender secara dinamis ikut tertangkap?
- Apakah CSS external tersimpan/terhubung dengan benar?
- Apakah gambar, font, dan aset penting tersedia?
- Apakah URL asset berubah menjadi invalid?
- Apakah script-heavy content menghasilkan HTML kosong?
- Apakah WebGL/canvas memiliki representation yang tepat?
- Apakah content serialization menghapus elemen penting?

Perbaiki bug yang terbukti menyebabkan hilangnya konten atau aset yang seharusnya dapat ditangkap.

Jangan mengeksekusi arbitrary third-party JavaScript tanpa pembatasan hanya demi interaktivitas.

## 4. Visual fidelity vs interactive functionality

Contoh:

```
WEBSITE ORIGINAL
┌──────────────────────────────────────┐
│ JELAJAH ANTARIKSA                    │
│                                      │
│ [Pilihan Pesawat]                    │
│ [Warna Pesawat]                      │
│ [Mulai Penjelajahan]                 │
│                                      │
│ Real-time 3D / game controls         │
└──────────────────────────────────────┘
                │
                ▼
HTML SCRAPE
┌──────────────────────────────────────┐
│ Captured visual structure            │
│ Captured content                     │
│ Captured styles                      │
│ Available verified assets            │
│                                      │
│ Dynamic functionality not guaranteed │
└──────────────────────────────────────┘
```

Jangan mengklaim game playable jika runtime, asset, dan seluruh dependensinya tidak dapat direkonstruksi secara aman.

Jika website bergantung pada server atau aplikasi frontend kompleks, jelaskan batasan tersebut dalam dokumentasi fitur yang relevan, bukan menambahkan pesan teknis panjang ke setiap preview.

## 5. Improve supported output

Target yang realistis:

- Tampilan hasil capture lebih lengkap.
- CSS dan asset lebih konsisten.
- Scroll/section yang tersedia tetap dapat dilihat.
- Screenshot memberikan representasi visual yang akurat.
- HTML download tidak kehilangan konten yang sebenarnya sudah dicapture.
- Preview tidak menavigasi user ke halaman internal everythings-vibe.
- Resource gagal diklasifikasikan dengan benar.
- Konten yang memang tidak bisa direkonstruksi tidak diklaim berhasil direkonstruksi.

Jangan menambahkan mode baru seperti `Clone Website` atau `Interactive Reconstruction` tanpa permintaan.

Jangan menciptakan UI editor game baru.

## 6. Preserve security

Tetap jaga:

- Iframe sandbox.
- Content Security Policy.
- Origin isolation.
- Safe URL/resource handling.
- Restrictions on form/navigation.
- No arbitrary execution with privileges of the host application.

Jika ada hambatan akibat kebijakan keamanan, jangan langsung menonaktifkannya. Cari solusi yang aman atau nyatakan keterbatasannya.

## 7. UI constraints

Jangan redesign HTML viewer.

Pertahankan:

- Visual / HTML Source tabs.
- Existing DOM / Screenshot controls.
- Copy/download actions.
- Layout detail page.
- Error recovery UI yang sudah ada.

Jika UI memang harus berubah, wajib eksplorasi komponen dari:

- Existing project components

Gunakan library components yang sesuai. Jangan membuat UI dari nol.

Jangan menambah action atau toolbar duplikat.

## 8. Tests

Buat fixtures untuk:

- Static HTML.
- JavaScript-rendered DOM.
- Canvas-based UI.
- External CSS.
- External fonts.
- Lazy-loaded content.
- Nested components.
- Asset URL rewriting.
- Missing assets.
- Security sandbox.
- Complex client-side application.
- HTML downloaded versus HTML previewed.

Gunakan unit/integration tests dan mock browser interfaces.

**Jangan lakukan browser QA.**

## Definition of Done

- Perbedaan capture, serialization, dan preview diidentifikasi.
- Bug kelengkapan konten yang terbukti diperbaiki.
- Asset handling tetap aman.
- Tidak ada klaim palsu bahwa hasil HTML pasti interaktif.
- Preview dan file download konsisten sejauh didukung format.
- Isolasi keamanan tetap terjaga.
- Tidak ada mode/fitur tambahan yang tidak diminta.
- Tests relevan berhasil.
- Laporan akhir membedakan bug yang diselesaikan dan keterbatasan teknis yang memang belum dapat dipenuhi.

Jangan mengorbankan keamanan demi membuat aplikasi pihak ketiga berjalan penuh di dalam preview.
