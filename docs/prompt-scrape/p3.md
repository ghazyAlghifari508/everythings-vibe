## TASK A — Eliminate Redundant Preview Navigation

```
┌─────────────────────────────────────────────────────────┐
│ [ Visual | HTML Source ]                [Copy] [Export]│
├─────────────────────────────────────────────────────────┤
│ Mode Tampilan Visual                 [DOM | Screenshot]│

│                                                        │
│                   SCREENSHOT                           │
│                                                        │
```

Issues:

- Three stacked toolbar/navigation layers.
- Duplicate "Lihat HTML Source".
- Retry appears even when a usable screenshot is already displayed.
- Explanatory text describes implementation rather than helping the user.
- Excessive visual chrome pushes actual content downward.

### TARGET UI — MAX TWO MEANINGFUL LAYERS

```
┌─────────────────────────────────────────────────────────┐
│ [ Visual | HTML Source ]                 [Copy] [↓]   │
├─────────────────────────────────────────────────────────┤
│                               [ DOM | Tangkapan Layar ]│
├─────────────────────────────────────────────────────────┤
│                                                        │
│                                                        │
│                  ACTUAL WEBSITE VIEW                   │
│                                                        │
│                                                        │
└─────────────────────────────────────────────────────────┘
```

Rules:

- Primary tabs: Visual and HTML Source.
- Secondary visual mode selector: DOM / Tangkapan Layar.
- Secondary selector only appears when BOTH modes are meaningfully available.
- If only a screenshot is available, show the screenshot directly; no meaningless one-option selector.
- If only DOM preview is available, show it directly.
- Remove the third informational toolbar.
- Remove screenshot toolbar actions "Lihat HTML Source" and "Coba lagi preview" when not truly needed.
- Retain useful retry capability for genuine failure states only.
- Do not duplicate Copy/Download actions.
- Do not add another fallback banner for the same information.
- Copywriting must be concise and user-centered.

Remove obsolete component props, imports, state and unreachable branches when they are no longer needed.

Do not leave dead controls behind under `display:none`.

## TASK C — Fix HTML Source Scrolling

Current implementation uses a `max-h-[720px]` parent around `CodebaseSourcePreview`, while the viewer relies on nested flex sizing and `overflow-auto`.

Investigate the computed layout requirements.

Possible causes:

- Scroll container does not get a definite height.
- Parent has `overflow-hidden`.
- Child grows with content.
- `min-height` or flex constraints prevent scrolling.
- A clipping/line limit hides later lines.
- Scroll wheel events are captured elsewhere.
- Large formatted content causes rendering stalls.

Do NOT assume CSS alone is the answer.

### TARGET SOURCE VIEW

```
┌─────────────────────────────────────────────────────┐
│ [Visual] [HTML Source]                              │
├─────────────────────────────────────────────────────┤
│ HTML · 131 KB · 713 baris      [Asli | Terformat]    │
│                                                     │
│ ┌─────────────────────────────────────────────────┐ │
│ │  1  <!DOCTYPE html>                            │ │
│ │  2  <html>                                     │ │
│ │  3    <head>                                   │ │
│ │  .    ...                                      │ │
│ │  .                                             │ │
│ │  .      SCROLLABLE SOURCE AREA                 │ │
│ │  .                                             │ │
│ │713  </html>                                   │ │
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

Acceptance:

- Users can reach the final line.
- Long horizontal lines remain inspectable.
- A scroll wheel inside the viewer scrolls source content.
- Parent page scrolling does not unexpectedly block source scrolling.
- Works in Asli and Terformat.
- Switching modes does not unexpectedly jump, freeze, or lose content.
- Source selection, copy and download still function.
- Mobile and desktop remain usable.

## TASK D — Prevent Silent Truncation

The shared source viewer includes limits designed for codebase file previews.

Inspect whether those limits are appropriate for scraped HTML.

Requirements:

- A source with 713 lines must be fully accessible.
- If large documents require virtualized rendering, use an existing reliable viewer strategy.
- Preserve full source for download.
- If preview is intentionally truncated, explicitly communicate it and provide access to the rest.
- Never claim all lines are visible when data is clipped.
- Avoid copying misleading messages such as "File lengkap tersedia di repository lokal" into Scrape HTML where no local repository exists.
- Avoid unbounded rendering of extremely large HTML in one React render.
