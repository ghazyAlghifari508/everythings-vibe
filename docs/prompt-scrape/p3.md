## Konteks dan masalah utama

VibeScrape memiliki fitur Generate [DESIGN.md](http://DESIGN.md) untuk mengekstrak panduan desain dari website referensi, sehingga hasilnya bisa dipakai AI coding agent dalam membangun aplikasi dengan bahasa visual yang serupa.

Saat ini, [DESIGN.md](http://DESIGN.md) masih memiliki masalah serius pada bagian pola komponen, terutama:

- Navigation
- Buttons and CTAs
- Header
- Typography treatments
- Komponen lain yang menghasilkan banyak variasi computed CSS

Contoh output yang buruk:

```

background-color: rgba(...);
border-radius: 9999px;
border-top-color: rgb(...);
box-shadow: ...;
font-family: Inter, ...;
padding: ...;

Measured nav treatment (4 samples):
background-color: ...;
border-radius: ...;
...

Evidence: html:nth-child(1) > body:nth-child(2)
> div:nth-child(31) > ... > nav:nth-child(1)
```

Ini terlalu panjang, repetitif, sulit dipahami, dan kurang efektif sebagai instruksi implementasi AI.

Saya tidak ingin [DESIGN.md](http://DESIGN.md) berubah menjadi laporan debugging browser.

**Tujuan sebenarnya:** [DESIGN.md](http://DESIGN.md) harus menjadi design specification yang ringkas, akurat, terstruktur, dan actionable untuk AI agent.

## 4. Aturan normalisasi wajib

### A. Deduplication

- Gabungkan sampel yang memiliki visual treatment setara.
- Jangan membuat komponen baru untuk setiap elemen DOM.
- Jangan mengulang properti identik berkali-kali.
- Jangan menyatukan variasi yang memang penting secara visual.

### B. Semantic grouping

- Prioritaskan makna elemen: navigation, CTA, input, card, header, dan sebagainya.
- Jangan menganggap semua elemen dengan tag sama sebagai satu komponen identik.
- Jangan salah mengidentifikasi elemen dekoratif sebagai tombol utama.
- Jangan membuat aturan global dari satu sampel yang tidak representatif.

### C. Property prioritization

Utamakan:

- Background dan foreground color.
- Border dan radius.
- Padding, gap, dan dimensi penting.
- Font family, size, weight, line-height.
- Shadow jika memiliki fungsi visual.
- Layout dan perbedaan responsif yang terbukti.

Jangan memenuhi output dengan:

- `background-image: none`
- `border-top-width: 0px`
- `font-style: normal`
- `box-shadow: none`
- Selector DOM berantai panjang
- Properti default yang tidak memberikan instruksi implementasi berguna

Kecuali nilai tersebut memang penting untuk menjelaskan sebuah perbedaan desain.

### D. Evidence accuracy

- Jangan mengarang design tokens.
- Jangan mengarang state interaksi.
- Jangan menganggap transparansi berarti warna hitam.
- Jangan menyalin setiap computed style sebagai design token.
- Jangan memperlakukan unknown sebagai nilai pasti.
- Jangan menyimpulkan pola global hanya dari satu sampel tanpa konteks.

## 5. Tangani parameter lanjutan dengan benar

Masalah sebelumnya semakin parah ketika pengguna memilih:

- Desktop + Mobile.
- Terang + Gelap.
- Kombinasi beberapa capture.

Pastikan setiap capture memiliki scope jelas.

```
DESKTOP — LIGHT
       │
       ├── Shared design tokens
       ├── Desktop-only patterns
       └── Light theme patterns

MOBILE — LIGHT
       │
       ├── Shared design tokens
       └── Mobile-only patterns

DESKTOP — DARK
       │
       ├── Shared design tokens
       └── Dark theme overrides
```

Jangan menggabungkan seluruh CSS menjadi satu paragraf panjang.

Jangan mencampurkan radius atau ukuran tombol mobile dan desktop sehingga AI agent tidak tahu nilai mana yang harus diterapkan.

Gunakan common tokens untuk nilai konsisten dan scoped overrides untuk perbedaan yang benar-benar teramati.

Apabila website tidak menyediakan dark mode yang dapat dibuktikan, jangan mengarang dark theme.

Tambahkan/perbaiki tests untuk:

- Banyak komponen dengan treatment CSS duplikat.

- Single capture desktop.

- Konsistensi source dan rendered.

Jangan menyelesaikan masalah menggunakan `substring`, line clamp, atau menghapus seluruh component guidance.

Lakukan tests, lint, dan typecheck yang relevan. **Jangan lakukan browser QA.**
