# TASK 4 — Improve [DESIGN.md](http://DESIGN.md) Theme Availability UX Without Fabricating Dark Mode

**Repository:** `ghazyAlghifari508/everythings-vibe`  
**Branch:** `feature/vibedesign-scrape`  
**Complexity:** MEDIUM  
**Scope:** [DESIGN.md](http://DESIGN.md) result controls, verified theme availability, and user-facing explanation.

## 1. Masalah user

Saat menggunakan Generate [DESIGN.md](http://DESIGN.md), saya mengaktifkan parameter:

- Light + Dark;
- Desktop + Mobile.

Pada hasil Notion, panel kanan sudah menampilkan pilihan **Desktop / Mobile**, tetapi tidak menampilkan **Light / Dark**.

Dari dokumen hasil scrape, ditemukan:

```
Capture 1: Desktop, requested light → observed light
Capture 2: Desktop, requested dark  → observed light
Capture 3: Mobile,  requested light → observed light
Capture 4: Mobile,  requested dark  → observed light
```

Artinya, tema Dark belum berhasil diverifikasi melalui capture tersebut.

**Jangan mengarang tema Dark hanya agar tab terlihat lengkap.**

Masalah UX yang harus diperbaiki adalah user tidak mendapat penjelasan yang jelas mengapa parameter Dark yang sudah dipilih tidak menghasilkan pilihan Dark di result panel.

## 3. Perilaku target

### Case A — Light dan Dark sama-sama terverifikasi

```
+-------------------------------------------------------+
|  [Rendered] [Source]       [Desktop] [Mobile] [☼][☾] |
+-------------------------------------------------------+
|                                                       |
|     Konten DESIGN.md sesuai context terpilih          |
|                                                       |
+-------------------------------------------------------+
```

- Switcher Light/Dark muncul.
- Light menampilkan data Light yang terverifikasi.
- Dark menampilkan data Dark yang terverifikasi.
- Pemilihan konteks harus konsisten antara Design Inspector kiri dan panel dokumen kanan.
- Rendered dan Source harus mengacu ke konteks yang sama.

### Case B — Dark diminta, tetapi tidak terverifikasi

```
+-------------------------------------------------------+
|  [Rendered] [Source]           [Desktop] [Mobile]     |
+-------------------------------------------------------+
|  (i) Tema gelap belum terverifikasi pada hasil ini.   |
|                                                       |
|     Konten hasil pengukuran tema terang               |
+-------------------------------------------------------+
```

Tidak perlu tombol Dark palsu atau tab disabled yang membingungkan.

Tampilkan penjelasan singkat:

**"Tema gelap belum terverifikasi pada hasil ini."**

Jika perlu konteks tambahan, gunakan teks detail singkat:

"Capture dengan preferensi gelap masih menampilkan tampilan terang."

Penjelasan tersebut harus terlihat dekat area pemilihan konteks, bukan hanya tertimbun dalam bagian Limitations di bawah dokumen panjang.

### Case C — Hanya satu tema yang memang diminta

Jangan menampilkan warning bahwa Dark tidak tersedia jika user tidak pernah meminta Dark.

### Case D — Data evidence tidak lengkap

Bedakan:

- tema tidak diminta;
- tema diminta tetapi hasilnya tidak terverifikasi;
- tema diverifikasi;
- data capture gagal.

Jangan menyamakan semua keadaan itu.

## 6. Canonical document tetap lengkap

Theme switcher hanya memfilter preview UI.

File [`DESIGN.md`](http://DESIGN.md) yang didownload dan disalin harus tetap menggunakan canonical document lengkap, termasuk seluruh capture valid serta keterbatasannya.

Jangan membuat download berubah menjadi file Desktop-only atau Light-only hanya karena user sedang melihat konteks tersebut.

Jangan membuat dua file terpisah untuk tema.

## 7. Accessibility dan state

Pastikan:

- selected state jelas;
- keyboard interaction benar;
- screen reader dapat membaca ketersediaan tema;
- perubahan viewport meng-update theme options secara valid;
- theme selection tidak tersangkut pada context yang tidak tersedia;
- tidak ada mismatch antara Inspector dan document preview;
- unavailable theme tidak ditampilkan sebagai verified token.

## 8. Validasi

1. Light only.
2. Dark only jika memang terverifikasi.
3. Light + Dark terverifikasi.
4. Requested Light + Dark, observed semuanya Light.
5. Desktop + Mobile dengan theme availability berbeda.
6. Tema tidak diminta.
7. Missing capture evidence.
8. Pergantian viewport dan theme.
9. Inspector dan panel kanan menggunakan context yang sama.
10. Copy/download tetap menggunakan full canonical [DESIGN.md](http://DESIGN.md).
