## TASK B — Improve Design Extraction Quality

Observed problem: [DESIGN.md](http://DESIGN.md) can contain:

- Theme: unknown.
- Unconvincing semantic role mapping.
- Brand accent assigned to gray/background variables.
- Large sets of meaningless 0px spacing observations.
- Extremely large border-radius values representing fully rounded elements.
- Transparent surfaces presented as the only system surface.
- Sparse guidelines.
- AI enrichment unavailable with fallback-only output.

Investigate each source of poor quality.

Improve:

- Color role classification grounded in actual element usage.
- Handling of CSS custom properties versus measured computed styles.
- Typography hierarchy and meaningful font specimens.
- Spacing normalization: distinguish zero/default values from meaningful spacing tokens.
- Border-radius analysis: classify fully rounded/pill values instead of exposing astronomical pixel numbers.
- Surface layers and contrast.
- Component patterns: buttons, inputs, cards, navigation, sections, when observed.
- Layout density, container widths, responsive evidence if available.
- Evidence provenance and confidence.
- High-quality guideline synthesis only when supported by evidence.

Do not invent branding, components, breakpoints, or design decisions from absent evidence.

## TASK C — AI Enrichment Reliability

Inspect why the AI narrative sometimes fails and the result falls back to measurement-only output.

Determine:

- Model/provider error?
- Prompt/schema mismatch?
- Output validation failure?
- Context/token limit?
- Timeout?
- Persistence issue?
- Missing evidence?
- Other verified reason?

Fix root cause rather than hiding the indicator.

If measurements succeed but enrichment fails:

- Keep verified measurements.
- Explicitly represent enrichment state internally.
- Offer an appropriate retry/resume path from persisted evidence, if safe and feasible.
- Respect credit/idempotency controls.
- Never call a measurement-only fallback a fully enriched design document.
