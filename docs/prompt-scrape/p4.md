## 3. Scrape HTML: Include Iframes

Parameter sekarang bernama `Sertakan iframe satu origin`.

### Actual behavior to verify

Implementasi `inlineIframes()` mencoba menyisipkan HTML frame yang mempunyai origin sama ke dalam HTML hasil scrape.

Ketika opsi nonaktif, iframe dihapus pada jalur HTML tertentu.

### UX revision

Ganti label publik menjadi:

**Sertakan konten tertanam**

Helper:

> Ikutkan konten tambahan dari website yang sama, seperti formulir atau bagian halaman yang ditampilkan terpisah.

Jika diperlukan, jelaskan batasan same-origin pada tooltip bantuan singkat. Jangan menambahkan penjelasan teknis panjang secara default.

### Behavioral requirements

- Checkbox OFF: tidak melakukan inline capture iframe.
- Checkbox ON: menangani iframe yang didukung sesuai kontrak.
- Cross-origin frame tidak boleh diperlakukan sebagai same-origin.
- Frame gagal atau terlalu besar tidak menyebabkan konten halaman utama rusak.
- Tidak ada double insertion atau HTML malformed.
- Jangan memperluas akses iframe dengan mengabaikan same-origin policy.
- Jangan mengklaim fitur ini akan merekonstruksi aplikasi JavaScript secara lengkap.

### Tests

Gunakan fixtures untuk:

- Halaman tanpa iframe.
- Satu iframe same-origin.
- Beberapa iframe same-origin.
- Iframe cross-origin.
- Iframe gagal dimuat.
- Iframe melebihi batas.
- Checkbox OFF dan ON.
- HTML hasil tetap valid dan aman.

## 4. Scrape Images: Measure Resolution

Label publik yang disarankan:

Helper:

> Catat lebar dan tinggi gambar agar lebih mudah memilih aset yang sesuai.

Actual behavior:

- Saat aktif, baca natural dimensions yang tersedia.
- Jika belum tersedia, lakukan pengukuran tambahan sesuai batas sistem.
- Saat nonaktif, hindari pemeriksaan dimensi tambahan.
- Proses menemukan dan menyimpan gambar tetap berjalan.
- Jangan menyebut gambar gagal hanya karena dimensi tidak dapat ditentukan.

Gunakan hasil aktual sebagai bukti bahwa ON/OFF memengaruhi measurement pipeline.

## 6. Wait Time

Parameter `Waktu tunggu tambahan` saat ini menggunakan `waitMs`.

Untuk UX, lebih baik tampilkan dalam satuan detik jika memungkinkan.

Contoh:

```
WAKTU TUNGGU TAMBAHAN

┌────────────────────────────┐
│  0                  detik  │
└────────────────────────────┘

Gunakan jika konten website muncul
beberapa saat setelah halaman dibuka.
```

Jika UI menggunakan detik:

- Konversikan secara eksplisit ke nilai milidetik untuk backend.
- Hindari mismatch unit.
- Validasi minimum/maksimum secara konsisten.
- Pertahankan kontrak internal jika tidak perlu dimigrasikan.
- Nilai nol harus berarti tidak ada tambahan waktu tunggu.
- Jangan menampilkan input `10000 ms` yang sulit dimengerti tanpa kebutuhan.
