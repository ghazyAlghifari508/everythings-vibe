# TASK: Fix VibeScrape [DESIGN.md](http://DESIGN.md) AI Synthesis Reliability &amp; Meaningful Deep Analysis

**Priority:** P1  
**Complexity:** Complex  
**Target branch:** `feature/vibedesign-scrape`

## 1. Goal

Pastikan parameter **Analisis Mendalam** pada Generate [DESIGN.md](http://DESIGN.md) benar-benar memberikan hasil analisis desain yang lebih bermakna, bukan hanya output yang lebih panjang atau pengulangan raw measurements.

Perbaiki keandalan AI synthesis/enrichment, validasi output, persistensi status, dan penanganan kegagalan tanpa memalsukan hasil.

Ini adalah perbaikan pipeline AI, bukan redesign UI.

## 2. Laporan user

User menghasilkan [DESIGN.md](http://DESIGN.md) untuk Notion dengan parameter:

- Desktop + Mobile.
- Light + Dark.
- Analisis mendalam.
- CSS + Tailwind.

File yang dihasilkan banyak berisi:

- Raw design tokens.
- Daftar measurements dan frequency.
- Pengulangan deskripsi komponen.
- Per-capture data yang panjang.
- Aturan Do/Don't yang repetitif.
- Catatan teknis yang mendominasi hasil.

Pada dokumen yang ditinjau, terdapat indikasi AI synthesis tidak menghasilkan narrative, tidak tersedia, atau tidak berjalan.

Output pengukuran tetap bisa berguna, tetapi pengguna tidak boleh mendapatkan kesan bahwa analisis mendalam telah berhasil jika tahap AI yang seharusnya menambah interpretasi desain ternyata gagal.

## 3. Audit pipeline secara end-to-end

Baca [AGENTS.md](http://AGENTS.md) dan aturan project.

Trace:

```
User selects Deep Analysis
          |
          v
Validated settings
          |
          v
Capture visual evidence
          |
          v
Canonical design model
          |
          v
AI synthesis / enrichment
          |

          |
          v

          |
          v

          |

```

Cari implementasi aktual untuk:

- Request schema dan parsing parameter.
- Capture-to-model transform.
- Prompt penyusunan design system.
- Provider/model gateway call.
- Timeout dan retry policy.
- AI response validation.
- Error handling.
- Persistence metadata.
- Rehydration dari history.
- Generation status/activity.
- Document renderer.
- Enrichment usability assessment.

Periksa kemungkinan AI gagal karena output terlalu panjang, token limit, schema mismatch, timeout, context size, konfigurasi provider, atau masalah persistence **hanya sebagai hipotesis yang harus diverifikasi**, bukan asumsi root cause.

## 4. Perjelas kontrak Analisis Mendalam

Parameter deep analysis harus meningkatkan kualitas interpretasi yang didukung evidence, misalnya:

1. Hierarki visual: ukuran dan penggunaan typography.
2. Sistem warna: primary, secondary, text, background, borders, dan state jika terbukti.
3. Struktur layout dan pola spacing.
4. Komponen reusable dan variasi yang benar-benar teramati.
5. Perbedaan desktop/mobile.
6. Perbedaan tema Light/Dark hanya jika terverifikasi.
7. Prinsip implementasi yang dapat dijalankan coding agent.
8. Design Do/Don't yang spesifik terhadap website.
9. Confidence dan ketidakpastian untuk bagian yang belum teramati.

Analisis mendalam **tidak sama dengan mengeluarkan lebih banyak angka mentah**.

Dilarang:

- Mengarang interaction states.
- Mengarang breakpoint.
- Mengarang dark theme.
- Menyatakan hasil inferensi sebagai measurement.
- Menghasilkan narasi panjang generik.
- Mengulang Do/Don't identik untuk setiap capture.
- Membuat prompt agent yang hanya berkata "ikuti semua measurements".

## 5. Reliability dan error handling

Gunakan structured, validated AI output dengan schema yang cocok dengan model data.

Pastikan:

- Kesalahan provider dan validasi dibedakan dengan benar.
- Status AI enrichment disimpan eksplisit.
- Dokumen fallback measurement-only tidak diberi label deep analysis yang sukses.
- AI output yang gagal divalidasi tidak boleh disisipkan diam-diam.
- Data pengukuran valid tidak hilang akibat AI synthesis gagal.
- Retry bila memang sudah tersedia tetap aman, idempotent, dan tidak menduplikasi record atau menagih operasi yang sama secara tidak benar.
- UI tidak membuat janji palsu tentang keberhasilan analisis.

Perbaiki akar masalah teknis yang ditemukan, bukan sekadar menambah retry atau memperbesar timeout tanpa evidence.

## 6. Aturan presentasi informasi publik

Jangan menjejali UI publik dengan debugging internal.

Contoh teks yang tidak layak dijadikan pesan dominan:

- Raw AI provider error.
- Prompt token diagnostics.
- Nama fungsi atau pipeline internal.
- "Synthesis enrichment unavailable" tanpa penjelasan manfaat.
- Alasan teknis berulang yang tidak membantu pengguna.

Jika hasil hanya berupa data terukur, user harus tetap bisa menggunakannya, tetapi aplikasi tidak boleh mengklaim hasil telah mendapat analisis lanjutan.

Jika perlu menyampaikan keterbatasan yang berdampak pada kualitas, gunakan bahasa singkat dan informatif, bukan paragraf teknis panjang.

Jangan menambahkan tombol atau banner baru tanpa kebutuhan nyata.
