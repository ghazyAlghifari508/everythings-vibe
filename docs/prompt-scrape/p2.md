# TASK — FIX SCRAPED HTML PREVIEW NAVIGATION LEAKAGE

## Problem

A user scrapes HTML from an external website and opens the result in VibeScrape.

Inside the preview, the user clicks a Login button, navigation link, or another website control.

Instead of behaving as a safe preview of the original website, the iframe may navigate to routes belonging to VibeEverything itself.

Example:

Original website:  
[`https://example.com/login`](https://example.com/login)

Incorrect result:  
[`https://everythings-vibe.app/login`](https://everythings-vibe.app/login)

This is a functional and isolation bug.

The preview must never accidentally reinterpret external website navigation as internal application navigation.

## Root-Cause Candidate To Verify

Current code removes `<base>` from captured HTML.

Some link attributes, especially navigation anchors, are not rewritten with the correct website source context.

A relative link such as:

```
<a href="/login">Login</a>
```

can therefore resolve relative to the application document hosting `srcDoc`.

Confirm the complete navigation behavior and related security constraints before patching.

## TASK A — Correct URL Semantics

Handle:

- Relative links: `/login`, `./pricing`, `../help`.
- Absolute URLs.
- Query-string links.
- Hash anchors.
- URLs with encoded characters.
- `<base>` tags.
- Different source origins and pathnames.
- Redirect-like controls where actual behavior can be established.

Never resolve external source navigation against the VibeEverything application origin by mistake.

Do not corrupt asset URL rewriting while fixing navigation.

Maintain a clear separation between:

1. Resource loading URLs (styles, fonts, images).
2. Navigational URLs (anchors, forms).
3. Internal VibeEverything routes.
4. Non-navigation URLs (hash, mailto, tel, etc.).

Do not treat navigation URLs as asset proxy URLs.

## TASK B — Choose a Deliberate Navigation Policy

Recommended default: read-only preview navigation.

- Clicking a link must not replace the main VibeEverything route.
- Do not let navigation silently replace the captured preview with another external page.
- Do not enable form submissions to external systems.
- Do not execute login flows, write actions, or external application behavior in the preview.
- If an explicit "Open original website" action already exists, reuse it rather than adding another button.
- External navigation, when explicitly available, must use validated destination URLs and appropriate tab isolation.

Hash navigation within the captured document may remain usable if safe.

If a different navigation policy is warranted by existing product contracts, document the rationale before implementing it.

Do not add toolbars, modal warnings, or duplicate navigation controls.

## TASK C — Preserve Preview Security

Preserve or strengthen:

- iframe sandbox isolation.
- CSP.
- No top-level navigation privileges.
- No same-origin escalation.
- No arbitrary third-party script execution.
- No unsafe form submission.
- No access to application localStorage/cookies.
- Asset proxy authorization.
- SSRF and URL validation.
- Correct isolation of preview readiness reporting.

The preview's own controlled reporting mechanism must continue to work.

Do not use a broad `allow-same-origin` or `allow-top-navigation` workaround.

Do not fix the bug by giving untrusted HTML unrestricted browser privileges.
