## 3. Perbaiki masalah spinner pada awal permintaan

Saat ini status awal `queued` menampilkan dot statis, lalu baru berubah menjadi spinner ketika status masuk ke tahap pemrosesan.

Saya ingin ada feedback loading yang jelas sejak permintaan berhasil dikirim.

Perilaku target:

```
User mengirim permintaan
         │
         ▼
◌ Menunggu giliran
         │
         ▼
◌ Mengambil halaman
         │
         ▼
✓ Mengambil halaman selesai
```

Gunakan spinner circular normal yang selaras dengan ikon proyek. Tetap gunakan teks **Menunggu giliran** ketika worker belum aktif, agar UI tidak mengklaim proses yang belum terjadi.

**Catatan:** Ini hanya koreksi kecil terhadap indikator antrean. Jangan gunakan masalah ini sebagai alasan untuk mengubah desain loading historis.

Jika implementasi historis sudah memiliki feedback antrean yang benar, pertahankan versi historis tersebut.

## 4. Pertahankan fungsi terbaru

Pastikan:

- Progress tetap disinkronkan dengan status job asli.
- Status queued, capturing, extracting, generating, saving, completed, dan failed tetap ditangani sesuai mode yang relevan.
- Mode yang tidak menjalankan tahap tertentu tidak menampilkan tahap palsu.
- Informasi yang belum tersedia tidak diberi angka atau persentase buatan.
- Perubahan status tidak menghilangkan data hasil.
- Status failed dan retry tetap berfungsi.
- Tampilan selesai tidak berubah menjadi loading permanen.
- Tidak ada flash atau pergantian layout besar saat status berubah.
- Konten responsif tetap nyaman dibaca.
