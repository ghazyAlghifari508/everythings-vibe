## 3. Temuan awal untuk diverifikasi

Pemeriksaan branch sebelumnya menemukan beberapa hal:

**A. Inline stylesheet dapat dilewati ketika fetch gagal.**

`html-document.ts` memiliki fungsi `inlineStyles()` yang mengambil stylesheet eksternal. Ketika fetch stylesheet gagal, error ditangkap dan hasil stylesheet dapat dikosongkan.

Periksa apakah hal ini menyebabkan CSS yang penting hilang pada HTML hasil scrape, apakah CSS asli masih dipertahankan, dan bagaimana kasus partial failure ditangani.

**B. Preview menggunakan asset proxy dan security capability.**

Periksa rewrite URL CSS, font, gambar, `@import`, relative paths, MIME, redirect, token/capability expiration, response status, dan kebijakan Content Security Policy.

Pastikan resource yang seharusnya berhasil dimuat tidak menjadi gagal hanya karena kesalahan rewrite, ketidaksesuaian origin, atau masalah request pertama.

**C. Readiness detection belum tentu sama dengan stylesheet readiness.**

Pada implementasi sebelumnya, status `ready` bisa dicapai ketika ada konten visual yang terdeteksi, meski tidak seluruh stylesheet penting berhasil dimuat.

Periksa kemungkinan false-positive ready, flash of unstyled content, respons iframe yang terlalu cepat, serta event load/error yang datang setelah status final.

**D. Pergantian DOM/Screenshot dapat memicu remount.**

Investigasi mengapa remount atau refresh terlihat memperbaiki keadaan. Cek apakah ada state lama, race condition, asset URL yang baru tersedia, atau readiness yang tidak disinkronkan.

Ini merupakan kandidat masalah berdasarkan kode, **bukan root cause yang sudah terbukti**. Validasi dengan bukti sebelum mengubah implementasi.

## 5. Requirements teknis

### A. First-load consistency

Perbaiki lifecycle preview supaya hasil pertama tidak kalah kualitas dengan hasil setelah refresh.

- Hindari race antara `srcDoc`, iframe mount, stylesheet loading, readiness report, dan asset proxy.
- Reset state secara tepat ketika dokumen/attempt berubah.
- Abaikan event lama dari attempt sebelumnya.
- Hindari remount yang tidak perlu.
- Bedakan `preparing`, `ready`, `degraded`, `empty`, dan `failed` dengan semantik yang konsisten.
- Jangan memutuskan gagal/empty berdasarkan satu observasi prematur.
- Gunakan penanganan timeout yang berbatas, bukan delay acak untuk menyembunyikan bug.
- Jangan membuat timer yang terus berjalan tanpa batas.
- Jangan menambahkan reload otomatis berulang sebagai solusi utama.

### B. Stylesheet readiness

Gunakan sinyal resource yang sesuai, termasuk load/error stylesheet bila relevan.

Periksa:

- CSS eksternal;
- CSS inline;
- CSS `@import`;
- resource hasil rewrite;
- font yang memengaruhi hasil visual;
- response status dan MIME;
- CSP;
- stylesheet yang dihilangkan ketika ekstraksi gagal.

Jangan menyamakan *DOM memiliki teks* dengan *CSS siap diterapkan*.

Tetapkan kriteria `ready` yang realistis bagi snapshot hasil scrape, dan laporkan `degraded` ketika CSS penting tidak tersedia.

### C. Resource recovery

Jika ditemukan kegagalan sementara yang benar-benar retryable, gunakan recovery terbatas dan dapat dijelaskan. Jangan retry request yang jelas diblokir secara permanen atau tidak diizinkan.

Jangan mengubah source website, merusak HTML hasil download, atau mengarang CSS pengganti supaya screenshot tampak mirip.

### D. Security tetap wajib

JANGAN:

- menonaktifkan CSP secara sembarangan;
- menghapus sandbox iframe;
- memberi `allow-same-origin` atau permission berbahaya tanpa pembuktian kebutuhan dan evaluasi keamanan;
- menjalankan seluruh JavaScript pihak ketiga untuk sekadar memperbaiki CSS;
- mem-bypass kontrol akses atau pembatasan website;
- membuat proxy terbuka yang bisa digunakan untuk arbitrary URL fetching tanpa validasi.

Pertahankan sifat **read-only, isolated visual preview**.

Jika suatu website sangat bergantung pada JavaScript dan tidak bisa direproduksi aman sebagai DOM snapshot, jelaskan keterbatasannya dan gunakan screenshot yang sudah tersedia sebagai fallback sesuai arsitektur existing.

Jangan menjanjikan website pihak ketiga dapat direplikasi secara interaktif 100%.
