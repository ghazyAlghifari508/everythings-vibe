
## 5. Multi-Viewport Behavior

Desktop + Mobile harus menghasilkan perbandingan, bukan sekadar penggabungan semua CSS.

Contoh bentuk keluaran:

```
RESPONSIVE DESIGN

                     DESKTOP        MOBILE
Typography / H1      48px           32px
Content width        1152px         fluid
Card radius          12px           12px
Grid columns         3              1

SHARED
- Font family
- Brand colors
- Consistent component radius

DIFFERENCES
- Heading size
- Column count
- Container spacing
```

**Angka di atas hanya ilustrasi struktur, bukan nilai untuk di-hardcode.**

Aturan:

- Perbedaan hanya boleh ditulis jika benar-benar didukung capture.
- Jangan mengklaim breakpoint CSS asli hanya dari dua ukuran layar.
- Jangan menganggap perbedaan konten antar-capture sebagai perubahan desain jika belum diverifikasi.
- Jangan menggabungkan token yang bertentangan menjadi satu aturan global.
- Hindari duplikasi identik pada banyak capture.
- Capture yang gagal harus menghasilkan hasil parsial atau status akurat sesuai kontrak, bukan aturan palsu.

## 6. Multi-Theme Behavior

Parameter Terang + Gelap saat ini menggunakan preferensi warna browser.

Pastikan sistem memahami perbedaan antara:

- `prefers-color-scheme` yang diminta.
- Tampilan website yang benar-benar terobservasi.
- Tema website yang mungkin dikelola melalui state, cookie, local storage, atau tombol.

Jangan melabeli suatu capture sebagai dark theme website hanya karena preferensi browser disetel ke dark.

Jika kedua capture mempunyai gaya yang sama, jangan mengarang dua palet berbeda.

Jika tema berbeda benar-benar terukur, buat section khusus:

```
COLOR SCHEME

LIGHT
- Background: measured value
- Text: measured value
- Action: measured value

DARK
- Background: measured value
- Text: measured value
- Action: measured value

SHARED
- Typography
- Spacing
- Component shape
```

Jika satu tema tidak dapat diverifikasi, jangan memunculkan klaim dukungan tema yang tidak terbukti.

### Component Specifications

- Identitas/peran komponen.
- Visual properties yang relevan.
- Ukuran, radius, spacing, typography.
- Perbedaan viewport/theme bila tersedia.
- Usage guidance.
- Constraint agar agent tidak salah menerapkan style.

Prioritaskan hal yang memengaruhi hasil implementasi.

Contoh:


```

- Background: [measured token]
- Radius: [measured radius]
- Height: [measured value]
- Typography: [measured typography]

Mobile:

DON'T:
- Jangan mengganti radius button dengan 0px
  jika spesifikasi button yang relevan memiliki
  rounded corners.
```

Jangan mencampur radius input, card, dan button menjadi satu global radius jika bukti menunjukkan nilai berbeda.
