# TASK: Replace VibeScrape Images Pagination with Progressive Load More

**Project:** EvVibe / Everythings-Vibe  
**Feature:** VibeScrape → Scrape Images → Images Explorer  
**Scope:** Frontend gallery interaction + relevant tests  
**Complexity:** Medium

## 1. Objective

Ubah navigasi galeri hasil Scrape Images dari pagination berbasis nomor halaman menjadi **Progressive Load More**.

Saat ini, pengguna hanya melihat 12 gambar per halaman. Untuk melihat gambar berikutnya, pengguna harus berpindah halaman melalui pagination, sehingga gambar sebelumnya menghilang dari tampilan.

Implementasi baru harus memungkinkan pengguna melihat 12 gambar pertama, kemudian menampilkan 12 gambar tambahan setiap kali menekan tombol **Tampilkan lebih banyak**.

Gambar yang sudah ditampilkan harus tetap berada di galeri. Gambar tambahan muncul setelah gambar sebelumnya, bukan menggantikannya.

Tujuan UX utama adalah mempermudah eksplorasi, perbandingan, dan pemilihan aset visual tanpa navigasi bolak-balik antarhalaman.

Ini merupakan perubahan interaksi galeri, bukan redesign keseluruhan fitur Scrape Images.

## 4. Implementation Requirements

### 4.1 Replace pagination state

Hapus mekanisme pagination khusus galeri Images Explorer yang tidak lagi dibutuhkan.

Ganti pendekatan `currentPage` dengan **visible item limit**, yaitu jumlah maksimum gambar yang boleh ditampilkan saat ini.

Gunakan batch awal sebanyak 12 gambar, mengikuti ukuran pagination lama.

Contoh algoritma referensi:

```
const LOAD_MORE_BATCH_SIZE = 12;

const [visibleLimit, setVisibleLimit] = useState(
  LOAD_MORE_BATCH_SIZE,
);

// `visible` adalah daftar gambar berhasil
// yang telah melewati filter yang aktif.
const displayedImages = visible.slice(0, visibleLimit);

const displayedCount = displayedImages.length;
const totalCount = visible.length;

const remainingCount = Math.max(
  0,
  totalCount - displayedCount,
);

const nextBatchCount = Math.min(
  LOAD_MORE_BATCH_SIZE,
  remainingCount,
);

const hasMore = remainingCount > 0;

function handleLoadMore() {
  setVisibleLimit((current) =>
    Math.min(current + LOAD_MORE_BATCH_SIZE, totalCount),
  );
}
```

Contoh ini menjelaskan perilaku yang diharapkan, bukan instruksi untuk menyalin kode tanpa penyesuaian.

Pastikan perubahan mengikuti gaya dan pola state management React yang sudah digunakan dalam proyek.

**Aturan wajib:**

1. Initial limit = 12.
2. Setiap klik menambah kapasitas sebanyak 12.
3. Tidak pernah melebihi jumlah gambar yang sesuai filter.
4. Gambar sebelumnya tetap ditampilkan.
5. Tidak ada duplikasi.
6. Urutan gambar tetap stabil.
7. Jika hasil kurang dari atau sama dengan 12, tampilkan semuanya.
8. Jika hasil sudah seluruhnya ditampilkan, sembunyikan tombol Load More.

Jangan memakai infinite scrolling otomatis atau Intersection Observer untuk memicu load tanpa klik pengguna.

### 4.2 Preserve existing ImageCard functionality

Pertahankan seluruh kemampuan `ImageCard` yang sudah tersedia.

Termasuk:

- Thumbnail gambar.
- Format dan resolusi gambar.
- Klasifikasi gambar.
- URL sumber.
- Copy source URL.
- Download gambar.
- Link menuju sumber asli.
- Penanganan gambar yang gagal dimuat.
- Refresh asset URL jika capability kedaluwarsa.
- Retry dan cooldown download.

Load More hanya mengatur **berapa banyak ImageCard yang dirender**, bukan mengubah cara tiap kartu bekerja.

Gunakan [`image.id`](http://image.id) sebagai stable React key seperti implementasi sekarang.

Jangan membuat ulang `ImageCard` atau menggantinya dengan komponen generik yang justru menghilangkan fitur.

### 4.3 Filtering behavior

Pertahankan filter Format dan Jenis beserta seluruh opsi yang tersedia.

Perilaku yang wajib diterapkan:

**Saat filter berubah:**

- Reset `visibleLimit` menjadi 12.
- Terapkan filter terlebih dahulu.
- Hitung ulang jumlah gambar dari hasil filter.
- Tampilkan maksimal 12 gambar pertama yang cocok.
- Hitung ulang sisa gambar dan label tombol.

**Saat Reset filter:**

- Kembalikan seluruh filter ke nilai awal.
- Reset visible limit menjadi 12.
- Tampilkan kembali 12 gambar pertama dari keseluruhan gambar berhasil.

**Saat tidak ada gambar yang cocok:**

- Pertahankan empty state yang sekarang.
- Tombol Load More tidak boleh muncul.
- Pengguna tetap bisa mereset filter.

Gunakan handler filter yang sudah tersedia. Tidak perlu membuat state management atau hook tambahan hanya untuk perilaku sederhana ini.

### 4.4 Handle changing image data

Daftar gambar dapat berubah melalui update props, polling, atau pembaruan hasil ekstraksi.

Pastikan logic tidak rusak ketika data berubah setelah pengguna melakukan Load More.

Contoh:

```
Awal:
25 gambar
Visible limit: 24

Kemudian data berubah:
10 gambar

Hasil:
10 gambar tampil
Tidak ada tombol Load More
Tidak ada akses indeks invalid
```

Jika data bertambah, limit yang sudah dipilih pengguna boleh tetap dipertahankan selama filter dan identitas galeri tidak berubah.

Namun, jangan membuat jumlah gambar yang ditampilkan melebihi batas limit hanya karena data baru bertambah.

Gunakan derived state untuk menghitung daftar yang tampil. Hindari penyimpanan array gambar duplikat dalam React state yang berpotensi tidak sinkron dengan props.

Jika komponen dipakai untuk berpindah antar-scrape tanpa unmount, pastikan state ekspansi dari scrape sebelumnya tidak bocor ke scrape berikutnya. Periksa lifecycle aktual sebelum menambahkan mekanisme reset.

### 4.5 Counter and progress indicator

Ganti ringkasan rentang pagination lama:

`Menampilkan 1–12 dari 67 gambar`

Menjadi ringkasan akumulatif:

`Menampilkan 12 dari 67 gambar`

Setelah klik:

`Menampilkan 24 dari 67 gambar`

Gunakan angka nyata dari daftar gambar yang sesuai filter.

**Penting:** Bedakan tiga jumlah berikut:

- `verifiedCount`: gambar yang benar-benar berhasil disimpan.
- `filteredCount`: gambar berhasil yang memenuhi filter aktif.
- `displayedCount`: gambar yang saat ini dirender di galeri.

Jangan memasukkan gambar gagal ke denominator galeri.

Pertahankan ringkasan galeri bagian atas, tetapi pastikan informasi atas dan bawah tidak saling bertentangan atau menghasilkan counter berulang yang tidak berguna.

Di footer Load More, tambahkan progress indicator horizontal yang sangat sederhana dan mengikuti design system EvVibe.

Persentasenya berasal dari:

`displayedCount / filteredCount * 100`

Progress indicator ini hanya menjelaskan bagian galeri yang sedang ditampilkan. **Jangan menyajikannya sebagai progres proses scraping atau download.**

Gunakan elemen progress yang semantik dan aksesibel jika tersedia. Jika belum ada, gunakan implementasi ringan dengan nilai aktual dan atribut ARIA yang sesuai.

Jangan menambahkan animasi palsu, progress yang menggunakan timer, atau visual yang tidak mewakili data nyata.

Footer progres hanya diperlukan ketika total hasil filter melebihi batch awal. Jika seluruh gambar sudah terlihat, teks ringkasan boleh tetap tampil, tetapi tombol harus hilang.

### 4.6 Load More button UX

Gunakan tombol yang konsisten dengan design system EvVibe.

Prioritaskan komponen `Button` atau pola tombol yang sudah tersedia di `src/components/ui`.

Spesifikasi:

- Posisi di bawah grid.
- Rata tengah.
- Label mudah dipahami.
- Contoh: `Tampilkan 12 gambar lagi`.
- Jika tersisa 5, label: `Tampilkan 5 gambar lagi`.
- Ikon chevron-down boleh digunakan jika sesuai dengan Hugeicons yang sudah terpasang.
- Ukuran touch target nyaman pada mobile.
- Hover, keyboard focus, dan disabled behavior mengikuti design system.

Jangan membuat tombol dengan warna acak, gradient berlebihan, shimmer, efek glowing, atau komponen UI baru yang tidak diperlukan.

Karena implementasi ini menggunakan penambahan item dari array lokal secara sinkron, **jangan menciptakan loading spinner, skeleton, atau artificial delay** setiap kali tombol diklik.

### 4.7 Scroll and navigation behavior

Hapus perilaku pagination yang memanggil `scrollIntoView` untuk membawa pengguna ke awal galeri.

Load More harus menambahkan item tanpa mengubah posisi scroll secara paksa.

Pastikan:

- Gambar baru berada setelah gambar terakhir.
- Konten lama tidak di-reset.
- Tidak ada smooth scroll ke atas.
- Tidak ada auto-scroll sampai akhir halaman.
- Tidak ada full-page navigation.
- Tidak ada URL query pagination yang diperkenalkan tanpa kebutuhan nyata.
- Button dapat dioperasikan menggunakan keyboard.

Perubahan ini tidak boleh mengakibatkan lompatan layout yang tidak perlu.

### 4.8 Performance

Jangan mengklaim Load More otomatis membuat backend lebih ringan.

Pada implementasi saat ini, pembatasan galeri dilakukan di frontend melalui array yang sudah diterima. Migrasi ini tetap dapat dilakukan secara client-side.

Hal yang perlu dipastikan:

- Hanya render maksimal sejumlah gambar sesuai `visibleLimit`.
- Jangan render seluruh gambar lalu menyembunyikan sisanya dengan CSS.
- Pertahankan lazy loading thumbnail yang sudah dipakai oleh `ImageCard`.
- Pertahankan `decoding="async"` jika masih digunakan.
- Jangan menambahkan request API baru setiap kali Load More diklik.
- Jangan mengubah API scraper, database, worker, atau image storage untuk perubahan ini.
- Hindari perhitungan dan state tambahan yang tidak dibutuhkan.

Server-side pagination atau virtualization bukan bagian dari task ini kecuali ditemukan kendala aktual yang benar-benar menghalangi implementasi.
