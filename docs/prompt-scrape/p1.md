# PHASE 1 — SCRAPE WORKSPACE UI/UX CLEANUP

## Objective

Perbaiki UI/UX bersama pada modul VibeDesign Scrape di branch aktif `feature/vibedesign-scrape`.

Cakupan utama:

1. Warning scraping dipindahkan ke atas input URL dan disatukan secara visual.
2. Hilangkan navigasi Kembali yang duplikat.
3. Standarkan dropdown agar icon, spacing, dan alignment rapi.
4. Investigasi dan hilangkan efek heading yang terlihat seperti mengetik–menghapus–mengetik ulang.
5. Pastikan seluruh perubahan konsisten pada Crawl, [DESIGN.md](http://DESIGN.md), HTML, dan Images.

Jangan redesign seluruh aplikasi atau mengubah business logic scraping tanpa alasan yang terverifikasi.

## Mandatory Repository Inspection

Sebelum implementasi:

- Baca [`AGENTS.md`](http://AGENTS.md) sampai EOF dan semua `.opencode/rules/*` yang relevan, terutama basic-rules, no-assumptions, anti-ai-slop, anti-satisficing, skills-mcp, no-hardcode, no-type-bypass, atomic-commit.
- Periksa branch, upstream, status Git, dan perubahan yang sudah ada. Jangan overwrite pekerjaan lain.
- Trace actual components dari route sampai UI.
- Inspeksi `scrap.index.tsx`, `scrap-mode-switcher.tsx`, `scrape-workspace-form.tsx`, `scrape-form-notice.tsx`, `scrape-back-link.tsx`, dan seluruh result component.
- Cek design tokens, komponen UI reusable, serta cara light/dark theme dikelola.
- Sebelum membuat komponen custom, cari opsi dari komponen existing atau library yang kompatibel, misalnya shadcn, HeroUI, Magic UI, React Bits, dan library relevan lain. Gunakan yang sesuai konteks; jangan memasang library hanya demi dekorasi.

## TASK A — Warning + URL Input Composition

Saat ini warning berada dalam card tersendiri di bawah input. Ini tidak sesuai.

Ubah menjadi satu area form yang utuh, dengan warning di atas input URL dan separator tipis.

### TARGET VISUAL

```
              WEBSITE EXTRACTION WORKSPACE

      [ Crawl ] [ DESIGN.md ] [ HTML ] [ Images ]

            Deskripsi mode yang dipilih

┌─────────────────────────────────────────────┐
│ ⓘ Tidak semua website dapat di-scrape        │
│   Beberapa website membatasi akses otomatis │
│   atau memerlukan login.                    │
│                                             │
│ ─────────────────────────────────────────── │
│                                             │
│ https:// │ example.com              │  ↑   │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ Parameter lanjutan                       ˅  │
└─────────────────────────────────────────────┘
```

Diagram menunjukkan pengelompokan, bukan keharusan memakai border besar pada semua elemen.

Implementation requirements:

- Warning harus berada sebelum input URL, baik secara visual maupun urutan DOM yang masuk akal.
- Jangan render warning sebagai card lain di luar form.
- Gunakan background dan border yang selaras dengan input.
- Gunakan divider ringan, bukan beberapa nested cards.
- Hilangkan instruksi redundant di bawah form: "Gunakan website publik yang dapat diakses tanpa login", selama informasi sudah disampaikan jelas di atas.
- Pertahankan input validation, loading submit, disabled states, idempotency key, dan error feedback.
- Warning merupakan informasi umum, bukan error alert yang tampil berwarna merah.
- Responsive dan accessible di mobile maupun desktop.

## TASK B — Single Back Navigation

Saat ini detail page mempunyai tombol `← Kembali`, tetapi beberapa result component juga memiliki copy navigasi seperti `← Kembali ke hasil scrape`.

### TARGET

```
← Kembali

Website Blueprint
https://example.com

[ Results ... ]
```

BUKAN:

```
← Kembali

← Kembali ke hasil scrape
Website Blueprint
```

Requirements:

- Gunakan satu canonical back-navigation component pada level detail route.
- Hilangkan teks/tombol back duplikat dari result component.
- Pertahankan kemampuan kembali ke History jika berasal dari History, atau ke Scrape jika berasal dari form.
- Jangan menggunakan `history.back()` secara sembarang jika return path yang aman sudah tersedia.
- Periksa semua result mode dan failed state.

## TASK D — Heading Stability

User melaporkan heading "Website Extraction Workspace" tampak mengetik, menghapus, lalu mengetik ulang.

Source yang sebelumnya diperiksa menampilkan heading statis pada `scrap.index.tsx`; tidak ada explicit typewriter animation di komponen tersebut.

Maka:

1. Trace parent layouts, global CSS, animation utilities, hydration, transition, suspense, route remount, dan sumber state terkait.
2. Cari bukti mekanisme sebenarnya sebelum mengubah kode.
3. Pastikan heading tidak dianimasikan sebagai typewriter atau di-remount secara tidak perlu saat mode berubah.
4. Jangan membuat workaround berupa delay atau penyembunyian heading yang tidak menyelesaikan masalah.
5. Jika bug tidak dapat dibuktikan secara statis tanpa browser runtime, catat investigasi dan keterbatasannya. Jangan mengklaim resolved tanpa dasar.

## TASK E — UI Consistency

Periksa bersama:

- Light mode dan dark mode.
- Hierarki heading dan subtitle.
- Warna muted/secondary text.
- Container width.
- Button sizing.
- Field focus states.
- Mobile overflow.
- Empty/validation/disabled states.
- Alignment icon dan typography.

Jangan menambahkan gradient dekoratif, kartu bertumpuk, atau animasi AI generik.

## Automated Verification

Tambahkan/perbarui unit/component tests untuk:

- Warning placement dan non-duplication.
- Form submit/validation.
- Canonical back link dan return path.
- Dropdown selection/state.
- Heading static rendering dan route behavior yang dapat diuji tanpa browser.

Jalankan test, typecheck, lint, dan build menggunakan scripts nyata di `package.json`.

Tidak menjalankan browser QA, Playwright UI, screenshot QA, atau localhost visual inspection.

## Delivery Rules

- Commit secara atomik untuk perubahan yang koheren.
- Push branch yang benar setelah verification.
- Periksa clean working tree, outgoing commits, dan upstream synchronization.
- Laporkan file yang berubah, root causes, komponen reusable yang dipakai, automated test results, dan keterbatasan yang belum bisa diverifikasi.

## Acceptance Criteria

- Warning ada DI ATAS input dan visually integrated.
- Tidak ada warning card terpisah atau instruksi redundant.
- Setiap result page hanya mempunyai satu tombol Kembali.
- Dropdown rapi dan konsisten pada kedua tema.
- Tidak ada efek typewriter yang tidak sengaja; jika diagnosis belum konklusif, jangan klaim selesai.
- Tidak ada regresi pada request form atau backend Scrape.
