# TASK — FIX VIBESCRAPE HISTORY SELECTION UX WITH PROGRESSIVE DISCLOSURE

## 1. Objective

Perbaiki pengalaman multi-select pada halaman **Riwayat VibeScrape** dengan menerapkan prinsip UX yang matang: **Progressive Disclosure, Primary User Intent, dan Contextual Bulk Actions**.

Saat ini halaman History langsung menampilkan checkbox pada seluruh item beserta "Pilih semua di halaman ini", bahkan ketika pengguna baru membuka halaman dan belum berniat melakukan tindakan apa pun.

Ini merupakan UX yang tidak tepat.

**Primary intent:** Pengguna membuka History untuk melihat, mencari, dan melanjutkan hasil scrape.

**Secondary intent:** Pengguna sesekali ingin memilih beberapa hasil untuk dihapus sekaligus.

Antarmuka harus memprioritaskan primary intent dan memperlihatkan kontrol secondary intent secara kontekstual.

### Goals

1. Hapus checkbox yang selalu terlihat pada initial state.
2. Checkbox desktop muncul ketika item di-hover atau mendapat keyboard focus.
3. Setelah satu item dipilih, tampilkan checkbox pada semua item yang terlihat.
4. Bulk action toolbar hanya muncul ketika ada pilihan.
5. Jangan mengembalikan tombol "Pilih" atau "Selesai memilih".
6. Jangan menampilkan "Pilih semua di halaman ini" pada initial state.
7. Tetap mendukung multi-select, select-all, bulk delete, search, filter, dan pagination.
8. Buat alur selection yang discoverable dan accessible di mobile.
9. Pertahankan desain History yang sekarang; jangan redesign seluruh halaman.
10. Perkuat aturan anti-AI-slop agar kesalahan initial-state UX seperti ini tidak diulangi.

**Important: Simplicity must come from removing unnecessary interaction steps, not from removing essential functionality.**

### STATE B — Hover / Keyboard Focus

Pada desktop, checkbox muncul ketika pengguna mengarahkan pointer ke suatu row.

#### TARGET

```
Mouse hovering first row
             │
             ▼

┌──────────────────────────────────────────────────────────┐
│ ☐ Anpundung      Images      Selesai               >  ⋯ │ ← Hover
├──────────────────────────────────────────────────────────┤
│   Desainpakeai   DESIGN.md   Selesai               >  ⋯ │
├──────────────────────────────────────────────────────────┤
│   Notion         Crawl       Selesai               >  ⋯ │
└──────────────────────────────────────────────────────────┘
```

**Only the hovered or keyboard-focused row should reveal its checkbox while no items are selected.**

Requirements:

- Checkbox appears with subtle hover/focus treatment.
- No layout shift when checkbox appears or disappears.
- Reserve stable horizontal space for the checkbox.
- Do not move row titles horizontally during hover.
- Keep the same row height.
- Avoid opacity-only accessibility bugs.
- Checkbox must be keyboard-focusable and have an accessible label.
- Focus must reveal the control clearly.
- Selected checkboxes remain visible regardless of hover.
- Do not make hover mandatory for assistive technology or touch users.

Do not animate the checkbox with excessive sliding, bouncing, or scaling.

Subtle opacity transition is acceptable if it respects reduced-motion preferences.

### STATE C — Active Selection

Begitu satu item dipilih, sistem masuk ke **selection state automatically**, without a separate entry button.

#### TARGET

```
User checks Anpundung
         │
         ▼

┌──────────────────────────────────────────────────────────┐
│ 1 hasil dipilih                  [Pilih semua] [Batal]    │
│                                                   [Hapus]│
├──────────────────────────────────────────────────────────┤
│ ☑ Anpundung      Images      Selesai                     │
├──────────────────────────────────────────────────────────┤
│ ☐ Desainpakeai   DESIGN.md   Selesai                     │
├──────────────────────────────────────────────────────────┤
│ ☐ Notion         Crawl       Selesai                     │
└──────────────────────────────────────────────────────────┘
```

When selection is active:

- Show checkboxes on all currently visible rows.
- Show one contextual bulk action toolbar.
- Display accurate selected count.
- Provide Batal / clear selection.
- Provide Hapus for selected records.
- Provide select-all in an appropriate location.
- Avoid simultaneously displaying redundant per-item delete actions if they make the selection workflow confusing.
- Preserve the user's selected items across supported pagination transitions.

### After Cancellation

```
Selected count = 0
          │
          ▼
Return to normal History appearance
          │
          ├── All persistent checkboxes disappear
          ├── Bulk toolbar disappears
          ├── Select-all disappears
          └── Hover/focus reveal still works
```

No "Selesai memilih" button is necessary.

## 5. Mobile / Touch UX

Hover does not exist on most touchscreens.

Do NOT implement a desktop-only selection feature.

Recommended mobile pattern:

### Default Mobile

```
┌─────────────────────────────────┐
│ Riwayat VibeScrape               │
│                                 │
│ [ Cari website...             ] │
│                                 │
│ [Semua][Crawl][DESIGN.md] →      │
│                                 │
│ ┌─────────────────────────────┐ │
│ │ Anpundung               ⋯   │ │
│ │ Images · 21 Okt 2026        │ │
│ ├─────────────────────────────┤ │
│ │ Notion                  ⋯   │ │
│ │ Crawl · 21 Okt 2026         │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

In the existing item's overflow menu, expose a clear "Pilih" action when appropriate.

Optionally support long-press on an item as a convenience, but NEVER rely solely on long-press.

### After First Selection

```
┌─────────────────────────────────┐
│ 1 dipilih        [Batal] [Hapus]│
├─────────────────────────────────┤
│ ☑ Anpundung                    │
│ ☐ Notion                       │
│ ☐ Desainpakeai                 │
└─────────────────────────────────┘
```

Requirements:

- Checkbox discovery possible without hover.
- Selection works with touch.
- Row navigation remains obvious in default state.
- No accidental navigation while selecting.
- No long-press-only hidden functionality.
- Avoid duplicate single-delete and bulk-delete menu actions.
- Touch targets must be accessible.
- No unnecessary mobile-only toolbar layers.

Use pointer-capability-aware behavior where applicable. Do not rely exclusively on viewport width to decide whether hover is available.

## 6. Row Interaction and Accessibility

Preserve a predictable interaction hierarchy.

### Default State

- Clicking the title/content opens the scrape detail.
- Clicking a revealed checkbox selects that record.
- Clicking the item's action menu opens its existing contextual actions.

### Active Selection

- Checkbox selects/deselects the individual record.
- Row interaction must not accidentally navigate or delete.
- Prefer a clear consistent selection interaction for the row while bulk selection is active.

Technical requirements:

- Do not nest checkboxes or buttons inside links.
- Do not use non-semantic clickable divs where proper controls are available.
- Provide accessible selection labels.
- Support keyboard focus.
- Support Space on checkbox.
- Support Enter on links.
- Keep visible focus indicators.
- Do not make selected-state detection dependent on color alone.
- Ensure no shifting layout or pointer targets.

## 7. Bulk Selection and Pagination Integrity

The previous implementation already includes bulk selection and pagination behavior.

**Do not break it while simplifying the interface.**

Cases to preserve:

1. Select one item.
2. Select multiple items on the same page.
3. Deselect an item.
4. Clear selection.
5. Select all current-page items.
6. Select items across multiple pages if supported.
7. Select all filtered results if currently supported.
8. Delete selected records.
9. Handle partial deletion failure.
10. Handle search/filter/sort changes safely.

### Select-All UX

Do not show select-all before any selection begins.

Once selection is active:

```
3 results selected
[Select all on this page]
```

If cross-page select-all exists, explicitly distinguish it:

```
10 results selected on this page.

[Select all 120 results matching this filter]
```

Do not accidentally delete additional results hidden by pagination or filters.

### After Deletion

- Clear or reconcile selected state.
- Update result count.
- Update pagination if current page becomes empty.
- Handle failed/partial deletion honestly.
- Never claim all records were deleted when some failed.
- Preserve existing owner authorization and asset cleanup.

Do not rewrite working backend deletion logic without a verified reason.

## 9. Strengthen Anti-AI-Slop Rules

Update the existing authoritative file:

`.agents/rules/[anti-ai-slop.md](http://anti-ai-slop.md)`

Do not create another duplicate rules file.

Add or refine a section:

### Progressive Disclosure &amp; Primary User Intent

The rule should establish:

1. Every page must prioritize its primary user task in the default state.
2. Secondary management actions must not dominate the initial interface.
3. Use contextual disclosure for bulk operations where it improves clarity.
4. Prefer established interactions over extra entry/exit modes.
5. Do not expose every available control simultaneously merely because the functionality exists.
6. Evaluate default, hover, focus, active, empty, error, and touch states before implementing UI.
7. Do not hide essential actions behind hover-only behavior.
8. A secondary action should become prominent only after clear user intent.
9. Existing actions must be reused rather than duplicated.
10. More visible features do not imply better UX.

### Mandatory Interaction-State Review

Include the following rule checklist:

```
[ ] Initial state prioritizes the primary task.
[ ] Secondary actions do not dominate initial UI.
[ ] No redundant selection mode or toggle.
[ ] Desktop hover behavior is deliberate.
[ ] Keyboard focus reveals discoverable actions.
[ ] Touch users can access the same functionality.
[ ] Active selection exposes appropriate bulk actions.
[ ] Clearing selection restores the clean default state.
[ ] Selection does not cause layout shift.
[ ] No duplicated controls or unnecessary UI layers.
[ ] Accessibility and destructive-action safety preserved.
```

Before adding UI, agents must inspect how all major interaction states compose together, not just how an individual component looks in isolation.

**Do not blindly apply hover-only controls everywhere.** This pattern is appropriate for the specific History selection context and must be evaluated per feature.
