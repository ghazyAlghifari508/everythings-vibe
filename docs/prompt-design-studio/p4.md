# PHASE 4 — Full Upstream Skill Fidelity Audit &amp; Genuine Studio Integration

**Priority: P1 — HIGH**  
**Complexity: COMPLEX**  
**Branch:** `feature/vibedesign-design-studio`

## 1. Mission

Audit and improve the fidelity of VibeDesign Studio's selectable design skills.

The current implementation has already been identified as using shortened, modified skill adapters.

Relevant files include:

- `src/features/studio/services/studio-design-skill-registry.server.ts`
- `src/features/studio/services/studio-design-skills.ts`
- `docs/studio-skills/[NOTICE.md](http://NOTICE.md)`

The repository's own documentation acknowledges that the integrated guidance is adapted and abridged rather than the full upstream skill.

The user explicitly wants genuine skill functionality, not superficially similar AI-generated substitutes.

**Your objective is to integrate upstream skill guidance faithfully and enable compatible capabilities, while maintaining security, provenance, licensing, and Studio's architecture.**

Do not present a rewritten summary as an unchanged original skill.

## 4. Required Fidelity Classification

For each skill, classify capabilities into:

**A. Native and compatible**

Can be integrated faithfully into the existing Studio agent/model pipeline.

**B. Compatible with an additional tool or service**

Requires a safe tool integration, dataset lookup, or other explicit capability.

**C. Not supported by the current runtime**

Requires capabilities Studio does not possess.

**D. Inapplicable to the requested surface**

For example, a workflow that only makes sense for editing a live source repository may not be directly applicable to static HTML generation.

Produce an evidence-based capability matrix.

Fill the matrix only after reading the original sources.

## 5. Integration Requirements

Where feasible:

- Keep original skill documents intact and attributable.
- Avoid manually paraphrasing away essential instructions.
- Preserve referenced skill material needed by the selected workflow.
- Build a versioned skill loading or resolution mechanism.
- Use an explicit compatibility adapter for Studio-specific inputs and output requirements.
- Keep upstream text separate from Studio-owned constraints.
- Ensure large skill documents are handled within practical context/token budgets.
- Avoid loading unrelated skill capabilities when not applicable.
- Maintain a single selected skill at a time.

Do not inject every skill simultaneously.

Do not execute untrusted repository scripts or arbitrary shell commands simply because upstream documentation describes them.

Do not grant file-system, browser, network, or credential access to external skill code without deliberate sandboxing, permission boundaries, and a supported integration contract.

For unsupported capabilities, document the limitation instead of pretending they run.

## 6. UI UX Pro Max Special Audit

Pay special attention to UI UX Pro Max.

Current Studio documentation describes the integration as a subset without searchable palettes, font pairings, or full datasets.

Verify original upstream functionality.

Where compatible, determine whether its curated design knowledge or lookup capability can be packaged safely for server-side use.

If full dataset access is feasible, implement it using an explicit, bounded lookup mechanism rather than copying a few generic UX instructions.

If it is not feasible, retain a clearly described partial integration and explain exactly what is missing.

## 7. Skill Resolution &amp; Priority

Use a clear precedence model:

```
Safety / platform validity
          |
          v
Explicit user requirements
          |
          v
Selected DESIGN.md/reference
          |
          v
Compatible selected skill guidance
          |
          v
Studio baseline defaults
```

Selected skills may refine composition, visual hierarchy, accessibility, typography, and consistency.

They must not automatically replace an explicit user-specified brand identity.

Also audit whether skill guidance conflicts with generated-screen navigation contracts or HTML validation.

Resolve conflicts deterministically.

## 8. Skill Selector Copywriting

Improve the selector so ordinary users understand when to choose each option.

Suggested intent:

- **No Skill:** AI merancang tanpa panduan desain tambahan.
- **Impeccable:** Untuk desain yang lebih rapi, detail, dan matang.
- **Frontend Design:** Untuk tampilan web dengan karakter visual yang kuat.
- **UI UX Pro Max:** Untuk navigasi, kemudahan penggunaan, dan aksesibilitas.
- **Anti-Slop:** Untuk mengurangi pola tampilan generik yang tidak diperlukan.
- **Taste:** Untuk komposisi, tipografi, dan keseimbangan visual.

Refine these descriptions after verifying actual available capabilities.

Avoid promises that the integration cannot fulfill.

Preserve authentic logos/assets where permitted. Use the established Hugeicons component only where no appropriate skill mark exists.

Reuse existing DropdownMenu and item primitives.

No generic sparkle decoration.

## 9. Component-First &amp; Anti-Slop Rules

Read `.agents/rules/[anti-ai-slop.md](http://anti-ai-slop.md)` and `.agents/rules/[design-layout-consistency.md](http://design-layout-consistency.md)`.

Before changing selector UI, inspect existing components and suitable equivalents from shadcn/ui, HeroUI, Magic UI, React Bits, and Thinking Orbs.

Reuse the most appropriate ready-made component instead of rebuilding the dropdown.

Do not add libraries merely for decoration.

Maintain:

- Single selection.
- Accessible keyboard navigation.
- Clear active state.
- Scrollable menu.
- Good contrast.
- Responsive positioning.

No unnecessary visual redesign.

## 10. Fidelity Tests

No browser QA.

Tests must prove actual functional integration.

At minimum:

- Original source revision metadata is correct.
- Required source files are present where locally bundled.
- Skill loader resolves the selected skill.
- Unknown skill IDs are rejected.
- No Skill adds no selected-skill guidance.
- Planning receives the correct skill.
- Frame generation receives the correct skill.
- Retry preserves the selected skill.
- Revision preserves the selected skill.
- Distinct skills resolve to distinct appropriate guidance.
- Reference and skill combination respects precedence.
- Capabilities requiring tools are not falsely marked executable.
- Token/context budget is bounded.
- Source/license metadata remains traceable.

Mock the model and inspect actual system inputs.

Do not claim that prompt-difference tests alone prove improved visual quality. Explain that output quality still requires later evaluation.

## 11. Acceptance Criteria

- Full audit against original upstream sources.
- Clear capability matrix for all five skills.
- No fake or invented upstream instructions.
- Original guidance preserved where technically applicable.
- Compatible supporting resources integrated where justified.
- Unsupported capabilities explicitly identified.
- No arbitrary remote script execution.
- Correct skill used in planning, generation, retry, and revision.
- No Skill behaves as the default without additional skill guidance.
- User-friendly selector descriptions.
- Accurate versioning and attribution.
- Relevant automated tests pass.
- No browser QA.
