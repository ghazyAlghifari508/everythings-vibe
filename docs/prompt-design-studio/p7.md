# P7 — Implement Professional Pencil Selection and Context-Aware Element Menus

**Complexity: COMPLEX**  
**Execution order: 07/11**

## Objective

Improve the existing element collection/inspection feature so normal users understand how to select and edit parts of a frame.

The current interaction feels like a technical search/inspection mode. Replace that experience with a visual element editing mode.

Use the shared renderer from P6.

Do not create a second HTML inspection renderer.

## 1. Canvas tools

Replace the current search/magnifier icon used for element inspection with a Pencil icon.

Target toolbar:

```
+------+
|  ↖   |    Frame selection
|  ✋  |    Pan canvas
|  ✎   |    Element editing
+------+
```

When Pencil is active:

- Cursor becomes crosshair.
- Pointer position identifies the relevant ready frame.
- Hovering a meaningful element shows a precise outline.
- Clicking selects the element.
- The editor opens the appropriate Edit Element menu.

Users should not be required to complete an unnecessarily complicated frame-selection sequence before selecting an element.

## 3. Meaningful element detection

Detect semantic/visual elements such as:

- Section.
- Card.
- Heading.
- Paragraph.
- Text label.
- Image.
- Button.
- Form group.
- Navigation item.
- Other useful visual components.

Do not expose every decorative wrapper and tiny structural DOM node as an equally important selectable target.

Exclude editor overlays and internal bridge elements.

Protect document root, body, required runtime infrastructure, and other non-editable structures.

For nested content, provide a predictable target-resolution policy.

Example:

```
Product Card
    ├── Product Image
    ├── Product Name
    ├── Price
    └── Add Button
```

Hovering the text should allow selecting the text itself.

Users should also be able to target the surrounding card when needed. Use a straightforward parent-selection mechanism consistent with the existing editor, without introducing a complicated full layers panel.

## 4. Hover selection

Visual behavior:

```
+--------------------------------+
| Detail Paket                   |
|                                |
| [ Destination photograph ]     |
|                                |
| +----------------------------+ |
| | Bali Escape                | | <- Hover outline
| | 4 Hari 3 Malam             | |
| | Rp3.900.000                | |
| +----------------------------+ |
|                                |
+--------------------------------+
```

The outline must:

- Follow the exact selectable element.
- Remain aligned under zoom and pan.
- Account for iframe scroll.
- Be clearly visible.
- Not change the rendered page's actual layout.
- Not be included in HTML export.
- Update efficiently without causing frequent full-frame rerenders.

Click selection may retain a stronger outline while the menu is open.

## 5. Pencil activation animation

The user does not want content blinking.

If an introductory selection animation is provided, animate only the editable-element overlays.

Sequence:

```
t0: Pencil activated

t1: Meaningful selectable regions gradually appear
    with subtle outlines

t2: Outlines remain briefly visible

t3: General outlines gradually fade

t4: Normal hover selection remains active
```

No whole-frame flash.

No content opacity animation.

No screenshot-to-blank-iframe transition.

No repeated animation on every pointer movement.

Use lightweight opacity transitions and a bounded number of visible overlays.

Respect reduced-motion preferences.

If many elements are available, prioritize meaningful visible groups instead of drawing hundreds of outlines.

## 6. Edit Element context menu

For a visual component/container/image:

```
+-------------------------+
| Edit Element          × |
|-------------------------|
| ✧ Edit with AI          |
| 🗑 Delete               |
+-------------------------+
```

For editable text:

```
+-------------------------+
| Edit Element          × |
|-------------------------|
| I Edit Text             |
| ✧ Edit with AI          |
| 🗑 Delete               |
+-------------------------+
```

The Edit Text action must appear only for targets that genuinely support direct text editing.

Do not show every option for every element type.

Delete must have appropriate destructive styling.

Position the menu near the selected target, while avoiding viewport clipping, floating chat overlap, and inaccessible offscreen placements.

Menu behavior:

- Close using X.
- Close using Escape.
- Close on appropriate outside interaction.
- Maintain selection when interacting with menu.
- Proper focus management.
- Keyboard-accessible actions.
- Correct accessible names.

## 7. Action integration boundary

P7 owns selection, hover, menu presentation, and action dispatch contracts.

P8 owns the actual direct text editing, deterministic deletion, AI Auto Apply behavior, and Undo improvements.

Reuse fully working existing actions where available.

Do not pretend an unimplemented menu action works, and do not fabricate successful feedback.

Ensure target identity includes the correct frame and document revision.

Clicking an element alone must not automatically attach it to the chat before the user chooses Edit with AI.

## 8. Component-first implementation mandatory

Explore:

- Existing canvas toolbar primitives.
- shadcn/ui Popover, Dropdown Menu, Tooltip, Toggle Group.
- HeroUI.
- Magic UI.
- React Bits.
- Thinking Orbs.
- affectUI.
- TUFFUI.
- CUI.
- SakaniUI.

Reuse the existing EvVibe icon system.

Use compatible, mature popover and menu infrastructure rather than custom global click listeners for every menu.

Only implement the specialized canvas outline layer yourself if no appropriate reusable pattern exists.

Do not add unnecessary glowing effects or decorative animation.
