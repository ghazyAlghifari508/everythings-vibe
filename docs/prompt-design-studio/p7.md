# PHASE 7 — Improve Studio Canvas Mouse-Wheel Zoom, Selection Controls &amp; Composer Position

**Priority: P2 — MEDIUM**  
**Complexity: MEDIUM**  
**Branch:** `feature/vibedesign-design-studio`

## 1. Objective

Improve the editing experience inside VibeDesign Studio's canvas.

Current user-reported problems:

1. Scrolling the physical mouse wheel pans the canvas instead of zooming.
2. The Select tool icon is ambiguous.
3. The floating chat composer is positioned slightly too high.
4. Floating controls should remain visually cohesive and not overlap.

Do not rewrite the canvas architecture.

Do not interfere with frame generation or the existing multi-frame selection feature.

## 3. Mouse Wheel Should Zoom

Current logic uses ordinary wheel scrolling to pan, while Ctrl/Cmd + wheel performs zoom.

The user wants regular physical mouse-wheel scrolling to zoom directly.

Target:

```
                    MOUSE WHEEL

                     Scroll Up
                         |
                         v
                      Zoom In

                     Scroll Down
                         |
                         v
                      Zoom Out
```

Zoom must be anchored to the pointer position.

Example:

```
Before Zoom                After Zoom

+------------------+       +------------------+
|                  |       |                  |
|      [Frame]     |       |    [  Frame  ]   |
|         X        |  -->  |         X        |
|                  |       |                  |
+------------------+       +------------------+

X = pointer anchor, preserved during zoom
```

Requirements:

- Smooth zoom.
- No uncontrolled scale jumps.
- Clamp to established minimum/maximum zoom.
- No non-finite scale.
- No whole-page scrolling while an eligible canvas zoom gesture is handled.
- Avoid zooming when scrolling inside an active textarea, dropdown, or other scrollable overlay.
- Preserve toolbar Zoom In, Zoom Out, and Fit controls.
- Preserve keyboard accessibility.

## 4. Mouse vs Trackpad Behavior

Do not simply convert every wheel event into zoom.

A touchpad can generate wheel events for two-dimensional scrolling, and browsers do not reliably expose the physical input device type.

Implement a deliberate interaction policy:

- Physical mouse-wheel zoom should work as expected where wheel input can be classified.
- Trackpad two-finger gestures should remain useful for canvas panning.
- Pinch or Ctrl/Cmd zoom should remain functional.
- Horizontal trackpad gestures should not unexpectedly zoom.
- Ambiguous input should have a sensible documented fallback.

Use wheel delta characteristics carefully, but do not pretend that all input hardware can be perfectly identified from a browser event.

Keep gestures predictable and testable.

Do not introduce a heavy gesture library if the existing zoom hook can handle the requirement.

## 5. Preserve Existing Zoom Limits

The current Studio constants include bounded zoom values.

Continue using the existing shared zoom clamp.

Do not create another independent zoom state in the controls.

All zoom entry points must share one authoritative zoom system:

```
Mouse Wheel ────┐
                │
Trackpad Pinch ─┤
                │
Zoom Buttons ───┼──> Shared Zoom State
                │         |
Fit Content ────┘         v
                       Clamp Limits
                           |
                           v
                      Canvas Transform
```

Ensure the visible percentage always reflects the actual zoom state.

## 7. Lower the Floating Composer

The current composer is visually too far above the bottom edge.

The existing layout calculation reserves space for the bottom-right zoom controls.

Refine the geometry without collisions.

Current conceptual positioning:

```
┌──────────────────────────────────────┐
│                                      │
│                                      │
│         [ Floating Composer ]        │
│                                      │
│                           [ Zoom ]   │
└──────────────────────────────────────┘
```

Target:

```
┌──────────────────────────────────────┐
│                                      │
│                                      │
│                                      │
│                                      │
│       [ Floating Composer ]          │
│                           [ Zoom ]   │
└──────────────────────────────────────┘
```

The composer should sit lower and feel anchored to the editing workspace.

Requirements:

- Reduce unnecessary bottom clearance.
- Keep zoom controls accessible.
- No overlap with toolbar or safe-area insets.
- Preserve responsive max-width.
- Maintain visual centering horizontally.
- Avoid fixed positioning that breaks small screens.
- Preserve dynamic composer height when selected frames appear.
- Preserve keyboard interaction.
- Avoid covering an unreasonable portion of the artboards.

Change shared layout constants or helper functions rather than scattering arbitrary pixel values across components.

## 8. Component-First UI Rules

Explore the appropriate existing components and relevant ready-made patterns from:

- shadcn/ui
- HeroUI
- Magic UI
- React Bits
- Thinking Orbs

For this phase, the existing Hugeicons icon primitive and established Button/Tooltip components should likely remain the main building blocks.

Reuse suitable components.

Do not rebuild the tool palette, zoom controls, or composer from basic divs if the existing components can be improved.

Do not introduce unnecessary animation libraries.

No heavy shadows, neon borders, gradients, oversized controls, or nested capsules.
