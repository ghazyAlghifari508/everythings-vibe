# FIX 07 — Replace Detailed Theme Dashboards With Clean UI Silhouettes

**Complexity: MEDIUM | Priority: P2 | Scope: VibeDesign Studio theme previews**

Kerjakan setelah FIX 06.

## 1. Masalah

Ketika user membuka pemilih tema di VibeDesign Studio, setiap tema menampilkan miniatur dashboard lengkap:

- Sidebar dengan tulisan Overview, Reports, Activity.
- Header Dashboard.
- Search.
- Metric cards.
- Angka revenue.
- Chart dan recent activity.

Padahal user sedang memilih **visual theme**, bukan memilih template dashboard.

Preview tersebut berukuran kecil sehingga teks dan angka terlihat seperti dashboard setengah jadi.

User ingin pratinjau berupa SILUET UI: bentuk sederhana yang menggambarkan layout sebuah dashboard atau halaman, dengan warna, radius, dan komposisi tema yang tetap terlihat.

## 2. File yang wajib diperiksa

- `src/features/studio/components/design-system/studio-theme-dashboard-preview.tsx`
- `src/features/studio/components/design-system/studio-design-picker-panels.tsx`
- `src/features/studio/components/design-system/studio-design-picker-dialog.tsx`
- `src/features/studio/services/studio-presets.ts`
- Existing theme-preview tests.

Jangan mengganti source of truth theme tokens atau merusak metadata tema.

## 3. Target desain

Gunakan abstract UI silhouette.

Siluet boleh merepresentasikan:

- Header.
- Sidebar.
- Content region.
- Beberapa panel.
- Placeholder grafik.
- Data rows abstrak.

Tetapi hilangkan:

- Tulisan Dashboard di dalam preview.
- Angka revenue palsu.
- Search text berukuran mikro.
- Nama-nama navigasi mini.
- Data metrik palsu.
- Status badges dan dots dekoratif.
- Elemen detail yang membuatnya terlihat seperti screenshot aplikasi belum jadi.

Contoh struktur:

```
WORKSPACE / LIGHT THEME

+------------------------------+
| [■]  [=========]       [○]   |
+------+-----------------------+
| [===]| [=======]  [=======]  |
| [===]| [=======]  [=======]  |
| [===]|                       |
|      | [===================] |
|      | [====] [====] [====]  |
+------+-----------------------+

Colors:
white / gray / blue

Workspace
Netral, padat, struktural
```

```
MIDNIGHT / DARK THEME

+------------------------------+
| [■]  [=========]       [○]   |
+------+-----------------------+
| [===]| [=======]  [=======]  |
| [===]| [=======]  [=======]  |
| [===]|                       |
|      | [===================] |
|      | [====] [====] [====]  |
+------+-----------------------+

Colors:
dark navy / white / blue

Midnight
Surface gelap, kontras tegas
```

Simbol di atas hanya visualisasi struktur. Implementasikan dengan blok UI yang rapi, bukan karakter ASCII di aplikasi.

## 4. Component-first implementation

Sebelum menulis ulang preview, eksplorasi:

- shadcn/ui Card dan komponen layout yang sudah tersedia.
- HeroUI Card.
- Magic UI dan React Bits untuk pola visual abstrak yang ringan.
- SakaniUI.
- affectUI dan TUFFUI.
- CUI.
- Existing components dalam EvVibe.

Pilih fondasi kartu siap pakai yang kompatibel dan reuse struktur theme grid existing.

Bila tidak ada silhouette component yang cocok, boleh membuat presentational silhouette internal, tetapi hanya setelah component discovery dan dengan komposisi berbasis primitives reusable.

Jangan membuat screenshot tiruan melalui banyak elemen detail.

Jangan memakai orb, animated particles, glowing gradients, atau efek berat yang tidak diperlukan.

## 5. Konsistensi antar tema

Penting: gunakan geometri siluet yang sama untuk semua tema agar perbandingan fokus pada visual identity.

Theme differences berasal dari:

- Semantic color tokens.
- Surface/background contrast.
- Border color.
- Accent color.
- Border radius.
- Typography characteristics apabila sesuai.

Jangan hardcode warna berdasarkan nama tema.

Gunakan preset tokens yang sudah ada.

Setiap preview tetap menampilkan di bawahnya:

- Warna palette.
- Nama tema.
- Deskripsi singkat yang sudah relevan.

Jangan mengganti theme catalog hanya karena mengganti preview.

## 6. Selection behavior

Pertahankan selected state yang sudah ada:

- Klik kartu = pilih.
- Klik ulang kartu terpilih = batalkan pilihan draft.
- Ada indikasi selected yang jelas dan tidak berlebihan.
- Keyboard dan accessible state tetap berfungsi.

Jangan mengubah CTA dialog pada task ini. Itu akan ditangani di FIX 08.

## 7. Acceptance criteria

1. Semua tema memakai siluet abstrak.
2. Tidak ada data dashboard palsu.
3. Tidak ada teks mikro yang sulit dibaca.
4. Theme tokens tetap akurat.
5. Cards tetap comparable.
6. Nama/deskripsi/palette tetap ditampilkan.
7. Layout 3 kolom desktop tetap responsif pada ukuran lain.
8. Seleksi tema tetap bekerja.
9. Tidak ada efek dekoratif AI slop.
10. Unit/component tests berhasil.

Jangan browser QA atau Playwright E2E.

Di laporan akhir, jelaskan komponen yang direuse, komponen visual lama yang diganti, dan bagaimana theme identity tetap terjaga tanpa miniature dashboard.
