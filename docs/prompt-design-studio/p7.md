## 4. Fullscreen Shell Requirements

The Dialog shell must behave like a full-page workspace.

Required:

- `position: fixed`
- `inset: 0`
- Full viewport width.
- Full dynamic viewport height (`100dvh`).
- No default max-width limitation.
- No default max-height limitation.
- No outer margin.
- No outer border radius.
- No floating-dialog shadow.
- No visible dark backdrop strip surrounding the dialog.
- No leftover centering transform from a standard Radix Dialog implementation.

Inspect existing DialogContent defaults and override only the constraints that conflict with fullscreen behavior.

Do not create a fake fullscreen effect using `scale()` or arbitrary negative margins.

Preserve correct portal behavior, focus trapping, Escape dismissal, and accessible dialog semantics.

## 5. Centered Content Architecture

Use a reusable inner layout structure.

Conceptually:

```
Fullscreen Dialog Shell
│
├── Close Button
│
├── Main Content Area
│   │
│   └── Centered Content Container
│       ├── Title & Description
│       ├── Compact Tabs
│       ├── Active Tab Content
│       │   ├── DESIGN.md Upload
│       │   └── Optional Application Logo
│       └── Footer Actions
│
└── Fullscreen Background
```

The centered content container must:

- Use `width: 100%`.
- Use a sensible responsive `max-width`.
- Use `margin-inline: auto` or equivalent centering.
- Have appropriate internal horizontal padding.
- Avoid excessive empty spacing between elements.
- Remain usable on small viewport widths.

Use existing design tokens and spacing conventions.

**Do not create a second visual modal/card around the centered content.** Only use an invisible layout wrapper.

A content width around 720–960px may be considered as a starting point, but choose actual dimensions based on the existing interface and content needs.

The Tema/Template gallery may use a somewhat wider centered container than the Punya Saya form if necessary. Both must remain horizontally centered.
