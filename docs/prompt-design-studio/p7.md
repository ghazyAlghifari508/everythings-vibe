## 2. Standardize Theme Silhouettes

Current code uses three separate preview components:

```
<WorkspaceSilhouette />
<EditorialSilhouette />
<MidnightSilhouette />
```

This makes their internal structure differ.

Replace the theme-specific dashboard geometry with ONE reusable preview component.

Suggested architecture:

```
<ThemeDashboardPreview tokens={preset.tokens} />
```

The exact API should fit existing types.

### All previews must use the same dashboard layout

```
+-----------------------------------+
| [S]  Dashboard       Search   [U] |
|-----------------------------------|
|      |                            |
| NAV  | [Metric 1] [Metric 2]      |
|      |                            |

|      |                            |
|      | [Recent Activity Table]    |
|      | [Row 1]                    |
|      | [Row 2]                    |
+-----------------------------------+
```

Apply this exact composition to all nine themes.

Only change:

- Canvas color.
- Surface color.
- Primary accent.
- Secondary accent.
- Typography direction.
- Border color.
- Border radius.
- Text color.
- Relevant elevation.

DO NOT change dashboard structure per theme.

### Preview craftsmanship

The miniature must look like a carefully constructed application preview rather than abstract bars placed randomly.

It should visibly communicate:

- Sidebar.
- Header.
- Navigation.
- Metric cards.
- Chart.
- Data table.
- Active state.
- Content hierarchy.

Use properly scaled details.

Keep a common aspect ratio such as 16:10.

Avoid overdecorating.

Avoid noisy gradients, unrelated blobs, fake glass effects, excessive shadows, and oversized illustrations.

The user should immediately understand how the same interface looks under different visual styles.
