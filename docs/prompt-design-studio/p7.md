# PROMPT 07 — Completely Retire VibeDesign Skills While Preserving Legacy Projects

**Complexity: COMPLEX**  
**Execution order: 07 of 13**

## Goal

Remove the user-facing Studio design skill feature because the user no longer wants to choose between options such as:

- Frontend Design
- Impeccable
- UI/UX Pro Max
- Anti-slop
- Taste
- Other Studio design skills currently supported.

The product should instead use one mandatory, high-quality internal generation standard, optionally guided by theme, [`DESIGN.md`](http://DESIGN.md), or VibeScrape reference.

Existing projects created using skills must remain usable.

## 1. Audit the full skill dependency graph

Search the repository for all references to:

- `designSkillId`
- Skill registries.
- Skill selectors.
- Skill prompt composition.
- Skill assets/manifests.
- Skill validation.
- Database columns.
- Project loaders.
- Create/generate API payloads.
- Frame revision APIs.
- Historical project records.
- Tests and documentation.

Likely locations include:

- `studio-skill-select.tsx`
- `studio-design-skills.ts`
- `studio-design-skill-registry.server.ts`
- `studio-skill-context.server.ts`
- `studio-frame-runtime.ts`
- `studio-planning.ts`
- `studio-generate-http.ts`
- `studio-landing-page.tsx`
- Studio project schema.

Verify actual locations first.

## 2. Preserve mandatory quality behavior

The new baseline must retain improvements established by Prompt 05 and Prompt 06.

Do not delete:

- Internal quality rules.
- HTML safety validation.
- Accessibility requirements.
- Component-first patterns.
- Platform-aware layout behavior.
- Structural quality checks.
- Bounded repair.
- Shared design tokens.

Skill removal means optional skill-selection infrastructure is retired, not that AI output becomes unconstrained.

## 3. Preserve design references

Must remain functional:

- Built-in themes.
- Custom [`DESIGN.md`](http://DESIGN.md).
- VibeScrape design references.
- Logo assets.
- PRD references.
- Existing project design blueprints.
- Previous frames, HTML, previews, revisions, exports.

No new UI should reintroduce a skill dropdown under another name.

## 4. Plan a safe migration

Do not immediately drop database columns or delete existing metadata without checking how historic projects are loaded.

Use a staged approach:

1. Identify legacy project representations.
2. Ensure current readers tolerate legacy skill values.
3. Remove obsolete user-facing controls and request requirements.
4. Remove unused prompt injection/skill loading.
5. Migrate or retire persisted metadata safely.
6. Remove dead code and assets after references are proven gone.
7. Verify old project history and export still work.

The user's decision is to preserve existing project results and history.

Do not wipe user rows, rerun generation automatically, or silently change old HTML.

If a historical skill value remains temporarily for compatibility, document why. Do not pretend the feature is completely removed while active runtime branches still depend on it.

## 5. Desired UI

```
BEFORE

Prompt input
Design mode: Web / Mobile
Design skill: [Frontend Design v]
Theme / DESIGN.md reference
[Generate]


AFTER

Prompt input
Design mode: Web / Mobile
Theme / DESIGN.md reference
[Generate]

No skill selector.
No obsolete skill branding.
No extra skill-loading stage.
```

## 6. Test requirements

- New project without skill fields.
- New project with a selected theme.
- New project with custom [DESIGN.md](http://DESIGN.md).
- New project using VibeScrape reference.
- Load an old project with historic `designSkillId`.
- Reopen existing workspace.
- Revise an existing legacy frame.
- Export an old project.
- Retry a legacy failed frame.
- No skill context injected during new generation.
- No broken loader/API contract.
- No accidental degradation of baseline quality rules.

Check any change to input token volume, but don't claim latency improvements until measured.

No browser QA or Playwright E2E in this phase.

## Definition of done

Deliver dependency inventory, removal plan, completed migration, impacted files, targeted tests, and a list of any retained legacy compatibility fields.

Do not leave a broken reference to a deleted skill module.

Do not commit/push/merge/deploy.
