## 3. True Fullscreen Shell

The Design Picker MUST occupy the entire available browser viewport.

Target:

```
┌────────────────────────────────────────────────────────────────────┐
│                                                                [X] │
│                                                                    │
│             ┌──────────────────────────────────────┐               │
│             │                                      │               │
│             │           Pilih tampilan             │               │
│             │                                      │               │
│             │  [Tema] [Template] [Punya Saya]      │               │
│             │                                      │               │
│             │      CENTERED TAB CONTENT            │               │
│             │                                      │               │
│             │               ...                    │               │
│             │                                      │               │
│             │             [Batal] [Gunakan]        │               │
│             └──────────────────────────────────────┘               │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

IMPORTANT:

The outlined internal column above is conceptual.

Do not render another floating dialog or bordered card around it.

Fullscreen shell requirements:

- `position: fixed`
- `inset: 0`
- `100vw`
- `100dvh`
- No outer margin.
- No outer corner radius.
- No floating dialog shadow.
- No unnecessary outer backdrop strip.
- Correct focus trapping and Escape handling.

## 4. Centered Content Composition

Use a constrained content wrapper with appropriate responsive max-width and horizontal centering.

The primary content must be visually balanced.

Requirements:

- Center the main layout horizontally.
- On spacious screens, allow the content group to sit nearer the visual center vertically when appropriate.
- On shorter screens, prioritize scrolling instead of forcing vertical centering.
- Keep field labels left-aligned within the centered content column.
- Maintain consistent header, tabs, section, and footer spacing.
- Avoid excessive fixed-height whitespace.
- Preserve adequate room for theme/template galleries.

Do not enlarge child elements just because the shell is fullscreen.

## 5. Compact Tabs

Keep:

- Tema.
- Template.
- Punya Saya.

Use restrained Tabs or Segmented Control patterns.

Do not:

- Stretch each tab to one-third of the entire viewport.
- Increase font size unnecessarily.
- Create giant black selected-state blocks.
- Add excessive horizontal padding.
- Introduce multiple nested rounded borders.

Preserve selected states and keyboard accessibility.

## 6. Custom Upload Layout Must Be Vertical

Current implementation uses a responsive two-column layout in the custom upload panel.

The user explicitly wants the [DESIGN.md](http://DESIGN.md) upload and logo upload to be stacked.

Wrong:

```
┌───────────────────────────┬───────────────────────────┐
│ DESIGN.md Upload          │ Application Logo Upload   │
└───────────────────────────┴───────────────────────────┘
```

Correct:

```
                  File DESIGN.md

          ┌─────────────────────────────┐
          │                             │
          │      Pilih file .md         │
          │                             │
          └─────────────────────────────┘

                Logo aplikasi
                  (opsional)

          ┌─────────────────────────────┐
          │         Pilih logo          │
          └─────────────────────────────┘
```

Requirements:

- Always stack these sections vertically.
- Align both upload surfaces to the same content column.
- Preserve their different purposes.
- Keep appropriate compact heights.
- Do not create two giant blank cards.
- Preserve file validation and replacement.
- Preserve optional logo behavior.
- Preserve error messages and clear actions.

Do not break the VibeScrape source-selection section.

## 7. Active Reference in Composer

Current:

```
┌─────────────────────────────────────────────────────┐
│ Referensi aktif: Ngoding Pake AI...      Ganti   X  │
└─────────────────────────────────────────────────────┘
```

Refine this into a compact, contextual selection indicator.

Suggested pattern:

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  Describe your application...                            │
│                                                          │
│  [ Palette  Ngoding Pake AI  × ]                          │
│                                                          │
│  Web  Mobile  Pages           Skill              [ ↑ ]   │
└──────────────────────────────────────────────────────────┘
```

This is a layout reference, not an instruction to introduce a new generic pill design system.

Requirements:

- Active reference must remain discoverable.
- Reference label must be readable and truncated appropriately.
- Provide a clear change action.
- Provide a clear remove action.
- Avoid taking a large separate row for a small amount of metadata.
- Work alongside the skill selector.
- Distinguish reference from skill.
- Maintain accessibility.
- Avoid composer height jumping excessively when reference is selected.
- Display active state based on real staged selection.
- Do not claim a reference is already applied to generated frames before submission.

Consider a compact reference chip or small inline attached item.

Use the pattern that best matches existing composer controls.
