# FIX 08 — Improve Theme Picker Selection States, Confirmation Actions &amp; Footer UX

**Complexity: MEDIUM | Priority: P2 | Scope: VibeDesign theme picker interaction**

Kerjakan setelah FIX 07.

## 1. Masalah

User tidak menyukai tombol footer dialog tema yang saat ini berubah antara:

- "Gunakan Tema"
- "Gunakan tanpa tema"

Copy tersebut terasa tidak natural dan membingungkan karena seolah-olah menggunakan tema dan tidak menggunakan tema merupakan satu tindakan yang sama.

User menginginkan UX pemilihan tema yang lebih terarah dan profesional.

Sebelumnya, fitur toggle selected theme sudah dibuat: klik kartu terpilih lagi seharusnya membatalkan pilihan.

Jangan merusak fungsi tersebut.

## 2. Periksa kode

- `src/features/studio/components/design-system/studio-design-picker-dialog.tsx`
- `src/features/studio/components/design-system/studio-design-picker-panels.tsx`
- `src/features/studio/components/workspace/studio-landing-page.tsx`
- `src/features/studio/components/composer/studio-launch-composer.tsx`
- Existing tests untuk theme selection dan design reference.
- Flow custom [`DESIGN.md`](http://DESIGN.md) dan VibeScrape reference.

Identifikasi perbedaan antara:

- Applied theme: tema yang sudah benar-benar disimpan di parent.
- Draft theme: tema yang dipilih di dialog tetapi belum diterapkan.
- Cleared draft: user ingin menghapus theme sebelumnya.
- Untouched state: user membuka dialog tanpa membuat perubahan.

Jangan mencampur draft dengan applied state.

## 3. Target UX

### State A — belum ada tema dipilih

Jangan tampilkan CTA utama "Gunakan tanpa tema".

User boleh menutup dialog dan kembali ke composer tanpa memilih tema.

```
                  PILIH TEMA

[ Workspace ] [ Editorial ] [ Midnight ]
[ Jade      ] [ Orchid    ] [ Rose     ]

Tidak ada tema terpilih.

-----------------------------------------
                              [ Tutup ]
```

Tidak perlu CTA aktif yang memaksa user melakukan "apply no theme".

### State B — user memilih tema

Gunakan tombol utama yang jelas:

**Terapkan Tema**

```
                  PILIH TEMA

[ Workspace ] [ Editorial ] [ Midnight ]
[ Jade      ] [ Orchid    ] [ Rose     ]
[ Graphite ✓]

Graphite dipilih

-----------------------------------------
                 [ Batal ] [ Terapkan Tema ]
```

Indikasi selected cukup dengan border dan check yang jelas, tidak perlu banyak badge atau animasi.

### State C — sebelumnya ada applied theme

Sediakan aksi sekunder yang jelas untuk menghapus referensi:

**Hapus Pilihan**

```
Tema aktif: Graphite

[ Graphite ✓ ]

-----------------------------------------
[ Hapus Pilihan ]   [ Batal ] [ Terapkan Tema ]
```

Ketika user menghapus pilihan, parent state benar-benar dibersihkan melalui aksi yang eksplisit. Jangan hanya menutup dialog sementara theme lama masih aktif.

### State D — user mengeklik ulang tema aktif

Klik ulang selected theme harus mengubah draft menjadi cleared/unselected.

Namun perubahan belum diterapkan hingga user mengonfirmasi aksi penghapusan.

Jika user menekan Batal atau menutup dialog, applied theme sebelumnya tetap dipertahankan.

Jangan membuat deselection secara diam-diam langsung mengubah parent state.

## 4. State transition contract

```
OPEN DIALOG
     |
     v
Read currently applied reference
     |
     +---- User selects a theme
     |           |
     |           v
     |        Draft selected
     |           |
     |           v
     |      Terapkan Tema
     |           |
     |           v
     |      Parent updated
     |
     +---- User clears existing theme
     |           |
     |           v
     |        Draft cleared
     |           |
     |           v
     |      Hapus Pilihan
     |           |
     |           v
     |      Parent cleared
     |
     +---- Batal / Close
                 |
                 v
       Discard draft changes
```

Pastikan flow tetap kompatibel ketika user beralih tab antara Tema, Template, dan Punya Saya.

Preserve:

- Custom [`DESIGN.md`](http://DESIGN.md) attachment.
- VibeScrape design reference.
- Logo attachment.
- Reference metadata.
- Selected theme toggle.
- Generate hanya ketika main composer disubmit.

Memilih atau menerapkan tema tidak boleh otomatis menjalankan AI generation.

## 5. Component discovery wajib

Sebelum mengganti footer/dialog action, eksplorasi komponen siap pakai:

- Existing shadcn-style `Dialog` dan `Button`.
- HeroUI Button/Dialog.
- TUFFUI Modal Sheet dan Action Button.
- affectUI.
- SakaniUI.
- Library UI lain yang relevan dari daftar project.

Reuse existing compatible dialog primitives. Jangan menduplikasi modal system atau memasang dependency hanya untuk satu tombol.

Pilih layout footer yang cocok dengan full-screen dialog existing dan tetap nyaman di layar kecil.

Tidak perlu shiny buttons, gradients, glowing border, atau visual clutter.

## 6. Accessibility

Pastikan:

- `aria-pressed` atau selected state sesuai kontrol.
- Focus terlihat.
- Escape/close tidak mengaplikasikan perubahan yang belum dikonfirmasi.
- Tombol disabled hanya ketika memang tidak ada action valid.
- Label tindakan konsisten dengan akibatnya.
- Tidak ada double submit.
- Keyboard selection tetap bekerja.

## 7. Targeted tests

Buat atau update tests untuk:

1. Open tanpa applied theme.
2. Pilih tema baru.
3. Terapkan tema.
4. Klik ulang tema yang dipilih.
5. Hapus pilihan existing.
6. Batal setelah mengganti tema.
7. Batal setelah menghapus draft.
8. Buka ulang dialog dengan applied state yang benar.
9. Switching tabs tidak menyebabkan kehilangan data secara tidak sengaja.
10. Custom reference dan VibeScrape flow tetap bekerja.
11. Theme selection tidak memicu generate atau credit deduction.

Jangan melakukan browser QA atau Playwright E2E.

## 8. Definition of done

- Tidak ada CTA "Gunakan tanpa tema" yang membingungkan.
- Tombol utama "Terapkan Tema" memiliki makna jelas.
- Ada tindakan "Hapus Pilihan" untuk menghapus theme existing.
- User dapat menutup dialog tanpa tema.
- Klik ulang selected theme tetap didukung.
- Draft dan applied state terpisah.
- Existing design reference flow tidak rusak.
- UI footer rapi dan menggunakan komponen siap pakai.

Laporkan state transitions, library/component yang digunakan, file yang diubah, dan targeted tests.

Jangan mengubah fitur lain di luar theme picker.
