# P12 — Browser QA Brief

**Prerequisite:** P11 Fix 01–06 implemented; see [`p11-fix06-report.md`](./p11-fix06-report.md).  
**Status:** Not started. No browser or Playwright acceptance has been performed in P11.

This document transfers the browser-dependent acceptance requirements out of `p11.md`. P11 performed targeted non-browser tests only; P12 is where those requirements are verified in a real browser.

## 1. Scope

Run comprehensive Browser QA on the VibeDesign Studio surface, using a real browser session and the project's existing Playwright/E2E conventions. Do not use unit-test results as a substitute for browser observations.

## 2. Transferred acceptance requirements

### HTML-first renderer

- The first valid frame is visible as real HTML, not as a JPEG or screenshot.
- Generated HTML remains standalone and valid after capture and export.
- No script execution or unsafe URL survives into the preview.

### Canvas, toolbar, and trackpad

- Canvas pan/zoom and frame selection behave correctly with mouse and trackpad.
- Toolbar actions apply to the selected frame only.
- Frame result cards from Fix 04 open the correct canvas frame and show a truthful preview.

### Pencil and editing

- Pencil annotations/edits remain scoped to the intended frame.
- Revisions preserve existing committed content, photo credits and stable screen identifiers.
- Failed or partial revisions report honestly and do not overwrite newer completed work.

### Chat explanations and result cards

- Explanations are grounded in actual screens and committed frames; no invented research, publication, payment, authentication or external integration claims.
- Operational status remains separate from explanatory content.
- Single-screen, multi-screen, add-screen, revision, failed and partially successful jobs are distinguishable in the UI.
- Safe Markdown renders paragraphs, lists, bold, headings, inline code and links without unsafe HTML.
- Long messages do not push the composer out of view; the original user prompt remains recoverable.
- Concurrency: stale worker updates cannot replace newer explanations; frame results do not duplicate after reload.

### Vertical suggestions and composer

- Suggestions appear in the intended vertical flow and submit the correct prompt.
- The composer remains usable while jobs run; queued messages are not overwritten by frame progress.
- There is no extra credit charge for displaying explanations.

### Design generation and photography (Fix 06)

- Navigation presentation follows the product journey. A discovery-first mobile app does not need a Home/Beranda tab; detail, checkout and confirmation screens are not promoted to primary tabs.
- No forced three-link navbar, hero, KPI row, card quota, back-arrow title bar or fixed header-action count appears across unrelated briefs.
- Search controls either filter a real prototype collection or are absent/disabled; repeated empty search bars are a defect.
- Sample names, prices, dates, currency format and workflow statuses stay consistent across connected screens and are visibly labelled as illustrative.
- Approved photography is genuinely resolved and placed in the planned slot with the declared ratio, cropping, alt text and required attribution.
- When a provider fails, the UI shows honest fallback text. Inline SVG scenery or CSS gradients must not impersonate a real photograph in a planned photography region.
- User-provided imagery remains usable.
- Legacy canonical projects retain their previous shell behavior; model-owned projects retain model-authored chrome.

## 3. Representative journeys

1. **Jelajahin mobile** — prompt with domestic travel booking and `Gunakan foto destinasi asli`: Jelajah → Detail Paket → Pemesanan → Pembayaran → Tiket Saya. Verify parent path, ticket/search usefulness, consistent sample dates/prices, and real destination photos or honest fallback.
2. **Public website / portfolio** — verify narrative composition without dashboard/KPI defaults and without a plain card wall.
3. **Finance workspace** — verify task-appropriate table/form composition, atomic currency grouping and status labels that reflect real conditions.
4. **Revision and export** — revise a frame with an approved photo, export the project, and verify credits/dependencies still resolve.

## 4. Performance and honesty

- Measure first valid, visibly rendered HTML frame against the unchanged **under 60 seconds** target. Record real timings; never modify timestamps.
- Record prompt size and media-pipeline timing effects from real runs.
- Record any observed provider failure verbatim; do not present a fallback as a resolved photograph.
- Do not claim visual excellence from mechanical tests, and do not claim browser acceptance before it is performed.

## 5. Deliverable

Produce a P12 browser QA report with: journey-by-journey observations, screenshots, performance measurements, defects with reproduction steps, and an explicit pass/fail statement for each transferred requirement above.
