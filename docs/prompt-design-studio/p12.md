# PROMPT 12 — Final Studio UI Cleanup: History Empty State, Redundant Loading, and Canvas Status

**Complexity: SIMPLE–MEDIUM**  
**Execution order: 12 of 13**

## Goal

Perform focused UI cleanup after the new chat workspace and core generation system are already implemented.

Do not redesign the entire Studio.

## 1. History sidebar empty state

Current issue:

When no project exists, the text is vertically centered, while project cards normally appear immediately below the search input.

Make the empty state follow the same top-aligned content region.

Target:

```
MY PROJECTS                  0
------------------------------
[ Cari proyek...             ]

[folder icon]
Belum ada proyek
Desain yang kamu buat akan
muncul di sini.
```

Not:

```
MY PROJECTS                  0
------------------------------
[ Cari proyek...             ]




       Belum ada proyek
       Tulis deskripsi...




```

Use:

- A small outline icon if appropriate.
- Clear title.
- One short description.
- Consistent spacing.
- No unnecessary large card or duplicate Create button.

Differentiate:

**History empty:** `Belum ada proyek`.

**Search has no matches:** `Tidak ada proyek yang cocok`.

Use natural wording that works on desktop and mobile. Avoid "di samping" because mobile may not have a side-by-side layout.

## 2. Remove redundant frame header spinner

If a frame already shows its generating shimmer, remove the rotating spinner next to the frame name.

Keep:

- Frame title.
- Shimmer.
- Useful accessible status.
- Real failure indication.
- Retry controls when valid.

Do not substitute another decorative blinking dot.

```
BEFORE
[Mobile] Kustomisasi Pesanan [spinner]
+-------------------------------+
| SHIMMER                       |
+-------------------------------+

AFTER
[Mobile] Kustomisasi Pesanan
+-------------------------------+
| SHIMMER                       |
+-------------------------------+
```

## 3. Remove "Menyusun struktur halaman..."

Find the status text in `StudioCanvasQueueReadout` or its current equivalent.

Remove that floating canvas copy if the new chat workspace already provides an accurate planning/generation status.

Do not remove actual status tracking from backend or accessibility.

Ensure no duplicated progress messages appear in both an overlay and the chat panel.

## 4. Component-first rule

Inspect existing UI primitives and relevant shadcn, HeroUI, TUFFUI, affectUI, SakaniUI, Magic UI, React Bits, Thinking Orbs, and CUI components before adding presentation.

Use existing shadcn Empty or an equivalent compatible installed component for the sidebar where appropriate.

Reuse existing shimmer; do not build new loaders.

Avoid gradients, colored badges, fake progress, and unnecessary motion.
