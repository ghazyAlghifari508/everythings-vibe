# TASK 05 — Fix Prompt Submission Loading, Enter Handling &amp; Duplicate Request Prevention

**Complexity:** MEDIUM  
**Priority:** P1  
**Branch:** `feature/vibedesign-design-studio`

## 1. Problem

The user submits a Studio prompt by pressing Enter.

Expected behavior:

- Submit starts immediately.
- Submit button changes from arrow to loading spinner.
- Button becomes disabled.
- Other conflicting submission actions are blocked.
- Repeated Enter cannot create duplicate requests.
- On successful project creation, user navigates to the canvas.
- On failure, the UI recovers and permits a new attempt.

Current behavior sometimes leaves the submit button visually active without showing a meaningful loading state.

## 2. Mandatory Investigation

Read repository rules and inspect:

- `studio-landing-page.tsx`
- `studio-launch-composer.tsx`
- `composer-keyboard.ts`
- Studio generate API.
- Project creation and deduplication logic.
- Related loading/navigation tests.

Previous code already included a loading spinner conditional and `loading` state.

Do NOT claim a spinner is entirely missing without examining the actual implementation.

A suspicious part of the submit lifecycle is:

```
void navigate(...);
```

followed by:

```
finally {
  setLoading(false);
}
```

The UI may exit the loading state before navigation completes.

Verify the actual behavior in the latest code.

## 4. Implementation Requirements

### Unified submission logic

Ensure these triggers use a single authoritative submission function:

- Enter inside textarea.
- Submit button click.
- Form submit event.
- Any supported keyboard shortcut.

Do not implement separate request logic for keyboard and button submission.

Maintain Shift+Enter for line breaks.

Respect IME composition so Enter does not prematurely submit while the user is composing text.

### Synchronous duplicate guard

Do not rely solely on React state updates to prevent rapid duplicate submissions.

Use an appropriate synchronous in-flight guard/ref or an existing mutation abstraction.

It must prevent:

- Rapid Enter presses.
- Enter + immediate button click.
- Double-click on submit.
- Repeat submissions before navigation.

Preserve the backend's existing idempotency/deduplication protections.

### Loading lifecycle

The previous UI already has `Loading01Icon`.

Reuse the existing canonical loading icon or an appropriate professional spinner component.

State must accurately represent:

```
idle -> submitting -> navigating -> completed/unmounted
                    |
                    -> failed -> idle
```

A successful response must not immediately reset loading while navigation is still in progress.

Handle navigation failure safely.

Reset the in-flight lock and show an actionable error when the request genuinely fails.

Do not leave the composer permanently disabled after an error.

### Accessibility

- Use `disabled` for genuinely unavailable submit actions.
- Add `aria-busy` where appropriate.
- Provide an accessible loading status.
- Preserve visible focus indicators.
- Avoid inserting large loading panels.
- Do not replace the entire composer with a skeleton.
