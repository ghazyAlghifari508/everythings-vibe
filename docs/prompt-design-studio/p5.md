### Pointer behavior

- Marquee starts only in Cursor/Select mode.
- Pressing an empty canvas area starts a potential selection.
- Actual marquee appears after a small drag threshold.
- Dragging updates the rectangle smoothly.
- Frames intersecting the rectangle receive a selection preview.
- On release, commit the selected frame IDs.
- Clicking empty canvas without dragging clears selection where appropriate.
- Clicking one frame continues to select it.
- Shift+click additive selection remains supported.

### Multi-selection behavior

Support:

- Single click.
- Shift+click.
- Drag rectangle.
- Shift+drag additive selection.
- Deselect.
- Removing a selected frame through the composer.
- Switching to Hand/Pan mode without corrupting selection.
- Escape to cancel an in-progress marquee.

Do not force selection to a maximum of one frame.

Do not automatically truncate `selectedFrameIds` or switch to the first selected frame when submitting revisions.

## 4. Coordinate &amp; Geometry Correctness

This is the most important technical part.

The canvas uses pan and zoom transformations.

Marquee selection must behave correctly at:

- Minimum zoom.
- Maximum zoom.
- Any intermediate zoom.
- Panned canvas positions.
- Different frame widths.
- Long mobile frames.
- Mixed frame heights.
- Resized viewport.
- Dynamic frame dimensions after screenshots load.

### Required approach

Use an explicit coordinate-space strategy.

Possible spaces:

- Viewport/client coordinates.
- Canvas-local screen coordinates.
- Transformed canvas-world coordinates.

Convert coordinates consistently.

Selection intersection must compare rectangles expressed in the same coordinate system.

Do not mix raw `clientX/clientY` with untransformed frame positions.

Account for canvas padding and layout gap.

### Intersection contract

Document whether a frame is selected when:

- Any part intersects the marquee; or
- Its center lies within the marquee.

**Preferred:** intersection-based selection matching the user's request that frames touched by the rectangle become selected.

Keep the rule consistent.

Use actual frame bounds, not assumed fixed heights.

### Performance

Avoid expensive full React rerenders for every pointer event.

Use pointer capture and efficient transient state.

Only update selection state when the intersected frame-ID set actually changes.

Do not make the whole canvas rerender unnecessarily during drag.

## 5. Pointer Lifecycle &amp; Conflict Prevention

Correctly handle:

- `pointerdown`
- `pointermove`
- `pointerup`
- `pointercancel`
- `lostpointercapture`
- Escape
- window blur
- tool switching
- component unmount

Avoid stuck selection rectangles or dragging states.

### Conflict avoidance

Marquee must not begin when interacting with:

- Frames' action buttons.
- Canvas composer.
- Zoom controls.
- Cursor/Hand toolbar.
- Menus/dialogs.
- Profile controls.
- Other interactive overlays.

Hand tool must continue panning rather than selecting.

Space-pan must temporarily override selection interaction.

Do not break existing wheel/trackpad zoom and pan constraints.

- Preserve the ability to submit a project-wide revision when no frames are selected.
- Keep selected frame context stable while polling updates complete.

Inspect current backend semantics. Do not invent a second revision API.

If current routing or selection state drops multiple IDs, fix the relevant root cause.
