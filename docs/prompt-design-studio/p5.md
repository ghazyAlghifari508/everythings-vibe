# FIX 05 — Canvas Minimum Zoom and Consistent View Restoration

**Severity:** P1  
**Complexity:** MEDIUM  
**Target:** `feature/vibedesign-design-studio`  
**Execution order:** 05/08. Execute after FIX 04.

## Problem

Canvas currently allows zooming out as far as 20%. At that scale the frames become unnecessarily tiny, hard to inspect, and frustrating to navigate.

The previous code audit found:

```
STUDIO_CANVAS_MIN_ZOOM = 0.2;
STUDIO_CANVAS_MAX_ZOOM = 2;
STUDIO_CANVAS_INITIAL_MIN_ZOOM = 0.5;
```

Verify these values in the latest checkout before editing.

**Important:** The requested change is to make the maximum zoom-out less extreme. This means **raising minimum zoom**, not lowering maximum zoom.

## Required behavior

Start with **35% minimum manual zoom** as a reasonable proposed limit, without treating it as a universal rule.

```
BEFORE
20% --- 35% --- 50% -------- 100% -------- 200%
 ^
 excessive zoom-out allowed

AFTER
       35% --- 50% -------- 100% -------- 200%
        ^
        minimum allowed
```

Expected UI:

```
┌───────────────────────────────┐
│  [ − ]      35%      [ + ]    │
└───────────────────────────────┘

At 35%, clicking minus:
- does not lower zoom;
- provides correct disabled state where supported.
```

## Requirements

1. Update manual minimum zoom consistently across controls, wheel gestures, pinch handling if present, and programmatic zoom setters.
2. Clamp saved per-project views created under the old 20% limit.
3. Do not cause sudden jumps or lost pan positions without reason.
4. Preserve zoom-to-cursor behavior where supported.
5. Preserve dragging/panning and selection modes.
6. Fit All must not silently reintroduce an unusably tiny zoom.
7. If all frames cannot fit at the minimum readable zoom, prioritize reasonable framing and panning rather than shrinking frames to miniature size.
8. Opening history should remain comfortable and should not always force a tiny entire-project overview.
9. The canvas must remain usable with many frames and mixed content heights.
10. Zoom controls must reflect actual state and bounds.

## UI component discovery

Review existing controls first. For any UI changes, explore shadcn/ui, HeroUI, Magic UI, React Bits, Thinking Orbs, and affectUI before building a new control.

However, do not install an unrelated library if the existing reusable zoom control already meets the task. Reuse and refine the current component.

Avoid unnecessary redesign.

## Tests

- Manual zoom cannot go below the new minimum.
- Zoom can still reach 100% and valid maximum.
- Restored old 20% view is clamped correctly.
- Fit All and Reset remain correct.
- Wheel/trackpad controls respect boundaries.
- Existing pan/selection behavior works.
- Projects with 1, 3, 5, and many frames remain navigable.

Use focused unit/integration tests and build/typecheck.

**No browser QA or browser-based E2E.**

## Definition of done

Minimum zoom no longer reaches 20%, all code paths respect the same limit, saved view restoration is safe, and unrelated canvas interactions have no regression.

Report exact values changed and tests performed.

Do not commit, push, merge, or deploy without authorization. Proceed to FIX 06 only after completion.
