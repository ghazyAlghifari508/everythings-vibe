# FIX 05 — Restore Compact Horizontal Prompt Suggestions Without Losing Context Quality

**Complexity: MEDIUM | Priority: P2 | Scope: Studio canvas composer suggestions**

Kerjakan setelah FIX 04.

## Masalah

Saran prompt saat ini ditampilkan dalam tiga kartu vertikal berisi judul dan deskripsi.

Komponen tersebut mengambil terlalu banyak ruang di atas composer dan menghalangi user melihat frame pada canvas.

User ingin mengembalikan bentuk UI sebelumnya berupa bubble/pill horizontal.

Penting: alasan desain sebelumnya dikritik adalah kualitas isi prompt yang terlalu generik, BUKAN bentuk bubble-nya.

Jadi jangan kembali menggunakan prompt generik lama. Pertahankan contextual suggestion engine yang sudah diperbaiki.

## Component-first discovery wajib

Sebelum implementasi, inspeksi komponen siap pakai dari:

- TUFFUI: Prompt Suggestions.
- shadcn/ui: Button, Scroll Area, atau patterns yang sesuai.
- HeroUI: Button/Chip.
- affectUI dan SakaniUI jika ada pola yang lebih cocok.
- React Bits, Magic UI, CUI, dan library lain bila relevan.

Wajib memakai atau mengadaptasi pola komponen yang kompatibel, bukan membuat UI generik dari nol.

Prioritaskan reuse existing design primitives dan jangan mengganti icon system EvVibe.

Tidak perlu menggunakan komponen animasi berat atau glowing effects.

## Target UI

Ganti vertical card stack menjadi single-row compact suggestion bubbles.

```
BEFORE

+----------------------------------------+
| Kelola stok barang                     |
| Level minimum dan peringatan menipis   |
+----------------------------------------+
| Buat halaman Beranda                    |
| Destinasi navigasi belum punya halaman |
+----------------------------------------+

+----------------------------------------+
| Frontend Design                        |
|                                        |
| Minta revisi atau tambah halaman...    |

+----------------------------------------+
```

## Perilaku

1. Bubble berada tepat di atas composer dan mengikuti batas lebarnya.
2. Ditampilkan satu baris secara horizontal.
3. Jika ruang tidak cukup, bubble dapat digeser horizontal.
4. Jangan membungkus seluruh suggestion menjadi card vertikal.
5. Jumlah suggestion maksimal tetap mengikuti batas existing, saat ini 3.
6. Bubble punya hit area yang nyaman, border dan hover/focus yang jelas.
7. Jangan menggunakan auto-scroll atau marquee bergerak terus-menerus.
8. Jangan menghalangi zoom controls, toolbar, atau konten canvas secara berlebihan.
9. Pada viewport sempit, suggestion tetap compact.
10. Selama generation aktif, behavior visibility/disabled mengikuti state nyata.

## Jangan mengorbankan kualitas prompt

Existing suggestion engine menghasilkan prompt berdasarkan blueprint, PRD, nama frame, serta konteks domain aplikasi.

Pertahankan kemampuan tersebut.

Contoh: bubble bertuliskan "+ Kelola Stok" harus tetap mengisi composer dengan prompt lengkap dan kontekstual untuk aplikasi kopi, bukan sekadar "Buat halaman Kelola Stok".

UI menampilkan judul singkat, tetapi internal prompt tetap detail.

Click behavior:

```
User clicks bubble
        |
        v
Composer receives full prompt
        |
        v
User can review/edit
        |
        v
User submits manually
        |
        v
Server resolves intent and generates
```

Klik bubble TIDAK boleh langsung generate, mengurangi credit, atau membuat frame.

Pertahankan filtering nama/alias untuk mencegah suggestion duplikat.

Jika perlu menampilkan alasan suggestion, gunakan accessible tooltip atau teks bantu tersembunyi, bukan card besar tambahan.

## Acceptance criteria

- Bubble horizontal menggantikan vertical card stack.
- Area canvas yang tertutup berkurang.
- Full prompt tetap berkualitas dan kontekstual.
- Click hanya mengisi composer.
- User masih dapat mengedit sebelum submit.
- Tidak ada duplicate suggestions.
- Keyboard navigation, focus, dan accessibility tetap baik.
- Loading/disabled state tetap benar.
- Tidak ada perubahan pada billing atau operation endpoint.
- Targeted unit/component tests berhasil.

Jangan melakukan browser QA atau Playwright E2E.

Laporan akhir wajib menyebut library/pattern yang dipakai, perbedaan ukuran/layout suggestion, serta pembuktian bahwa contextual prompt tidak mengalami regresi.
