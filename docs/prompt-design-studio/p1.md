# 5. Select a Correct Cross-Runtime Asset Loading Strategy

## DO NOT blindly switch to `vite-node`

An earlier suggestion was:

```
{
  "studio:worker": "vite-node src/features/studio/services/studio-worker.ts"
}
```

Do not use this as the default fix.

The standalone worker should not acquire an unnecessary runtime dependency on Vite merely to load Markdown and CSV content.

Preserve the existing `tsx` worker unless concrete evidence requires another execution architecture.

## Preferred approach: Native Node filesystem loading

Investigate replacing Vite `?raw` imports with a shared, server-only asset loader using:

- `node:fs`
- `node:path` / URL-based paths
- `import.meta.url`

Example concept:

```
import { readFileSync } from "node:fs";

const content = readFileSync(
  new URL("../skills/impeccable/SKILL.md", import.meta.url),
  "utf8",
);
```

However, **do not implement this blindly**.

Verify:

1. The relative path resolves on Windows.
2. It resolves through `tsx`.
3. It works in Vitest.
4. It works in Vite SSR.
5. Required assets exist in production.
6. The build process does not relocate the module without its assets.
7. Server-side modules are not accidentally imported into the browser bundle.

### Packaging consideration

A direct `node:fs` loader may work in development but fail in production if raw Markdown/CSV assets are not deployed alongside the compiled server.

If the existing build and deployment cannot reliably include those files, choose a stronger portable alternative.

## Alternative: Generated TypeScript asset modules

If necessary, implement a deterministic build/preparation step that transforms verified local assets into importable TypeScript modules.

```
      SAME ASSET CONTENT
```

Requirements:

- No runtime GitHub fetching.
- No arbitrary remote script execution.
- Generated output must be reproducible.
- Generated files should follow the repository's generated-code conventions.
- The build step must run before relevant development/production executions.
- CI must detect stale generated artifacts if this approach is chosen.

### Important architectural requirement

**Choose ONE coherent asset-loading mechanism compatible with every supported runtime.**

Do not maintain one independently edited copy of the skill for Vite and another for Node.
