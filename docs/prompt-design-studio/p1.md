### Logo and profile

Currently, the logo and avatar follow the centered content area.

Fix the DOM/layout ownership so:

- VibeEverything logo is near the **top-left viewport edge**, not centered above the main composer.
- User avatar is near the **top-right viewport edge**.
- Both align to a consistent shared header inset.
- The header has no unnecessary full-width opaque navbar.
- The sidebar starts below the floating header.
- Main content is positioned independently beneath the header.

Do not solve this with arbitrary negative margins or giant absolute offsets.

Use a clean page-shell structure.

Preserve account menu and theme actions.

### Back button

Add a compact back-navigation control next to the app identity, using existing navigation/button primitives.

Behavior:

- Return to a legitimate previous in-app route when available.
- Provide a stable fallback to the appropriate parent design/product page.
- Avoid returning users to an external site or relying blindly on browser-history length.
- Preserve route state where appropriate.
- Support keyboard focus and an accessible label.

Do not hardcode an unsafe redirect.

## 4. Horizontal Prompt Carousel

Replace the current vertically expanding two-column grid.

**Required behavior:**

- Single horizontal row of brief cards on desktop.
- Cards move horizontally rather than creating additional grid rows.
- Left/right arrow controls appear near the section heading.
- Clicking arrows scrolls one logical step.
- Disable/hide unavailable direction appropriately.
- Allow trackpad horizontal gestures.
- Support touch swipe.
- Support keyboard navigation and visible focus.
- Keep selected/hover appearance polished.
- Do not let horizontal wheel interaction unexpectedly scroll the whole document sideways.

Example:

```
Mulai dari brief siap pakai                              (‹) (›)

┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ Specialty Coffee │ │ Personal Finance │ │ SaaS Analytics   │ →
│ Ordering         │ │ Tracker          │ │ Dashboard        │
│                  │ │                  │ │                  │
│ Mobile · 4 pages │ │ Mobile · 4 pages │ │ Web · 3 pages    │
└──────────────────┘ └──────────────────┘ └──────────────────┘
```

The brief content must remain substantive. Do not shorten the underlying prompt payload or replace detailed shortcut data with generic one-line instructions.

Clicking a card must continue to populate the composer and apply its existing recommended platform/page count.

Do not automatically submit.

Use consistent fixed/minimum card widths and restrained styling.

No default browser horizontal scrollbar should visibly cut through the card area unless that is the intended accessible fallback.

## 5. Fix Page Scroll Ownership

Current issue: the vertical scrollbar appears at the edge of the internal main content region, not at the far-right viewport boundary.

Requirements:

- The main landing page must scroll with its scrollbar at the far-right viewport edge.
- The floating sidebar may retain its own independent internal scroll when history exceeds available height.
- The landing content must not become trapped inside a narrow nested scrolling container.
- Header and profile positioning must not shift incorrectly during scroll.
- Modal scroll locking must remain correct.
- Avoid two competing vertical scrollbars for the same content.
- Do not break narrow-screen accessibility.

Inspect the existing `h-dvh`, `overflow-hidden`, and `overflow-y-auto` ownership rather than merely hiding the scrollbar with CSS.
