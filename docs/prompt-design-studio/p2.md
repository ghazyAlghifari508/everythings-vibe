Current implementation uses a dialog constrained by `max-w-2xl` and `max-h-[90dvh]`.

The user wants the picker to occupy nearly the entire application viewport, not resemble a medium-sized popup.

- Desktop: approximately viewport-sized dialog with intentional safe insets.

- Responsive sheet/fullscreen treatment on small screens.
- No clipped tab content.
- No footer covering upload controls.
- Preserve actual selection/validation and original three tabs.

Do not expand the dialog to 100% by simply adding `w-screen` while retaining conflicting max-width CSS.

Inspect shadcn/Radix Dialog behavior and ensure proper overrides.

The "Template" tab may continue using clearly labeled unavailable placeholders until real template assets exist. Do not fake usable templates.
