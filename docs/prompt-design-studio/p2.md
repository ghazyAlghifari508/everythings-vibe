# TASK 02 — Refactor Canonical App Shell for Realistic Web/Mobile UI and Cross-Screen Consistency

**Kategori:** CRITICAL / COMPLEX  
**Prioritas:** P0  
**Repository:** ghazyAlghifari508/everythings-vibe

## MISI

Perbaiki sistem canonical shell VibeDesign Studio agar halaman yang dihasilkan terlihat seperti aplikasi web/mobile sungguhan, bukan kumpulan HTML dengan header generik yang diulang pada setiap frame.

Masalah user:

1. Setiap screen cenderung memiliki brand kecil di kiri dan judul halaman besar di sebelahnya.
2. Contoh: `Jelajahin Eksplorasi Paket`.
3. Struktur tersebut terasa dipaksakan, terutama pada aplikasi mobile.
4. Ada perbedaan penggunaan header, navigasi, jarak, dan komponen global di antara layar aplikasi yang sama.
5. Beberapa halaman memiliki struktur yang tidak sesuai dengan tujuan halamannya.
6. AI dan canonical shell berpotensi saling mengulang elemen yang sama.
7. User ingin hasil benar-benar seperti aplikasi produksi, bukan hanya mockup dashboard generik.

## TARGET ARSITEKTUR

Jangan membuat header tunggal yang identik untuk semua aplikasi.

Gunakan canonical shell yang tetap konsisten dalam satu proyek, tetapi memiliki variasi berdasarkan platform dan kebutuhan produk.

```
PROJECT BLUEPRINT
       |
       v
Product Identity
       |
       v
Platform & App Structure
       |
       +--> WEB APPLICATION SHELL
       |
       +--> MOBILE APPLICATION SHELL
       |
       v
Shared Navigation / Components
       |
       v
Individual Screen Content
```

### Contoh web

```
┌─────────────────────────────────────────────┐
│ Metriq                         [User Avatar]│
├──────────┬──────────────────────────────────┤
│          │                                  │
│ Ikhtisar │ Pelanggan                        │
│ Pelanggan│ Kelola akun dan langganan        │
│ Laporan  │                                  │
│          │ [Search] [Filter] [New Customer] │
│          │                                  │
│          │ [Main Content]                   │
└──────────┴──────────────────────────────────┘
```

### Contoh mobile

```
┌────────────────────────────┐
│ ‹  Eksplorasi Paket     ♡  │
├────────────────────────────┤
│                            │
│ Content                    │
│                            │

```

Contoh di atas adalah arahan hierarki, bukan layout wajib untuk setiap aplikasi.

## IMPLEMENTATION RULES

1. Pisahkan product branding dan screen title.
2. Jangan otomatis menempatkan keduanya pada satu horizontal row.
3. Untuk web, evaluasi topbar + sidebar dengan judul screen di content header.
4. Untuk mobile, pilih app bar/navigation yang sesuai konteks: back button, title, trailing actions, atau logo jika relevan.
5. Konsistensi berlaku untuk aplikasi yang sama, bukan semua aplikasi yang berbeda.
6. Gunakan screen role metadata jika sudah tersedia.
7. Jangan hardcode satu layout untuk portfolio, finance, travel, dan admin dashboard.
8. Hindari duplikasi header dari AI dan canonical shell.
9. Hindari perubahan global CSS yang mematahkan konten layar lain.
10. Jangan merombak isi layar yang sudah bagus tanpa kebutuhan nyata.

## SHARED CONTRACT

Definisikan sumber kebenaran untuk:

- Header structure.
- Primary navigation.
- Active destination.
- Icon family.
- Spacing and density.
- Typography.
- Color tokens.
- Global actions.
- Screen role.
- Safe areas untuk mobile.
- Content boundaries.

Pastikan frame baru menggunakan blueprint yang sudah ada.

Jangan membuat blueprint atau theme baru setiap kali user menambah halaman.

Untuk screen turunan seperti Detail Paket, pertahankan shell aplikasi namun izinkan header yang sesuai dengan navigasi balik.

## COMPONENT-FIRST

Explore terlebih dahulu:

- shadcn/ui
- HeroUI
- Magic UI
- React Bits
- Thinking Orbs
- AffectUI

Gunakan komponen Header, NavigationMenu, Sidebar, Breadcrumb, Toolbar, Tabs, dan Button yang cocok.

Untuk HTML standalone, reuse implementasi markup/CSS yang kompatibel, bukan import React tanpa runtime.

Jangan membuat semua UI dari nol. Jangan menambahkan animasi/dekorasi yang tidak relevan.

## VERIFIKASI

Gunakan unit dan integration tests dengan fixtures:

- Web SaaS dashboard.
- Web customer directory.
- Web analytics report.
- Mobile travel booking.
- Mobile package detail.
- Mobile checkout.
- Mobile account/profile.
- Frame baru dalam proyek lama.
- Correct active navigation.
- No duplicate header.
- No conflicting global styles.
- Existing HTML/export compatibility.

## ACCEPTANCE CRITERIA

- Header tidak lagi selalu berupa `Brand + Screen Title` horizontal.
- Web dan mobile memakai struktur yang sesuai platform.
- Semua frame dalam satu proyek konsisten.
- Screen detail bisa memiliki header yang berbeda secara semantik tanpa kehilangan identitas aplikasi.
- Tidak ada duplicate header/navigation.
- Existing screen bodies tetap aman.
- New frame memakai shared blueprint.
- Export HTML konsisten dengan preview.
- Component-first implementation.
- No browser QA.

Laporan akhir wajib memuat penyebab header generik, perubahan shell contract, bagaimana menjaga screen lama, test results, dan Git status.

**GOAL:** Semua frame memiliki struktur yang terasa seperti aplikasi sungguhan, dengan navigasi, header, tipografi, dan branding yang tepat, tanpa memaksa satu template global untuk setiap produk.
