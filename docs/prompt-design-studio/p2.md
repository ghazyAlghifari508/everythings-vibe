## 1. Masalah yang harus diperbaiki

User melaporkan dua skenario:

**Kasus A — [DESIGN.md](http://DESIGN.md) dari VibeScrape:**

- User memilih referensi desain hasil scrape.
- User dapat memilih skill, termasuk Frontend Design.
- Generation menjadi sangat lama.
- Beberapa frame berakhir gagal.
- Retry dapat mengulangi proses lama yang sama.

**Kasus B — [DESIGN.md](http://DESIGN.md) custom:**

- User mengunggah dokumen `.md` milik sendiri melalui "Punya Saya".
- Setelah submit, generation juga dapat mengalami kegagalan.
- Dalam salah satu screenshot, empat frame berakhir pada failed state.

**Jangan menyatukan dua kasus ini sebagai masalah upload.** [DESIGN.md](http://DESIGN.md) VibeScrape tidak berasal dari file input yang sama dengan custom upload.

Jangan pula menyimpulkan bahwa [DESIGN.md](http://DESIGN.md) atau skill pasti penyebab tunggal. Buktikan dengan memeriksa tahap yang gagal.

## 3. Temuan awal yang harus diverifikasi

Server memiliki beberapa reference kind:

```
THEME
  -> built-in preset DESIGN.md
  -> design tokens

VIBESCRAPE
  -> scrape reference ID
  -> ownership check
  -> stored DESIGN.md
  -> design tokens

CUSTOM
  -> uploaded Markdown
  -> filename/content validation
  -> design tokens
```

Semua akhirnya digunakan oleh Studio planning dan frame generation.

Existing token validator memerlukan warna atau tipografi yang dapat dipahami parser.

Risiko:

- Dokumen Markdown valid secara isi tetapi tidak cocok dengan parser;
- dokumen terlalu besar;
- referensi scrape tidak tersedia;
- token invalid;
- dokumen lolos preflight tetapi membuat prompt terlalu besar;
- provider gagal;
- HTML gagal validasi setelah generation.

Temukan titik putus yang sebenarnya.

## 4. Required solution — robust reference preflight

Implementasikan atau perbaiki **satu validation contract** yang dipakai seluruh reference source, tetapi pertahankan source-specific resolution.

Preflight harus memeriksa:

1. Source ownership dan existence untuk scrape reference.
2. File extension `.md` untuk custom [DESIGN.md](http://DESIGN.md).
3. UTF-8, empty content, content length, byte limit.
4. Validitas token warna/font/spacing sesuai dukungan parser.
5. Struktur dokumen yang dapat dipahami tanpa memaksakan satu heading format jika format sah lainnya bisa dinormalisasi.
6. Safety terhadap konten tak tepercaya atau prompt injection.
7. Ketepatan sanitasi: jangan menghapus aturan visual valid secara agresif.
8. Budget konteks yang akan dipakai generation.
9. Descriptive validation result yang dapat ditampilkan sebelum membuat job.

Jika dokumen tidak memenuhi syarat, **jangan membuat project dengan job yang pasti gagal**.

Jangan diam-diam mengganti [DESIGN.md](http://DESIGN.md) user menjadi tema bawaan atau `No Skill`.

## 5. Normalization, not arbitrary truncation

Bila perlu, buat representation terstruktur seperti:

```
DESIGN REFERENCE
  id / source / version
  name
  originalContent
  validatedTokens
  relevantRules
  typography
  spacing
  components
  imageGuidance
  effectiveContextSummary
```

Tetapi:

- Jangan menduplikasi data secara tidak perlu di database.
- Jangan memperkenalkan format persisten baru tanpa kebutuhan jelas.
- Pertahankan original source untuk audit/trace.
- Jangan membuat tokenizer/prompt truncation yang memotong bagian penting dokumen secara acak.
- Jika ada summary, pisahkan summary yang dipakai planning dari aturan visual yang dibutuhkan frame.
- Gunakan hash/ID untuk tracing, jangan menaruh raw private [DESIGN.md](http://DESIGN.md) ke log.

## 6. Integrasi dengan skill

Uji perilaku [DESIGN.md](http://DESIGN.md) dengan:

- No Skill
- Frontend Design
- skill lain yang tersedia jika masih relevan.

**Priority contract:**

```
Security / HTML safety
          |
Explicit user requirements
          |
PRD product requirements
          |
Selected DESIGN.md / theme
          |
Shared project blueprint
          |
Skill-specific advice
          |
Default styling guidance
```

Skill tidak boleh mengganti warna, font, layout constraints, atau component guidance eksplisit yang berasal dari [DESIGN.md](http://DESIGN.md) valid tanpa alasan yang sah.

Sebaliknya, [DESIGN.md](http://DESIGN.md) tidak boleh menyelundupkan instruksi yang mengabaikan keamanan atau kontrak output.

Jangan menyelesaikan error dengan menonaktifkan semua skills.

## 7. Error flow yang diinginkan

```
PILIH REFERENSI
       |
       v
REFERENCE PREFLIGHT
       |
       +-- invalid ---> Show actionable validation message
       |                 Keep selection/file for correction
       |                 NO GENERATION JOB
       |
       v
REFERENCE VALID
       |
       v
SUBMIT -> QUEUED -> PLANNING -> FRAME GENERATION
                              |
                              +-- provider failure
                              |
                              +-- output contract failure
                              |
                              +-- capture failure
                              |
                              v
                     CLASSIFIED RECOVERY
```

### User-facing example

**Invalid custom file**

> [DESIGN.md](http://DESIGN.md) belum bisa digunakan. Periksa bagian warna atau tipografi dalam file, lalu coba lagi.

**Stored scrape reference unavailable**

> Referensi dari VibeScrape sudah tidak tersedia. Pilih referensi lain.

**Provider generation incomplete**

> Halaman belum selesai dibuat karena hasil AI terputus. Coba generate ulang halaman ini.

**Preview failure after valid HTML**

> Desain sudah dibuat, tetapi pratinjaunya belum berhasil ditampilkan. Muat ulang pratinjau.

Copy final harus sesuai klasifikasi kegagalan, bukan selalu pesan yang sama.

Tidak perlu menampilkan pesan teknis seperti `INVALID_OUTPUT` kepada user.

## 8. Preserve data and bounded recovery

- Validasi di server adalah sumber kebenaran.
- UI boleh membantu preflight, tetapi client-side validation tidak cukup.
- Jika satu dari empat frame gagal, tiga frame valid harus tetap tersimpan.
- Jika penyebab ada pada shared planning context, jangan memaksa retry individual yang berulang tanpa memperbaiki shared failure.
- Jika retry adalah recovery yang sah, gunakan mekanisme FIX 01.
- Jangan menciptakan duplicate job/credit charge.
- Jangan melakukan re-generation otomatis terhadap frame completed.
- Jangan menghapus custom upload setelah error kecuali user sengaja menghapusnya.

## 10. Acceptance criteria

- Referensi valid diterima dan aturan desainnya benar-benar diteruskan ke pipeline.
- Referensi tidak valid tertolak sebelum job dibuat.
- Tidak ada silent fallback ke default theme.
- Tidak ada raw user file di logs.
- Custom dan scrape memiliki test terpisah.
- Error generation tidak otomatis dilabeli sebagai error upload.
- Retry mengikuti tahap yang gagal.
- Completed frames tidak hilang akibat satu failure.
