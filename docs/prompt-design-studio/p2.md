# FIX 02 — Fix Canonical CSS Interference, Mobile Layout &amp; HTML Export Fidelity

**Complexity: COMPLEX | Priority: P1 | Scope: Studio generated HTML, canonical shell, CSS and export**

Kerjakan setelah FIX 01 selesai.

## 1. Konteks masalah

Hasil di Studio canvas terlihat cukup rapi, tetapi saat HTML diunduh lalu dibuka langsung, sebagian UI menjadi berantakan.

Dua contoh nyata dari user:

- `2-kustomisasi-pesanan.html`
- `4-pelacakan-pesanan.html`

Audit sebelumnya menemukan bahwa kedua HTML membawa CSS hasil AI sekaligus CSS tambahan dari Studio.

Beberapa konflik konkret:

**Pertama:** desain memakai gutter 16px, sedangkan canonical shell menyuntikkan `--app-gutter: 24px`.

**Kedua:** aturan global untuk button/input memberikan `min-height:44px` dan `padding:10px 14px`, sehingga kontrol kecil seperti quantity stepper bisa berubah proporsinya.

**Ketiga:** aturan gambar universal seperti `aspect-ratio:16/9` dapat bertabrakan dengan container produk berasio 16/10 dan merusak media layout.

**Keempat:** pada desktop 1440px, konten mobile dibatasi sekitar 440px tetapi dapat menempel di kiri karena posisi body/app shell tidak konsisten.

Masalah tersebut tidak boleh diperbaiki hanya dengan meminta AI "buat lebih responsif". Akar masalah CSS perlu ditangani pada sistem HTML assembly.

## 3. Perbaikan canonical CSS

### A. Tentukan batas tanggung jawab CSS

Canonical shell boleh menjamin:

- Identitas aplikasi.
- Header/navigation bersama.
- Semantic design tokens.
- Normalisasi dasar `box-sizing` dan body.
- Struktur shell yang stabil.

Canonical shell tidak boleh secara membabi buta:

- Mengubah ukuran semua button.
- Memaksa semua gambar ke aspect ratio yang sama.
- Menimpa padding spesifik form.
- Mengubah ukuran radio/checkbox/quantity control.
- Memaksa setiap card menjadi `max-width:100%` bila card memang bagian dari horizontal carousel.
- Mengubah typography tanpa menghormati hierarki yang sudah valid.

Pisahkan styling structural shell dari component-specific styling.

Gunakan strategi CSS cascade yang benar, low-specificity defaults, dan scoping. Jangan menambah `!important` secara massal.

### B. Benahi aturan tombol

Audit selector canonical berikut beserta dampak sebenarnya:

```
:where(
  [data-studio-shell] button,
  [data-studio-shell] input,
  [data-studio-shell] select,
  [data-studio-shell] textarea
)
```

Jangan menerapkan satu paket ukuran dan padding yang sama pada semua kontrol.

Target:

- Primary CTA boleh memiliki touch target memadai.
- Quantity stepper tetap proporsional.
- Radio button tidak berubah menjadi kotak gepeng.
- Input tidak kehilangan alignment.
- Kontrol yang memang kecil tetap bisa mempunyai visual ukuran kecil, tanpa mengabaikan kebutuhan area interaksi.

Prioritaskan component-specific rules di atas forced global dimensions.

### C. Benahi media dan gambar

Jangan lagi menjadikan semua `<img>` atau gambar dari provider tertentu sebagai media 16:9 universal.

Dukung beberapa pola yang sengaja berbeda:

- Product thumbnail: bounded media dengan rasio kontekstual.
- Avatar: rasio 1:1.
- Banner/promo: rasio landscape.
- Logo: `object-fit: contain`.
- Photo preview: object-fit sesuai kebutuhan.
- Carousel: tetap menghormati width dan overflow komponennya.

Pastikan stylesheet global tidak mengubah rasio yang sudah dideklarasikan komponen.

### D. Benahi shell mobile yang dibuka di desktop

Untuk output mobile:

- Konten tetap memiliki lebar yang sesuai desain mobile.
- App shell terpusat ketika HTML dibuka pada desktop.
- Background halaman luar tetap harmonis.
- Navigation dan header mengikuti lebar shell.
- Pada viewport mobile, halaman menggunakan lebar yang tersedia tanpa overflow tidak sengaja.

Untuk output web:

- Jangan memasang batas lebar mobile.
- Pertahankan grid desktop dan responsivitas sesuai blueprint.

Jangan menganggap semua halaman harus maksimum 440px. Itu hanya relevan untuk desain mobile.

## 4. Pastikan preview dan export memakai dokumen final konsisten

Periksa apakah screenshot canvas dan export menggunakan sumber HTML final yang sama.

Target architecture:

```
AI generated HTML
       |
       v
Design tokens + canonical assembly
       |
       v
CSS normalization / validation
       |
       v
Final persisted HTML
       |
       +------------------------+
       |                        |
       v                        v
Canvas visual capture       HTML ZIP export
       |                        |
390px mobile viewport       Standalone HTML
       |                        |
       +-----------+------------+
                   |
       Same layout at equal viewport
```

Jangan membuat dua HTML renderer dengan aturan styling berbeda hanya untuk menutupi bug.

### Aset dan dependencies

Audit:

- Local Studio assets.
- Image URLs.
- Google Fonts.
- CSS eksternal.
- Icon sources.
- CSS atau JS runtime yang hanya tersedia saat screenshot.

Existing ZIP exporter sudah mengumpulkan sebagian asset internal. Pertahankan kemampuan tersebut.

Pastikan export tidak menghasilkan referensi asset internal yang hanya dapat diakses ketika user login ke EvVibe.

Untuk external resources, buat keputusan jelas: asset dibundel secara aman jika memungkinkan, atau didokumentasikan sebagai dependency eksternal yang memang diperlukan. Jangan mengklaim offline-ready bila asset belum tersedia offline.

Jangan memasukkan React runtime ke standalone HTML hanya demi menyamakan preview.

## 5. Perbaiki HTML yang sudah dihasilkan

Jika perubahan CSS hanya berlaku untuk proyek baru, tentukan apakah proyek existing dapat diperbaiki melalui transformasi yang aman dan idempotent.

Jangan meregenerasi seluruh screen menggunakan AI hanya untuk mengatasi CSS shell.

Perubahan harus:

- Idempotent.
- Tidak menduplikasi header/navigation/style tag.
- Tidak menghilangkan HTML custom user.
- Tidak merusak revision history.
- Tidak menyebabkan perubahan visual acak pada screen yang sebelumnya valid.

## 7. Component-first requirement

Task ini menyentuh generated HTML, bukan UI React Studio.

Sebelum membuat pola komponen statis baru, audit katalog komponen existing serta referensi resmi shadcn/ui, HeroUI, Magic UI, React Bits, affectUI, TUFFUI, CUI, SakaniUI, dan Thinking Orbs.

Gunakan pola dari komponen matang yang relevan, terutama untuk form, card, segmented input, carousel, dan action group. Jangan langsung menulis pola generik dari nol.

Namun React components tidak boleh diimpor mentah ke HTML standalone. Bila memakai pola dari library, pastikan hasilnya benar-benar HTML/CSS standalone dan lisensinya mengizinkan adaptasi.

Jangan menambahkan efek dekoratif atau animasi yang tidak relevan.

## 8. Acceptance criteria

Targeted tests wajib membuktikan:

1. Canonical assembly tidak menimpa ukuran quantity stepper.
2. Gutter proyek dan shell tidak konflik.
3. Product media mempertahankan rasio spesifik.
4. Logo/avatar tidak dipaksa mengikuti rasio banner.
5. Mobile app shell bisa dipusatkan pada viewport desktop.
6. Web output tidak memakai batas mobile.
7. Carousel horizontal tidak dipotong secara global.
8. Assembly idempotent dan navigation tidak ganda.
9. Export mempertahankan HTML/style yang semestinya.
10. Asset lokal tidak menghasilkan broken internal URL dalam ZIP.
11. HTML final pada input yang sama stabil antarproses.
12. Tidak ada regression pada multi-screen generation.

Gunakan inspeksi source, static checks, targeted tests, dan typecheck. Jangan menjalankan browser QA atau Playwright E2E; pengujian visual langsung ditunda, dan laporkan keterbatasan verifikasinya secara jujur.

## 9. Laporan akhir

Jelaskan CSS rule yang menyebabkan masalah, strategi perbaikannya, file yang diubah, bukti test, dan dampaknya pada HTML existing maupun output baru.

Jangan menandai task selesai hanya karena HTML berhasil diunduh. Kualitas struktur HTML/CSS dan konsistensi transformasi harus dibuktikan melalui pengujian yang memungkinkan tanpa browser QA.
