# PROMPT 09 — Fix Frame Attachment Removal and Generate Meaningful Contextual Prompt Suggestions

**Complexity: MEDIUM–COMPLEX**  
**Execution order: 09 of 13**

## Objective

Fix composer target selection and improve suggested prompts in the new left-side chat workspace.

Two important user complaints:

1. Selected frames become attachments, but the user cannot reliably remove an attachment.
2. Suggestion prompts remain generic, such as "Bikin Profil", instead of expressing meaningful context.

The previous large suggestion-card layout is NOT wanted. Keep compact horizontal bubbles.

## 2. Attachment removal semantics

Desired composer:

```
Selected targets:

[ Beranda  × ] [ Studi Kasus  × ]

+------------------------------------+
| Revisi kedua halaman ini...         |
|                                    |
|                       [ Send ]     |
+------------------------------------+
```

Requirements:

- Each attachment has a clearly visible X.
- X has a sufficient hit target and accessible name.
- Clicking X removes only the corresponding composer target.
- Removing a target never deletes the actual canvas frame.
- Frame ID and version remain explicit internally.
- Multiple selected frames remain correctly represented.
- Selected frame state and composer attachment state must have clearly defined ownership.
- No stale attachment references after a frame is deleted or replaced.
- Provide a clear-all operation if useful and consistent with the chosen component pattern.
- Draft and attachments must not be silently lost when chat collapses.
- When a message is submitted, the target set must be snapshotted so later canvas selection changes do not change that already-submitted operation.

Decide whether removing a chip also deselects the frame on canvas. Use one documented, predictable behavior; do not leave mismatched states.

If Prompt 01 observed a strong Stitch pattern, compare that behavior before choosing.

## 3. Shortcut prompt quality

Do NOT use vague suggestions:

```
[ Bikin Profil ]
[ Bikin Beranda ]
[ Tambah Halaman ]
```

Use concise, domain-specific actions:

```
Travel:
[ + Jelajahi Destinasi ]
[ + Temukan Festival ]
[ + Bagi Biaya Trip ]

Coffee:
[ + Riwayat Pesanan ]
[ + Favorit Kopi ]
[ + Detail Promo ]

Portfolio:
[ + Studi Kasus Proyek ]
[ + Pengalaman Kerja ]
[ + Form Kontak ]
```

These are illustrations, not hardcoded permanent suggestions.

Every bubble maps to a complete contextual prompt internally.

Example:

Visible bubble:  
" + Bagi Biaya Trip "

Actual composer prompt:  
"Tambahkan halaman pembagian biaya perjalanan untuk anggota Squad pada aplikasi ini. Tampilkan item pengeluaran, siapa pembayar, peserta yang berbagi biaya, total per anggota, dan status pelunasan. Pertahankan design system serta navigasi proyek yang sudah ada dan jangan mengubah frame lain."

## 4. Better recommendation logic

Use available context:

- Project purpose and audience.
- Original user prompt.
- PRD, if any.
- Persisted design blueprint.
- Existing frame names/descriptions.
- Navigation destinations.
- User journey gaps.
- Recent conversation and generated screens.
- Platform type.

Reject duplicate screen suggestions and near-synonym duplicates.

Existing deterministic recipes are useful as fallback, but they should not force bland suggestions when richer project context exists.

If using AI to compose better suggestions, evaluate cost and delay. Do not make a new model request on every canvas pan, zoom, or rerender.

Cache based on meaningful project/blueprint revision.

## 5. Bubble UI

```
+--------------------------------------+
| [ + Riwayat ] [ + Favorit ] [ + ... ] |
|                                      |
| [ Attached frame × ]                 |
|                                      |
| Minta revisi atau tambah halaman...  |
|                                [↑]   |
+--------------------------------------+
```

Single horizontal row, scrollable when needed.

Do not turn bubbles into large vertical cards.

Clicking a suggestion must:

1. Prefill the composer with a complete prompt.
2. Allow the user to edit it.
3. Not auto-submit.
4. Not generate or charge credits without submission.

- Remove one attachment out of two.
- Remove all attachments.
- Selected frame remains on canvas after detachment unless intentional policy says otherwise.
- Deleting the underlying frame invalidates its attachment.
- Draft survives collapse/reopen.
- Submitted message retains original target snapshot.
- Multiple targets do not cross project boundaries.
- Click suggestion only prefills composer.
- Full prompt is preserved.
- No duplicate suggestions.
