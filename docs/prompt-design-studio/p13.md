# PROMPT 13 — Final VibeDesign Studio Browser QA, Real Generation Verification, and Product Acceptance

**Complexity: VERY COMPLEX**  
**Execution order: 13 of 13 — FINAL PHASE**

## 1. Mission

Perform comprehensive browser-based quality assurance of EvVibe VibeDesign Studio after all previous implementation phases are complete.

The product must be evaluated as a real user would use it.

The final objectives are:

1. Initial web/mobile frame generation works reliably.
2. The first complete, valid, usable frame is visible within the target of 60 seconds after prompt submission.
3. Generated UI is visually good, contextually appropriate, responsive, and free from the previously reported AI-slop patterns.
4. Frames do not show misleading generation/planning failures.
5. New screens can be added using the AI chat workspace and contextual shortcut bubbles.
6. Frame selection and attachment removal work.
7. Selected theme, custom [DESIGN.md](http://DESIGN.md), and VibeScrape design references genuinely influence output.
8. AI chat persists and remains synchronized with canvas and jobs.
9. Concurrent user requests do not corrupt initial generation.
10. Element-level AI editing works, affects only the intended target, and supports preview/apply/undo.
11. HTML exports look consistent with the Studio preview.
12. Existing projects and historic frames remain accessible after design-skill retirement.

The task is a final verification phase. Do not declare success based on a passing build or screenshots that have not been inspected.

## 5. Test suite B — Error prevention and recovery

Verify:

- No false "Perencanaan layar gagal" while generation is ongoing.
- No false "Halaman belum berhasil dimuat" for a valid loaded preview.
- A failed preview does not delete ready HTML.
- Retry preview does not regenerate HTML.
- Genuine frame failure gives correct recovery action.
- Partial project completion preserves successful frames.
- Refreshing the page during generation does not corrupt progress.
- Worker recovery does not create duplicate frames.
- No unhandled frontend exceptions.
- No unexplained infinite spinner.
- No rejected image asset silently represented as a successful preview.

Use normal controlled failure fixtures where needed; do not deliberately abuse the provider to force rate limits.

## 6. Test suite C — Chat workspace

Validate:

1. Submit initial prompt from landing.
2. Workspace opens with chat panel on left.
3. Original user prompt appears exactly once.
4. Assistant explains the actual plan.
5. Progress corresponds to job state.
6. Frames appear independently as they become available.
7. Collapse chat panel.
8. Canvas gains appropriate space.
9. Reopen chat.
10. History, draft, and frame status remain.
11. Reload page.
12. Conversation and jobs recover.
13. Open project from history.
14. All previous chat/frames are still present.

Do not accept fake assistant confirmations or invented progress percentages.

## 7. Test suite D — Generation while another request is submitted

Critical concurrency scenario:

```
Submit:
"Generate 4 travel screens"

Initial generation active:
Frame 1 ready or generating
Frame 2 generating
Frame 3 generating
Frame 4 queued

Then submit:
"Tambahkan halaman Profil"
```

Expected:

- Request is accepted and represented correctly.
- Initial generation continues.
- Planning is not corrupted.
- Frame titles/descriptions are not replaced by temporary placeholders.
- No duplicated Profile frame.
- The additional request respects actual dependencies.
- Successful frames remain unchanged.
- Profile uses the project's design context.
- Reload preserves the queued request.
- Credit/accounting behavior remains correct.

Also test repeated clicks/network retries and targeted revision while another frame is generating.

## 10. Test suite G — Generated UI visual quality

Review actual screenshots with human-readable criteria:

### Web

- Real desktop navigation patterns.
- No forced mobile tab navbar.
- Consistent content width.
- Appropriate header hierarchy.
- Clear primary action.
- No fabricated factual claims.

### Mobile

- Appropriate app bar and navigation.
- Readable product cards.
- Correct use of horizontal scrolling.
- Form option labels not clipped.
- Price and quantity labels not split.
- Media not awkwardly cropped.
- No content overlap.
- No compressed critical controls.

### Anti-slop

Inspect for:

- Decorative green/yellow/red dots.
- Meaningless status pills.
- Repetitive tinted success/error/warning cards.
- Colored side borders without meaning.
- Fake metrics.
- Fake testimonials presented as real.
- Excessive gradients or nested cards.
- Generic hero/app-bar copy unrelated to the product.
- Unnecessary visual clutter.

Functional statuses are allowed. Do not penalize valid badge use.

Record concrete defects with screenshots and locations, not subjective labels alone.
