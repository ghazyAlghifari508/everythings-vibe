## LANGKAH 3 — EVALUASI PERAN MASING-MASING SKILL

Gunakan pembagian awal berikut sebagai hipotesis desain yang harus diverifikasi dengan upstream dan testing.

### UI UX Pro Max

Cocok sebagai panduan luas untuk:

- SaaS.
- Mobile app.
- Dashboard.
- Data-heavy interface.
- Design tokens.
- Charts.
- UX patterns.
- Typography.
- Platform-specific guidelines.

Pastikan dataset lookup yang sudah ada bekerja secara relevan dan tidak memasukkan seluruh CSV secara membabi buta.

### Frontend Design

Cocok sebagai panduan:

- Distinctive visual identity.
- Non-generic composition.
- Visual hierarchy.
- Typography direction.
- Brand personality.
- Interface craft.

Jangan memaksa layout marketing pada aplikasi operasional.

### Impeccable

Prioritas sebagai:

- UI refinement guidance.
- Critique/polish instructions.
- Revision quality.
- Spacing and typography improvements.
- Accessibility and interaction checks.

Perhatikan bahwa interactive upstream tooling tidak otomatis dijalankan hanya karena [SKILL.md](http://SKILL.md) dipakai.

### Anti-Slop

Cocok untuk:

- Detecting generic design patterns.
- Redundant components.
- Weak hierarchy.
- Excessive badges.
- Inconsistent spacing.
- UI layout anti-patterns.
- Accessibility/layout warnings.

Jangan gunakan seluruh Anti-Slop sebagai pengganti product design direction.

### Taste

Setelah upgrade, cocok untuk:

- Intentional art direction.
- Brand personality.
- Context-appropriate composition.
- App-screen design principles.
- Typography and spatial rhythm.
- Visual specificity.

Gunakan workflow app-screen yang sesuai, bukan marketing landing flow untuk semua project.

### No Skill

Tetap harus menghasilkan:

- Valid HTML.
- Responsive layout.
- Clear hierarchy.
- Accessible controls.
- Consistent shared design system.
- No clipping.
- No overlapping components.
- Good default product UX.

No Skill tidak boleh berarti No Quality.

## LANGKAH 4 — PISAHKAN QUALITY RULES DARI SELECTED SKILL

TARGET ARCHITECTURE:

```
USER BRIEF + PRD + DESIGN.md
              |
              v
       STUDIO DESIGN ENGINE
              |
              v
        SHARED BLUEPRINT
              |
      +-------+-------+
      |               |
      v               v
 SELECTED SKILL    BASE QUALITY RULES
      |               |
      +-------+-------+
              |
              v
       GENERATE FRAME HTML
              |
              v
        VALIDATION GATE
              |
              v
             READY
```

Base Quality Rules adalah standar Studio yang selalu berlaku, bukan skill baru yang dipilih user.

Isinya harus ringkas, konkret, dan dapat diuji:

- No horizontal overflow.
- No controls overlapping.
- Correct responsive behavior.
- Appropriate content hierarchy.
- Consistent spacing.
- Proper accessible names.
- No duplicated shell.
- No pointless skeleton.
- No redundant badges.
- No broken component structure.
- No randomly detached icons.
- No arbitrary text splitting.
- Shared design tokens respected.

Jangan menyalin seluruh Anti-Slop menjadi permanent system prompt.

Pilih prinsip kualitas yang universal sebagai produk Studio sendiri, bukan berpura-pura menjalankan seluruh upstream Anti-Slop ketika user memilih No Skill.

Pisahkan metadata provenance agar tidak membingungkan.
