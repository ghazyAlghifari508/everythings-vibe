## 1. Objective

Generated frames VibeDesign harus terlihat seperti halaman aplikasi profesional yang benar-benar dirancang, bukan kumpulan card generik, HTML berantakan, placeholder yang dianggap hasil akhir, atau ilustrasi kode yang tidak cocok dengan domain produk.

Jangan mengerjakan task ini dengan hanya menambahkan kalimat "make beautiful UI" ke system prompt.

Perbaiki penyebab pada:
- design planning;
- component guidance;
- canonical HTML assembly;
- CSS/layout contracts;
- generated HTML validation;
- renderer;
- prompt shortcut content;
- media sourcing;
- quality enforcement.

Pertahankan kualitas desain, variasi produk, dan konsistensi antarhalaman.

## 2. Bug report yang harus direproduksi dengan fixtures

### A. Broken text and wrapping

Observed defects:
- \`Rp\` berada di atas angka nominal.
- \`Rp 7.750.000\` terpecah secara vertikal.
- \`Mulai Dari / Rp 3.900.000 / orang / nett\` mempunyai alignment tidak masuk akal.
- \`Terverifikasi Lunas\` menjadi badge yang memanjang ke bawah.
- \`Private Trip\` terpotong menjadi dua baris.
- Label atau button terpotong.
- Dropdown dan icon chevron menempel di tepi card.

### B. Poor component composition

- Badges berlebihan.
- Card di dalam card tanpa makna.
- Gap terlalu kecil atau tidak konsisten.
- Heading/header generik.
- Double navigation/app bar.
- Konten di luar viewport.
- Tombol atau search controls overlap.
- Panel terasa seperti kumpulan template, bukan product UI.

### C. Wrong visual states

- Skeleton muncul di desain utama padahal user tidak meminta loading screen.
- Empty cards atau placeholder generik muncul sebagai konten final.
- AI menambahkan teks seperti internal state, telemetry, atau implementasi.

### D. Inappropriate images

Travel app kadang menggunakan ilustrasi SVG berbentuk pemandangan/gunung yang dibuat di source code, padahal user menginginkan media destinasi yang realistis dan profesional.

Jangan memakai ilustrasi kode sebagai pengganti foto produk/travel hanya karena lebih mudah.

### E. Inconsistent shell

- Brand kecil di kiri dan screen heading besar di kanan, terlihat seperti dua judul yang tidak terkoordinasi.
- Mobile screens punya header dan nav berbeda-beda.
- App bar/navigation kadang diduplikasi oleh AI.
- Some content has unexpected outer margins/gaps or clipping.

## 5. Expected layout contracts

### Currency and pricing

Correct:

\`\`\`text
┌──────────────────────────────────────┐
│ Mulai dari                           │
│                                      │
│ Rp 3.900.000  / orang                │
│                                      │
│ \[ Lihat detail paket             → \] │
└──────────────────────────────────────┘
\`\`\`

Wrong:

\`\`\`text
Mulai Dari
Rp
3.900.000
/ orang
nett
\`\`\`

Use proper inline grouping, font sizing, tabular numbers, responsive containers, and enough room.

Do not apply \`white-space: nowrap\` indiscriminately to large text or paragraphs. Keep atomic values together and let surrounding layout wrap or stack logically.

### Label and badge

Correct:

\`\`\`text
Status pembayaran
✓ Lunas
\`\`\`

Not:

\`\`\`text
\[ Terverifikasi
       Lunas  \]
\`\`\`

A badge must convey useful status. If normal body text or a status row is clearer, do not invent badges.

## 6. Fix canonical shell and CSS collisions

Verify the current ownership contract:

- Studio owns app shell, outer gutter, global navigation, shared header, tokens.
- Generated screen owns its screen-specific content.
- No duplicated global navigation or app bar.
- No nested full-screen wrapper that creates unexpected gaps.
- No CSS rules that override canonical layout accidentally.
- Shared navigation remains consistent across all project screens.

Review whether generated CSS selectors are overly broad:
- \`body\`, \`header\`, \`nav\`, \`main\`, \`button\`;
- global element selectors;
- fixed/sticky elements;
- utility classes that collide with canonical shell;
- nested viewport-height wrappers;
- tables with large intrinsic width.

Use namespacing/contract enforcement where justified. Do not solve collisions by deleting all frame styling.

For previously stored frame HTML, do not silently regenerate every screen. Preserve existing content and revisions unless the user explicitly requests regeneration or a safe compatibility migration is necessary.

## 7. Professional design quality rules

Enforce:
- realistic product hierarchy;
- role-appropriate density;
- meaningful components;
- consistent spacing scale;
- appropriate image ratios;
- coherent typography;
- sufficient contrast;
- controlled badge usage;
- responsive width management;
- intentional empty states;
- consistent navigation;
- readable labels;
- restrained effects;
- domain-appropriate visual composition.

Quality must be product-dependent.

Do not turn every finance project green, every travel project blue, or every dashboard into identical cards. Selected theme/valid DESIGN.md wins where applicable.

Skill may refine design, but must not override explicit design tokens or global shell rules.

## 8. Stop unnecessary skeletons

Inspect launch shortcut prompts and domain guidance. Some current shortcuts explicitly describe skeleton loading states.

For normal requested screens:

\`\`\`text
Requested:
"Design a travel search page"

Expected:
Search fields + destination results + relevant content.

NOT expected:
Main area dominated by skeleton placeholders.
\`\`\`

If user explicitly asks to design the loading state, skeletons are legitimate. Otherwise, they are not a substitute for completing the page.

Do not globally forbid meaningful loading states; prevent them from replacing the requested primary screen.

## 9. Image / asset strategy

Research official media integrations and the actual renderer.

For realistic travel/product photography, use approved providers and verified URLs where legally and technically permitted.

If integrating Unsplash API, follow their official current documentation:
https://unsplash.com/documentation
https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines

Respect provider attribution, URLs, hotlinking rules, access keys, rate limits, and usage restrictions. Never copy arbitrary Pinterest images or scrape copyrighted photos blindly.

The current renderer has guarded remote resource loading. Trace that before adding image sources.

A real photo must:
- be relevant to the actual screen;
- load reliably in saved previews;
- have correct aspect ratio and cropping;
- not break frame generation if an external provider is unavailable;
- have a safe fallback consistent with design;
- obey provider licensing/terms.

If production credentials are unavailable, do not invent tokens or claim the image API is integrated. Keep the system usable without fabricated media.

## 10. Quality validation design

The goal is preventing broken output, not merely producing warnings.

Introduce or improve detection for:
- content outside viewport;
- invalid horizontal overflow;
- overlapping control regions;
- incomplete cards;
- empty main content;
- duplicated app navigation;
- illegible/broken button labels;
- split currency values;
- suspicious placeholder/skeleton-heavy primary screens;
- CSS collisions with canonical shell;
- missing images and styles.

Use safe DOM/style diagnostics within the actual generation/capture pipeline where supported.

Do not claim JSDOM alone can validate pixel geometry.

Distinguish:
- fatal defect requiring correction;
- deterministic repair candidate;
- actionable quality warning;
- acceptable intentional responsive wrapping.

Prevent false positives: long tables can scroll within bounded containers, paragraphs may wrap, and intentionally designed loading screens can contain skeletons.

Avoid sending the full HTML to the model again for every small warning. Reuse FIX 01's bounded correction strategy.

## 12. Explicit non-goals

- No redesign of VibeDesign Studio landing itself.
- No giant new UI framework just to solve a CSS bug.
- No blanket hardcoded HTML template used for every project.
- No replacing user-selected DESIGN.md with default styles.
- No generating all existing frames again.
- No removing valid features just because they complicate layout.
- No blind addition of animations or visual clutter.
- No fake placeholder data pretending to be functional backend data.

## 13. Definition of done

- Known currency/label wrapping defects are addressed with regression tests.
- Canonical header/navigation ownership is consistent.
- Frames cannot pass validation with known critical structural defects.
- Skeletons are no longer substituted for normal screens.
- Images use valid, safe asset strategies rather than fake source-code artwork where realistic media is expected.
- Existing finished frames are preserved.
- Core quality standards apply with No Skill as well as selected skills.
- Selected themes and DESIGN.md remain authoritative.
- No unjustified AI-slop components are added.

Final report must distinguish what was fixed deterministically, what still depends on AI model quality, and what requires provider availability.
