# PHASE 3 — Repair Design Reference Resolution, Validation, Persistence &amp; AI Generation Integration

**Priority: P1 — HIGH**  
**Complexity: COMPLEX**  
**Branch:** `feature/vibedesign-design-studio`

## 1. Objective

Fix VibeDesign Studio's design-reference feature end to end.

The user can select a visual reference from:

1. Built-in themes.
2. Existing VibeScrape [DESIGN.md](http://DESIGN.md) documents.
3. Uploaded custom [DESIGN.md](http://DESIGN.md) files.
4. Optional uploaded application logos.

However, generation sometimes fails with:

"Terjadi kendala saat memproses permintaan Studio. Silakan coba beberapa saat lagi."

The feature must work with every supported design skill, including No Skill.

The goal is not merely to make the API return success.

**The selected reference must actually influence generated HTML, persist correctly, survive reloads, and remain compatible with the selected design skill.**

## 4. Audit Actual Error Sources

Investigate:

- Invalid or unavailable scrape ID.
- Ownership/authorization mismatch.
- Missing persisted [DESIGN.md](http://DESIGN.md).
- Incompatible source document format.
- Failure in token extraction.
- Invalid hex values.
- Incorrect maximum-byte or character handling.
- Failed Zod validation.
- Database persistence failures.
- Invalid optional logo payload.
- Reference metadata mismatch.
- Generation request construction.
- Unhandled exceptions.

The existing token gate may require usable color or typography tokens.

Check whether valid VibeScrape [DESIGN.md](http://DESIGN.md) documents can be rejected because the parser expects a narrower format.

Do not solve this by accepting arbitrary malformed Markdown without validation.

Instead, define and document a shared accepted [DESIGN.md](http://DESIGN.md) contract that both VibeScrape and Studio can understand.

If legacy formats exist, implement a safe compatibility adapter where justified.

## 5. Validation &amp; Persistence

The user should experience:

```
Select reference
       |
       v
Reference staged in composer
       |
       v
User submits
       |
       v
Server validates reference
       |
  +----+-----+
  |          |
Valid       Invalid
  |          |
  v          v
Persist    Specific safe error
  |
  v
Generate with reference
  |
  v
Reopen project later
  |
  v
Reference still associated with project
```

Requirements:

- Treat draft selection and submitted reference separately.
- Preserve staged selection until user changes or removes it.
- Enforce ownership of private scrape data.
- Persist source type and identifier correctly.
- Handle unavailable/deleted sources explicitly.
- Avoid duplicate copying of unnecessarily large reference documents.
- Use stable metadata/provenance where appropriate.
- Prevent accidental fallback to unrelated references.
- Preserve valid uploaded logos.
- Verify that the persisted reference is actually consumed by generation.

## 6. Compatibility with Design Skills

Support the following combinations:

```
                      DESIGN SKILL

Reference           None   Impeccable   Frontend   UI UX Pro Max   Anti-Slop   Taste
------------------------------------------------------------------------------------
Built-in Theme       ✓         ✓           ✓            ✓            ✓         ✓
VibeScrape .md       ✓         ✓           ✓            ✓            ✓         ✓
Custom DESIGN.md     ✓         ✓           ✓            ✓            ✓         ✓
```

The matrix defines required compatibility, not current verified behavior.

Important precedence rules:

1. Safety and application output contracts remain mandatory.
2. Explicit user requirements remain authoritative within those contracts.
3. Selected [DESIGN.md](http://DESIGN.md) defines the visual identity where specified.
4. The selected skill provides compatible guidance and refinement.
5. Baseline Studio defaults fill genuinely unspecified details.

Example:


If [DESIGN.md](http://DESIGN.md) specifies a teal brand palette and Impeccable is selected, Impeccable must not arbitrarily replace teal with an unrelated palette.

The skill should improve hierarchy, composition, craft, and usability while respecting the supplied design system.

**Never silently discard the design reference just to make generation succeed.**

## 7. Real Reference Application

Audit whether reference information affects:

- Primary and secondary colors.
- Font family.
- Typography hierarchy.
- Corner-radius conventions.
- Surface/background tokens.
- Button and input styles.
- Navigation identity.
- Spacing patterns.
- Cross-frame consistency.
- Optional application logo.

Not every reference contains every token. Apply available information faithfully.

For absent details, allow sensible defaults rather than fabricating source-specific values.

Avoid hardcoded palettes that override user references.

## 8. Error Handling

Eliminate the generic unexplained failure where specific, safe recovery guidance is available.

Examples:

**Invalid [DESIGN.md](http://DESIGN.md)**

"File desain belum bisa digunakan. Periksa isinya lalu unggah kembali."

**Source unavailable**

"Referensi desain ini sudah tidak tersedia. Pilih referensi lain."

**Temporary service problem**

"Desain belum berhasil diproses. Coba lagi."

Internal logs should retain the actual error category, operation, and correlation ID.

Public UI must not expose internal database or AI-processing terminology.

Never log full user [DESIGN.md](http://DESIGN.md) contents or credentials.

- All supported references resolve correctly.
- VibeScrape and Studio use compatible [DESIGN.md](http://DESIGN.md) parsing.
