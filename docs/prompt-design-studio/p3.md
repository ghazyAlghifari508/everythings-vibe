## 1. Critical Objective

Fix the existing "Pilih tampilan" Design Picker fullscreen layout.

The user explicitly wants the layout composition of Google Stitch's "Start with your design" screen.

This does NOT mean creating a new modal from scratch or copying unrelated Stitch features.

The current implementation is visually inconsistent:

- The modal itself fills the viewport, but content groups are positioned incorrectly.
- The Tema tab appears too low.
- The Template tab starts at a different vertical position.
- The Punya Saya tab has another starting position.
- The title, description, tabs, content, and footer do not share a stable visual structure.
- The close icon remains pinned to the viewport's extreme top-right corner instead of aligning with the content column.
- Some headings and sections have inconsistent left alignment.

**The target is a TRUE FULLSCREEN SURFACE with a SINGLE, TOP-ALIGNED, HORIZONTALLY CENTERED CONTENT COLUMN.**

### Non-negotiable

**DO NOT vertically center the entire content group.**

**DO NOT place the close button at the far-right edge of the viewport.**

**DO NOT allow switching tabs to move the header or tabs vertically.**

**DO NOT enlarge the tabs, cards, typography, or upload fields to fill the fullscreen area.**

## 4. Required Structural Fix

Use a structure conceptually like:

```
Fullscreen Dialog Root
│
└── Scrollable Fullscreen Surface
    │
    └── Centered Content Container
        │
        ├── Header Row
        │   ├── Title + Description
        │   └── Close Button
        │
        ├── Compact Tabs
        │
        ├── Active Tab Panel
        │   ├── Tema
        │   ├── Template
        │   └── Punya Saya
        │
        └── Footer Actions
```

### Fullscreen shell

- `inset: 0`.
- `width: 100vw`.
- `height: 100dvh`.
- No floating margin.
- No outer rounded corners.
- No outer dialog shadow.
- No separate backdrop strip visible around the dialog.
- Maintain proper modal semantics and focus trapping.

### Centered content

- Use `width: 100%`.
- Apply a sensible responsive `max-width` (around 780–960px as a starting point).
- `margin-inline: auto`.
- Use top padding appropriate to the reference, e.g. a restrained 40–64px range on large displays, adjusted responsively.
- Do not use `my-auto`, `justify-center`, or equivalent logic to vertically center the full group.
- Do not introduce a bordered card around the inner wrapper.
- Keep one stable content column for all three tabs.

### Header

- Title and description aligned to the same left edge.
- Close button aligned to the right edge of the SAME content container.
- Title and description should not float at different horizontal origins.
- Use the current product typography and appropriate sizing.
- Keep header height stable when switching tabs.

### Close button

The existing shared Dialog primitive currently renders a built-in X in the top-right corner of the dialog.

Fix this properly.

Preferred approach:

- Add a narrowly scoped optional mechanism to the existing Dialog primitive to suppress its default close button, only when explicitly requested.
- Render ONE accessible `DialogClose` button within the centered header row.
- Maintain Escape dismissal.
- Preserve focus behavior and accessibility.
- Do not create duplicate X buttons.
- Do not globally move every Dialog's close button.
- Do not hide the old X with brittle arbitrary CSS selectors while leaving duplicate controls in the accessibility tree.

### Tabs

- Keep Tema, Template, and Punya Saya compact.
- No massive full-width segmented control.
- Maintain appropriate active/focus states.
- Keep tab navigation at exactly the same position across tabs.
- Prefer existing Radix/shadcn Tabs primitives where compatible.
- Preserve keyboard behavior.
