# FIX 03 — Rebuild Studio Quality Enforcement Without Rebuilding Studio UI

\*\*Complexity: VERY COMPLEX | Priority: P1 | Scope: AI-generated prototype quality\*\*

Kerjakan setelah FIX 02 selesai.

## 1. Tujuan

Perbaiki kualitas AI-generated screens secara sistematis agar EvVibe VibeDesign Studio menghasilkan antarmuka yang rapi, kontekstual, konsisten, dan responsif.

Masalah user bukan soal desain yang kurang banyak animasi. Masalahnya adalah banyak generated UI tampak seperti AI slop, tidak menghormati kebutuhan aplikasi, dan memiliki layout rusak.

Jangan sekadar memperpanjang system prompt dengan kata "professional", "premium", "beautiful", atau "world-class".

Buat quality pipeline yang benar, reusable, measurable, serta tetap mempertahankan kreativitas desain sesuai domain aplikasi.

## 2. Semua masalah yang wajib diselesaikan

### A. Inconsistent screen layout

Contoh proyek Ruang Seduh:

- Frame 1 mempunyai konten terlalu terpusat dan menyisakan ruang kanan/kiri yang tidak proporsional.
- Frame 2 dan 3 terlihat lebih rapi dengan penggunaan lebar mobile yang lebih baik.
- Design identity sebenarnya mirip, tetapi komposisi antarscreen tidak konsisten.

Perbaiki sistem perencanaan supaya seluruh screen berbagi kontrak layout yang sesuai produk, seperti:

- App gutter.
- Content width.
- Typography scale.
- Spacing scale.
- Corner radius.
- Component density.
- Navigation structure.
- Brand colors.
- Interactive affordance.

Jangan membuat semua screen identik. Halaman eksplorasi, detail produk, checkout, dan tracking harus punya komposisi berbeda sesuai fungsinya tetapi tetap terasa berasal dari aplikasi yang sama.

### B. Product image clipping

Contoh gambar Cascara Berry dan Aeropress:

Gambar hanya terlihat sebagian pada card, sementara area media lainnya terlihat kosong atau tidak proporsional.

Selidiki:

- Parent height dan aspect ratio.
- \`object-fit\` / \`object-position\`.
- CSS canonical yang memengaruhi image.
- Intrinsic image dimensions.
- Overflow pada wrapper.
- Media fallback.
- Layout composition hasil model.

Jangan langsung menyimpulkan jaringan atau image provider sebagai satu-satunya penyebab. FIX 02 telah menangani gangguan CSS global; FIX 03 harus memastikan model menghasilkan media patterns yang benar sejak awal.

### C. Decorative badge and random dots

User tidak ingin:

- Badge status palsu.
- Dot warna hijau, kuning, merah yang tidak menjelaskan apa pun.
- Pill/pill bertumpuk.
- Label dekoratif yang hanya menambah keramaian.
- Floating icons yang tidak berhubungan dengan aktivitas user.
- Repetisi "premium", "verified", "live", dan dekorasi generik pada semua card.

Tetapi jangan menghapus seluruh badge/dot secara membabi buta.

Badge dan dot tetap diperbolehkan jika secara fungsional menunjukkan:

- Selected option.
- Availability seperti Buka/Tutup.
- Payment state.
- Stok tersedia/habis.
- Error atau warning nyata.
- Progress yang betul-betul mempunyai data.
- Kategori yang memang diperlukan untuk scanning.

Gunakan status semantik, bukan warna sebagai satu-satunya penanda.

### D. Horizontal cards dipaksa mengecil

Pada aplikasi mobile, tidak semua komponen harus dipaksa muat dalam satu viewport.

Contoh yang boleh menggunakan horizontal scrolling:

- Product recommendation carousel.
- Promo banner carousel.
- Travel destination cards.
- Featured category cards.
- Collection thumbnails.

Jangan memperkecil card sampai kontennya rusak.

Berikan aturan pada AI untuk memilih antara:

1. Vertical reflow.
2. Responsive grid.
3. Horizontal overflow with intentional scrolling.
4. Proper content truncation.
5. Detail expansion.

Keputusan tersebut harus berdasarkan fungsi, bukan aturan global bahwa mobile selalu satu kolom.

### E. Awkward line wrapping

Contoh buruk:

\`\`\`text
\[ 3    \]
\[ item \]
\`\`\`

Padahal harus:

\`\`\`text
\[ 3 Item \]
\`\`\`

Contoh lain:

- Nominal rupiah terpisah.
- Label button pecah.
- Judul card memakan ruang berlebihan.
- Metadata turun secara acak.
- Text clipping ketika tersedia ruang yang seharusnya bisa digunakan.

Terapkan aturan untuk atomic labels, currency formatting, flex sizing, min-width, text wrapping, dan overflow yang sesuai.

### F. Squashed controls and form options

Contoh nyata:

- Pilihan susu menampilkan label yang dipotong.
- Quantity stepper kehilangan proporsi.
- Button \`+ Ke Keranjang\` dan harga saling berebut ruang.
- Form option memiliki layout terlalu sempit.

Kualitas form wajib mencakup:

- Text readability.
- Tap target yang memadai.
- Clear selected state.
- Space untuk label dan informasi harga.
- Form controls tidak overlap.
- Tidak ada label penting yang hilang karena ellipsis.
- Prioritas visual antara nama, deskripsi, dan extra price.

### G. Generic application UI

Jangan menghasilkan satu komposisi dashboard yang sama untuk semua domain.

Aplikasi kopi, travel, keuangan, marketplace, dashboard SaaS, dan portofolio mempunyai kebutuhan yang berbeda.

AI harus memilih komponen berdasarkan user journey, density, domain, jenis konten, dan platform.

\`\`\`text

Prinsip implementasi:

- Reuse existing component yang kompatibel.
- Untuk UI React Studio, install/adapt komponen resmi ketika perlu.
- Untuk generated standalone HTML, ambil pendekatan HTML/CSS yang sesuai dari pola komponen yang diizinkan lisensinya.

- Jangan copy source premium tanpa lisensi.
- Jangan menggunakan efek animasi hanya karena library menyediakannya.
- Jika tidak ada komponen yang cocok, buat komponen statis sendiri yang benar-benar diperlukan setelah discovery terdokumentasi.

Quality lebih penting daripada jumlah library yang terpasang.

## 5. Improve planning contract

Tambahkan informasi perencanaan yang benar-benar diperlukan, bukan schema bloat.

Shared blueprint harus cukup memberi arahan mengenai:

- Design identity.
- Layout density.
- Responsive intent.
- Component roles.
- Content hierarchy.
- Media presentation.
- Screen-specific layout.
- Shared spacing dan typography.
- Domain-specific visual needs.

Jangan menduplikasi data yang sudah ada pada blueprint.

Contoh:

\`\`\`text
Product: Ruang Seduh
Platform: Mobile

Shared:
- Consistent warm neutral palette
- Consistent 16px content gutter
- Clear functional typography
- Product photos use suitable media frames
- App navigation shared
- Buttons and status elements have clear purpose

Screen: Menu

- Full-width search field
- Horizontal promotional carousel

Angka spacing pada contoh hanya konteks desain Ruang Seduh, bukan aturan global untuk semua produk.

## 6. Improve generation rules

Buat generation lebih component-aware dan layout-aware.

Prioritaskan:

- Semantic HTML.
- Content-first composition.
- Intentional spacing.
- Correct media sizing.
- Responsive behavior by component type.
- Purposeful badges.
- Proper typography and contrast.
- Domain-specific structure.
- Shared design tokens.
- Distinct but consistent screen compositions.

Cegah:

- Generic KPI card di semua domain.
- Tiny unreadable text.
- Oversized decorative whitespace.
- Decorative status pills.
- Fake loading states.
- Arbitrary dots and colored chips.
- Nested borders tanpa alasan.
- Repeated cards with identical hierarchy.
- Forced line breaks.
- Horizontal cards yang dipaksa menyusut.
- Images dengan crop yang tidak sesuai.

Pertahankan kebebasan visual jika user secara eksplisit meminta gaya tertentu. Jangan mengubah taste preference menjadi larangan absolut untuk semua desain.

## 7. Strengthen quality enforcement

Audit masalah penting: di \`studio-frame-generation.ts\`, hasil \`diagnostics.hard\` dimasukkan ke issues, tetapi \`diagnostics.warnings\` belum dijadikan dasar koreksi.

Jangan langsung mengubah seluruh warnings menjadi hard errors. Itu berisiko membuat AI terjebak retry loop.

Buat klasifikasi:

\*\*Hard violations:\*\*

- Invalid HTML.
- Unsafe markup.
- Broken canonical structure.
- Severe overflow.
- Essential control missing.
- Definite unreadable or inaccessible structure.

\*\*Repairable quality violations:\*\*

- Essential text clipped.
- Product image sizing conflict yang terdeteksi secara pasti.
- Invalid narrow-width composition.
- Broken price/quantity grouping.
- Critical content hidden by parent layout.

\*\*Advisory:\*\*

- Badge yang mungkin berlebihan.
- Optional visual polish.
- Minor typography refinement.

Gunakan severity dan confidence, sehingga quality gate tidak menghasilkan false positives.

Preserve bounded correction retry. Jangan membakar token tanpa batas hanya untuk mengejar skor estetika.

Audit apakah validation check sekarang hanya menilai source CSS/DOM tanpa memahami hasil layout. Jika memang begitu, perkuat deterministic checks yang bisa dilakukan secara aman tanpa browser QA.

Jangan mengklaim bisa membuktikan pixel-perfect visual hanya dari parsing HTML statis.

## 8. Prevent canonical CSS regression

FIX 02 sudah mengatur baseline CSS.

FIX 03 harus memastikan AI output mengikuti kontrak tersebut:

- Jangan melawan shell dengan duplicated header/nav.
- Jangan bergantung pada override \`!important\`.
- Jangan menggunakan width hack untuk menutupi CSS global.
- Jangan meminta AI memperbaiki bug yang sebetulnya berasal dari canonical assembly.

Pisahkan kegagalan model generation dari kegagalan post-processing.

## 10. Deterministic tests

Buat targeted regression tests untuk:

- Quality rules aktif meskipun design skill \`none\`.
- Selected design skill tidak menghilangkan baseline quality.
- Domain rules tidak memaksa semua layout sama.
- Consistent blueprint tokens antarscreen.
- Media aspect ratio tidak ditimpa.
- Horizontal scroller tidak diganti forced shrinking.
- Valid mobile input controls.
- Atomic price and quantity labels.
- No duplicated status badge dalam satu konteks.
- Essential texts tidak sengaja diberi clipping rule.
- \`hard\`, \`repairable\`, dan \`advisory\` diproses berbeda.
- Bounded correction tetap berfungsi.
- False-positive warning tidak memicu retry tanpa akhir.
- Invalid output tidak dinyatakan berhasil.
- Existing generated HTML tidak rusak akibat perubahan generator.

Gunakan contoh Ruang Seduh sebagai regression fixture bila sesuai, tetapi jangan hardcode nama brand, teks, atau layout proyek ini sebagai special case.

Jangan membuat test yang membandingkan AI-generated copy secara persis.

## 11. Batasan implementasi

Tidak boleh:

- Menulis ulang seluruh Studio.
- Membuat design system paralel yang tidak diperlukan.
- Menghapus existing skills.
- Memaksa satu template UI untuk semua domain.
- Menggunakan React runtime dalam standalone HTML.
- Menginstal seluruh component libraries sekaligus.
- Membuat fake progress/validation.
- Menambahkan visual clutter demi tampilan "premium".
- Melemahkan tests.
- Menjalankan browser QA atau Playwright E2E.

Quality improvements harus berlaku untuk generation, revision, dan correction stage yang relevan, bukan hanya initial generation.

## 12. Definition of done

Laporkan:

1. Akar masalah quality pipeline.
2. Rules yang diperbaiki.
3. Component patterns yang dipilih dan sumbernya.
4. Perubahan planning dan generation.
5. Quality checks baru.
6. Regression tests.
7. Tradeoff token/performance.
8. Keterbatasan validasi visual yang belum dilakukan.

Task belum selesai jika solusi hanya menambahkan beberapa larangan ke system prompt, sementara HTML tetap melewati quality gate tanpa perbaikan struktural.
