# PROMPT 10 — Implement Select-Element, Scoped AI Revision, Preview, Apply, and Undo

**Complexity: VERY COMPLEX**  
**Execution order: 10 of 13**

## Goal

Implement element-level AI editing in VibeDesign Studio.

Desired interaction:

1. User selects a frame.
2. User activates Select Element mode.
3. User clicks a specific section, card, text block, image, or other meaningful HTML element.
4. The target becomes attached to the AI composer.
5. User writes an instruction such as "Hapus section Statistik Karier".
6. AI or a safe deterministic patch modifies only the selected target and necessary dependent layout.
7. User previews the proposed change.
8. User chooses Apply or Cancel.
9. User can undo an applied revision.

**Do not implement full manual visual editing** such as direct dragging/resizing/recoloring through a property inspector. That is explicitly out of scope.

## 2. Understand the existing limitation

VibeDesign currently displays generated frame screenshots in the canvas.

A screenshot does not reveal DOM node identity.

Therefore do not implement element selection by guessing which CSS selector corresponds to an arbitrary click coordinate on JPEG.

Design an authorized, isolated HTML inspection surface for element selection.

The normal canvas can remain image-based where practical.

An element-selection mode may use a live, isolated iframe or another verified DOM-backed mapping mechanism.

## 4. Element identity and targeting

Store enough information to identify the intended target safely:

- Project ID.
- Frame ID.
- HTML revision/version.
- Stable element ID where available.
- Structural selector or DOM path as secondary context.
- Element tag/role.
- Short content/context signature.
- Relevant parent/ancestor identity.
- Selection bounds for UI overlays.

Consider generating stable element identifiers in final HTML when feasible.

Avoid relying exclusively on `nth-child()` selectors because insertions/reordering can invalidate them.

If target identity cannot be resolved with confidence, require re-selection.

Never silently apply a revision to another element with similar text.

## 5. Sandboxed iframe and bridge

Design a minimal selection bridge compatible with existing security constraints.

Requirements:

- Generated HTML remains untrusted.
- Use appropriate iframe sandbox boundaries.
- Avoid enabling unrelated script execution privileges.
- Parent verifies message source, origin policy, message type, and frame identity.
- Use a bounded, typed message protocol.
- Do not accept arbitrary HTML/JS commands from postMessage.
- Selection overlay should not become part of exported HTML.
- Frame zoom/pan coordinates must map correctly to element bounds.
- The selection UI should respect scrolling inside the frame.

Do not disable existing HTML sanitization because interactive selection becomes easier.

## 6. Scoped revision operations

Differentiate operations.

### Deterministic operations

For straightforward changes, prefer safe structural edits if possible:

- Remove exactly one identified section.
- Change a known text node.
- Replace a known image reference.
- Modify a narrowly scoped attribute.

### AI-assisted operations

For context-dependent changes:

- Redesign selected card.
- Improve selected hero.
- Rework a particular form section.
- Adjust one component hierarchy.

Send the model the selected element, relevant surrounding context, shared design tokens, and explicit change boundaries.

Do not send every unrelated frame when a localized edit is sufficient.

Do not let the model replace the entire HTML file unnecessarily.

If a whole-document rewrite is technically unavoidable, compare the result to the base revision and reject changes outside the permitted scope unless they are necessary dependencies and explicitly justified.

## 7. Version safety

Use optimistic concurrency or an equivalent persisted guard.

```
Selected:
Frame A / version 5 / element X

AI creates candidate based on version 5
               |
               v
Before Apply:
Is current version still 5?
       /                    \
      Yes                   No
       |                     |
     Apply             Stale revision
       |                     |
  Save version 6       Ask to reselect/rebase
```

A new AI request must not overwrite a newer user-approved edit.

Store enough revision information for undo and auditability.

Cancel must leave the original persisted frame untouched.

## 8. Preserve surrounding UI

Example:

Before:  
Navbar + Hero + Statistics + Projects + Contact

Instruction:  
Remove Statistics.

After:  
Navbar + Hero + Projects + Contact

No accidental:

- Navbar redesign.
- New color palette.
- Removed footer.
- Changed unrelated images.
- Rewritten testimonials.
- Duplicated sections.
- Broken HTML structure.

Avoid interpreting "edit selected element" as "regenerate entire screen".
