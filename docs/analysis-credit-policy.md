# Existing Codebase: initial analysis entitlement

One successful initial repository analysis is included per account for its lifetime. This is not an allocation per repository name, Git remote, project, subscription period, or payment. Accounts with a ready analysis or a historically settled/refunded codebase-analysis operation before rollout have already used the entitlement. A synced repository whose initial analysis never succeeded remains eligible if its account has no successful analysis. Failed attempts release the entitlement; ready results remain reusable without a charge.

`users.initial_analysis_used_at` retains the consumed entitlement across repository deletion and subscription renewal. The migration backfills only that entitlement marker; it neither refunds nor rewrites historical charges or ledger entries. Apply `0040_initial_analysis_allowance.sql` before deploying the application. Its additions and backfill are idempotent. The migration is tested in an isolated PostgreSQL schema. Development migration uses `pnpm db:migrate`; it adds columns/index and backfills entitlement metadata without removing data.

Allowance attempts use the existing `credit_operations` lifecycle with `initial_analysis_allowance = true`, zero reservation, and zero final charge. No zero-amount financial ledger entries are inserted because the ledger forbids them. A user-scoped transaction advisory lock and partial unique index permit only one active allowance operation per account. The entitlement is consumed in the same transaction as analysis persistence and settlement. Rename, duplicate records, deletion, refresh, and subscription renewal do not reset it. Creating another account remains an account-abuse concern, not repository identity verification.

Paid analysis uses the existing adaptive pricing version and snapshot metrics. Pre-sync displays the configured maximum (currently 12 credits), not a fabricated exact estimate. The final quote uses uploaded file count and byte size; final settlement uses those same metrics and cannot exceed the accepted maximum. Missing or outdated consent fails closed. Consent stored in a sync session applies only to its onboarding project, not every feature subsequently created for that repository. Starter-suggestion regeneration requires separate confirmation. An allowance promised at preflight never silently falls back to a paid charge if another request consumes it first.

Preflight reuses `GET /api/codebases?preflight=analysis`; final quote reuses the analysis POST with `preflight: true`. Neither reserves or charges credits. Repository creation and session retry require explicit policy acceptance before issuing CLI credentials. Home, onboarding, workspace sync, legacy project creation, analysis retry, and starter-suggestion refresh use the same server policy. Ready analysis returns before the billing gate.

Provider calls have a bounded timeout. Analysis reservations expire after ten minutes and are reconciled on preflight, trigger, and sync-status reads. Expired linked pending analyses become failed and their holds are released; late settlement is rejected. A disconnected browser does not itself release a running operation. With no traffic, reconciliation happens on the next read rather than a separate scheduler. Existing size, upload validation, authentication, and rate limits still apply. Paused subscriptions cannot start analysis, including the allowance; legacy paid subscriptions without an end date remain valid.
