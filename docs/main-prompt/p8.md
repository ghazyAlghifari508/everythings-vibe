## Architecture

Move canonical domain code into:

- `src/features/scrape/services/`
- `src/features/scrape/types/`
- `src/features/scrape/utils/`
- `src/features/scrape/tests/`

Separate responsibilities according to the existing implementation:

1. Scrape job lifecycle and persistence.
2. Browser rendering and crawler execution.
3. URL validation and SSRF protection.
4. HTML/CSS/design token extraction.
5. Image and asset storage.
6. Crawl graph and traversal utilities.
7. Worker initialization, shutdown, and recovery.
8. Extraction error mapping and instrumentation.

Avoid creating one monolithic scrape service inside the new directory.

## Critical Invariants

Preserve:

- URL filtering and SSRF restrictions.
- Redirect and network destination validation.
- Crawl depth and URL traversal constraints.
- Existing scraping limits and resource controls.
- Worker process isolation.
- Job creation, retries, cancellation, and recovery.
- Accurate progress and failure reporting.
- Data sanitization and extraction semantics.
- Asset access controls and storage paths.
- Existing DB persistence and job ownership checks.
- API response formats and error contracts.

Do not weaken security validation for easier refactoring.

## Worker Integration

When worker entry files move:

- Update relevant package scripts and process-entry references.
- Inspect child-process spawning logic and execution paths.
- Preserve development and production startup behavior.
- Preserve graceful shutdown and cancellation semantics.

- Do not introduce a second worker pipeline.

Keep the existing runtime and package manager configuration unchanged.
