## 1. UI Route Refactoring

Refactor oversized UI routes into focused route files.

Route responsibilities should generally be limited to:

- `createFileRoute` configuration.
- Route parameters and search schemas.
- Loader or server function connections.
- Route-level redirects.
- Error and pending component connections.
- Rendering feature-owned page components.

Extract substantial stateful UI logic into appropriate feature components and hooks.

Move business logic into feature services without breaking server/client boundaries.

Keep route files near the repository's 100–150-line target where technically appropriate.

Do not force a line limit by hiding complexity in one oversized component.

## 2. API Route Refactoring

Inspect and refactor oversized API handlers separately from UI routes.

Preserve:

- HTTP methods.
- URL paths.
- Request and response schemas.
- Status codes and error contracts.
- Authentication and authorization.
- Tenant isolation.
- Credit consumption boundaries.
- SSE streaming and cancellation.
- Retry and idempotency behavior.

Place reusable request validation, orchestration, and domain logic in appropriate feature-owned server modules.

Avoid reimplementing endpoints or changing their semantics.

## 3. TanStack Start Constraints

Preserve:

- Existing file-based route discovery.
- Route parameters and search validation.
- Correct loader execution behavior.
- Type-safe navigation and redirects.
- Server-only boundaries.
- SSR and client hydration.
- Existing lazy-loading and code-splitting behavior.

Do not introduce server-only imports into client components.

Keep framework-specific route definitions in the correct location.

Do not manually modify generated route files.
