## Architecture

Use cohesive locations under:

- `src/features/studio/components/`
- `src/features/studio/hooks/`
- `src/features/studio/types/`
- `src/features/studio/utils/`
- `src/features/studio/tests/`

Suggested internal component ownership:

- Workspace shell and layout.
- Canvas and frame rendering.
- Composer and prompt controls.
- Skills and design picker.
- Frame inspection and preview.
- Version/history presentation.

Only introduce these groups when beneficial.

## Preserve Existing UX

No changes to:

- Floating Studio layout and sidebar positioning.
- Canvas dimensions and zoom behavior.
- Frame sizing or corner radii.
- Shimmer states and generation feedback.
- DesignMD modal layout and tab sizing.
- Prompt composer and skill selection.
- Shortcut carousel.
- Existing keyboard/mouse behavior.
- Project selection and navigation.
- Light/dark appearance.

Do not rebuild existing UI primitives from scratch.

Reuse current components and existing approved libraries whenever relevant.

## Engineering Requirements

Update imports and associated tests.

Preserve component props, state lifecycle, callbacks, and asset references.

Keep existing Studio routes functioning without changing their URLs.

Avoid adding shared abstractions unless supported by multiple real consumers.

No duplicate components, orphan exports, unnecessary wrappers, or CSS regressions.

## Verification

Use focused component tests and static validation.

Verify compatibility through tests covering frame rendering, composer behavior, canvas state, and existing selection logic.

No browser QA, screenshot automation, Playwright execution, or UI redesign.

Commit the migration atomically, push the working branch, and report new module ownership and test results.
