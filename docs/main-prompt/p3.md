# TASK — Phase 3: Templates &amp; Admin Domain Migration

## Objective

Migrate the Templates and Admin domains to feature-driven modules while keeping their current functionality and appearance unchanged.

These domains should have independent ownership and must not be combined into a generic dashboard module.

## Mandatory Inspection

Read [`AGENTS.md`](http://AGENTS.md), [TODO.md](http://TODO.md) Bagian 7, and applicable `.agents/rules/`.

Inspect:

- `src/components/templates/`
- `src/components/admin/`
- `src/lib/services/admin-service.ts`
- `src/lib/services/admin-trend-utils.ts`
- `src/routes/templates.tsx`
- `src/routes/admin/`
- Related template helpers, API endpoints, and test files.

Discover additional domain-owned files through actual import graphs.

## Target

Use:

- `src/features/templates/`
- `src/features/admin/`

Create only the relevant `components/`, `hooks/`, `services/`, `types/`, `utils/`, or `tests/` directories.

## Implementation

### Templates

Move the template catalog, domain-specific filters, selection logic, blueprint metadata handling, and related tests into the Templates domain.

Preserve any genuine shared design primitives.

### Admin

Move admin metrics, charts, data transformations, management components, and domain-specific services into the Admin domain.

Keep reusable chart mathematics separate from user-management business logic where justified.

### Shared Boundaries

Do not move global layout, authentication infrastructure, or genuinely shared primitives solely because these domains import them.

Update imports throughout the repository and remove unused compatibility modules after consumers are migrated.

## Invariants

Preserve:

- Existing template selection and navigation.
- Template filtering and data presentation.
- Admin authentication and authorization.
- Admin user/project/feedback/transaction functionality.
- Existing data contracts and API behavior.
- Chart data calculations and reporting semantics.
- Responsive styling, loading states, and accessibility.

Never weaken admin authorization or expose server-side data to client bundles.

## Completion

Run relevant unit/component tests and static checks.

Update source-location-dependent tests where necessary without weakening their behavioral assertions.

No browser QA or Playwright browser execution.

Commit each domain as an atomic change, push to the working branch, and report verification evidence.

Do not expand this task into redesigning marketing pages or the entire global layout.
