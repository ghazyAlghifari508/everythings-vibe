Make VibeScrape a clearly independent top-level product surface throughout application navigation, history, links, breadcrumbs, SEO metadata, and return-navigation behavior.

Preserve the current UI design system. Improve information architecture without unrelated visual redesign.

## 2. Product Navigation

Make VibeScrape an independent navigation destination.

Expected information architecture:

HOME  
├── VibePlan  
├── VibeDesign Studio  
├── VibeScrape  
└── VibeTemplate

VibeScrape should not require entering a VibeDesign landing page before reaching its workspace.

Ensure:

- Navigation to Scrape uses `/scrape`.
- Scrape history uses `/scrape/history`.
- Scrape detail uses `/scrape/$id`.
- Studio navigation remains `/design/studio`.
- Home/history cards and shortcut links resolve correctly.

Do not duplicate navigation entries or introduce a second navigation system.

## 3. Return-Path Compatibility

Update Scrape-specific return path constants and Zod validation to use canonical URLs.

Preserve compatibility for saved links containing old `from` values.

Normalize supported legacy return values to safe new equivalents rather than breaking them.

Preserve:

- Filtered history return paths.
- Page index and page size.
- Sorting and selected mode.
- Returning from detail to history.
- Existing Studio-to-Scrape transitions.
- Browser back/forward behavior.

Never use arbitrary user-supplied URLs as redirect destinations.

## 4. Product Identity

Update route metadata and user-facing labels that incorrectly describe Scrape as a subfeature of Studio.

For example, current source includes titles resembling:

- `Scrap website | VibeDesign`
- `Hasil Scrape | VibeDesign`
- `Riwayat Scrape | VibeDesign`

Use consistent naming based on the existing product identity, with VibeScrape as the domain name.

Keep product copy concise, functional, and aligned with the current design system.

Do not launch a separate broad rebranding project.

## 5. Design Constraints

Preserve all component styling unless a narrowly scoped adjustment is required by the new navigation structure.

No:

- Unnecessary cards or generic dashboard UI.
- Large hero redesign.
- Decorative gradients/glows.
- Oversized tabs.
- Unnecessary animations.
- Duplicated history interfaces.

## 6. Verification

Add or update focused tests for:

- Canonical link destinations.
- Legacy return-path normalization.
- History round trips.
- Query/filter preservation.
- Correct page metadata.
- Studio navigation isolation.

Run targeted tests, TypeScript checks, and Biome validation.

Do not run browser QA or Playwright browsers.

Create atomic commits, push to the working branch, confirm clean git status, and report changes and tests.
